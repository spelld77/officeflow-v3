# 입력·하루 보기 가독성 후속 구현·검증

2026-10-16. 71번 상세설계의 개발 소스 구현·최종 전체/배율 검증 완료. 사용자 사용 확인 전이다.
사용자 자료·버전·배포물·Git 작업은 변경하지 않는다. 이전 68~70번의 미커밋 변경을 보존했다.

## 구현

- 저장/취소 동일 높이 최소 40 DIP·폭 최소 72 DIP·좌우 22 DIP 여백.
  공통 시간 +/-는 고정 32 DIP를 없애고 최소 36 DIP/글자 힌트와 내부 패딩을 사용한다.
- 일정 아래 독립 안내 구역을 없앴다. 일반 날짜/내일 안내는 표시하지 않고 날짜·요일 입력은 유지한다.
  DateCaution 공통 위젯은 위험 입력만 주황 칸/바로 아래 한 줄로 표시하고 해제 시 공간/색을 복원한다.
- 연도만 변경/같은 해 포함 180일 이상 이동/새 업무·알림의 먼 날짜를 구분한다.
  정상 연말/기존 장기 제목 변경은 강조하지 않는다. 명시적 최초 먼 날짜는 표시만 하고 새 변경 재확인을 강제하지 않는다.
- 새 경고가 스크롤 끝에 잘리는 사례를 실제 캡처에서 발견해 해당 행을 한 번 보여준다.
  여러 필드가 함께 바뀌면 현재 편집 중인 칸을 우선하며 같은 경고 갱신 때 반복 점프하지 않는다. 종료 시 대기 타이머를 정리한다.
- 실제 입력 오류의 빨간 표시가 주의의 주황 표시보다 우선하도록 focus 스타일도 보완하고 해소 시 주의 색으로 복원하는 검사를 추가했다.
- 직접 지정 알림 날짜/시각 유지 안내는 알림 행에 모으고 위험한 알림 날짜는 설정 버튼도 강조한다.
  알림 추가/수정에도 동일 날짜 강조를 사용한다. 기존 최종 저장 경계·확인 중 수정·실패 후 재시도는 유지한다.
- 월/하루 중요도 팔레트를 공유한다. 하루 일정 왼쪽 띠와 종일/목록 아이콘에 색을 사용하고 중요도 이름은 도움말에 제공한다.
- 시간표의 짧은 카드에도 상태 공간을 따로 확보한다. 업무는 진행/대기/완료/취소/보관, 알림은 예정/재알림/미확인/확인 필요로 구분한다.
  완료·취소·보관은 회색이며 반복은 회차 투영 상태를 따른다. 종일/목록/선택 상세도 같은 상태를 보여준다.
- 혼합 묶음은 첫 업무가 완료됐다고 전체를 회색 완료로 그리지 않는다. 개수/전체 목록에서 각 상태를 확인한다.
- 관리 표기는 점을 빼고 기존 QMenu 화살표만 사용한다. 하위 기능/트레이·선택/키보드 흐름은 유지한다.

  날짜칸 내부 요일·편집 섹션 3개·별도 요일 라벨 없음·키보드/팝업 검사는 유지했다.
- Ruff·mypy 151개 소스·이번 변경 Python 14개 format·diff 공백 검사 통과.
- 실제 Windows 150% 예비 30개 통과 후 주의 행 스크롤/캡처를 보완했다.
- 최종 소스의 Windows 100/150/200% 관련 60개씩 통과했다(`artifacts/readability-native-final-1.xml`,
  `readability-native-final-1.5.xml`, `readability-native-final-2.xml`). 밝은/어두운 앱 기본 팔레트와 좁은 창을 포함한다.
  편집창/알림 설정/하루 보기 캡처 18개를 남기고 최종 100/150/200% 대표 이미지도 직접 확인했다.
  실제 Windows 설정 자체의 밝음/어두움 전환이나 회사 PC 확인을 대신하지는 않는다.
- 마지막 입력 오류 색상 검토를 반영하기 위해 진행 중 전체 검사를 중단했다. 최종 소스로 다시 실행하며 중단 실행은 통과 집계에 넣지 않는다.
- 이후 전체 단일 프로세스 실행에서 기존 `test_document_lifecycle_ui.py`의 보기 사본 창 종료 경로가 약 3분 이상 대기해 중단했다.
  같은 파일을 단독 실행하면 원래 12개 검사가 3.01초에 통과했다(`artifacts/readability-lifecycle-isolated.xml`).
  단독 통과만으로 원인이 밝혀졌거나 실사용 종료 문제가 없다고 단정하지 않는다. 해당 첨부 처리 소스는 이번에 변경하지 않았다.
  먼저 이 12개와 나머지 파일을 독립 실행으로 나눠 확인했고, 이후 아래 최종 전체 재실행도 완료했다.
- 분리 실행의 나머지 1,561개 중 1,560개 통과/알림 회차 조회 1개 실패였다(`artifacts/readability-suite-partition.xml`).
  같은 소스의 해당 파일 6개는 재실행에서 모두 통과했다(`artifacts/readability-reminder-recheck.xml`).
  단독 통과만으로 최초 실패 원인을 확정하지 않으며 검사 시간 제한/알림 동작을 임의로 바꾸지 않았다.
  최종 전체 재실행 결과는 아래와 같다. 실패한 실행은 전부 통과라고 집계하지 않는다.
- 이어진 제한 환경 전체 재실행도 실패해 중단하고 최초 실패 지점을 `-x`로 확인했다.
  55개 통과 후 기존 첨부 보호 검사의 `os.link`에서 `WinError 5`(권한 거부)가 발생했다

  중단된 제한 환경 실행에는 완성 XML이 없으므로 최종 통과 집계에 넣지 않는다.
- 실사용 데이터/회사 보안 제품/실제 다중 모니터를 검증했다고 간주하지 않는다. 새 설치·EXE·Python ZIP은 이번 범위 밖이다.

## 확인 방법

개발 실행을 완전히 종료하고 `run-officeflow-dev.cmd`로 다시 연다.

1. 좁은 새 업무 창의 저장/취소·시간 +/-를 확인한다.
2. 일반 날짜를 바꾸면 별도 안내가 없고, 연도만 바꾸면 입력칸과 가까운 주의 표시/저장 확인이 나오는지 본다.
3. 알림 직접 지정과 종료/반복 날짜의 주의를 확인한다. 유효한 장기 일정 저장 자체를 막지는 않는다.
4. 하루 보기의 중요도 띠/업무 상태/알림 상태, 종일 완료·처리 이력·원래 반복 회차를 확인한다.
5. `관리`의 점이 없고 기존 데이터 관리/설정/도움말이 열리는지 확인한다.
