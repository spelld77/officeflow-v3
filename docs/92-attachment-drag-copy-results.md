## 구현과 사용자 흐름

- 현재 업무 첨부 목록/썸네일의 Ctrl/Shift 다중 선택을 사용한다. 선택 후 300ms 지연을 두고
  worker가 독립 사본을 미리 만든다. 준비 전 끌면 완료 뒤 다시 끌도록 안내한다.
- 준비 완료 상태를 목록 위에 표시한다. 실제 드래그는 사본 URL과 CopyAction만 전달한다.
  관리 파일/고정 원본/수정된 보기 사본 경로를 외부에 넘기지 않는다.
- 같은 표시 이름은 대소문자를 무시해 번호로 구분한다. 청크 읽기/취소, source pin,
  Windows protected_read, 전후 파일 identity, 고정 자료 해시와 준비 사본의 해시를 검증한다.
  한 파일이라도 실패하면 전체 배치를 준비 실패로 처리한다.
- 준비된 내용은 준비 시점의 저장 내용이다. 외부 편집 후에는 선택 해제/재선택으로 새로 준비한다.
  자동 파일 감시나 미저장 편집 내용을 반영하는 기능은 아니다.
- 외부 전달 후 드롭 성공 여부를 대상 파일 저장 검증 완료로 기록하지 않는다.
  목적지의 동명 파일 처리/복사 진행/취소는 탐색기가 담당한다.
- 드래그 중 자기 앱으로 돌아온 파일은 중복 첨부하지 않는다. 기존 외부 파일 받기는 유지한다.
- 준비 중 선택 변경은 취소/최신 요청으로 합친다. 종료 때 debounce·worker·native drag를 취소 요청하고
  ShutdownScope의 native join 뒤 소유 잠금을 해제한다. 종료 중 새 worker를 만들지 않는다.

한 번에 100개, 한 창의 보존 사본은 1GiB/32배치까지다. 넘으면 기존 저장 기능을 안내한다.
OS 임시 폴더의 무작위 소유 세션에만 저장하며 DB·백업·기존 보기 사본 원장과 분리한다.
외부 전달 직전에 마지막 전달 시각을 기록한다. 최소 24시간 지난 세션 중 소유 잠금이 해제되고
소유 표시/안전 경로가 확인된 세션만 다음 준비 worker가 정리한다. 다른 살아 있는 창은 삭제하지 않는다.
미전달 이전 배치는 다음 준비 때, 실패 배치는 실패 worker에서 정리한다. 종료 직전 남은 사본은
만료 정리에 맡기므로 앱 미실행 중 즉시 삭제되는 것은 아니다. 공통 계약은 24번 17절에 반영했다.

## 실패/중단과 보완

- 초기 새 검사 13개 중 2개는 QUrl의 `/`와 Windows Path의 `\`를 문자열로 비교한 검사 가정 때문에 실패했다.
  경로 객체 비교로 고쳤다. 기존 썸네일 설정의 setDragEnabled(False)도 발견해 export 서비스가 있을 때만 켜도록 보완했다.
- 기존 저장 검사 39개 중 덮어쓰기 1개·하드링크 1개가 제한 권한에서 실패했다.
  실제 사용자 자료 없이 실패한 두 합성 검사만 별도 권한으로 다시 실행해 통과했다.
- 기존 썸네일 파일 전체 실행은 60초 제한으로 중단했다. 출력 저장용 래퍼도 timeout stdout 타입 가정 때문에 실패해
  해당 실행은 완료 수에 포함하지 않는다. 영향이 큰 세 검사를 별도로 골라 통과했다. 전체 썸네일 완주를 주장하지 않는다.
- 중간/추가 실행은 고유 수에 합산하지 않는다. 전체 제품 회귀·장시간/대용량 stress는 실행하지 않았다.

## 운영 보존과 남은 확인

모든 DB는 tmp_path이며 앱/파일 작업은 자식 프로세스에 OFFICEFLOW_DATA_DIR와 소유 TEMP/TMP를 명시했다.
운영 실행 cmd·DB·첨부·설정·사용 중인 프로세스·실행 폴더를 사용하거나 변경하지 않았다.
이번 소유 fixture는 안전 경로 확인 후 정리하고 XML/작은 캡처를 보존한다.
사용자 추가 결정은 현재 없다. 탐색기·바탕화면의 실제 드롭, 느린 목적지/네트워크 폴더,
회사 보안 환경과 실사용 동시 종료는 별도 확인이다. 배포가 필요하면 Python ZIP 원칙을 따른다.
