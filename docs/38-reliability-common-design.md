# 운영 신뢰성·자료 조회 개선 공통설계

작성일: 2026-10-10. 사용자 승인: 공통설계와 1차 상세설계·구현·격리 테스트.
후속 승인: 1차 사용 확인 완료, 2차 상세설계·구현·테스트까지 진행(41번 상세설계).
추가 승인: 2차 사용 확인 완료, 3차 상세설계·구현·테스트(43번 상세설계).
최종 후속 요청: 오늘 완료한 새 1~3차의 3.0.9 마감·배포물 재생성·커밋·공개(45번 체크리스트).
U17 폴더 바로가기/U16 외부 업무 묶음과 내부 정리는 이번에 계획 기록만 하며 구현하지 않는다.
기존 자료 보존 계약은 [24번 공통설계](24-follow-up-common-design.md)를 유지한다.

## 범위와 차수

| 차수 | 범위 | 다음 단계와 공유할 계약 |
| --- | --- | --- |
| 1차 | 백업 실패 안내, 수동 자료 검사, 종료/예외 진단 | 자료 종류·안전 경로·상태 분류·읽기 전용 조회 |
| 2차 | 보관 자료 검색, 백업에서 선택 파일 외부 저장 | 첨부/보관본/중요 보관 파일의 ID와 당시 이름을 구분 |
| 3차 | 달력·오늘의 일정/알림 묶음 표시(U1) | 업무 ID와 원래 반복 회차 시각, 독립 알림 상태 |

1 → 6 → 3 → 4 → 5의 순서다. 2차/3차 상세설계는 앞 차수 사용 확인 뒤 작성한다.
보기 사본의 백업 제외 안내(이전 제안 2번)는 사용자 요청으로 제외한다.
U16 장기 자료 정리·자동 삭제·자료 자동 복구·외부 동기화는 이번 범위가 아니다.
버전 변경, EXE/ZIP/설치 파일, 커밋·GitHub 업로드는 별도 요청 때 한다.

## 공통 계약

- 자료 검사는 읽기 전용이다. 해시/이름/원장/내용을 자동 갱신하지 않는다.
- 실제 파일 단위는 자산 ID, 사용자 항목은 첨부/보관본/중요 보관 파일 ID다.
  한 파일의 공유 참조를 중복 검사하지 않고 종류를 함께 표시한다.
- 일반 첨부·작업본의 수정은 정상 편집일 수 있다. frozen의 기준 불일치와 구분한다.
- 누락, 보관 후 변경, 기준 없음, 읽기/잠금/복구 보호로 확인 불가를 구분한다.
- 검사는 사용자가 요청할 때 worker에서 스트리밍한다. 정상 시작에 전수 해시를 추가하지 않는다.
  페이지·결과 표시 상한, 취소, GUI 스레드 전달, 안전한 종료를 모든 단계에서 유지한다.
- 진행 중 사용자 변경을 한 시점의 전수 검사로 약속하지 않는다. 시작 범위 상한을 고정하고
  파일별 참조/기준 변경은 확인 불가로 표시한다. 검사 이후 편집까지 보장하지 않는다.
- 검색 결과/검사 보고를 영구 삭제 권한으로 사용하지 않는다. 백업 선택 저장도 내부 복원이 아니다.
- 로그에는 업무 제목·설명·결과·첨부 메모·문서 내용·계정 비밀을 기록하지 않는다.
  오류 종류와 코드 위치를 기록하며 상세 정보는 사용자 자료 화면에서만 확인한다.
- 보안 제품/OS의 강제 종료 전 안내나 모든 native crash의 원인 확보를 보장하지 않는다.
  감시 프로세스/자동 재시작을 추가하지 않는다.
- 밝은 공통 스타일과 viewport/선택/비활성 색을 명시한다. 좁은 창에서도 핵심 동선에 접근한다.

## 완료 기준

각 차수는 상세설계 → 구현 → 정상/실패/취소/테마·레이아웃 검사 → 사용자 확인 순서다.
DB 스키마는 필요한 차수에만 바꾼다. 1차는 업무 DB/백업 형식 변경이 필요 없다.
이전 U16 문서 변경은 그대로 보존한다. 실제 운영 프로필은 테스트에 사용하지 않는다.
