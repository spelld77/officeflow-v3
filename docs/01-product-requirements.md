# 제품 요구사항

문서 상태: Draft 0.1
기준 제품: OfficeFlow v3
대상 사용자: Windows에서 개인 업무를 관리하는 단일 사용자

## 1. 문제 정의

기존 버전은 업무가 하루에 많이 쌓이면 긴 목록을 스크롤해야 하며, 시작일과 종료일이 다른 기간 일정을 표현할 수 없다. 기능이 하나의 대형 UI 클래스에 집중되어 있어 화면과 데이터 구조를 크게 변경하기도 어렵다.

OfficeFlow v3는 다음 문제를 우선 해결한다.

- 많은 업무 중 지금 처리해야 할 업무를 빠르게 찾기 어렵다.
- 하루를 넘는 출장, 점검, 제출 기간 같은 일정을 등록할 수 없다.
- 업무, 캘린더, 업무일지와 첨부파일 사이의 이동이 단절되어 있다.
- 반복 업무가 하나의 레코드를 갱신하는 방식이어서 발생 건별 이력을 다루기 어렵다.
- 기존 데이터가 손실될까 봐 새 버전으로 옮기기 어렵다.

## 2. 제품 목표

### G1. 대량 업무 탐색

- 사용자는 오늘 화면에서 지연, 진행 중, 다음 업무, 시간 미정, 완료 업무를 구분해서 본다.
- 검색 결과는 입력 중 갱신되고 제목, 설명, 업무일지를 대상으로 한다.
- 날짜, 상태, 중요도, 반복 여부, 첨부 여부를 조합해 필터링한다.
- 중요 업무를 상단에 고정할 수 있다.
- 완료 업무는 기본적으로 접혀 있어 활성 업무 탐색을 방해하지 않는다.

### G2. 기간 일정

- 업무는 일정 없음, 하루 일정, 여러 날 일정 중 하나로 등록할 수 있다.
- 종일 일정과 시간이 있는 일정을 모두 지원한다.
- 사용자가 입력한 종료일은 일정에 포함된다.
- 월간 캘린더에서 여러 날 일정은 이어진 막대로 표시한다.
- 일정 중간 날짜를 선택해도 해당 업무를 찾을 수 있다.
- 시작 전과 종료 전 알림을 각각 설정할 수 있다.

### G3. 신뢰할 수 있는 알림

- 알림, 다시 알림, 완료, 대기 전환을 제공한다.
- 동일한 알림이 중복 표시되지 않는다.
- 앱 재시작 후 놓친 알림을 정책에 따라 한 번만 복구한다.
- 반복 업무의 각 발생 건은 독립적으로 완료 또는 건너뛰기 처리한다.

### G4. 데이터 보존

- 기존 DB를 수정하기 전에 타임스탬프가 포함된 백업을 만든다.
- 이전 전후 업무, 일지, 첨부파일 개수를 비교한다.
- 변환 실패 항목은 건너뛰지 않고 오류 보고서에 남긴다.
- 이전 실패 시 기존 DB와 첨부파일은 변경하지 않는다.

## 3. 1차 출시 필수 기능

### 업무

- 빠른 등록, 상세 등록, 수정, 완료, 대기, 취소, 보관
- 제목, 설명, 중요도, 시작·종료, 종일 여부, 반복, 알림
- 고정, 체크리스트, 결과 메모
- 첨부파일 추가, 열기, 연결 해제

### 탐색

- 오늘, 예정, 중요, 대기, 완료, 전체 업무 보기
- 검색, 복합 필터, 정렬, 그룹 접기
- 선택 업무 상세 패널
- 키보드 탐색과 주요 단축키

### 캘린더

- 월간 보기
- 하루 및 여러 날 일정 표시
- 날짜 선택을 통한 업무 필터링
- 일정 생성과 편집
- 오늘 이동, 이전·다음 달 이동

### 알림과 실행

- 시스템 트레이
- 앱 중복 실행 방지
- 지정 시각 알림과 다시 알림
- Windows 시작 시 실행 옵션
- 앱 종료와 창 숨기기 구분

### 기록과 데이터

- 업무 완료 기록과 업무일지
- 수동 및 자동 백업
- 기존 v2.6 데이터 가져오기
- Excel 및 ICS 내보내기

## 4. 비기능 요구사항

- 5,000개 업무가 있는 기준 데이터에서 일반 검색과 날짜 필터는 목표 장비에서 200ms 이내에 결과를 반환한다.
- 목록은 한 번에 모든 위젯을 생성하지 않고 Qt 모델/뷰와 지연 로딩을 사용한다.
- UI 스레드에서 장시간 DB 작업이나 파일 복사를 실행하지 않는다.
- 데이터 변경은 트랜잭션으로 처리한다.
- 사용자 데이터 파일 위치와 로그 위치를 명확히 분리한다.
- 예외를 조용히 무시하지 않고 사용자 메시지와 진단 로그로 구분한다.
- 기본 글꼴 배율 100~200%와 키보드 사용을 지원한다.
- 전체화면을 전제로 하지 않으며 760×560 이상의 창 크기에서 핵심 업무 탐색과 등록 기능을 사용할 수 있어야 한다.
- 한국어를 기본으로 하되 문자열은 UI 코드와 분리한다.

## 5. 초기 범위에서 제외

- 여러 사용자와 권한 관리
- 실시간 공동 편집
- 클라우드 계정 동기화
- 모바일 및 웹 앱
- 이메일 비밀번호 직접 저장
- AI 자동 분류와 요약
- 외부 캘린더 양방향 동기화

제외 항목은 데이터 모델을 깨뜨리지 않는 범위에서 후속 버전 후보로 관리한다.

## 6. 핵심 수용 기준

1. 하루에 50개 업무가 있어도 사용자가 지연 업무와 다음 업무를 별도 그룹에서 바로 확인할 수 있다.
2. 9월 14일부터 17일까지의 종일 일정을 한 번 등록하면 네 날짜 모두에서 조회된다.
3. 기간 일정은 월간 캘린더에서 가능한 범위까지 연결된 막대로 표현된다.
4. 검색어와 필터를 함께 적용하고 한 번에 초기화할 수 있다.
5. 반복 업무 한 건을 완료해도 이후 반복 일정은 유지되고 해당 발생 건의 완료 기록이 남는다.
6. v2.6 샘플 DB를 이전한 뒤 원본 수량과 변환 결과를 확인할 수 있다.
