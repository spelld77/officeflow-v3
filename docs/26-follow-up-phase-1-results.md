# 후속 개선 1차 구현·검증 보고

날짜: 2026-10-08. 상세설계: [25](25-follow-up-phase-1-design.md).
상태: 1차 코드 구현·개발 환경 검증 및 사용자 사용 확인 완료.
구현·자동 검증에서는 실제 사용자 데이터/버전/EXE/ZIP/커밋/GitHub를 변경하지 않았다.
2026-10-08 사용자 요청에 따라 이 확인 기록과 관련 소스를 로컬 커밋한 뒤 2차 상세설계를 진행한다.
GitHub 업로드·버전 변경·EXE/ZIP 재생성은 이번 작업 범위가 아니다.

## 사용자 사용 확인과 기준점

2026-10-08 사용자가 `사용확인했다`고 알렸다. 새 수정 요청 없이 1차를 완료 기준점으로 남기고
2차 상세설계로 진행하도록 승인했다. 이는 사용 확인이며 미검증 환경 전체의 안전 보장은 아니다.
아래 자동 검증 결과와 미검증 범위는 그대로 유지한다.

로컬 커밋 대상은 관련 코드·DB migration·테스트·지침·설계/사용 문서다.
운영/개발 DB·첨부·백업·로그·테스트 생성물·배포물은 포함하지 않는다.
Git 기준점은 소스 복구용이다. DB/첨부 복구는 호환되는 프로그램과 전체 백업으로 별도 수행한다.

## 반영 범위

- U2: 실제 업무/회차 상태와 알림 처리 이력 분리. 완료 때문에 기확인 이력을 덮어쓰지 않으며
  미발생 미래 예약을 가짜 처리 이력으로 만들지 않는다. 오늘/달력의 유효 수·이력·확인 필요를 구분한다.
  열린 업무/알림 창은 runtime만 갱신하고 초안·하위 입력·선택·스크롤·원래 저장 충돌 기준을 유지한다.
  회차 상태는 읽기 스냅샷 안에서 일괄 조회한다. 다음 예약 계산용 닫힌 회차는 최대 512개로 제한한다.
- U4: 최초 크기/해시를 유지하고 최근 관측 6컬럼을 별도 저장한다. 기존 기준 없음은 소급 채우지 않는다.
  보이는/선택한 첨부 최대 100개의 stat 표본을 worker에서 확인하고 오래된 결과는 버린다.
  전체 내용 확인은 명시적 요청/저장/중복 판별 때만 한다. 정상 편집은 `첨부 후 수정됨`으로 안내한다.
  중복은 최초 해시가 아닌 안정적으로 읽은 현재 내용으로 판정한다. 확인 못한 후보 때문에 새 파일을 버리지 않는다.
  사용량은 실제 디스크 크기, 중복 집계는 최근 관측 후보로 표시한다.
- U3/U6: 표준 단일 저장/폴더 선택, Ctrl/Shift 선택, 선택을 보존하는 오른쪽 메뉴,
  같은 업무의 여러 첨부 저장, 자동 번호, 부분 결과, 실패/미처리만 재시도.
  내부 연결/파일은 유지한다. 현재 저장된 내용을 복사하고 문서는 자동으로 열지 않는다.
  검색 단일 결과와 해제/휴지통 첨부에도 같은 저장 서비스를 사용한다.
- U8 일부: 첨부 정리의 열기/외부 저장과 복원/영구 삭제를 분리한다.
- 공통 안전: 생성자에서 파일 조정자를 공유 주입한다. 큰 파일 작업 한 개씩, 취소 가능한 대기,
  앱 내 사용 예약과 Windows 쓰기/삭제 공유 금지 읽기 핸들, 1 MiB 스트리밍,
  독립 준비 파일 검증, 덮어쓰기 없는 새 파일 공개, 복구 파일을 남기는 ReplaceFileW 교체.
  업무 영구 삭제는 DB CASCADE 전에 파일 예약을 검사한다.
- 외부 작업 저널: `external-file-operations`에 정확한 경로/검증값/준비 파일 식별을 보존한다.
  재시작은 중단 확인을 알릴 뿐 사용자 폴더를 자동 변경하지 않는다.
  `데이터 → 첨부 정리 → 중단된 저장 확인`에서 명시적 복구/정리를 제공한다.
  이미 성공한 출력은 재출력하지 않고 이후 수정된/미분류 자료는 보존한다.
  부분 복사의 완성 내용/소유를 확정할 수 없으면 자동 정리하지 않고 위치를 안내한다.

## 스키마와 이행

- head: `0012_attachment_observation` (이전 `0011_attachment_sort_order`). 새 관측 필드는 nullable이다.
- 기존 정보/순서/경로/파일 내용은 유지하고 migration에서 파일을 해시하거나 이동하지 않는다.
- 이행 전 DB 보호 사본은 `data/schema-backups/pre-attachment-observation-*.db`에 생성한다.
- 새/옛 백업 복원 후 이행 및 관측 정보와 현재 저장 내용의 전체 백업/복원을 검사했다.
- 구버전 코드로 새 DB를 열지 않는다. 되돌릴 때는 이전 프로그램과 이행 전 전체 백업을 별도 데이터 루트에 복원한다.
- 외부 독립 사본과 외부 임시/복구 파일은 OfficeFlow 전체 백업이 대신 보관하지 않는다.

## 검증

- 기존 테스트 포함 전체 회귀: **700개 통과**, 81.26초.
- 사용자 사용 확인 후 로컬 커밋 직전 재검사: **700개 통과, 1개 제외**, 74.89초.
  제외한 것은 앞서 검증한 1 GiB 대용량 스트리밍 검사이며 실패/건너뜀을 성공으로 센 것이 아니다.
  이 재검사는 offscreen 환경이다. 실제 Windows 렌더러/배율 검사는 아래 기존 결과와 구분한다.
- Ruff / mypy: 통과 (87 source files). `git diff --check` 통과.
- 새 격리 데이터 루트의 실제 부트스트랩/이행/서비스 연결/종료 smoke test 통과.
- 최종 Windows 렌더러의 GUI 취소·저장·휴지통·초안 보존 검사 6개 통과.
- 마지막 저장 폴더를 이미 열린 첨부/검색 창에도 공유하도록 보완한 뒤 관련 UI 회귀 40개 통과.
  신규 폴더 공유 테스트 1개는 위 전체 700개 실행 이후 추가했다.
- 실제 Windows 자식 프로세스를 복사 중/새 공개 전·후/덮어쓰기 전·후에 강제 종료한 5개 검사.
  출처와 기존 대상/완료 출력 보존, 정확한 저널 확인, 재출력 없이 확인 가능한 잔여물만 정리.
- ReplaceFile 부분 실패, 대상 경쟁, 명시적 복구, 사용자 확인 후 변경, 잠금/공간 부족,
  파일 예약 중 삭제, 큐 대기 취소, 관측 DB 오류, 중복 판별 A→B, 최초 기준 없음,
  잘못된 저널과 설정 필드 오류를 격리 자료로 검사.
- Ctrl/Shift·오른쪽 메뉴·선택 유지·표준 선택창 기본 이름·휴지통 저장·실패만 재시도·
  GUI 취소·긴 작업 중 업무 완료/다른 행 선택·열린 알림 초안/저장 충돌을 검사.
- Windows Qt 렌더러에서 한글을 포함한 기록/저장 결과/복구 창 캡처를 직접 확인했다.
  Qt 배율 100%/150%/200%, 좁은 창 및 어두운 QPalette 입력에서 밝은 UI 대비/핵심 버튼 접근을 확인.
  offscreen 검사만으로 끝내지 않고, 실제 Windows 검사에서 발견한 진행창 종료/취소 연결 문제를 수정했다.

## 테스트 실행과 다음 단계

프로젝트 루트의 `run-officeflow-dev.cmd`를 더블클릭하면 현재 소스로 실행하고
프로젝트의 `.local-data`를 사용한다. 회사 운영 데이터에 대한 자동 테스트는 수행하지 않았다.
기존 테스트 데이터로 시작할 때도 최초 이행이 있으므로 중요한 내용은 전체 백업 후 확인한다.

권장 사용 확인 흐름은 파일 하나 저장 → 여러 파일 저장 → 편집 후 사본 내용 확인 → 알림 처리 후 열린 편집 상태다.
사용자 사용 확인은 완료했다. 로컬 커밋 후 2차 상세설계(원본/작업본/보관본/메모/보기 캐시)로 진행한다.
달력 일정/알림 행 통합(U1), 처리필요 변경, 2·3차 기능은 아직 구현하지 않았다.

미검증: 회사 보안 제품, 실제 OS 테마/시스템 DPI 설정을 각각 전환한 전 조합,
회사 네트워크·외부 문서 편집기별 공유 잠금, 전원 차단/저장 장치 고장.
Windows API가 거절한 잠금·교체에 우회 복사 fallback을 하지 않는다.
외부 관리자/탐색기의 동시 변경과 하드웨어 장애까지 완전한 파일시스템 트랜잭션으로 보장하지 않는다.
