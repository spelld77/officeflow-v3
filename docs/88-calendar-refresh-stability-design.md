## 3. 갱신을 세 경로로 나누기

| 조건 | 처리 | 선택 처리 |
| --- | --- | --- |
| 표시·행 데이터·표시 맥락이 모두 같음 | Qt setter/clear/선택 변경 없이 반환 | 기존 선택/스크롤 유지, 선택 신호 0회 |
| 행 키 순서가 같고 일부 내용/상태만 변경 | 기존 항목의 달라진 text/tooltip/data/색/높이만 갱신 | setCurrentItem 없이 기존 current 유지 |
| 날짜 또는 행 구성/순서가 실제로 변경 | 기존 전체 구성 경로를 제한적으로 사용 | 목록 구성 완료 후 필요한 선택만 한 번 복원 |

이번 단계에서는 QListView 모델 전환이나 복잡한 행 이동 알고리즘을 도입하지 않는다.
구조가 바뀌는 경로에는 Qt 선택 설정이 남는다. 이 경로에서도 재발하면 별도 native 증거와 함께 재설계한다.

### 3.1 재알림 입력의 변화 확인

`set_snoozed_reminders`는 전달받은 Mapping을 복사한 뒤 저장된 값과 비교한다.
같은 dict 객체라는 이유로 생략하거나 호출자가 나중에 바꿀 수 있는 원본을 보관하지 않는다.
동일한 값이고 표시 날짜/시간대 등 표시 맥락도 같으며 미반영 입력·선택 요청·캐시 무효화가 없을 때만 목록 갱신을 요청하지 않는다.
직전 입력과 같은지는 적용 성공 여부와 다르다. 실패/재진입으로 미반영 상태라면 동일 원장도 반영 대상으로 남긴다.
다른 날짜의 업무 재알림만 바뀐 경우 새 원장은 보관하되 현재 행 출력이 같으면 Qt에는 쓰지 않는다.

재알림 시간 문구는 `format_snoozed_time`이 현재 지역 날짜를 사용한다.
따라서 원장이 같아도 자정·시간대 변경 시 문구를 재평가한다. 기존 자정/날짜 전환 갱신도 유지한다.
원장 비교만으로 모든 갱신을 차단하지 않는다.

### 3.2 순수한 표시 계산과 Qt 반영 분리

기존 merge_day_reminders와 calendar_row_key의 합치기/정렬 계약을 그대로 사용한다.
Qt 객체를 생성하기 전에 행별로 다음 불변 값을 계산한다.

- 논리 행 키, ScheduledTask 또는 ReminderGroup의 최신 payload
- text, tooltip, foreground, sizeHint에 필요한 값
- 선택 날짜·시간대·지역 오늘 날짜·compact/폰트/배율 등 표시 맥락
- 건수/완전성/추가 조회·설명 문구·열린 알림 상세에 필요한 상태

화면 문구만 같아도 payload가 바뀌면 UserRole을 최신 값으로 바꿔야 한다.
중요도·상태·첨부·원래 회차·알림 대표/전달 ID 변경을 놓치지 않도록 전체 불변 payload를 비교한다.
명시적 필드 비교를 쓰는 경우 해당 데이터 종류의 모든 동작 관련 필드를 포함하는 검사를 둔다.
업무 ID만 같다는 이유로 갱신을 생략하지 않는다. 비교 비용은 현재 적재된 행/재알림 원장 범위로 제한한다.
추가 DB 조회·파일 I/O·전체 일정 전개를 UI 경로에 넣지 않는다.

### 3.3 같은 행은 기존 항목 유지

키 순서가 같으면 clear/addItem/setCurrentItem을 호출하지 않는다.
같지 않은 속성에만 setter를 호출하고, 새 알림 묶음/일반 업무로 바뀌어도 같은 논리 행이면 항목을 재사용한다.
QSignalBlocker는 부분 변경 중 불필요한 외부 선택 처리를 막는 용도로 유지한다.
동일 키의 데이터가 바뀌었다면 `_selected_task`와 버튼 상태를 최신 payload로 동기화한다.
선택된 업무의 동작 데이터가 바뀐 경우에만 상위 선택 동기화 신호를 최대 한 번 전달한다.
미선택 행의 재알림 문구만 바뀌면 taskSelected/taskSelectionCleared를 내보내지 않는다.
기존 업무 보기의 미저장 입력을 갱신하거나 창을 새로 열지 않는다.

부분 갱신도 행 높이·글꼴·스크롤바/주변 패널 배치가 달라지면 화면 위치가 바뀔 수 있다.
이 경우 반영 전에 위쪽 행 키/픽셀 오프셋을 저장하고 최종 배치 후 복원한다.
선택을 복원하려고 setCurrentItem을 호출하지 않는다. 높이/배치 변화가 없는 내용 변경에는
doItemsLayout/scrollToItem/스크롤 setter도 호출하지 않는다.

## 4. 선택·스크롤 계약

단일 보조 함수로 일반 업무와 ReminderGroup의 논리 키를 통일한다.

```text
일반 업무: (task.id, None)
반복 회차: (task.id, 원래 occurrence_start)
알림 묶음: group.key (기존 reminder_scope_key 규칙)
표시 범위: (selected_date, timezone, mode)로 별도 구분
```

날짜가 이동된 회차도 실제 표시 시각으로 키를 바꾸지 않는다.
표시 문자열·row 번호·Python 객체 identity·대표 알림 하나의 ID를 논리 키로 쓰지 않는다.
그룹에 scheduled가 없어도 그룹 키로 선택을 유지한다. `_selected_task`만으로 선택을 복원하지 않는다.
저장 전 id=None 자료가 들어오거나 키가 중복되면 잘못 재사용하지 않고 명시적인 재구성 경로로 처리한다.

재구성은 다음 순서다.

1. Qt currentItem의 논리 키와 맨 위 보이는 행 키/픽셀 오프셋·스크롤 값을 캡처한다.
2. 신호 차단 범위에서 모든 행을 구성한다. 행 생성 중 선택을 바꾸지 않는다.
3. 같은 표시 범위이고 선택 키가 남아 있을 때만 구성 완료 후 한 번 선택한다.
4. 기존 키가 사라졌으면 임의로 첫 행을 선택하지 않는다. 기존 선택 해제/상위 상태 정리를 한 번 수행한다.
5. 위쪽 기준 행이 남으면 그 행과 오프셋으로 복원하고, 없으면 이전 스크롤 값을 유효 범위로 제한한다.
6. 건수·버튼·알림 상세·추가 조회/접근성 설명을 반영한다.

`preserve_selection=True`의 월 overview→day rows 교체 중 임시 빈 목록 계약을 유지한다.
이 때 논리 선택은 보관하되 행이 없는 동안 동작 버튼을 비활성화한다.
최종 day rows에서도 항목이 없어졌으면 선택을 해제한다. 입력 함수의 월/일 결과 갱신 목적을 구분한다.
날짜/보기 전환은 기존 선택 해제 규칙을 따른다. 다른 날짜에 같은 업무가 있다는 이유로 자동 재선택하지 않는다.
명시적인 알림 날짜 클릭의 `_alarm_focus_date`는 기존처럼 대상을 선택/스크롤하고 한 번 소비한다.
변경 없음 판정 때문에 대기 중인 사용자 포커스 요청을 누락하지 않는다.

### 4.1 사용자 선택과 자동 보존을 구분

`MonthCalendarWidget.taskSelected → CalendarPage._select_task`도 명시적인 사용자 선택이다.
현재 행만 선택 근거로 삼으면 달력에서 다른 업무를 클릭해도 이전 행을 유지하는 회귀가 생긴다.
업무 클릭과 알림 클릭은 대상 범위/키를 가진 일회성 선택 요청으로 처리하며 자동 갱신의 무변경 판정보다 우선한다.
이미 같은 항목이 선택되어 있으면 불필요한 선택 setter는 생략한다. 새 선택은 행 반영 후 한 번 적용하고
상위 상세 동기화도 한 번만 전달한다. 기존 `_select_task`의 직접 emit과 갱신 후 emit을 중복하지 않는다.
날짜/보기 이동 또는 더 새로운 사용자 선택은 이전 요청을 취소한다. 알림 클릭의 지연 포커스 계약은 유지한다.
따라서 3절의 '선택 신호 0회'는 별도의 사용자 요청이 없는 자동 갱신에 적용한다.

### 4.2 임시 결과와 최종 결과의 선택 수명

`preserve_selection` 호출 인자만으로 로딩 상태를 추측하지 않는다. `set_overview`에서 시작한
월→일 교체 상태와 범위가 지정된 논리 선택 의도를 따로 보관하고 `set_day_tasks`에서 종료한다.
중간 재알림/preview 갱신은 이 의도를 지우거나 최종 결과로 확정하지 않는다.
임시 결과에는 알림 전용 행이 남을 수도 있으므로 '목록이 비었는가'를 로딩 판별 조건으로 쓰지 않는다.
사용자가 그 중 다른 행을 선택하면 이전 복원 의도를 취소한다. 날짜/보기 이동도 취소 경계다.

최종 빈 결과가 임시 빈 결과와 행 단위로 같아도 선택 의도 해제/상위 상세 정리는 실행한다.
현재 일 조회 실패는 MainWindow가 `set_day_tasks(())`를 호출하므로 같은 종료 경계를 사용하고,
기존 오류 안내를 유지한다. 별도 조회 실패 UI나 새로운 조회 프로토콜은 추가하지 않는다.
로딩 상태·선택 의도·선택 동작 payload·버튼/상세 상태는 행 projection과 별도로 비교한다.
목록이 같다는 이유로 이 상태 정리를 생략하지 않는다.

## 5. 갱신 상태와 재진입

CalendarPage 안에 마지막 반영된 행 표시 정보만 보관한다. 전역 캐시나 이전 날짜별 원장을 만들지 않는다.
표시 범위/폰트/배율/compact 변경은 표시 캐시를 무효화한다. 데이터 원장은 mode와 무관하게 최신 값으로 유지한다.
월 모드 복귀/새 날짜 조회에서는 범위가 맞는 최신 스냅샷을 그리며 다른 날짜의 지연 결과를 표시하지 않는다.

Qt 반영 중 `_refresh_day_list`가 다시 요청되면 중첩 반영하지 않고 pending 상태에 최신 입력을 합친다.
정상 반환 후 다음 GUI turn에 한 번 처리한다. 무한 동기 재실행 루프를 두지 않는다.
필요한 단일-shot timer/slot은 생성 시 연결하고 종료 시작 시 취소한다. 종료 중 새 worker나 창을 만들지 않는다.
적용 성공 후에만 마지막 반영 상태를 갱신하며, 실패하면 캐시를 무효화하고 기존 예외 진단 경로로 알린다.
Qt의 C++ 호출이 반환하지 않는 상황을 이 재진입 처리나 Python 예외 처리로 복구할 수 있다고 설명하지 않는다.

각 반영은 시작 시 입력 스냅샷과 로컬 변경 번호를 캡처한다. 반영 도중 setter가 호출되면
최신 원장과 변경 번호만 갱신하고 pending에 합친다. 완료 캐시는 실제 적용한 스냅샷으로 기록하며,
도중에 도착한 최신 입력을 적용 완료로 잘못 기록하지 않는다. pending은 그 변경 번호까지 처리한 뒤에만 해제한다.
최종 일 결과/명시적 선택/날짜 전환의 의미를 단순한 마지막 `preserve_selection` 값으로 덮어쓰지 않는다.
예외 시 즉시 무한 재시도하지 않고 캐시를 무효화한 채 다음 정상 갱신 기회를 기다린다.
기존 CalendarPage.shutdown에서 예약 타이머를 중단하고 종료 플래그를 설정하며 콜백도 종료 여부를 확인한다.

## 6. 구현 순서와 검증 계획

구현 요청 후 동일한 작업 안에서 아래 순서로 진행한다. 단계별로 범위를 넓히기 전에 관련 검사를 통과시킨다.

1. 입력 비교·표시 날짜 처리와 행 projection/키 보조 함수를 추가한다.
2. 같은 행 순서의 변경 없음/부분 갱신을 적용한다.
3. 실제 재구성의 선택/스크롤·알림 그룹·임시 빈 결과 계약을 정리한다.
4. 관련 자동/Windows UI 검증 결과와 미검증을 별도 결과 문서에 기록한다.

| 검사 | 확인할 결과 |
| --- | --- |
| 같은 재알림 입력 반복, 빈 원장 포함 | QListWidgetItem/currentItem 유지, 모델 reset/선택 신호 0회 |
| 재알림 추가·시각 변경·해제, 보이지 않는 업무 변경 | 필요한 문구만 변경, 기존 선택/스크롤 유지 |
| 같은 문구·같은 키지만 업무/알림 payload 변경 | UserRole/선택 동작 대상/버튼은 새 데이터, 옛 알림 ID로 동작하지 않음 |
| 일반 업무↔알림 묶음, 알림만 존재, 대표 알림 변경 | 같은 논리 행의 선택 유지, 알림 상세/완전성/건수 정확 |
| 완료/취소·추가/삭제·정렬 변경 | 미완료 우선 정렬, 살아 있는 선택·스크롤 유지, 삭제된 선택 해제 |
| 반복/이동 회차, 다일 일반 업무 | 원래 회차 키 보존, 날짜 이동으로 잘못된 회차를 열지 않음 |
| overview 임시 빈 결과→day rows | 선택 의도 보존, 빈 동안 비활성, 실제 누락은 최종 해제 |
| 임시 결과 사이 preview/재알림 갱신, 최종 빈 결과/조회 실패 | 중간 갱신은 복원 의도 유지, 같은 빈 행이어도 최종 상세/선택 정리 |
| 달력에서 다른 업무 클릭, 같은 업무 재클릭, 중간 사용자 선택 | 사용자 요청 우선, 행과 상세 일치, 선택 setter/상위 신호 중복 없음 |
| 동일 키 행의 높이/주변 배치 변경 | 위쪽 기준 행/픽셀 위치 보존, 내용만 변경 시 추가 스크롤 조작 없음 |
| 자정·시간대·mode·compact·DPI/폰트 변경 | 캐시 무효화, 재알림 문구/높이/배치 최신화 |
| 알림 포커스 지연·사용자 날짜 이동 | 대상 날짜에서만 한 번 선택, 반복 자동 갱신으로 스크롤을 뺏지 않음 |
| 갱신 중 추가 요청·실패·종료 | 실제 적용 스냅샷만 캐시, 최신 요청 누락 없음, 실패 후 동일 입력 재적용, 중첩/종료 뒤 실행 없음 |
| MainWindow 정기 알림 흐름 | 표시 갱신 생략 중에도 알림 poll/전달/확인·재알림 계약 유지 |

검사는 합성 자료와 소유한 별도 OFFICEFLOW_DATA_DIR/tmp_path에서만 수행한다.
기본 범위는 달력 주의 표시·알림 묶음·선택 유지·정기 알림 통합의 관련 회귀 한 번이다.
추가 반복은 작은 합성 변경 없음/부분 변경 시나리오 최대 200회 한 번으로 제한하고
각 GUI 검사 프로세스에 60초 상한을 둔다. 실패 시 해당 범위만 재검사한다.
전체 회귀·3,000회 stress·6시간 운영을 자동으로 다시 수행하지 않는다.
실제 응답 없음이 합성 반복에서 재현되지 않으면 '재현 안 됨'으로 기록하고 해결 증거로 바꾸지 않는다.

Windows에서는 달력의 좁은 창에서 선택·스크롤·재알림/알림 상세를 직접 확인한다.
영향 화면의 밝은 스타일/어두운 시스템 팔레트 혼입과 100/150/200% 표시를 확인하되,
실제 OS 테마를 바꿨는지 주입 팔레트인지 구분한다. 제품 UI 변경이 없더라도 동작 검증과 렌더링 확인을 나눠 기록한다.
기능 확인은 새 배포물 생성이나 사용 중인 앱 교체의 승인이 아니다.

## 7. 완료 기준과 남는 한계

변화 없는 알림 주기에서 Qt 목록 재생성·선택 복원 호출이 없어지고,
같은 키 순서의 표시 변화는 기존 항목에서 반영되며 위 보존 회귀가 통과하면 이번 개선의 구현 완료로 판단한다.
네이티브 원인 확정 또는 실사용 무재발 확인은 별도의 상태로 기록한다.
재발 시 새 Python/native 증거와 이번 세 경로 중 어느 경로였는지 먼저 대조한다.
실제 정지 재조사는 사용자의 기존 '10분 이상 걸릴 것 같으면 중단' 제한을 따른다.

최초 승인은 설계 작성이었다. 후속 `구현해` 요청으로 구현·관련 격리 검증을 진행했다.
버전 변경·Python ZIP·커밋·GitHub 공개는 아직 진행하지 않았다.

## 8. 설계 검토 기록 (2026-11-11)

사용자 `설계에 문제 없는지 검토해` 요청으로 실제 호출 경로와 기존 검사를 대조했다.
구현 전 보완 항목은 다음과 같으며 위 계약과 검증 계획에 반영했다.

- 사용자 업무 클릭 누락: `_select_task`의 명시적 선택을 자동 보존과 분리했다(4.1절).
- 임시/최종 동일 행의 잘못된 생략: 별도 로딩/선택 수명과 최종 빈 결과 처리를 명시했다(4.2절).
- 부분 갱신의 높이 변화에 따른 스크롤 이동: 필요한 경우만 앵커를 복원한다(3.3절).
- 재진입/실패 입력의 잘못된 적용 완료 판정: 입력 스냅샷·변경 번호와 캐시 성공 경계를 명시했다(3.1·5절).

이는 소스 대조에 따른 설계 검토이며 제품 구현/실행 검증 결과가 아니다.
native 잠금 원인 미확정과 실제 재발 가능성은 그대로 남는다. 실행 코드·실사용 자료는 변경하지 않았다.
