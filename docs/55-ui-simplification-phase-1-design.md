# 화면 문구·설명·상시 버튼 정돈 상세설계 — 개선 후보 1~7

2026-10-10. 상태: **구현·자동 검증·사용자 확인 완료, 배포 전**.

사용자가 전체 화면 점검에서 찾은 14개 후보를 기록하고, 그중 1~7번의 개선 준비 설계를 요청했다.
후속 목록의 U22-1~U22-7과 이 문서의 번호는 직전 검토에서 설명한 1~7번에 그대로 대응한다.
기존 첨부/썸네일·업무 입력·달력 개선을 되돌리지 않는다. 최초 설계 요청은 문서 작성만이었으며,
이후 사용자 `구현 및 테스트해` 요청으로 1~7번을 반영했다. [구현·검증 결과](56-ui-simplification-phase-1-results.md)를 함께 확인한다.

## 1. 범위와 목표

목표는 **같은 동작은 같은 이름으로 부르고, 자주 쓰는 동작과 목록을 먼저 보여주는 것**이다.
정보나 안전장치를 없애서 화면만 짧게 만들지 않는다.

| 번호 | 대상 | 이번 설계의 결정 |
| --- | --- | --- |
| 1 | 업무 목록·달력·업무일지의 기록 창 진입 | `업무 보기`와 `수정`을 분리하고 이름을 통일 |
| 2 | 체크리스트의 순서 버튼 | 상시 `위로/아래로`를 제거하고 오른쪽 메뉴에서 기존 순서 이동 유지 |
| 3 | 보관함의 선택 파일 설명 | 일반 요약 1~2줄, 전체 정보는 `파일 정보…`에서 확인 |
| 4 | 보관함의 7개 버튼과 선택 표현 | 기본 3개 행동, 나머지는 메뉴. 저장 체크와 삭제 선택을 명확히 구분 |
| 5 | 임시 사본의 9개 버튼과 페이지 이동 | 중복 닫음 확인을 합치고 부가 행동을 메뉴로 이동. 필요한 경우에만 페이지 표시 |
| 6 | 업무 이력의 비교·보관 행동 | 일반 화면과 두 시점 선택 모드를 분리. 선택한 시점을 실제로 표시 |
| 7 | 업무 등록/수정 창의 알림 요약 | 실제 예약과 저장 전 미리보기를 중복 출력하지 않고 상태별 짧은 요약 제공 |

이 문서의 구현 범위는 1~7번이다. 사용자 사용 확인 뒤 요청받은 8~14번 상세설계는
[57번 문서](57-ui-simplification-phase-2-design.md)에 분리했다. 8~14번 구현은 아직 하지 않았다.

### 1.1 변경하지 않는 것

- 업무 상태, 처리 필요 분류, 일정·반복·알림 발생/확인/재알림의 규칙.
- 원본·작업본·보관본의 내용 보존, 임시 사본의 보호/만료/사용 중 판정.
- 첨부의 이름·메모·순서·출처, 저장 체크의 페이지 간 유지, 다중 삭제의 대상과 확정 절차.
- 업무 자동 이력의 기록 항목, 중요 시점의 캡처/파일 선택, 비교 가능한 범위.
- 백업/복원/외부 보관 형식과 기존 데이터. 새 DB 이행·파일 이동은 계획하지 않는다.
- 썸네일 전환 및 이미지 미리보기, 현재 날짜·시각 입력과 요일 표시.
- 업무 목록의 더블클릭 편집, 달력의 더블클릭 업무 보기 등 현재 화면별 동작.

공통 계약은 [첨부·이력 공통설계](24-follow-up-common-design.md),
[사본 버리기 설계](33-original-release-and-view-discard.md),
[페이지·다중 삭제 설계](34-document-paging-and-multiple-delete.md)를 유지한다.
공통 보존 계약을 바꾸는 설계가 아니라 표시·진입 동선을 정돈하는 설계다.

## 2. 공통 표시·행동 기준

### 2.1 용어

| 용어/버튼 | 뜻 | 혼동시키지 않을 것 |
| --- | --- | --- |
| 업무 보기 | 기존 업무 기록 창에서 체크리스트·완료 요약·업무일지·첨부 등을 확인 | 업무 편집이나 완료 실행이 아님 |
| 수정 | 기존 업무 등록/수정 창 열기 | `열기`로만 표시하지 않음 |
| 첨부 | 업무 보기 창의 첨부 탭 바로 열기 | 자주 쓰는 별도 진입은 유지 |
| 열기 | 선택한 파일을 현재 파일 열기 정책으로 열기 | 고정 원본을 직접 편집 가능하게 만드는 동작이 아님 |
| 작업본 만들기… | 선택 자료를 바탕으로 독립 편집 파일 생성 | 이름만 바꾸는 동작이나 외부 저장이 아님 |
| 작업본으로 저장… | 임시 사본에 저장된 변경을 새 작업본으로 보존 | 고정 원본/보관본을 덮어쓰지 않음 |
| 시점 보관… | 현재 업무 정보와 사용자가 고른 파일을 중요 시점으로 보관 | 업무 상태의 `보관`, 파일 개별 보관본, 외부 보관과 별개 |
| 파일 정보… | 전체 이름·출처·메모 등을 읽기 전용으로 확인 | 파일 열기/정보 수정/내용 해시 검사와 별개 |
| 새로고침 | 저장된 최신 자료 다시 조회 | 미저장 내용을 저장하거나 되돌리지 않음 |

`…`는 이름 입력·대상 선택·확인 등 후속 창이 있는 행동에 사용한다.
즉시 조회/순서 이동과 메뉴를 여는 `더보기`에는 의미 없이 붙이지 않는다.
긴 설명은 툴팁/도움말로 옮길 수 있지만, **파괴적 행동의 대상과 결과는 확인창에 남긴다**.

### 2.2 정보와 공간

- 제목/목록은 중심 정보, 상태/첨부 여부/출처는 보조 정보로 표시한다.
- 일반 선택 요약은 1~2줄. 빈 메모나 같은 출처 정보를 위해 빈 줄을 만들지 않는다.
- 긴 이름은 실제 폭에 맞춰 생략하고 전체 값은 툴팁과 `파일 정보…`에서 확인한다.
  단순 글자 수 제한으로 화면 적합성을 보장하지 않는다.
- 목록은 남는 높이를 우선 배정하고 세로 스크롤을 유지한다. 선택 시 설명이 목록 높이를 계속 빼앗지 않는다.
- 일반 안내/선택 수/작업 결과/오류를 한 라벨로 덮어쓰지 않는다. 정상 안내는 짧게,
  오류는 사라지지 않는 별도 상태 표시와 필요한 상세 동선을 둔다.
- 핵심 경고가 여러 개면 예외적으로 설명 영역을 확장할 수 있다. 안전 문구를 잘라서 2줄을 강제하지 않는다.
- 한 페이지인 창은 페이지 이동 영역을 숨긴다. 마지막 페이지에서 빈 페이지로 이동시키지 않는다.

### 2.3 메뉴와 조작

- 오른쪽 메뉴와 `더보기`는 같은 명령과 활성 조건을 사용한다.
- 여러 행 중 이미 선택한 행을 오른쪽 클릭하면 기존 다중 선택을 보존한다.
  선택 밖의 행을 오른쪽 클릭하면 그 행을 새 대상으로 삼고 대상 수를 즉시 갱신한다.
- 빈 공간 메뉴에는 특정 파일 삭제/수정 명령을 제공하지 않는다.
- 메뉴 키/Shift+F10과 Tab/Shift+Tab으로 마우스 없이 같은 동작에 접근한다.
- 새 QAction도 읽기 전용·휴지통·작업 중 상태를 직접 검사한다.
  기존 QPushButton 비활성화만으로 새 메뉴까지 보호된다고 가정하지 않는다.
- 메뉴를 연 당시의 이름/행 번호만으로 실행하지 않는다. 안정적인 항목 ID와 기존 revision/use token으로 재검증한다.
- 파일 작업과 이력 조회는 기존 비동기 처리·취소·창 수명 관리·늦은 응답 방지 정책을 유지한다.
  UI 정돈을 위해 파일 전체 검사나 모든 이력 적재를 추가하지 않는다.

## 3. 후보 1 — 업무 보기 진입 이름 통일

### 3.1 현재와 변경

| 위치 | 현재 표시 | 변경 표시/동작 |
| --- | --- | --- |
| 좁은 업무 화면의 선택 업무 행동 | `열기` → 실제로 업무 편집 | `수정` → 기존 편집 동작 |
| 같은 영역의 기록 버튼 | `기록` | `업무 보기` → 기존 기록 창 |
| 넓은 업무 상세의 긴 기록 버튼 | `체크리스트 · 완료 요약 · 업무일지` | `업무 보기` |
| 같은 상세의 첨부 버튼 | `첨부파일 보기 · 관리` | `첨부` → 첨부 탭 |
| 달력 하단의 기록 버튼 | `기록` | `업무 보기` |
| 업무일지 검색/조회 창 | `완료 요약 · 기록 열기` | `업무 보기` |
| 기존 오른쪽 메뉴 | 이미 `업무 보기` | 같은 이름/기존 동작 유지 |

```text
선택 업무                            [업무 보기] [첨부] [수정]

업무 보기
  [체크리스트] [완료 요약] [업무일지] [첨부] [폴더]
```

표의 행동들은 모든 화면에 새 버튼을 추가한다는 뜻이 아니다.
현재 있는 진입의 이름을 바꾸고, 넓은 화면에서 이미 상세에 있는 행동은 상단에 중복 표시하지 않는다.

### 3.2 상태와 회귀 방지

- 일반 업무: 업무 보기/첨부/수정 활성 조건은 현재대로 유지한다.
- 휴지통: 편집 버튼은 기존 `복원`을 유지한다. 업무 보기는 읽기 전용 기록 확인이다.
- 반복 업무: 실제 선택 업무·원래 회차 시각을 전달한다. 다른 날짜/회차로 임의 이동하지 않는다.
- 이미 열린 같은 기록 창은 재사용하고, 일반 업무 보기는 기존 마지막 탭 정책을 유지한다.
  명시적인 `첨부`는 첨부 탭으로 이동한다. 업무 보기로 들어갈 때마다 특정 탭으로 강제 초기화하지 않는다.
- 업무 보기만으로 완료·알림 확인·업무일지 추가를 실행하지 않는다.
- 고아 업무일지/없는 업무는 기존 안내를 유지한다. 클릭 가능한 정상 업무처럼 위장하지 않는다.
- 업무 목록 더블클릭은 편집, 달력 더블클릭은 업무 보기, 업무일지 더블클릭은 연결 기록 확인을 유지한다.
  서로 다른 실제 동작을 일괄 `업무 보기`로 바꾸는 범위는 아니다.

## 4. 후보 2 — 체크리스트 순서 버튼 정돈

### 4.1 배치

```text
체크리스트
[해야 할 일 입력...........................] [추가]
┌───────────────────────────────────────────────┐
│ ☐ 자료 수집                                   │
│ ☑ 담당자 확인                                 │
│ ☐ 제출                                        │
└───────────────────────────────────────────────┘
                                    [선택 삭제]

항목 오른쪽 메뉴
  수정
  ─────────
  위로 이동
  아래로 이동
  ─────────
  삭제
```

- `위로/아래로` 상시 버튼만 제거한다. 현재 순서 이동 서비스와 저장 순서는 유지한다.
- 입력 후 Enter 추가, 체크 완료, 더블클릭/F2 편집, 선택 삭제는 현재대로 유지한다.
- 첫 항목의 위로, 마지막 항목의 아래로는 비활성화한다. 선택 없는 상태에서는 항목 메뉴를 열지 않는다.
- 이동 후 같은 항목 ID를 다시 선택하고 보이게 한다. 실패하면 기존 순서로 재조회하고 오류를 알린다.
- 휴지통/읽기 전용에서는 편집·추가·삭제·순서 이동을 메뉴와 처리 함수 양쪽에서 거절한다.
- 새 드래그 순서 변경, 별도 순서 관리창, 체크리스트 자동 이력은 추가하지 않는다.

## 5. 후보 3 — 보관함 파일 정보는 요약과 상세로 분리

현재 선택 시 `당시 파일 이름 / 당시 출처 / 현재 출처 / 메모`가 최대 4줄로 바뀌고,
같은 라벨을 사용해 저장 체크 수와 작업 피드백도 덮어쓴다.

### 5.1 기본 화면

- 목록의 이름/역할 표시를 반복해서 아래에 다시 출력하지 않는다.
- 단일 선택: 첫 줄은 `보관본 · 10.10(토) 14:20 · 메모 있음` 같은 짧은 상태.
  출처가 이름 변경/삭제 상태인 경우에만 두 번째 줄에 `출처 이름 변경됨` 또는 `출처 항목 삭제됨`을 표시한다.
- 일반 첨부는 `일반 첨부`, 작업본은 `작업본`, 원본은 `원본`처럼 실제 역할을 사용한다.
  현재 항목에 `당시 파일 이름`이라는 과거 표현을 무조건 붙이지 않는다.
- 다중 선택: 개별 파일 정보 대신 `선택 2개 · 일반 1 / 작업본 1`처럼 선택 요약만 표시한다.
  마지막으로 클릭한 한 파일의 메모를 여러 파일의 정보처럼 보여주지 않는다.
- 선택 없음: 요약을 숨긴다. 목록 높이와 스크롤 위치를 유지한다.

### 5.2 전체 파일 정보

오른쪽 메뉴/더보기의 `파일 정보…`는 단일 선택일 때 활성화한다.

- 전체 표시 이름, 실제 역할, 생성/보관 시각, 메모, 생성 당시 출처 이름, 현재 출처 상태를 보여준다.
- 현재와 과거 이름이 다르면 둘 다 표시한다. 과거 이름을 현재 이름으로 덮어쓰지 않는다.
- 없는 출처와 조회 실패를 구분한다. 조회 실패를 `직접 첨부`나 `삭제됨`으로 추정하지 않는다.
- 메모/긴 이름은 읽기 전용 선택·복사와 세로 스크롤을 지원한다. 전체 정보는 툴팁에만 의존하지 않는다.
- 메타데이터를 필요한 ID 하나만 조회한다. 자동 해시/파일 전체 읽기는 실행하지 않는다.
- 비모달 창으로 열고 부모가 닫히면 기존 자식 창 정리 정책을 따른다.
  고정 파일의 실제 경로를 편집 가능한 직접 열기 동선으로 노출하지 않는다.

## 6. 후보 4 — 보관함 행동과 선택 구분

후보 3과 같은 화면을 수정하므로 **3·4번은 하나의 화면 변경으로 함께 구현/검증한다**.

### 6.1 목표 화면

```text
보관함
[현재 첨부 ▼]                 ☐ 이 업무 전체 보기
┌───────────────────────────────────────────────┐
│ ☑ 원본    신청서.docx                          │
│ ☐ 작업본  신청서 - 검토 반영.docx             │
│ ☐ 일반    참고자료.pdf                         │
│                                         ↕     │
└───────────────────────────────────────────────┘
현재 페이지 선택 1개 · 저장 체크 1개
원본 · 메모 있음
                 [열기] [체크한 파일 저장…] [더보기 ▾]
```

- `업무의 모든 계열`은 `이 업무 전체 보기`로 바꾼다.
  특정 첨부의 연결 자료만 보던 경우 체크하면 현재 업무 전체 자료로 넓힌다는 뜻이다.
  처음부터 제한할 계열이 없는 진입에서는 이 토글을 숨긴다. 의미 없는 껐다 켜기를 만들지 않는다.
- 현재 첨부/보관본 종류 전환과 기존 페이지 크기·필터 초기화는 유지한다.
- 페이지가 여러 개일 때만 별도 이동 영역을 표시한다. 34번 설계의 완료된 동작을 다시 구현하지 않는다.
- `열기`는 한 파일 선택, `체크한 파일 저장…`은 저장 체크가 1개 이상일 때 활성화한다.
  여러 행 선택에서 `열기`가 임의의 한 파일만 여는 모호함은 없앤다.

### 6.2 메뉴

| 메뉴 | 대상/조건 |
| --- | --- |
| 파일 정보… | 현재 페이지의 단일 선택; 읽기 전용에서도 가능 |
| 작업본 만들기… | 단일 선택, 살아 있는 업무, 기존 작업 생성 정책 충족 |
| 메모 수정… | 보관본 단일 선택만; 현재 첨부 메모 편집은 기존 첨부 화면을 사용 |
| 이 페이지 저장 체크 | 현재 페이지의 파일을 외부 저장 대상으로 체크 |
| 이 페이지 저장 체크 해제 | 현재 페이지 체크만 해제 |
| 저장 체크 모두 해제 | 페이지/종류를 넘겨 유지된 외부 저장 체크를 모두 해제; 자료 변경 없음 |
| 선택 파일 N개 삭제… | 현재 페이지에서 강조 선택한 파일만; 1~100개, 변경 가능 상태 |

삭제는 구분선 아래 두고 파일 정보/열기 바로 옆에 배치하지 않는다.
단일 파일 작업의 현재 ID와 다중 삭제 ID를 혼용하지 않는다.

### 6.3 두 선택 체계는 유지하되 명확히 표시

| 선택 | 표시/유지 | 쓰는 동작 |
| --- | --- | --- |
| 체크박스의 저장 체크 | 현재 첨부/보관본/페이지를 바꿔도 유지 | 체크한 파일 외부 저장 |
| Ctrl/Shift의 강조 선택 | 현재 보이는 페이지의 행 선택 | 파일 정보·작업본·메모 또는 선택 파일 삭제 |

- 상태 줄에 `현재 페이지 선택 N개 · 저장 체크 M개`를 분리해 표시한다.
  둘 다 `선택 N개`라고 쓰지 않는다. 저장 체크가 다른 페이지에도 있으면 짧은 부가 표시를 둔다.
- 체크 수, 선택 설명, 파일 작업 결과는 별도 표시 대상으로 관리한다.
- 삭제 확인창에는 **강조 선택한 파일명과 삭제 범위**를 기존대로 보여준다.
  저장 체크가 삭제에 섞이지 않으며 전체 체크 해제도 파일 삭제가 아니다.
- 삭제 성공 항목만 저장 체크에서 제거한다. 취소/실패 시 두 선택을 유지하고 항목을 지우지 않는다.
- 읽기 전용/휴지통에서는 열기·파일 정보·체크 저장은 유지하고 작업본/메모/삭제는 막는다.
- 작업 중 메뉴·중복 실행은 기존 controller의 실행 조건을 따른다. 늦은 상세 응답이 새 선택 요약을 덮지 않게 한다.

## 7. 후보 5 — 임시 사본 화면 정돈

### 7.1 기본과 메뉴

```text
임시 사본
저장된 변경은 작업본으로 남길 수 있습니다.
┌───────────────────────────────────────────────┐
│ 신청서.docx              변경 있음             │
│ 참고자료.docx            수정 없음             │
│                                         ↕     │
└───────────────────────────────────────────────┘
선택 1개 · 변경 있음
                     [작업본으로 저장…] [더보기 ▾]

더보기
  내용 다시 확인
  문서 닫음 확인…
  사본 외부 저장…
  ───────────────
  선택 사본 버리기…
  선택 미수정 사본 정리…
```

- 일반 안내는 한 문장. 저장된 파일 내용만 판정하며 편집기 미저장 내용은 읽지 못한다는 설명은
  상태 툴팁/보존 확인창에 남긴다. 변경 자료를 임시 사본에 장기 보관하도록 유도하지 않는다.
- `수정본 저장…`은 `작업본으로 저장…`로 변경하고, 단일 선택에서 현재의 보존 절차로 연결한다.
  정상 미수정 상태에서는 보존 버튼을 비활성화한다. 상태가 오래됐으면 먼저 `내용 다시 확인`하도록 안내한다.
  확인 불가/준비 중단/이전 복원 자료의 처리 제한은 기존 서비스가 최종 판정한다.
- `내용 다시 확인`, `사본 외부 저장…`, `선택 사본 버리기…`는 단일 선택용이다.
  다중 선택에서는 비활성화하며 임의의 현재 행만 처리하지 않는다.
- **현재 코드의 `선택 사본 외부 저장…`은 실제로 현재 사본 하나만 전달한다.**
  이번에는 정확한 이름과 단일 선택 조건으로 맞춘다. 임시 사본 다중 외부 저장은 새로 약속하지 않는다.
  정식 첨부/보관본의 다중 외부 저장은 후보 4의 기존 기능으로 유지한다.

### 7.2 닫음 확인 합치기

- 단일 `닫음 확인`과 다중 `선택 문서 닫음 확인`을 `문서 닫음 확인…` 한 명령으로 합친다.
- 대상은 현재 페이지의 강조 선택 1~100개. 사용자가 문서를 저장하고 닫았음을 확인하는 창에서
  이름과 개수를 보여주고 기존 use token을 적용한다. 편집기의 실제 닫힘을 자동 감지했다고 표시하지 않는다.
- 선택 없음은 비활성화한다. 상한을 넘으면 안내하고 실행하지 않는다. 앞의 100개만 조용히 처리하지 않는다.
- 확인 자체는 변경 내용 보존이나 파일 삭제가 아니다. 처리 수/실패/미처리를 실제 결과대로 표시한다.

### 7.3 버리기와 안전 정리는 분리

- `선택 사본 버리기…`: 선택한 1개 변경 내용을 명시적으로 버릴 수 있는 기존 확인 흐름.
  33번 설계의 사전 관측 → 문서 닫음 동의 → use token/내용/잠금 재확인 → 해당 사본만 삭제를 그대로 사용한다.
  되돌릴 수 없음과 원본/보관본 유지 안내를 생략하지 않는다.
- `선택 미수정 사본 정리…`: 선택 1~100개 중 **닫음 확인 + 재검사 후 미수정인 사본만** 정리한다.
  변경/사용 중/이전 복원/확인 불가 자료를 함께 지우지 않는다. 보류 이유와 실제 정리 수를 알린다.
- 두 행동을 하나의 `정리`로 합치지 않는다. 정리를 눌렀다가 수정 내용을 뜻하지 않게 잃는 구조를 피한다.
- 파일 다시 열기/승인 이후 수정/잠금/취소/삭제 실패 시 기존 보존·재시도 정책을 유지한다.
  고정 원본/작업본/보관본/사용자의 외부 파일은 이 명령 대상이 아니다.

### 7.4 페이지 표시

- 처음부터 한 페이지면 이전/다음 전체를 숨긴다. 여러 페이지일 때만 별도 이동 영역을 둔다.
- 현재 cache.page()는 최대 100개로 제한되고 전체 100개인 경우에도 다음 버튼을 제공할 수 있다.
  UI의 `len(page)==100` 추정 대신 읽기 전용 페이지 정보에서 `has_next`를 받도록 보완한다.
- 기존 후보 인덱스에서 해당 필터/offset의 100개와 다음 존재 정보만 제한 조회한다.
  다음 존재 확인은 인덱스 키 1개/EXISTS 등으로 하며 전체 JSON·파일 해시는 읽지 않는다.
- 불러오지 못한 인덱스 항목이 있으면 `상태 확인 필요`로 안내한다. 이를 정상 0건이나
  삭제 허가로 바꾸지 않는다. 끝 페이지 삭제 후에는 직전 유효 페이지로 돌아간다.
- 재조회 전후 현재/선택 항목은 `(generation, cache_id)`로, 범위는 기존 asset_id 필터로 유지한다.
  작업 중인 ID가 새 페이지의 같은 행 번호로 잘못 연결되지 않는다.
- 이 보완은 조회 반환 정보에 한정하며 cache 소유 원장/보호 상한/만료 규칙/DB 스키마를 바꾸지 않는다.

## 8. 후보 6 — 이력 비교는 선택한 시점이 보이게

### 8.1 일반 모드

```text
업무 이력                         [시점 보관…] [⋯]
[범위 ▼] [종류 ▼] [항목 ▼]                  ☐ 기간
┌───────────────────────────────────────────────┐
│ 10.10(토) 14:20  시점 보관  제출 전            │
│ 10.10(토) 11:30  변경       설명               │
│ 10.09(금) 09:00  변경       일정               │
│                                         ↕     │
└───────────────────────────────────────────────┘
                          [상세] [비교 ▾] [새로고침]

비교 메뉴
  선택 이력을 현재와 비교
  두 시점 선택해서 비교…
```

- `현재 상태 보관…` 등 같은 수동 캡처 진입은 이 범위에서 `시점 보관…`으로 맞춘다.
  연결된 기록 창의 진입은 `이력·시점 보관`, 창/도움말의 정식 설명은 `중요 시점 보관`으로 구분한다.
- 이력 종류의 `중요 보관`은 `시점 보관`으로 통일한다. 업무 상태 `보관`이나 개별 파일 `보관본`은 바꾸지 않는다.
- 현재와 비교는 선택한 과거 상태와 **지금 저장된 업무 정보 6항목**의 비교다.
  미저장 편집 내용·현재 파일 바이너리·체크리스트까지 비교한다는 의미를 주지 않는다.
  메뉴 툴팁과 비교창 제목에 기존 비교 범위를 남긴다.
- `최신 조회`는 `새로고침`으로 바꾼다. 현재 범위/종류/기간 필터는 유지하고 첫 페이지를 다시 조회한다.
- 다른 페이지에 새 이력이 생기면 `새 이력 있음 · 새로고침`을 표시한다.
  사용자가 보고 있던 과거 페이지를 알리지 않고 첫 페이지로 옮기지 않는다.
- `중단된 보관 확인…`은 상단 `⋯` 메뉴로 옮긴다. 보고된 중단 자료가 있으면 짧은 상태 표시로 강조한다.
  버튼 숨김 여부를 정하려고 전체 보관 작업/파일을 스캔하지 않는다. 수동 확인 메뉴는 남긴다.
- 기존 필터·커서 페이지·상세 비동기 조회·휴지통 읽기 전용·캡처 전 미저장 내용 확인을 유지한다.

### 8.2 두 시점 비교 모드

```text
비교할 두 시점을 체크하세요.                         1/2
┌───────────────────────────────────────────────┐
│ ☐ 10.10(토) 14:20  시점 보관  제출 전          │
│ ☑ 10.10(토) 11:30  변경       설명             │
│ ☐ 10.09(금) 09:00  변경       일정             │
└───────────────────────────────────────────────┘
① 10.10(토) 11:30 · 설명                    [해제]
② 아직 선택하지 않음
                                [비교하기] [취소]
```

- 비교 메뉴에서 들어갈 때 기존 현재 행이 있으면 첫 시점으로 표시하고, 없으면 0/2로 시작한다.
- 이 모드에서만 체크박스를 제공하고 Space로도 고를 수 있다. 단순 강조 선택/더블클릭 상세와 분리한다.
- 선택한 두 시점의 시각·이름·업무/회차 범위를 짧은 두 요약으로 실제 표시한다.
  긴 이름/다른 페이지의 항목은 전체 정보 툴팁과 표시로 확인한다. 보이지 않는 내부 ID만 선택하지 않는다.
- 최대 2개. 세 번째는 기존 선택을 유지한 채 안내한다. 선택별 해제와 취소를 제공한다.
- 같은 종류라도 `(kind, id)`로 식별한다. 같은 시점 두 번 선택은 중복 추가하지 않는다.
- 같은 업무 공통끼리 또는 동일 원래 회차끼리만 비교한다. 범위가 다른 두 번째 선택은 이유를 표시하고 거절한다.
  서비스의 최종 범위 검증도 유지한다.
- 페이지 이동/새로고침/필터 변경 뒤에도 선택한 두 시점과 요약은 유지한다.
  필터 밖에 있는 선택은 그 사실을 표시한다. 대상이 삭제되었으면 비교를 실행하지 않고 다시 선택하게 한다.
- `비교하기`는 유효한 두 항목일 때만 활성화한다. 과거→최근 순서로 표시하고 좌/우 기준 시각을 명시한다.
  기존 텍스트의 문자 그대로 비교와 보관 자료의 파일 정보 비교를 재사용한다. 의미가 같다고 자동 추정하지 않는다.
- 비교창을 닫아도 선택은 비교 모드 안에서 유지한다. 취소/모드 종료에서만 비교용 선택을 비운다.
- 일반 모드의 비교에 추가/선택 해제/0시점 비교 버튼을 두지 않는다.
  비교 모드에서는 일반 행동 줄 대신 비교하기/취소만 보여 목록 공간을 확보한다.
- 창 안에 현재 50개 요약과 최대 두 선택 요약만 보관한다. 페이지별 이력 전체나 첨부 내용을 누적하지 않는다.

## 9. 후보 7 — 알림 요약은 짧게, 실제/초안은 정확하게

### 9.1 기본 화면

```text
알림   알림 3개 · 다음 10.15(목) 14:00           [알림 설정…]

변경한 경우
알림   알림 3개 · 다음 10.15(목) 14:00           [알림 설정…]
       저장 전 변경 있음 · 저장 후 적용
```

기존 업무의 첫 줄은 저장된 실제 실행 상태다.
업무 날짜/시각/알림을 수정해도 첫 줄을 저장 전 예상으로 몰래 바꾸지 않는다.
기본 상세 버튼 `설정…`은 `알림 설정…`로 목적을 분명히 한다.

### 9.2 상태별 표시

| 상태 | 요약 정책 |
| --- | --- |
| 새 업무 | `저장 전 · 알림 1개 · 예상 …`처럼 아직 예약이 아니라는 사실 표시 |
| 기존 업무, 알림 관련 변경 없음 | 실제 개수/다음 예약 한 번만 표시. 동일 초안 미리보기 반복하지 않음 |
| 기존 업무, 저장할 알림 관련 변경 있음 | 실제 요약 + `저장 전 변경 있음 · 저장 후 적용`; 예상은 설정창에서 확인 |
| 실행 상태 정보가 아직 없는 진입 | `설정 미리보기`라고 표시. 실제 예약을 읽었다고 주장하지 않음 |
| 다음 예약 없음 | `알림 N개 · 다음 예약 없음`; 설정 개수만으로 활성 예약이 있다고 표시하지 않음 |
| 업무 완료/취소/보관/휴지통 | 기존 실제 범위 설명 + `이후 알림 중단`을 유지 |
| 반복 회차 완료 | 해당 회차 중단과 다른 회차 예약을 구분. 업무 전체 중단으로 바꾸지 않음 |
| 이미 울렸으나 미확인 | `확인할 알림 있음`을 짧게 유지. 미래 예약과 같은 상태로 합치지 않음 |
| 재알림 | 실제 snoozed_until을 다음 시각 계산에 포함. 처음 설정 시각만 표시하지 않음 |
| 일부 사용 안 함 | 필요한 짧은 비활성 개수 표시와 설정창 전체 상태. 전체 개수와 실제 다음 예약 구분 |
| 입력 불완전/유효하지 않음 | 실제 상태는 유지하고 `입력 확인 필요` 표시. 유효한 예상이 있는 것처럼 만들지 않음 |

정상 상태 1줄, 저장 전 변경/주의 상태가 있으면 보조 1줄을 목표로 한다.
좁은 창에서는 자연스러운 구분점에서 배치하거나 보조 정보만 생략 표시한다.
다음 시각·저장 전 변경·중단/확인 필요 같은 필수 상태가 겹치면 무리하게 한 줄을 강제하지 않는다.
연도 경계와 시간대는 기존 날짜 포맷터를 사용하고, 전체 시각/시간대는 설정창에 남긴다.

### 9.3 초안과 실제를 구분하는 기준

- 화면 문자열 비교나 개수 비교로 변경 여부를 판정하지 않는다.
- 알림 계산에 영향 있는 일정 유형/종일/시작·종료/시간대/반복·예외/상태와
  알림의 relation/offset/absolute/enabled 및 기존 rule ID 연결을 정규화해서 비교한다.
  알림 줄의 순서나 제목/설명만 바뀐 것을 알림 변경으로 오인하지 않는다.
- 창을 열 때의 편집 기준, 현재 사용자 초안, 최신 실제 실행 상태를 따로 유지한다.
  로컬 변경과 외부 완료/재알림에 따른 실제 갱신을 구분한다.
- 알림이 울리거나 확인되거나 업무가 외부에서 완료되면 실제 요약만 재조회한다.
  열린 초안·입력 포커스·설정창의 사용자 지정 값을 덮어쓰지 않는다.
- 초안과 실제가 달라도 외부 상태 변화만으로 `사용자가 미저장 수정함`이라고 표시하지 않는다.
  필요한 경우 `실제 상태 갱신됨`을 표시하고 기존 저장 충돌 검사를 유지한다.
- 설정창에서 적용해도 업무 편집창 최종 저장 전에는 실제 예약으로 확정하지 않는다.
  최종 저장 성공 뒤 실제 상태를 다시 받아 요약을 갱신한다. 취소/실패는 예약을 바꾸지 않는다.
- 예상 계산과 실제 요약 계산에 같은 now를 전달해 시각 경계에서 가짜 차이를 줄인다.
  실제 알림/회차의 상태 계산 서비스는 변경하지 않는다.

### 9.4 자세한 상태의 위치

기존 알림 설정창은 실제 처리 상태와 저장 전 미리보기를 구분해서 유지한다.
알림 개수/활성 여부, 다음 시각, 확인·재알림, 업무/회차 중단 이유, 새로 계산한 예상 시각을 여기에서 확인한다.
이번 범위에서 알림 설정의 표/추가·수정·삭제/최대 20개 규칙을 전면 재설계하지 않는다.
짧은 요약으로 옮기면서 상세 정보가 툴팁에만 남거나 사라지지 않게 한다.

- 후속 구현 때 사용자 안내/도움말의 해당 용어를 함께 갱신한다.
  디자인 문서만 작성한 지금은 도움말에 구현된 것처럼 설명을 추가하지 않는다.
- 각 묶음은 구현→관련 검사→화면 검증→결과 기록으로 진행한다.
  EXE/설치 파일/ZIP·버전·Git 커밋·업로드는 별도 요청 후 진행한다.

### 11.1 가독성·창 크기

- [품질 지침](06-development-process.md)의 공통 밝은 테마를 본문·viewport·메뉴·상세/확인창까지 명시한다.
- 영향받는 화면은 현재 최소 크기와 일반 비최대화 크기에서 직접 확인한다.
  대표 기준은 업무 편집 460×520, 보관함 640×480, 임시 사본 600×450,
  이력 420×350/720×520 및 주 화면 상세 패널 경계의 양쪽이다. 단위는 logical px다.
- 목록이 있는 세 보조 창은 기본 설정/필터 접힘 상태에서 목록 viewport 최소 150 logical px를 목표로 한다.
  이력 비교 요약/기간 펼침이나 필수 오류가 있는 상태도 스크롤·핵심 행동에 접근해야 한다.
  목표를 맞추려고 글꼴을 줄이거나 경고를 숨기지 않는다.
- 시스템 밝은/어두운 환경의 실제 팔레트 영향과 100%/150%/200% 배율에서 대표 작은 창,
  긴 이름·선택·비활성·메뉴·오류 상태를 확인한다. 기능 통과를 화면 가독성 통과로 기록하지 않는다.
- 변경마다 관계없는 모든 화면을 반복 검사하지 않는다. 이 작업은 여러 화면을 정돈하므로
  최종 묶음에서는 각 영향 화면과 공통 메뉴의 대표 조합을 검증한다.

### 11.2 안전·성능

- 기존 격리 fixture/합성 자료로 검사한다. 실제 사용 DB/첨부·백업·외부 보관 폴더를 테스트에 쓰지 않는다.
- 파일 정보/메뉴/선택만으로 파일 복사·삭제·보관·자동 이력이 발생하지 않는지 확인한다.
- 파일 작업 중에도 알림을 처리할 수 있고, 비모달 창의 닫힘/worker 종료가 프로그램 종료나 충돌을 만들지 않는지 확인한다.
- 캐시 페이지 조회는 인덱스 기반 제한 조회, 이력은 50건과 비교 2건만 사용한다.
  대량 자료에서도 초기 표시를 위해 모든 파일/JSON/이력을 읽지 않는다.
- 후속 구현 결과는 별도 보고에 테스트 수/범위·캡처·실측·미검증 회사 환경을 구분해 기록한다.

## 12. 설계 검토 결과와 보류

1. 일괄 단어 치환만 하면 `수정`을 업무 보기로 잘못 연결하거나 파일 선택 대상이 달라질 수 있다.
   실제 행동과 화면별 읽기 전용/회차를 먼저 정한 뒤 표시를 바꾸도록 설계했다.
2. 보관함의 체크 저장과 강조 삭제는 이미 다른 목적이다. 이번에 합치지 않고 이름·개수·확인 대상을 분리한다.
3. 임시 사본 단일 외부 저장을 다중 저장처럼 설명하지 않는다. 정식 첨부 다중 저장과 혼동하지 않는다.
4. 버튼을 메뉴로 옮겨도 수정 내용 버리기·다중 삭제·중단 보관 확인을 찾을 수 있고 기존 보호가 유지되어야 한다.
5. 비교 선택은 보이는 임시 UI 상태로 만든다. 새 DB/복원 기능이나 첨부 바이너리 비교를 추가하지 않는다.
6. 알림 요약은 실제/초안 분리 원칙을 유지한다. 짧게 만들기 위해 외부 완료/미저장 변경을 숨기지 않는다.
7. 표시 변경만으로 모든 회사 PC의 테마/DRM/배율이 검증되었다고 하지 않는다. 후속 구현의 실검증 항목으로 남긴다.
