# 장시간 실행 신뢰성·업무 찾기 개선 공통설계

작성일: 2026-10-26. 기준: OfficeFlow 3.0.13 / DB0016 / 전체 백업 v3.
사용자 승인: U36~U38 개선 목록 기록과 설계. **구현·동작 검증·자료 이행·배포 승인은 아니다.**

후속 `구현과 테스트 실행해` 요청으로 세 차수의 소스 구현·격리 검증을 승인받았다.
아래 차수별 사용 확인 대기는 이번 일괄 요청으로 대체하며, 사용 확인·배포/Git는 여전히 별도다.
구현 결과와 실제 검증/한계는 [83번](83-resource-and-task-finding-results.md)을 따른다.

상세설계: [81번 자원 정리](81-resource-lifecycle-detail-design.md), [82번 업무 찾기](82-task-finding-detail-design.md).
관측한 사실과 한계는 [79번 조사 기록](79-memory-and-resource-review.md)에 보존한다.
시안은 배치/동작 검토용이며 제품 구현·성능 검증 결과가 아니다.

## 1. 목표와 범위

| 차수 | 범위 | 사용자가 얻는 변화 |
| --- | --- | --- |
| 1차 U36 | 닫힌 객체 정리, 숨김/유휴 비용 절감, 제한된 진단·저메모리 대응 | 오래 켜둬도 불필요한 창/메뉴가 쌓이지 않으며 종료 원인 조사 단서 확보 |
| 2차 U37 | 최근 본 업무 + 기존 고정 업무 | 제목/날짜를 정확히 기억하지 않아도 다시 열기 |
| 3차 U38 | 완료 화면의 월별 묶음 | 대략적인 완료 시기로 제목/상태를 훑어보기 |

각 차수의 구현·검증 후 사용 확인을 받고 다음으로 간다. 모두 설계한 것은 공유 계약을 맞추기 위해서이며
앞 차수 피드백이 이후 상세설계를 보완할 수 있다. 한 번에 실행하거나 중간 배포를 자동 수행하지 않는다.
1차 안에서는 `정리 누락 수정 → 배경 비용/관측 → 저메모리 정책` 순으로 검증 가능한 단위를 만든다.

## 2. 유지할 공통 계약

- [24번](24-follow-up-common-design.md)의 파일·DB·회차·백업 보존과 [38번](38-reliability-common-design.md)의 진단/개인정보 원칙을 유지한다.
- 알림 확인/재알림/업무 완료는 기존 서비스만 사용한다. 화면을 없애는 행위가 남은 알림 삭제를 뜻하지 않는다.
- worker가 쓰는 소유자·파일 예약·DB session은 작업 완료 전 삭제하지 않는다. QThread 강제 종료는 금지한다.
- 조회는 업무 수정일·완료일·업무 이력·알림 상태를 바꾸지 않는다. 최근 조회 기록은 업무 변경 이력과 다르다.
- 반복의 원래 `occurrence_start`가 식별자다. 이동한 날짜·완료한 날짜를 회차 키로 사용하지 않는다.
- 기존 업무 보기 재사용과 미저장 결과/일지 보호, 검색어의 탭 전환 시 해제, U34 위치 복귀를 유지한다.
- 휴지통/영구 삭제·기존 파일 정리 정책은 변경하지 않는다. 메모리 캐시와 디스크 보기 사본을 혼동하지 않는다.
- 새 화면도 밝은 공통 테마를 명시한다. 작은 창·키보드·100/150/200% 가독성을 완료 기준으로 둔다.

## 3. 역할 분리

| 경계 | 책임 | 하지 않는 일 |
| --- | --- | --- |
| Presentation 수명 관리 | 완료 신호·삭제 예약·메뉴 종료·조회 토큰 처리 | 업무/알림 상태를 임의 변경 |
| Application 자원 정책 | normal/pressure/unknown, 안전한 부가 작업 조정 | 다른 프로세스 종료, 물리 파일 정리 |
| Infrastructure 관측/기록 | 자기 프로세스/시스템 숫자·제한된 로컬 기록 | 문서 내용/다른 앱 명령줄 수집 |
| RecentTaskService/Store | 최대 20개 조회 참조·현재 자료 해석 | Task/QWidget/이미지 객체 영구 보유 |
| CompletedBrowseService/Repository | 같은 조건의 월 집계/완료 기록 페이지 | 전체 업무/반복 발생을 메모리에서 전개 |

실제 클래스명은 상세설계의 논리 이름이다. 공용 수명 관리 원칙은 맞추되 모든 창/worker를 새 프레임워크로 교체하지 않는다.

## 4. 객체 수명과 읽기 요청

1. 창/메뉴/진행창은 소유자가 명확하고 종료 후 목록/연결/네이티브 객체를 정리한다.
2. 재사용하는 창은 명시적으로 한 개만 유지한다. 숨긴 채로 새 창을 계속 만드는 방식을 금지한다.
3. 오래된 종료 콜백이 새 창의 포인터를 지우지 않도록 객체 동일성 또는 요청 토큰을 확인한다.
4. 최근/월별 조회는 기능별 worker 최대 1개, 대기 요청은 최신 1개만 유지한다. 닫힌 화면의 결과는 폐기한다.
5. 실제 일/알림 검사와 화면 갱신을 분리한다. 숨김 상태는 dirty 표시만 쌓고 복귀 시 한 번 읽는다.
6. 조회 결과 DTO는 필요한 요약만 가지며 worker 밖에 ORM/session/파일 핸들을 전달하지 않는다.
7. 새 `최근` 메뉴도 매번 추가 생성해 방치하지 않는다. 기본 메뉴는 실행 중 한 개 재사용, 전체 목록 보조 창은 최대 한 개다.

## 5. 공통 상한

| 대상 | 설계 상한/기본값 |
| --- | --- |
| 최근 조회 참조 | 업무 ID 기준 20개, 하나의 업무는 최신 회차 참조 1개 |
| 기본 바로 찾기 메뉴 | 고정 3행 + 최근 5행, 고정과 최근 중복 ID 생략 |
| 최근 로컬 파일 | JSON 버전 포함 32KiB 이하, 한 번에 쓰는 최신 스냅샷 1개 |
| 바로 찾기 요약 조회 | 최근 최대 20 ID 일괄 + 고정 4행(초과 판정 포함), 전체 업무 스캔 없음 |
| 완료 헤더 | 6개 달력 월 범위 1페이지 + 완료일 미상 1개, 비어 있는 월은 생략 |
| 완료 행 | 그룹당 50행 1페이지, 미상 포함 동시 펼침 최대 2개 = 행 최대 100개 |
| 관측 메모리 | 최근 숫자 sample 최대 16개, traceback/문자열 업무 데이터 보관 없음 |
| 추가 자원 로그 | 1MiB × 현재/회전 2개 = 최대 3MiB, 정상 기록 60초 간격 |
| 관측/저메모리 판정 | 기본 30초, 같은 원인의 반복 알림/로그는 억제 |

실제 화면 높이가 부족하면 메뉴의 보이는 행 수만 줄인다. 저장된 최근 기록을 화면 높이에 맞춰 버리지 않는다.
기존 32MiB 이미지 LRU와 원본/보기 사본 규칙은 유지하고 압박 시 메모리 LRU만 제한한다.

## 6. 저장·백업·복원

- U36: 업무 DB 이행 없음. 로컬 자원 로그는 기존 로그 영역에 두며 업무 백업에 넣지 않는다.
- U37: `AppPaths.root/recent-tasks.json`을 새 **재생성 가능한 이 PC의 조회 정보**로 사용한다.
  업무 ID·생성 시각·원래 회차 키·열어 본 시각만 저장하며 제목/설명/메모/첨부 바이트는 저장하지 않는다.
  AppSettings와 분리하여 설정창의 오래된 스냅샷 저장이 최근 기록을 덮어쓰지 않게 한다.
  기존 백업 whitelist/구성은 유지하며 새 파일은 전체 백업/외부 HTML/ICS/자동 이력에 포함하지 않는다.
- 지원되는 백업 복원을 시작할 때 최근 기록을 무효화하고 성공 후 빈 목록으로 시작한다.
  복원 실패/취소로 최근 기록만 비어도 업무 자료는 영향을 받지 않는다. 실패한 무효화는 이번 실행에서 최근 읽기를 차단한다.
- 각 참조의 `task_id + task.created_at`를 현재 DB와 대조해 삭제/ID 재사용을 걸러낸다.
  envelope의 DB 파일 식별값도 대조하며 미지원 환경은 RAM 최근 목록만 사용한다(82번 계약).
  수동으로 DB만 교체하는 비지원 작업의 완벽한 계보 추적까지 약속하지 않는다.
- U38: 기존 완료 컬럼을 재사용하고 `task_occurrences(status, completed_at, task_id, id)` 조회 색인 하나를 추가할 계획이다.
  계획 revision은 다음 빈 번호인 `0017_completion_browse_index`이며 구현 시 충돌 여부를 재확인한다.
  테이블/기존 컬럼 삭제·완료 시각 보정·파일 이동은 없다. 일반 업무의 완료일 색인은 기존 것을 재사용한다.
- 색인만의 추가라도 schema head가 바뀐다. 이행 전 DB 보호 사본·구버전 DB 업그레이드·미지원 head 거절·백업 복원 시험이 필요하다.
  전체 백업 형식은 v3 유지 계획이지만 0017 DB/백업을 0016만 아는 실행기로 열 수 있다고 안내하지 않는다.
- 업무 데이터 0건인 첫 실행, 기존 최근 파일 없음/손상/권한 거절도 시작과 알림을 막지 않아야 한다.

## 7. 화면 정책

- 검색창 옆 `최근` 버튼 하나만 추가한다. 기존 `중요`와 고정의 의미를 합치지 않는다.
- `최근` 선택은 검색/필터·캘린더 날짜·현재 목록을 바꾸지 않고 기존 업무 보기를 연다.
- 최근 목록이 비거나 고정이 없어도 빈 패널을 크게 차지하지 않는다. 제목은 줄임+전체 도움말, 상태·회차 표시는 보존한다.
- 월별 묶음은 기존 `완료` 안의 보기 방식이다. 새 사이드바·태그·프로젝트·추천·AI 기능을 추가하지 않는다.
- 정상 상태에 큰 진단 배너를 늘리지 않는다. 자원 압박/백업 지연만 작고 지속적인 상태 표시로 안내한다.
- 시안의 예시 업무/개수/고정값은 제품 요구 수치나 실제 사용자 자료가 아니다.

## 8. 공통 검증·구현 게이트

- 수명: 반복 후 window/menu/progress·구독자·worker가 기준 개수로 돌아옴. queued 신호 후 use-after-delete 없음.
- 데이터: 읽기로 업무/알림/이력/완료일을 바꾸지 않음. 회차 이동·삭제·복원·미저장 입력을 보존함.
- 자원: bounded 조회/큐/파일 크기 및 정상/압박/관측 실패·복구를 테스트함. 실PC 메모리 고갈 시험은 하지 않음.
- 단위/통합과 native Windows/Python의 실제 표시·종료 시험을 구분함. 숨긴 생성 시험만으로 native 안정성을 승인하지 않음.
- UI: 공통 테마·작은 창·100/150/200%·상태/선택/스크롤·긴 제목·실제 화면 가독성 확인.
- 기존 전체 회귀·Ruff/mypy·변경 format·DB/백업 호환은 구현/마감 시 게이트다. 이 문서 작성으로 통과했다고 표시하지 않는다.
- 미해결 native 시험 프로세스의 조기 종료(79번)는 독립 확인 항목으로 유지한다.

## 9. 이번에 하지 않는 것

프로그램 코드·실제 사용자 DB/첨부·버전·설치/EXE/ZIP·Git 커밋/업로드·자동 실행/PC 설정을 변경하지 않는다.
추가 메모리 누수 없음이나 회사 PC 종료 해결을 보장하지 않는다. 감시 프로세스·자동 재시작·RAM 강제 비우기는 범위 밖이다.
