작성일: 2026-10-10. 구현 반영: 2026-10-11. 상태: **구현·자동 검증 완료, 사용자 사용 확인 전**.

### 1.1 바꾸지 않는 것

- 업무 상태·처리 필요 분류·알림 발생/확인/재알림/완료 규칙.
- 매시 알림의 기본 켜짐, 제외 시간, 08시 조건, 오늘 예외와 재실행 정책.
- 백업 주기·보관 개수·복원 시점, 파일 보호·검증·취소·복구 절차.
- 외부 폴더의 소유권, 외부 업무 보관 범위·형식·완료 판정.
- 원본·작업본·보관본·이력·임시 사본의 저장·삭제 계약.
- 기존 DB 스키마와 백업 형식. 새 이행·파일 이동·자동 삭제를 추가하지 않는다.
- URL 바로가기, 외부 보관 내역 관리, 내부 자료 경량화는 추가하지 않는다.

## 2. 공통 화면 원칙

1. 자주 쓰는 행동은 기본 버튼에, 보조 행동은 이름 있는 `더보기` 메뉴에 둔다.
   마우스 오른쪽 메뉴가 유일한 진입점이 되지 않게 한다.
2. 정상 설명은 짧게 만들되 미확인·조회 실패·누락·취소 중·완료 미확인·되돌릴 수 없는
   삭제·전체 백업 아님은 색상이나 툴팁에만 의존하지 않는다.
3. 긴 이름/경로는 말줄임과 전체 툴팁을 제공한다. `전체 경로…`/`상세…`처럼
   키보드로도 열 수 있는 읽기 전용 표시를 함께 둔다. 사용자 문자열은 일반 텍스트로 표시한다.
4. 필수 상태는 줄바꿈에 필요한 높이를 확보한다. 고정 높이로 자르거나 글꼴을 줄이지 않는다.
   도움말은 접힌 상태가 기본이며 펼칠 때 목록/하단 버튼을 밀어 화면 밖으로 내보내지 않는다.
5. 창 전체 대신 설명 영역을 스크롤하고, 목록이 주목적인 창은 목록 공간을 우선한다.
   접힌 기본 화면에서 목록 viewport 150 logical px 이상을 목표로 한다.
   긴 필수 오류가 있으면 본문 스크롤 또는 상세 분리로 행동 접근을 유지한다.
6. 메뉴로 옮긴 행동도 선택 없음·읽기 전용·작업 중 조건과 기존 명령 검증을 모두 유지한다.
   버튼만 비활성화하고 메뉴로는 실행할 수 있는 우회 경로를 만들지 않는다.
7. 조회/메뉴/도움말만 열어도 파일을 복사·삭제하거나 알림을 확인 처리하지 않는다.
   목록을 새로 그릴 때 같은 ID/회차의 선택과 스크롤을 가능한 범위에서 유지한다.
8. 밝은 공통 테마를 본문·viewport·메뉴·선택·비활성·오류·상세 창에 명시한다.
   기존 `CompactLabel`/`WrappingLabel`을 용도에 맞게 재사용한다.

## 3. U22-8 — 오늘 알림 미리보기

### 현재 확인

`ReminderPreviewWidget`은 한 업무/원래 반복 회차의 알림을 묶어 2~3행 표시한다.
헤더에 업무 수·총 알림 건수·표시 수를 모두 쓰고, 검색/필터 독립 안내가 항상 있다.
`complete=False`인 부분 조회와 미확인/발생 기록 확인 필요 상태가 존재한다.
이 구조를 유지하며 표시만 줄인다. 달력의 날짜·일정/알림 연결 방식은 바꾸지 않는다.

### 기본 화면

```text
오늘 알림 총 6건 · 다음 15:00       [알림 시각] [2개 더 보기]
15:00  제출 준비                           알림 3건
16:00  결재 확인                           알림 1건

조건부 안내: 미확인 1건 · 발생 기록 확인 필요 1건
조건부 안내: 업무 검색·필터와 관계없이 오늘 알림을 표시합니다.
```

- 헤더의 `총 N건`은 오늘 투영에 포함된 개별 알림 건수다. 남은 알림 수나 업무 수가 아니다.
  전체 보기에서 업무·회차 묶음 수와 예정/재알림/미확인/처리 이력의 수를 분리한다.
- `다음`은 현재 이후의 예정/재알림 중 가장 이른 실제 표시 시각이다.
  이미 울린 미확인을 미래 알림처럼 `다음`으로 부르지 않는다.
  업무/회차 완료·취소로 중단된 알림, 다른 날로 옮긴 원래 날짜의 이력은 후보에서 제외한다.
- 미확인과 `시각 지남 · 발생 기록 없음`은 서로 다른 상태다. 각각 해당 건수와 명칭을
  짧은 조건부 줄에 표시하며, 발생 기록 없음을 실제 알림 발생으로 단정하지 않는다.
- 전체 조회가 끝났고 미래 예정·미확인·발생 기록 확인 대상이 없을 때만 `남은 알림 없음`을 쓴다.
  알림이 없을 때는 `오늘 알림 없음`, 조회 중/실패일 때는 그 상태를 표시한다.
- 부분 조회는 `조회된 알림 N건 · 일부 조회`와 `더 조회…`를 유지한다.
  시각을 표시한다면 `조회분 중 예정 HH:MM`으로 한정한다. 전체의 다음 시각이나
  정확한 총수·없음을 약속하지 않는다. 부분 조회와 실패 안내는 도움말로 숨기지 않는다.
- `N개 더 보기`는 현재 받은 업무·회차 묶음 중 미리보기에서 숨은 수다.
  전체 묶음이 반복 회차를 포함할 수 있음을 전체 보기에서 명시한다.
  일부 조회 때는 알려지지 않은 전체 숨은 수를 계산하지 않고 `더 조회…`로 표시한다.
- 검색어가 있거나 상태/중요도/고정/첨부 필터가 켜졌을 때만 독립 범위 안내를 표시한다.
  정렬·간결 보기·필터 설정을 단순히 펼친 상태는 필터로 세지 않는다.
  검색을 입력/지우는 즉시 안내 상태를 갱신하고 알림 조회 결과를 필터링하지 않는다.
- 버튼/메뉴는 `알림 시각…`, `업무 보기`, `알림 설정…`으로 통일한다.
  더블클릭은 업무 보기, 개별 알림 상세는 읽기 전용 비모달이다.
  전체 보기의 100행 페이지·추가 조회·회차 키·선택 유지 계약은 그대로다.
- 다음 시각의 기준 현재 시각은 주창의 기존 시계/갱신 경로에서 전달한다.
  알림 처리·재알림·시간 경과 후 재계산하되 새 고빈도 DB 폴링을 만들지 않는다.

## 4. U22-9 — 외부 폴더

```text
외부 폴더의 파일은 OfficeFlow 백업에 포함되지 않습니다.
[업무 자료] [제출 자료]                    ← 스크롤 목록
D:\업무\…\2026년 제출자료                 ← 한 줄 경로
[열기] [추가…] [더보기 ▾]
                 ├ 전체 경로…
                 ├ 표시 이름 변경…
                 ├ 폴더 다시 지정…
                 ├ 연결 삭제…
                 └ 새로고침
```

- 6개 상시 버튼을 3개로 줄인다. 오른쪽 메뉴도 동일한 행동/활성 조건을 사용한다.
- `표시 이름 변경…`은 OfficeFlow 목록의 이름만 바꾼다. 실제 폴더 이름은 바꾸지 않는다.
- 전체 경로 창에서 원문 선택/복사가 가능하다. 경로는 가운데 생략으로 마지막 폴더명을 남긴다.
  폴더 목록을 선택할 때마다 탐색기·네트워크 경로를 검사하지 않는다.
- 비백업 안내는 기본 화면에 남긴다. 내용 복사/수집/관리하지 않는다는 상세 설명은 도움말에 둔다.
- 연결 삭제 확인에는 대상 표시 이름과 `실제 폴더와 파일은 삭제하지 않습니다`를 표시한다.
  재지정/열기 실패로 기존 연결을 자동 삭제하지 않는다. 자동 위치 추적은 추가하지 않는다.
- 휴지통 업무는 열기·전체 경로·새로고침만 가능하다. 추가/이름 변경/재지정/삭제는 숨기거나
  비활성화하고 실제 명령에서도 거절한다. 작업 중 충돌하는 명령은 메뉴에서도 막는다.
- 실제 경로 검증·열기 전 확인은 기존 worker/service를 사용한다.
  관리 폴더·junction 거절, 최대 50개, 이전 값 확인을 통한 충돌 방지는 유지한다.

## 5. U22-10 — 일반 설정

일반 설정의 하단에 섞인 긴 설명을 없애고 `실행 / 업무 알림 / 자동 백업`의 짧은 구역으로 나눈다.
새 설정 페이지나 새 정책을 만들지 않으며 기존 적용/취소와 입력 순서를 유지한다.

| 항목 | 기본 설명/라벨 | 펼침 도움말에 남길 내용 |
| --- | --- | --- |
| 빠른 등록 | `빠른 등록 단축키` / 예: Ctrl+Alt+O | 지원 조합, Windows 전역 단축키의 의미·등록 실패 |
| 놓친 알림 | `놓친 알림 확인 범위` / 종료·절전 중 놓친 미처리 알림 | 설정 범위 밖은 자동 재표시하지 않음, 기존 한 번 복구 정책 |
| 자동 백업 | 기존 켜기·끄기 유지 | 앱 실행 중 주기 확인, PC가 꺼져 있으면 다음 실행 뒤 처리 |
| 백업 주기 | `자동 백업 주기` | 정해진 시각에 PC가 꺼져 있어도 별도 서비스가 백업하는 기능은 아님 |
| 보관 개수 | `자동 백업 보관 개수` | 오래된 자동 백업의 기존 정리 정책. 수동·복원 보호본은 적용 대상 아님 |

- 단순히 `보관할 백업 개수`로 바꾸면 수동 백업까지 삭제하는 것으로 오해할 수 있어 자동 범위를 표시한다.
- 자동 백업을 끄면 주기/보관 개수 입력은 기존처럼 비활성화한다. 값을 지우거나 초기화하지 않는다.
- 입력 오류는 해당 항목 가까이 또는 하단 오류 영역에 계속 표시한다. 자세한 설명과 오류를 합치지 않는다.
- 도움말을 열거나 매시 알림 설정을 열어도 일반 설정의 미저장 값은 저장/취소되지 않는다.
  일반 설정은 `적용` 전에는 바뀌지 않으며, 독립된 매시 설정을 일반 `취소`로 되돌린다고 안내하지 않는다.

## 6. U22-11 — 매시 알림 설정

### 배치

```text
매시 알림 설정
현재: 켜짐 · 다음 18:35

알림 문구   [인사랑 업무기록을 확인하세요.]
알림 시점   매시 [35]분
평일 제외   [09:00] ~ [18:00]
토·일은 하루 전체 대상입니다. 추가 제외 시간은 적용됩니다.

오늘만 바로 적용 · 10월 10일(토)
[ ] 오늘 휴일근무        ← 주말에는 이미 적용됨 표시/비활성
[오늘 08시 알림 받기]    ← 허용 가능한 경우에만 표시

[추가 설정 ▾] [동작 설명 ▾]
                         [저장] [닫기]
```

- 상단 `현재`와 다음 시각은 실제 `HourlyState`에서 읽는다. 입력을 바꿨으나 저장 전이면
  `설정 변경 · 저장 전`을 표시하고 현재 예약 시각을 새 입력의 시각으로 바꿔 보여주지 않는다.
- 알림 문구/분/평일 제외 시간/추가 제외 시간/소리/08시 기본 조건은 `저장`해야 적용된다.
  저장 실패는 실패로 표시하고 초안은 남긴다. 저장 성공 안내는 오류용 빨간 문구와 구분한다.
- `오늘 휴일근무`와 `오늘 08시 알림 받기`는 기존처럼 선택 즉시 적용한다.
  날짜와 `오늘만 바로 적용`을 가까이 표시한다. `닫기`는 즉시 적용한 오늘 선택을 취소하지 않는다.
- 오늘 휴일근무는 오늘 날짜에만 유효하며 같은 날짜 재실행에서는 기존 저장값을 유지한다.
  다음 날 만료되는 동작은 그대로다. 주말에는 평일 제외가 원래 적용되지 않지만 추가 제외는 적용된다.
- 끄기는 이번 실행에만 유효하고 완전 종료 후 다시 실행하면 켜진다. 설정 전체/오늘 예외까지
  재실행 때 모두 초기화된다는 문구는 쓰지 않는다. 기존 켜기·끄기 진입점은 유지한다.
- 오늘 선택과 다른 창의 변경 후 `저장`해도 최신 날짜 예외를 덮어쓰지 않는다.
  현재 controller의 날짜 값 병합을 유지한다. 입력값 자동 덮어쓰기로 사용자 초안을 잃지 않는다.

### 08시 조건을 설명하는 방법

추가 설정의 기본 조건은 `평일 08시: 늦게 켜도 알림 받기`로 표시한다.
기본 끔이며 08:00~08:59에 처음 켜면 해당 시간대 알림을 생략한다.
짧은 설명은 `08시 전에 켜두었다면 08시에도 이어서 알립니다`다.
옵션을 켜도 평일/추가 제외 시간, 이번 실행 끄기, 해당 시간대 처리 상태는 우선한다.

상세 도움말의 예시는 다음과 같다. 출근 시각을 추정하거나 인사랑 출근을 자동 기록하는 기능이 아니다.

| 상황 | 기본 조건에서의 동작 |
| --- | --- |
| 평일 05시부터 켜둠 | 아침 대상 시간에 알리고 08시도 이어서 대상. 기존 제외/처리 조건 적용 |
| 평일 08:30 처음 켬, 오늘 허용 기록 없음 | 08시 시간대 알림 생략 |
| 08시 전 출근·기록했지만 앱만 늦게 켬 | `오늘 08시 알림 받기`로 오늘의 08시를 명시적으로 허용 |
| 전날부터 계속 켜둠 | 08시 이전부터 실행된 기존 연속 조건을 적용. 실제 출근 사실은 판정하지 않음 |
| 같은 날짜의 기존 연속/오늘 허용값을 가진 채 재실행 | 저장된 날짜 값과 기존 정책 적용. 최초 실행 시각만으로 재판정하지 않음 |
| 주말 또는 오늘 휴일근무 | 평일 08시 제한은 적용하지 않음. 추가 제외 시간은 유지 |

프로그램 시작 때 대상 시간대이면 바로 안내하는 기존 정책, 시간대당 확인/미루기 동작,
59분 주의와 최대 8개 추가 제외 시간 검증은 유지한다. 오류/59분 경고는 접힌 도움말에 숨기지 않는다.

## 7. U22-12 — 데이터 관리

### 기본 화면과 문제 화면

- 최상단의 포괄 설명을 제거한다. `사용량 / 첨부 정리 / 내보내기·백업 / 자료 검사` 탭은 유지한다.
- 사용량의 총량·DB/첨부/백업 크기와 업무 수는 간결한 현황으로 유지한다.
  해제·중복 후보·오래된 자료의 세부 설명은 `현황 상세`에 두되 건수와 확인 동선은 남긴다.
  해제됨·오래됨·내용 미확인은 곧바로 손상/삭제 대상으로 분류하지 않는다.
- 누락·삭제 복구 대기·조회 실패는 건수/이유와 확인 동선을 기본 화면에 표시한다.
  읽기 실패를 `문제 없음`으로 바꾸지 않는다. 정상적인 빈 상태/아직 조회 안 함/조회 실패를 구분한다.
- 큰 파일은 기존 최대 5개 표시와 범위를 유지한다. 새 전체 목록·자동 삭제를 추가하지 않는다.
  `첨부 저장 폴더 열기` 근처의 내부 파일 이동/이름 변경/삭제 금지 안내는 짧게 남긴다.
- 첨부 정리 설명은 `연결을 해제한 파일은 자동 삭제되지 않습니다`를 기본으로 둔다.
  30일 경과 등 반복 설명은 상세로 옮긴다. 영구 삭제 확인과 참조 보호는 그대로다.

### 사본·복구 도구

첨부 정리의 기존 `더보기`에 아래 세 진입점을 구분해 넣고 상시 3개 버튼을 없앤다.

1. `보기 사본 확인…` — 임시 사본의 변경/사용 상태와 보존·버리기 확인.
2. `중단된 내부 작업 확인…` — 내부 파일 보관/삭제 등의 작업 기록 확인.
3. `중단된 외부 저장 확인…` — 외부 사본 저장의 완료/불확실한 교체 확인.

세 도구를 하나의 자동 복구 명령으로 합치지 않는다. 메뉴를 여는 것으로 검사를 시작하지 않는다.
기존 조회 응답/이미 확보한 진단에 확인 필요 상태가 있으면 해당 종류와 `확인…` 진입점을
문제 영역에 직접 노출한다. 상태가 아직 없으면 메뉴는 항상 접근 가능하게 두고 `없음`으로 추정하지 않는다.
버튼을 숨긴다는 이유로 앱 시작/탭 전환에 작업 저널·사본 전체 검사나 해시 조회를 추가하지 않는다.

### 백업 구역

```text
자동 백업: 켜짐 · 다음 확인 시점 10.11(일) 18:00 이후
최근 자동 성공: 10.10(토) 18:00    수동 성공: 기록 없음
[지금 백업] [백업에서 복원…] [더보기 ▾]
                             ├ 백업에서 파일 꺼내기…
                             ├ 백업 폴더 열기
                             ├ 오래된 수동 백업 정리…
                             └ 백업 상태 상세…

문제가 있으면: 자동 백업 실패 · 파일 접근 확인 필요
              [상세…] [자료 검사] [백업 안내 확인]
```

- 정상 상태에서는 최근 성공과 다음 확인 기준을 요약하고 시도/지난 실패 원문은 상세에 둔다.
  `이후`와 앱 실행 중 확인이라는 의미를 유지한다. 백업 파일이 있다는 이유로 검증 성공을 표시하지 않는다.
- 실제 진행 중·실패·완료 미확인·상태 기록 읽기 실패·미해결 실패는 기본 영역에 남긴다.
  이전 실패 후 다른 시도의 성공이 있어도 상태 원장의 미해결 경고를 임의 해소하지 않는다.
- `백업 안내 확인`은 경고를 읽었다는 처리다. 실패를 성공으로 바꾸거나 파일을 복구하지 않는다.
  확인한 실패도 짧은 상태와 `안내 확인함`으로 남기고 상세에서 기록을 볼 수 있다.
  새 주의 상태가 발생하면 다시 표시하며 사용자가 접어둔 상세로 새 경고를 숨기지 않는다.
- 기존 2초 상태 확인은 저장된 상태 snapshot을 재사용한다. 주기마다 파일 전수 검증을 하지 않는다.
- 백업 복원 확인의 다음 실행 적용·현재 자료 보호, 수동 백업 정리의 정확한 대상 수·복구 불가,
  수동 백업이 자동으로 지워지지 않는 안내는 실제 명령 가까이 유지한다.
- 내보내기의 Excel 현재 검색/필터 적용과 ICS의 범위 선택을 짧게 분리한다.
  현재 목록과 전체 자료를 같은 범위처럼 안내하지 않는다.

## 8. U22-13 — 업무 묶음 외부 보관

```text
업무 묶음 보관
HTML·Excel 목록과 파일 사본을 외부 폴더에 남깁니다.
내부 자료는 유지됩니다. 전체 백업·복원 파일은 아닙니다.

범위       [연도별 ▾]
연도       [2026]    날짜 기준 [등록일 ▾]
[✓] 완료 업무만
[✓] 현재 첨부파일 포함
[ ] 파일 보관본 포함
[ ] 중요 시점의 파일 포함

대상: 2026년 등록된 완료 업무 · 주 화면 검색·필터와 별도
[포함·제외 상세 ▾]
                         [보관 폴더 선택…] [취소]
```

- 연도별이면 연도, 기간이면 시작/종료일을 표시한다. 사용하지 않는 날짜 입력은 숨긴다.
  선택 업무면 날짜/완료 조건을 숨기고 `선택한 업무 N개 · 날짜/완료 조건 미적용`을 표시한다.
  모드를 바꿔도 입력값/파일 옵션을 무조건 초기화하지 않는다. 숨긴 입력은 Tab 순서에 들어가지 않는다.
- 날짜 기준·양끝 포함·설정 시간대는 기존 계약 그대로다. 주 화면 검색/필터와 별도라는 안내는
  기간/연도 대상 요약에 남기고, 선택 업무는 명시적인 ID 범위임을 표시한다.
  `N개`는 전달받은 선택 수이며 실행 시 변경/삭제/휴지통 등 유효성 재검사는 기존 서비스가 수행한다.
- 현재 첨부 기본 켬, 파일 보관본/중요 시점의 파일 기본 끔을 유지한다.
  `중요 시점의 파일` 선택이 업무 정보/이력 전체를 보관한다는 뜻은 아니다.
- 펼침 상세는 업무 정보·결과·체크리스트·일지·저장된 회차·폴더 연결 정보와 선택한 파일 종류를 설명한다.
  제외 대상은 휴지통·해제 첨부·보기 사본·자동 변경 이력·중요 시점 정보 전체·외부 폴더 내용이다.
  폴더 경로 정보만 포함되고 실제 폴더 파일은 수집하지 않는다고 구분한다.
- 반복 업무는 저장된 회차만 포함하며 미래 회차를 생성하지 않는다.
  상세를 줄여도 실제 HTML/XLSX/보관정보의 범위·제외 기록을 없애지 않는다.
- 폴더 선택 취소는 시작하지 않음, 실행 취소/실패는 미완료다.
  파일 하나라도 보관하지 못하면 정상 완료로 표시하지 않는다.
  미완료 위치·사유는 남기고 사용자 폴더를 자동 삭제하지 않는다.
- 성공은 업무/파일 수와 폴더 열기, 필요하면 전체 경로/정리 경고를 표시한다.
  내부 파일 정리·재가져오기·문서 자동 열기는 추가하지 않는다.
  작업 중 비모달 전환과 알림 처리 가능 상태, worker 취소/종료를 유지한다.

## 9. U22-14 — 백업에서 파일 꺼내기

### 탐색과 페이지

- 기본 안내를 `파일 사본만 저장하며 현재 업무·DB는 바뀌지 않습니다` 한 번으로 합친다.
  백업 전체 검증·시간이 걸림·손상/지원 불가/현재 백업 교체 안내는 해당 상태에서 표시한다.
- `BackupFilePage.has_more`는 이미 101건 조회 후 100건을 반환하는 정확한 다음 페이지 신호다.
  새 COUNT/전수 조회·DB 이행 없이 이를 사용한다.
- 이동 영역은 `이전 페이지가 있음 또는 has_more`일 때만 보인다.
  첫 페이지 0/1/100건이면 숨김, 101건이면 표시, 마지막 페이지는 이전만 활성화한다.
  검색으로 한 페이지가 되면 다시 숨긴다. 탐색 중에는 건수 요약 자체는 유지한다.
- 기존 Ctrl/Shift 강조 선택은 **현재 페이지에서만 최대 100개**다.
  보관함의 페이지 간 저장 체크와 합치지 않는다. `선택 N개 · 페이지 이동 시 선택 해제`를
  필요한 이동 화면에 표시하고 단일 페이지에는 `선택 N개`와 짧은 선택 방법만 둔다.
- 백업 파일명은 문자 수로 자르기보다 현재 폭에 맞춰 생략한다. 원문 경로 확인을 제공한다.

### 작업과 결과 상태

| 상태 | 기본 행동/표시 |
| --- | --- |
| 백업 미선택 | 백업 선택, 닫기. 저장/검색/페이지 이동 불가, 작업 취소 숨김 |
| 검증/검색/저장 중 | 진행 안내, 작업 취소 표시. 충돌하는 선택/조회/저장 비활성 |
| 취소 요청 후 | `취소 중… 이미 저장한 파일은 유지합니다` 유지. 중복 취소는 비활성 |
| 탐색 준비 | 검색·현재 페이지 다중 선택·선택 파일 저장. 작업 취소 숨김 |
| 저장 결과 | 저장/실패/미처리/확인 필요 수와 항목. 탐색 페이지 버튼 숨김 |
| 실패/불완전 | 짧고 구별 가능한 이유와 상세 진입점. 성공/자료 없음으로 대체 금지 |

- 취소 버튼은 worker가 실제 실행 중일 때만 보인다. 취소 요청은 안전한 마무리 요청이며
  즉시 종료 완료로 표시하지 않는다. 완료 신호 후 숨기고 관련 행동을 복구한다.
- 결과 행은 백업 탐색 항목과 다른 종류다. 결과 상태에서는 저장/이전/다음 명령을 비활성화하고
  상단 검색 행동을 `목록 다시 보기`로 제시한다. 재조회 시 검색 첫 페이지부터 다시 시작한다.
- 실패/미처리/확인 필요를 `저장 N/전체 M` 안에만 감추지 않고 각각 표시한다.
  오류·복구 경로·실제 출력 이름은 읽기 전용 결과 상세에서도 확인할 수 있게 한다.
- 저장 폴더 열기는 결과 행동 쪽에 두고 페이지 이동과 분리한다. 성공 파일이 있을 때만 제공한다.
  완료 파일을 취소 때문에 되지우거나, 현재 DB로 복원/재첨부하지 않는다.
- 읽기 전용 세션·백업 교체 검사·파일별 해시/안전 경로·동명 번호·무덮어쓰기·복구 저널은 그대로다.
  창 닫기/앱 종료 시 worker를 안전하게 마무리한 뒤 세션을 닫는다. 강제 thread 종료는 쓰지 않는다.

- UI는 SQL/직접 파일 삭제/전수 해시를 추가하지 않는다. 기존 제한 조회와 worker를 유지한다.
- 오늘 요약은 이미 받은 항목에서 계산하고 백업 페이지는 기존 `has_more`를 사용한다.
  경로/도움말 표시를 위해 새 전체 파일 스캔을 하지 않는다.
- 비동기 결과는 기존 요청 세대·선택 ID·닫힘 상태를 확인한다.
  메뉴에 옮긴 데이터 행동도 작업 중 guard/비활성 상태를 공유한다.
- 사용자 가이드와 HTML 안내 원문을 구현과 함께 갱신한다. 배포물 재생성은 별도 요청이다.

### 화면·성능 검증

- 일반 비최대화 창과 현재 최소 크기를 모두 검사한다. 기준은 주창 760×560,
  폴더를 포함한 업무 보기의 현재 최소 크기, 일반 설정 460×450, 매시 설정 430×420,
  데이터 관리 500×480, 외부 보관 520×570 및 낮은 창, 백업 파일 창 500×420 logical px다.
  펼친 도움말과 긴 오류에서도 스크롤/목록/닫기·저장 접근을 확인한다.
- 공통 밝은 테마에 밝은/어두운 palette를 주입하고 100/150/200% 배율의 대표 작은 창을 렌더링한다.
  본문·viewport·메뉴·경로·확인/결과 상세·선택/비활성·필수 경고의 대비와 글자 잘림을 확인한다.
  실제 회사 PC/DRM/모든 모니터 환경까지 검증했다고 하지 않는다.
- 기존 합성 DB/파일/백업 fixture만 사용한다. 운영 DB·첨부·개발 사용 자료는 테스트에 쓰지 않는다.
- 대량 자료에서 조회 제한과 파일 스트리밍을 유지하고 새 시작 시 전수 검사/중복 worker가 없는지 확인한다.
  큰 백업 검증/외부 보관 중에도 업무 알림과 매시 알림을 처리할 수 있어야 한다.
- 완료 보고에는 실제 테스트 수·측정·캡처와 미검증 항목을 구분한다. 1차의 1,289개 통과를
  2차 구현의 검증 결과로 재사용하지 않는다.

## 12. 설계 검토와 다음 단계

확인한 위험은 `짧아진 알림 요약이 미확인을 감춤`, `자동 백업 개수의 적용 범위 오해`,
`매시 설정의 즉시/저장 적용 혼동`, `복구 버튼을 숨긴 뒤 문제도 안 보임`,
`외부 보관을 전체 백업으로 오해`, `백업 결과 행에서 탐색 명령 실행`이다.
각각 조건부 필수 표시·정확한 라벨·현재/초안 분리·문제 진입점·고정 주의·명시적인 결과 상태로 대응한다.

추가 사용자 결정을 요구할 새 기능/삭제 정책은 넣지 않았다.
위 순서로 구현·격리 테스트를 진행했다. 다음 단계는 개발 소스의 사용자 사용 확인이다.
버전 변경·EXE/설치 파일/ZIP·커밋·GitHub 업로드는 이번 구현 요청에 포함하지 않았다.
