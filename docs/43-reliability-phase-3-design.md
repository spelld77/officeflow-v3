# 달력·오늘 알림 묶음 3차 상세설계

작성: 2026-10-10. 2차 사용 확인 후 상세설계·구현·격리 테스트 승인.
현재: 소스 구현·격리 회귀 완료, 사용자 사용 확인 전. 실제 결과는 44번 보고를 따른다.
38번 공통설계와 24번 보존/회차 계약을 유지한다. U1 표시 개선이며 처리 규칙 변경은 아니다.

## 1. 사용자 흐름과 수용 기준

- 달력 하단: 같은 날짜의 업무 일정과 알림 여러 개를 한 줄로 표시한다.
  일정의 시각·제목은 유지하고 `알림 N건 · 다음 HH:MM`을 붙인다.
- 그날 일정이 없으면 `알림만` 표시로 업무를 노출한다. 업무 일정 날짜를 알림 날짜로 옮기지 않는다.
- 오늘 알림: 한 업무의 다중 알림이 미리보기 2~3줄을 독점하지 않게 회차별 한 줄로 묶는다.
  알림 영역은 업무 검색/필터와 무관하며, 아래 오늘 업무 목록은 그대로 유지한다.
- 선택 후 `알림 시각 보기`로 개별 알림 시각/상태/원래 예정/재알림을 확인한다.
  더블클릭과 기존 기록·첨부·오른쪽 메뉴는 업무/정확한 회차에 연결한다.
- 개별 알림 보기 창은 비모달이며 확인/재알림/완료 명령을 추가하지 않는다.
  실제 알림 창은 기존대로 알림별 확인/재알림, 업무/회차 완료를 수행한다.

## 2. 읽기 전용 투영과 식별

- 공통 묶음 키는 `(task.id, original_occurrence_start)`이며 비반복은 업무 범위 `None`이다.
  비반복 상대 알림의 저장 occurrence_start가 업무 시작이어도 별도 회차로 취급하지 않는다.
  반복의 절대 날짜 알림(None)은 업무 공통 범위다. 특정 회차에 임의로 합치지 않는다.
- 제목이 같아도 ID가 다르면 별개이며, 이동된 날짜/시각으로 반복 회차를 식별하지 않는다.
- 묶음은 기존 ReminderPreviewItem들을 그대로 보유한다. key/delivery ID/처리 상태는 변경하지 않는다.
  중복 key 입력은 한 번만 표시하며 서로 다른 reminder ID는 같은 시각이어도 별개다.
- 대표 시각은 미확인 → 재알림/예정 → 발생 기록 확인 필요 → 처리 이력 순으로 선택하고
  같은 우선순위는 effective_at/reminder_id로 정렬한다. 대표 시각이 가장 가까운 '다음' 알림이며
  미확인은 `미확인`, 시간 지났으나 발생 기록 없음은 `확인 필요`, 모두 처리된 경우 `처리 이력`이다.
- 달력 일정/알림 합치기는 선택 날짜 투영 후 수행한다. 기간 일정의 각 날짜에도 동일 키로 연결한다.
  알림 이동의 원래 날짜 이력과 새 날짜 재알림은 양쪽에 보이되 서로 다른 실제 알림처럼 복제하지 않는다.
- 일정만 있는 행은 기존 ScheduledTask를 유지한다. 일정+알림/알림만 행은 공통 묶음 모델을 사용한다.
  일정이 뒤늦게 도착해도 같은 키 선택과 기록/첨부 동선이 유지된다.
- 업무 완료/취소와 알림 확인/처리/중단은 독립적으로 표시한다. 미래 중단 알림을 새 이력으로 만들지 않는다.

## 3. 화면과 조회 상한

```text
달력 선택 날짜: 업무 2개 · 알림 4건
10:00  제출 준비          알림 3건 · 다음 11:00
14:00  결재 확인          알림 1건 · 미확인
                          [알림 시각 보기]

오늘 알림: 업무 2개 · 총 4건 · 2개 표시
11:00  제출 준비          알림 3건
14:00  결재 확인          알림 1건
                [알림 시각 보기] [전체 보기]
```

- 헤더는 업무 묶음 수와 실제 알림 건수를 분리한다. 서로 다른 회차는 별개 묶음이다.
  부분 조회이면 `이상/일부 조회`로 표기하고 더 조회 동선을 유지한다. 없는 알림을 0건이라 단정하지 않는다.
- 달력 셀의 기간 막대/일정 개수와 날짜별 알림 건수 배지는 기존 역할을 유지한다.
  별도 알림 막대를 추가하지 않는다. 배지 선택은 알림을 가진 묶음으로 스크롤한다.
- 미리보기는 2~3개 묶음만 보인다. 전체 보기와 개별 시각 창은 100행 단위 페이지이며
  원래 조회 예산/취소/요청 generation을 유지한다. 최대 조회 100,000건이어도 이 두 창은
  한 번에 100행만 만든다. 달력 선택 날짜의 기존 전체 일정 조회/스크롤은 유지한다.
  같은 날 고유 업무/회차가 매우 많으면 묶음만으로 행 수를 줄일 수 없다는 제한은 보고에 명시한다.
- 상세 시각 창이 열린 동안 결과 갱신 시 같은 키의 최신 내용을 반영한다. 업무가 사라지면
  목록을 비우고 '현재 날짜에 표시할 알림 없음'을 안내한다. 부모 종료 시 연결 창도 종료한다.
- 제목은 한 줄 생략+툴팁, 요약은 줄바꿈 가능, viewport/선택/스크롤 색은 명시적인 밝은 스타일이다.
  좁은 주창 760×560 및 상세 창 460×340, palette/배율 100/150/200%를 격리 렌더링한다.
  캡처에서 확인한 낮은 창 목록/안내 겹침을 막기 위해 하단 최소 높이를 실제 자식 레이아웃으로
  계산한다. 좁은 창은 달력 도구줄/격자를 줄이고 개수 요약 모드에서 일정·알림 hit 영역을
  따로 배치한다. 작은 알림 배지는 짧게 표시하고 전체 건수는 툴팁/하단에서 확인한다.
  긴 제목이어도 첨부 표시는 행 앞에 남기며 업무 일정 없는 알림의 상세에 가짜 일정을 넣지 않는다.

## 4. 구현 경계와 변경하지 않는 것

- Application: 묶음 모델, scope key, 그룹 정렬, 일정 연결의 순수 함수.
- Presentation: 한 줄 delegate, 제한된 상세/전체 조회 창, 달력 선택/오늘 상세 연결.
- DB/스키마/백업/파일/스케줄러/알림 쓰기 경로는 변경하지 않는다.
  실행 중 편집 초안, 처리필요 분류, 알림 팝업 묶기, 자동 자료 정리도 범위 밖이다.
- 운영 프로필/개발 데이터는 테스트하지 않는다. 버전·EXE/ZIP·설치파일·커밋·업로드는 별도 요청 사항이다.

## 5. 검증 계획

실패 테스트 후 구현한다. 같은 이름/다른 ID, 비반복 상대·절대 혼합, 반복 공통/회차,
이동 회차, 기간/자정/월 경계, 재알림 다른 날짜, 완료/확인 상태 분리, 선택 유지,
오늘 검색 독립성, 기록/첨부/메뉴 연결, 부분 조회/더 조회, 100행 상한, 종료를 검사한다.
기존 알림별 확인/재알림/회차 완료 회귀를 재사용하며 읽기만으로 delivery 행을 만들지 않음을 확인한다.
전체 정적 검사와 단위·통합·성능/UI 회귀를 실시하고 실제 수행/미검증 환경을 44번 보고에 구분한다.
