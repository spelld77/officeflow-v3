배포 후속 기록: 2026-10-11 사용자 요청으로 3.0.10에 포함한다. 이 문서의 미배포 표기는 작성 당시 기록이며
최신 검증·GitHub 공개 결과는 [3.0.10 릴리스 체크리스트](59-release-checklist.md)를 따른다.

작성일: 2026-10-11. 공개 3.0.9 이후 개발 소스, U22-8~U22-14.
[57번 상세설계](57-ui-simplification-phase-2-design.md) 이후 `이제 구현 테스트까지 해라` 요청으로 적용했다.
상태: 구현·최종 전체 자동 검증 완료. 사용자 사용 확인·배포는 아직이다.

## 2. 보존·부하 경계

- 알림 발생·확인·다시 알림·완료·처리 필요 분류는 바꾸지 않았다. 오늘 헤더의 총수는
  개별 알림 건수이고 전체 보기의 업무·회차 묶음 수와 구분한다. 일부 조회로 정확한 전체 수/다음 시각/없음을 약속하지 않는다.
- 오늘 요약은 기존 조회 결과에서 계산한다. 검색·필터 범위 안내는 실제 조건에만 반응하고
  알림 조회 자체를 필터링하지 않는다. 회차 키·읽기 전용 시각 창·100행 페이지는 유지한다.
- 외부 폴더는 사용자가 소유한다. 표시/메뉴를 위해 새 파일 스캔을 추가하지 않고,
  휴지통의 이름 변경/재지정/삭제를 명령 단계에서도 막는다. 외부 파일은 OfficeFlow 백업에 포함되지 않는다.
- 일반 설정의 적용/취소와 매시 설정의 저장/즉시 오늘 선택을 분리한다. 저장 시 최신 오늘 날짜 예외를 보존한다.
  08시 조건·59분 경고·제외 시간 최대 8개·끄기/재실행 정책은 그대로다.
- 복구 도구는 선택 없이 접근할 수 있지만 메뉴를 여는 것만으로 검사·복구·삭제하지 않는다.
  실행 중 메뉴/명령을 막으며 백업 안내 확인을 실제 백업 성공으로 바꾸지 않는다.
- 외부 보관 파일 범위와 서비스는 유지한다. 현재 첨부 기본 포함, 개별 보관본/중요 시점 파일 기본 제외.
  선택 업무에는 날짜/완료 조건을 적용하지 않으며 내부 자료를 변경하거나 복원용 전체 백업을 만들지 않는다.
- 백업 파일 조회는 기존 100+1건 제한과 `has_more`로 이동 여부를 판정한다. 선택은 현재 페이지 최대 100건이다.
  해시·안전 경로·기존 파일 무덮어쓰기·동명 번호·복구 저널·완료 파일 보호는 기존 구현을 사용한다.
  결과 행에서 이전 탐색 커서/저장 명령을 재사용하지 않는다.

## 3. 검증 중 발견·보완

- 데이터 관리 창을 생성 직후 닫으면 예약된 현황 조회가 뒤늦게 시작할 수 있었다.
  연속 테스트에서 `QThread: Destroyed while thread is still running` 비정상 종료를 확인했다.
  닫힌 소유자는 조회/작업을 시작하지 않도록 막고 종료 신호 뒤 native 작업 정리까지 기다리도록 보완했다.
  즉시 종료·취소·적용 닫기의 회귀 검사를 추가했다. 강제 thread 종료는 사용하지 않는다.
- 작은 Windows 백업 창의 목록 viewport가 150 logical px 미만으로 줄어드는 것을 확인했다.
  목록 최소 공간을 확보했다. 필요한 경우 창의 최소 높이가 조금 커지며 하단 행동을 자르지 않는다.
- 일반/매시 설정의 스크롤 가장자리 어두운 배경과 가로 잘림을 실제 캡처에서 확인했다.
  본문·viewport·스크롤 스타일을 명시하고 좁은 form 줄바꿈, 짧은 항목 문구로 보완했다.
  대체 글꼴 환경에서도 사용량 제목/추가 제외 시간의 불필요한 너비를 줄였다.
- 이전 문구/항상 보이는 페이지 버튼을 기대하던 기존 테스트를 새 표시 계약에 맞췄다.
  선택·범위·파일 보호 검사를 제거한 것이 아니며 숨은 버튼의 기하 검사만 현재 보이는 버튼으로 제한한다.
- 중간 전체 UI 실행 한 차례가 기존 썸네일 검사에서 지연되어 중단됐다.
  해당 검사의 단독 재실행과 최종 전체 547개 재실행은 통과했고, 이후 전체 검증에 정지 위치 출력 옵션을 사용했다.
  이 지연의 원인을 보안 프로그램이나 특정 소스 변경 때문이라고 단정하지 않는다.

## 4. 자동 검증

합성 DB·파일·백업만 `.test-tmp`에 만들었다. 실제 사용자 자료·`.local-data`는 사용하지 않았다.

| 검사 | 결과 |
| --- | --- |
| 단위·통합 전체 | 765개 통과 |
| UI 전체 최종 재실행 | 547개 통과 (221.53초) |
| 최종 영향 화면 재검증 | 69개 통과 |
| 대량 자료 성능 전체 | 5개 통과 |
| Ruff / mypy | 통과 / 소스 136개 통과 |
| 변경 파일 형식 / 공백 | 통과 |
| Windows 실제 Qt 렌더링 | 밝은/어두운 팔레트·작은/일반 창 × 100/150/200%, 12개 조합 통과 |

이번 신규 검사는 기능/실패 24개와 화면 조합 4개다. 기본 전체 검사에 포함되며,
별도 배율 프로세스와 영향 화면 재검증을 중복해서 전체 검사 수에 더하지 않는다.
기본 전체 검사 합계는 1,317개다. 중간 검사에서 발견한 배치·문구 기대값을 보완한 뒤 최종 전체 UI를 재실행했다.
이전 1차의 통과 결과를 이번 구현의 통과 결과로 재사용하지 않았다.

대표 캡처는 `artifacts/ui-simplification-phase2-captures/`에 남긴다(Git 제외).
오늘 알림·폴더·일반/매시 설정·펼친 도움말/추가 설정·데이터 사용량/백업·외부 보관·백업 파일/상세를 확인했다.
창 최소 크기, 목록 공간, 버튼/체크 글자 너비, 본문 가로 넘침과 스크롤 viewport 대비를 자동 검사한다.
Windows Qt에 밝은/어두운 팔레트를 주입한 검증이며 실제 회사 PC의 시스템 테마/DRM/모든 모니터를 검사한 것은 아니다.

한글 파일 경로 관련 샌드박스 권한 오류는 격리된 승인 실행으로 확인했다.
권한 오류를 OfficeFlow 기능 성공/실패 결과로 섞지 않는다.

## 5. 다음 사용 확인

기존 미커밋 작업을 보존했다. 이번 변경은 새 DB 이행·저장 정책·자료 이동/자동 삭제를 추가하지 않는다.
실제 사용자 DB/첨부/백업, 버전, EXE·설치 파일·ZIP, Git 커밋·GitHub 업로드는 변경하지 않았다.
도움말 Markdown과 배포용 HTML 원문을 갱신했지만 기존 공개 배포물은 그대로다.

개발 프로그램을 트레이까지 완전히 종료한 뒤 `run-officeflow-dev.cmd`로 다시 실행한다.
이 실행은 `.local-data`의 개발용 자료를 사용하며 실제 사용 자료로 테스트하지 않았다.

1. 오늘 알림의 건수/다음 시각·미확인 안내와 검색어/필터를 입력·해제할 때의 범위 안내.
2. 폴더 `더보기 → 전체 경로…`, 일반/매시 설정의 접힌 설명과 실제/저장 전 구분.
3. 데이터 더보기 메뉴·현황/백업 상세, 외부 보관 범위를 바꿀 때 불필요한 입력이 사라지는지.
4. 백업 파일 조회의 한 페이지/여러 페이지·작업 취소·결과 상세·목록 다시 보기.

실제 회사 문서 편집기·보안 프로그램과 장기간 운영 확인은 별도다. 처리 필요 분류와 내부 경량화는 계속 보류한다.

## 6. 사용 확인 후 보완: 빠른 등록 Enter (2026-10-11)

- 사용자 보고: 빠른 등록에 제목을 입력하고 Enter를 누르면 등록되지 않고 선택 업무 수정창이 열린다.
- 원인: 창 전체에 걸린 `Return` 단축키가 입력칸의 `returnPressed`보다 먼저 선택 업무 열기를 실행했다.
  기존 빠른 등록 테스트는 입력칸에 실제 포커스를 주지 않고 키 이벤트를 직접 전달해 이 충돌을 놓쳤다.
- 수정: 업무 열기는 업무 목록·캘린더 하단 목록 각각의 `WidgetShortcut`으로 제한한다.
  두 목록에서 일반 Enter/숫자키패드 Enter를 지원하며 입력칸과 다른 화면의 Enter를 가로채지 않는다.
  빠른 등록의 저장 방식·일정 기본값·알림 처리 정책은 변경하지 않았다.
- 회귀 검사: 실제 창에 포커스를 주고 키를 전달해 오늘/전체 보기의 선택 업무가 있는 상태에서 연속 등록,
  빈 제목 검증, 검색 Enter, 업무 목록의 단 한 번 열기, 캘린더 업무 기록 열기를 확인했다.
  빈 목록의 기존 빠른 등록 검사도 같은 창 키 전달 방식으로 강화했다.
- 수정 전 충돌 재현 후, 관련 UI·업무 서비스 검사 **136개 통과**.
  별도 Windows Qt 키 입력 검사 **12개 통과**(일반/숫자키패드 Enter).
  Ruff·변경 파일 형식·mypy 통과. 앞 절의 전체 1,317개 결과는 이 후속 수정 전 결과이며,
  이번에는 영향 범위 검사를 실행했다. 한글 경로 샌드박스 권한 오류 2건은 합성 자료의 승인 실행에서 해소됐다.
- 실제 사용자 자료·DB 이행·버전·EXE·설치 파일·ZIP·Git 작업은 변경하지 않았다.
