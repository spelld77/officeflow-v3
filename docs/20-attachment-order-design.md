# 첨부 수동 순서 설계

설계일: 2026-10-06. 첨부 순서와 0011 DB 업그레이드만 적용한다. 체크리스트·업무 정렬·드래그 정렬·묶음 이동·되돌리기는 제외한다. 배포 버전·EXE·ZIP·GitHub 공개는 별도 릴리스 단계다.

## 동작

- 파일 추가 옆 위로·아래로, 오른쪽 클릭 메뉴에 열기·위로·아래로·맨 위로·맨 아래로.
- 첨부 ID로 최신 DB에서 이동 대상을 계산한다. 오래된 화면의 전체 순서 배열은 저장하지 않는다.
- 즉시 저장하고 선택·스크롤·포커스를 유지한다. 실패 시 경고하고 최신 목록을 표시한다.
- 선택 없음·이동 경계·복사/검사 중·휴지통 업무 제한. 서비스/DB에서도 업무와 연결 상태 재검사.
- 새 파일은 맨 아래. 여러 파일은 전달받은 순서대로 성공한 파일끼리의 순서를 유지한다. 중복/실패는 기존 순서를 바꾸지 않는다.
- 반복 업무의 첨부와 순서는 모든 회차 공통임을 첨부 탭에 안내한다.

## 저장

- attachments.sort_order: NOT NULL 정수, 기본 0은 미할당 표식. 등록 시 정리 대기를 포함한 업무별 최대값 + 10을 원자적 쓰기 트랜잭션에서 배정한다.
- sort_order ASC, created_at DESC, id DESC 조회 및 업무별 인덱스. 전체 첨부 검색/정리 화면의 날짜순은 유지.
- 이동은 활성 파일의 슬롯을 교환/회전하고 정리 대기 슬롯은 유지한다. 연결 해제/복원은 순서값 보존. 그동안 재배열했다면 원래 이웃까지 복귀하지는 않는다.
- ID·파일명·경로·체크섬·날짜·업무 수정일·알림을 변경하지 않는다. 순서 이동에는 파일 I/O가 없다.
- 이동·등록 순번은 SQLite BEGIN IMMEDIATE로 최신 상태를 읽고 원자적으로 저장한다.

## DB 보호

- 0011에서 업무별 created_at DESC, id DESC(정리 대기 포함)를 10,20,…으로 변환해 기존 활성 목록 순서 유지.
- ADD COLUMN과 인덱스 추가로 테이블 재생성을 피하고 첨부 검색 트리거·색인·외래키 보존.
- 기존 DB의 지원 리비전과 head를 비교. 업그레이드 전 SQLite 온라인 보호 사본·여유 공간·무결성 검사. 최신 DB는 다시 백업/순번 생성하지 않는다.
- 마이그레이션과 Alembic 버전 기록을 명시적 트랜잭션에 넣는다. 실패 시 롤백하고 사본 보존·시작 중단. 재실행 재시도 가능.
- 개인 PC는 가상 자료로 검증하고 코드만 업무 PC에 전달. 실제 업무 PC 첫 실행에서 그 PC의 DB 업그레이드. 업무 자료 반출 불필요.
- 이전 백업 복원 후 같은 보호 업그레이드. 이후 구 버전으로 실행하지 않는다. 구 버전 복귀는 앱과 업데이트 전 백업을 함께 사용하며 이후 입력 자료가 되돌아갈 수 있음에 유의.

## 창 동기화

- 서비스 변경 알림을 Qt queued signal로 받아 같은 업무의 모든 기록 창(주 창·업무일지·반복 회차)의 첨부 목록만 갱신.
- 결과 메모·체크리스트·업무일지 입력은 유지. 순서 이동으로 전체 업무 목록을 갱신하지 않는다.
- 복사/검사 중인 창은 완료 뒤 최신 메타데이터를 조회. 창 닫힘·종료·삭제 시 구독 해제.

## 검증 기준

0010 순서·정리 대기·검색 보존, 실패 롤백/재시도·보호 사본/공간 부족·최신 DB 무변경·이전 백업 복원,
재실행 유지·이동 경계·동시 등록·최신 상태 기준 이동·다른 업무/휴지통/연결 해제 방어·파일 I/O 없는 이동,
여러 창 입력/선택 유지·작업 중 제한·작은 창과 125% 배율·전체 회귀 검사.

## 구현 및 검증 결과

2026-10-06 소스 구현 완료. 버전 번호와 공개 배포 파일은 변경하지 않았다.

- 전체 회귀 검사: 589개 통과(63.15초).
- Windows 125% 배율: 밝은 앱 테마의 첨부 순서·무결성 확인·알림 상호작용 UI 검사 39개 통과(9.53초). 작은 창의 버튼 배치도 이미지로 확인.
- Ruff·엄격한 mypy·git diff --check 통과.
- 별도 가상 데이터 폴더에서 소스 앱 시작/종료 smoke-test 통과.
- 테스트용 DB만 사용했다. 실제 업무 자료·기존 EXE/ZIP·GitHub 릴리스에는 적용하지 않았다.

소스를 업무 PC에 적용하면 첫 실행에서 해당 PC의 기존 DB를 보호 사본 생성 후 0011로 업그레이드한다.
업그레이드된 DB를 기존 공개 3.0.6 프로그램에 다시 연결하지 않는다. 공개 배포는 버전을 올리는 별도 단계에서 진행한다.
