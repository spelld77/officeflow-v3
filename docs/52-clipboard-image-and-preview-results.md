# 클립보드 이미지 첨부·미리보기 구현 및 검증

배포 후속 기록: 2026-10-11 사용자 요청으로 3.0.10에 포함한다. 이 문서의 미배포 표기는 작성 당시 기록이며
최신 검증·GitHub 공개 결과는 [3.0.10 릴리스 체크리스트](59-release-checklist.md)를 따른다.

2026-10-10. U20/U21을 개선 목록에 기록하고 [51번 상세설계](51-clipboard-image-and-preview-design.md)에 따라 구현했다.
기존 미커밋 외부 폴더·업무 묶음·시간 입력 변경은 보존했다.

## 구현 결과

- 새 업무와 업무 수정 창의 `클립보드 이미지 추가`: 명시적 클릭 때 이미지 사본을 확보한다.
  추가 시각 이름, PNG 이름 변경, 작은 미리보기, 확대 보기, 제거, 최대 8장 대기를 제공한다.
  자동 감시/클립보드 변경/전역 Ctrl+V는 없다. 기존 업무 입력 Tab 순서는 유지한다.
- 기존 첨부 탭의 `클립보드 이미지`: 별도 비모달 창에서 확인 후 `첨부`로 등록한다.
  성공 팝업을 추가하지 않았고 중복은 짧은 화면 안내로 알린다.
- 사진은 업무 저장 후 기존 서비스로 일반 PNG 첨부를 만든다. 실패 사진만 남겨 재시도하며
  이미 저장된 업무 정보는 잠근다. 업무·알림·기존 이력을 재저장하거나 중복 생성하지 않는다.
  여러 긴 오류는 첫 오류·추가 건수로 줄이고 전체는 tooltip에 남긴다.
- 기존 첨부 목록의 `미리보기`: 선택한 PNG/JPG/JPEG/BMP 한 개만 별도 읽기 전용 창에 표시한다.
  열어둔 창은 단일 선택에 따라 갱신하며 복수/비이미지/선택 해제 시 이전 사진을 지운다.
  명시적으로 첨부 ID를 선택하는 동작도 기존 복수 선택을 해제하도록 정돈했다.
  목록 높이는 그대로이고 외부 열기/더블클릭은 기존 편집기 동작이다.
- 읽기 예약·보호 핸들로 파일을 읽고 원본은 고정 크기/해시를 검증한다.
  DB 관측값/보관 상태를 바꾸거나 보기 사본·캐시·작업본·보관본을 만들지 않는다.
  휴지통은 읽기 전용 미리보기만 허용한다. 저장된 사진의 외부 복사와 백업/복원은 기존 서비스를 따른다.
- PNG 인코딩·첨부 복사와 기존 이미지 읽기·검증·decode는 worker에서 수행한다.
  미리보기 worker는 하나이며 늦은 결과는 버린다. 닫기/종료는 취소 요청 후 안전한 완료를 기다린다.
  worker 결과는 명시적 GUI queued slot으로 전달하고 native thread cleanup 전 객체를 해제하지 않는다.
- 입력 사진 한 장 16M 픽셀·64 MiB, 대기 합계 128 MiB, 미리보기 파일 64 MiB·16M 픽셀 제한이다.
  이는 대기 이미지/파일 제한이지 OfficeFlow 프로세스 전체 메모리 상한이라는 뜻은 아니다.
  작은 썸네일용으로 전체 pixmap을 먼저 만들지 않고, 미리보기 출력은 최대 1200x900이다.

  내용 중복 방지, 사진 외부 저장·백업/복원, 휴지통 읽기 전용을 검사했다.
- PNG/JPEG/BMP, 손상/누락/형식 위장/크기 상한/권한 거절,
  고정 원본 해시 불일치·읽기 후 DB/파일 불변·보기 캐시 미생성을 확인했다.
- 선택 전환/복수 선택/닫기·재사용/늦은 결과 버림을 검사했다.
  사진 입력/미리보기 창과 함께 알림을 QWindow 이벤트로 처리하는 비모달 입력 검사를 통과했다.
- 개발 중 worker 종료의 경합에서 native 종료를 발견해 wrapper 소유권 해제 시점과
  GUI 결과 전달을 보완했다. 취소·종료 10회 사례를 포함한 사진 검사 전체를 별도 프로세스에서
  5회 재실행했다. 이를 모든 OS/보안 환경에서 절대 종료하지 않는다는 보장으로 표현하지 않는다.
- 최초 전체 UI 실행은 최종 요약 없이 종료되어 통과로 인정하지 않았다.
  해당 기록/알림 구간 26개는 별도 검사에서 통과했다. 다음 전체 실행은 462 통과·500px 도구막대 1개 실패였다.
  기존 `파일 선택 (여러 개)`를 짧은 `파일 추가`로 정돈하고 여러 선택은 tooltip과 안내로 유지했다.
  관련 55개와 배율 검사를 통과한 뒤 최종 전체 UI 464개도 모두 통과했다.
- `artifacts/image-feature-regression-core.log`, `image-feature-complete-ui.log`,
  `image-feature-toolbar-final.log`, `image-worker-repeat-1..5.log`에 결과를 남겼다.
  중간 실패 로그도 원인/진행 기록이며 최신 통과 결과와 구분한다.
  수정한 9개 Python 파일의 format 검사도 통과했다. 기존 미수정 파일의 포맷까지 일괄 변경하지 않았다.

## 화면 검사 및 한계

Windows 한국어 글꼴, offscreen 밝음/어둠 제어 팔레트에서 460px 업무 입력·사진 창,
500px 첨부 목록·400px 미리보기 창과 Qt 배율 100/150/200%를 렌더링했다.
글자/배경색·버튼 경계·목록 높이·좁은 미리보기 창을 검사하고 캡처를 직접 확인했다.
캡처는 `artifacts/image-attachment-ui-captures/`에 있다.
실제 Windows 설정의 테마/DPI 전환, 다중 모니터·회사 PC 보안 제품은 미검증이다.
시험은 합성 사진과 격리 DB/파일만 사용했다. 실제 클립보드 내용·사용자 프로필·`.local-data`는 읽지 않았다.

미저장 사진은 메모리 대기 자료로, 취소/종료/강제 종료 후 복원하지 않는다.
업무 저장 후 첨부 단계에서 닫으면 업무와 성공 첨부는 남고 미처리 사진은 버린다.
정상 성공/실패/취소는 전용 임시 PNG를 정리하지만 강제 프로세스 종료/정전은 OS 임시 파일을 남길 수 있다.
업무와 모든 사진을 하나의 원자적 저장으로 만들거나 사용자 임시 폴더를 임의 청소하는 기능은 아니다.

## 사용자 확인·배포 상태

`run-officeflow-dev.cmd`를 더블클릭해 개발 소스를 실행한다.
캡처 → 새 업무의 `클립보드 이미지 추가` → 이름/보기 → 저장,
기존 업무의 `첨부파일 → 클립보드 이미지 → 첨부`,
이미지 선택 → `미리보기` → 다른 사진 선택을 확인하면 된다.

개선 목록·설계·사용자 안내/도움말 소스에 반영했다. 추가 DB 이행·새 의존성은 없다.
기존 외부 폴더 기능의 미배포 DB 0016은 그대로이며 버전은 3.0.9다.
EXE·설치 파일·ZIP 재생성, 커밋·GitHub 업로드는 이번 범위에 없어 하지 않았다.
따라서 현재 공개 배포물에는 이번 기능이 없고 사용자 사용 확인은 개발 소스로 진행한다.
