# 업무 흐름 연속성: 공통·상세설계

2026-10-16. 사용자 `설계및 구현 테스트까지 완료해` 승인으로 직전 제안 세 가지를 구현한다.
U34 탭 복귀, U35 완료 요약 성공 안내, 기존 U26 날짜 간편 변경이다.
첨부 묶음/검색 추가·관심 등급 정리는 사용자가 제외했다. 철학은 입력/화면을 늘리지 않고
업무로 돌아가기 쉽게 한다는 판단 기준이며 별도 철학 기능을 만들지 않는다.
기존 미커밋 변경·DB0016·백업 v3·첨부 보존을 유지한다. 배포/버전/Git/실사용 자료 변경은 제외한다.

## 1. 탭별 보던 위치

- 같은 실행 중 탭별 선택 업무 ID/원래 회차 키, 화면 맨 위 항목 ID/상대 위치,
  로드한 건수와 정렬/필터 지문을 메모리에 기억한다. 업무 본문/파일을 복사 저장하지 않는다.
- 탭 전환/달력 진입 전에 기억하고 다시 돌아오면 현재 자료를 재조회한 뒤 ID로 선택/위치를 복원한다.
  검색어는 종전처럼 해제하며 검색 중 위치를 검색 해제된 목록에 적용하지 않는다.
- 정렬/필터 변경이나 오늘 날짜 변경 때는 이전 순서/날짜의 위치를 무리하게 적용하지 않는다.
  사라진/다른 탭으로 옮겨진 업무를 대신 다른 업무로 선택하지 않는다.
- 재조회는 기존 페이지 단위를 유지하며 복귀용 로드는 보기/그룹당 최대 500행으로 제한한다.
  그보다 깊은 위치의 완전 복원을 보장하지 않으며 첫 500행에 없는 선택은 해제한다.
  임의 전체 자료 조회/DB·설정 이행/재시작 복원은 추가하지 않는다.
  상한 밖의 맨 위 항목을 찾지 못하면 처음으로 돌아가며 목록 끝 고정에 따른 자동 추가 조회를 유발하지 않는다.
- 입력/빠른 등록·새 날짜 이동 후의 명시적 선택이 복귀 타이머에 덮이지 않게 한다.
  새 입력/사용자 스크롤·클릭/다른 탭 이동/종료는 대기 중 복귀를 취소한다.

## 2. 완료 요약 저장 안내

완료 요약의 성공 확인 팝업만 없앤다. 기존 버튼 옆 한 줄에 저장됨/다시 편집 중을 표시한다.
저장 성공을 짧은 토스트만으로 대신하지 않고 다음 편집 전까지 남긴다. 같은 요청 재시도는 그 사실을 표시한다.
실패/다른 창 충돌은 기존 경고와 입력/승인 기준을 보존한다. 영구 삭제/해제/백업 경고를 일괄 제거하지 않는다.
저장만으로 업무를 완료하지 않으며 기존 완료 요약/업무일지/결과 입력의 역할을 바꾸지 않는다.

## 3. 업무 날짜 간편 변경

### 3.1 진입과 대상

- 목록/월·하루 달력 공통 우클릭: `내일로 이동…`, `날짜·시간 변경…`.
  내일은 현재 날짜 기준이며 같은 날짜를 다시 하루 더하는 명령이 아니다.
- 일반 업무는 업무 전체, 반복은 선택한 원래 회차 한 건만 대상으로 한다. 전체 반복 변경은 기존 수정 화면을 사용한다.
  유효한 회차가 없는 템플릿에서는 간편 이동을 제공하지 않는다. 완료/취소/보관/휴지통과 완료/건너뜀 회차는 제외한다.
- 작은 비모달 창에서 대상/범위·변경 전후 날짜/요일·알림 영향을 확인한다. 목록 선택이 바뀌어도 캡처한 ID/회차를 쓴다.
  알림을 막는 새 모달을 만들지 않는다. 내일 명령도 영향 안내가 있는 이 창에서 확정한다.
- 날짜/시각에는 기존 휠 방지·요일·전체 시각 입력·위험 날짜 확인을 사용한다.

### 3.2 계산

- 기존 시각/종일을 기본 유지한다. 시작 날짜를 옮기면 종료도 같은 로컬 날짜 차이만큼 옮겨 기간을 유지한다.
  시작 시각만 바꾸면 종료도 같은 로컬 시간 차이를 적용한다. 종일 배타 종료는 유지한다.
- 일정 없는 업무는 지정 날짜의 종일 1일이 기본이며 원하면 시각을 지정한다. 새 알림을 자동 생성하지 않는다.
- DST의 존재하지 않는 시각/중복되어 식별할 수 없는 시각은 조용히 보정하지 않고 안내한다.
  같은 값 저장은 이력/되돌리기 항목을 새로 만들지 않는다.

### 3.3 저장/알림/반복

기존 업무 저장 UOW·의미 있는 자동 이력·요청 식별을 재사용한다. 일정/알림 캐시/이력은 한 트랜잭션이다.
다른 창의 업무/일정/알림 변경은 예상값 비교로 거절하며 입력을 보존한다.
직접 날짜 지정 알림은 그대로 둔다. 상대 알림만 이동된 기준을 따르며 과거 새 알림은 기존 규칙대로 거절한다.

반복 이동은 effective 시작/종료만 바꾸고 원래 발생 키·템플릿·다른 회차를 바꾸지 않는다.
달력/오늘/하루의 예외 조회와 알림 예정/실행 계산이 같은 유효 일정을 사용하도록 함께 보완한다.
발생/확인/재알림 기록은 삭제하지 않는다. 이미 발생한 상대 알림은 같은 회차 이동으로 새로 복제 발송하지 않는다.
아직 발생하지 않은 상대 알림의 캐시는 다시 계산한다. 같은 규칙의 다른 회차와 알림 시각이 겹치는 이동은
조용히 하나를 누락시키지 않고 거절한다. 기존 원래 날짜에는 이동 전 일정이 중복 표시되지 않아야 한다.
선택 회차에서 이미 뜬 상대 알림·재알림은 확인 처리하여 종료하고, 이 점을 이동 창에 표시한다.

### 3.4 결과/되돌리기

성공 시 이동 날짜를 주 화면의 짧은 안내와 `해당 날짜 보기 / 되돌리기`로 제공한다.
사용자 확인 후 후속 보완: 안내는 8초 후 자동 숨김이며 탭/달력 전환·닫기·되돌리기·종료 때도 즉시 닫는다.
안내와 함께 마지막 이동 되돌리기도 해제하고 본문 공간을 돌려준다. 안내 종료는 저장한 날짜를 바꾸지 않는다.
새 이동은 8초를 다시 시작한다. 되돌리기 실패 경고는 자동으로 지우지 않고 닫기/화면 전환까지 남긴다.
현재 탭/달력을 자동 이동시키지 않는다. 해당 날짜 보기는 사용자가 눌렀을 때만 달력 날짜를 연다.
되돌리기는 마지막 한 건/안내가 보이는 동안에만 제공한다. 다른 일정 변경은 이전 되돌리기를 대체한다.
실행 전 이동 후 업무/회차/알림이 그대로인지 비교하며 후속 수정/완료/삭제 뒤에는 덮어쓰지 않는다.
되돌리기도 별도 사용자 명령/이력이다. 과거 알림 이력/파일/전체 과거 상태를 복원하지 않는다.
원래 알림 시각이 이미 지나 안전한 예약으로 되돌릴 수 없으면 실패를 안내하고 현재 상태를 유지한다.
되돌리기의 예상값은 이동 명령이 반환한 시점의 결과이며, 이동 직후 새로 읽은 후속 수정 상태를 승인값으로 삼지 않는다.
응답 유실 뒤 같은 요청을 재시도하여 이미 처리된 요청으로 판정되면 현재 객체를 보여 주되 되돌리기를 새로 제공하지 않는다.

## 4. 검증

이번 범위는 앱 내부 일정/알림 이동이다. 기존 ICS의 반복 규칙 내보내기에 개별 회차 이동 예외를 추가하는 기능은 포함하지 않는다.

단위: 로컬 날짜/기간/종일/일정 없음/DST/잘못된 시각.
통합: 일반/여러 알림·직접 지정 유지·이력/원자적 롤백·재시도·충돌·안전한 되돌리기,
반복 한 회차 이동·원래/이동 월·오늘/하루·미발생 상대 예약·발생 이력 보존·동시 시각 충돌.
UI: 탭 복귀/검색 해제/삭제/깊은 목록 제한/사용자 이동 취소/빠른 등록 공존,
성공 팝업 없음/편집 표시/실패 보존, 우클릭 실제 대상/비모달/입력 오류·성공/직접 날짜 보기/종료.
공통 테마·좁은 창·Windows 100/150/200%와 밝은/어두운 앱 기본 팔레트를 확인한다.
전체 회귀/정적 검사와 합성 fixture 정리를 수행한다. 수행/미검증 환경은 76번 결과에 구분한다.
