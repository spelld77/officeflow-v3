# OfficeFlow 3.0.11 릴리스 체크리스트

작성일: 2026-10-14. 사용자 요청으로 U23 첨부 화면 개선의 문서·빌드·검증·커밋·공개를 마감한다.
60/61번 문서의 미배포 표기는 작성 당시 상태이며 최신 배포 결과는 이 문서가 기준이다.

## 범위와 안전

- 첨부 공간·종류 필터·직접 출처·관련 자료·같은 창 크기 조절/기억.
- DB0016·전체 백업 v3 유지, 새 migration/첨부 내용·경로 변경 없음.
- 기존 생성 배포물을 보존하고 EXE/설치본/Windows ZIP/Python ZIP/체크섬/manifest를 생성한다.
- 실제 사용자 자료·실사용 설치 등록/자동 시작/Python 실행 폴더는 변경하지 않는다.
- 이전 릴리스는 변경하지 않고 v3.0.11을 새 정식 릴리스로 게시한다.

### 검증 중 확인 사항

- 최초 전체 UI 연속 실행에서 다중 삭제 계획 조회가 대기 상태에 머물렀다. 명령줄로 식별한 합성 테스트 프로세스만 중단했다.
  해당 모듈을 새 프로세스로 실행해 12개를 통과했고 이후 전체 재실행에서는 그 대기가 재현되지 않았다.
  당시 stack은 Qt event 처리와 SQLite schema 조회에 있었으며 근본 원인은 확정하지 않았다.
  이를 제품 오류를 수정한 결과로 보고하지 않는다. 최종 전체 578개는 정상 완료했다.
- 중간 전체 재검사의 유일한 실패는 UI 테스트에 남은 `3.0.10` 고정 문자열이었다.
  실제 패키지 버전의 표시를 검증하도록 바꾸고 최종 전체 검사를 다시 실행했다. 실행 코드/완료 정책은 변경하지 않았다.
- 검증 도우미의 실행 기준 경로·Windows 환경변수 대소문자·합성 기록 날짜를 보완한 뒤 ZIP 검증을 완료했다.
  실패한 추출 폴더는 해당 작업의 소유 경로 확인 후 재생성했다. 사용자 프로필은 검증에 사용하지 않았다.

### 패키지·호환

- 이전 `dist`와 `build/release`를 Git 제외 `artifacts/release-before-3.0.11-dist`,
  `artifacts/release-before-3.0.11-build`에 보존했다. 사용자 실행 폴더는 교체하지 않았다.
- `artifacts/release-3.0.11-build.log`: EXE 새 프로필 smoke와 별도 VerificationBuild의
  설치·재설치·제거 및 데이터 표식 보존 통과. 실제 설치 등록/자동 시작을 변경하지 않았다.
- Python ZIP을 새 폴더에 풀어 별도 실행기에서 소스/메타데이터 3.0.11·추출 경로·진단 8/8·smoke를 확인했다.
  빈 DB0016·integrity/FK 통과. 실행 라이브러리는 개발용 가상환경을 읽기 참조하며
  실사용 환경 또는 온라인 최초 setup의 재현 검사는 아니다. Python/오프라인 wheel은 ZIP에 없다.
- manifest 874개 파일의 크기·SHA-256과 체크섬을 대조했다. Windows ZIP 870개 파일을 EXE 폴더와
  1:1 해시/CRC 대조하고 새 추출 폴더의 clean PATH·격리 프로필로 실행해 빈 DB0016을 확인했다.
- 보존한 3.0.10 EXE로 합성 DB0016을 만든 뒤 업무·원본/작업본·보관본·일지·이력·중요 시점·파일 내용·설정을 준비했다.
  새 ZIP EXE 실행 후 행/파일 해시·백업/매시 설정·integrity/FK 보존을 확인하고 전체 백업 검증도 통과했다.
  3.0.10에서 새 migration은 없다. 이전 DB 이행/백업·복원 경로도 전체 통합 검사에 포함했다.
- EXE 리소스 3.0.11, 설치 리소스 3.0.11.0. 배포물에 사용자 DB·첨부·백업·로그·개발 캐시가 없다.
  Python ZIP 자체 체크섬도 일치한다.
- 이번 검사/새 추출/검증 실행기의 소유 임시 폴더 총 11개(논리 용량 약 11.66 GiB)를 정리했다.

## 업데이트

전체 백업 후 트레이까지 종료한다. Python형은 새 ZIP을 별도 폴더에 풀고 setup을 한 번 실행한다.
같은 사용자 데이터 경로이면 DB/첨부 복사는 불필요하다. 3.0.10과 DB0016·백업 v3가 같다.
더 오래된 DB의 이행과 구버전 복귀는 업데이트 전 자료가 필요하다.
