# 입력 보호·하루 보기·메뉴 정돈 구현·검증

2026-10-15~16. 사용자 요청: 69번 설계의 구현 및 테스트.
상태: 개발 소스 구현·격리 검증 완료. 사용자 사용 확인·커밋·배포 전.

## 1. 반영한 동작

- U30: 기준 날짜 대비 연도/먼 날짜 주의, 실제 이전/이후 날짜·요일 확인, 정상 연말/기존 제목 수정 경고 제외.
  비모달 확인창에서 초안을 다시 검증하며 저장 실패 시 승인/내용을 유지한다. 업무 편집 안의 알림 확인은 최종 저장으로 모은다.
- 자정 날짜 전환, 직접 지정 알림 유지, 접힌 종료/반복 요약. 휠·HHMM·과거 새 알림 금지·기존 저장 충돌 계약 유지.
- U32: 상시 메뉴 10개, 역할별 순서·하단 휴지통/관리, 관리의 데이터 관리·설정·도움말.
  상단 탐색만 높이 부족 시 스크롤, 기존 트레이/자료 이상 직접 진입 유지.
- U31-1: 선택 날짜 전체 업무 알림의 시간순 목록, 상태/처리 이력 구분, 100행 페이지·더 조회·부분 조회 표시.
- U31-2: 같은 달력 영역의 월/하루/하루 알림 전환. 24시간·종일·기간·시점·야간·최대 3 lane/숨은 개수·밀집 알림.
  일정/알림별 원래 회차 키·기록 진입·오른쪽 메뉴·검색 범위 안내. 드래그 편집/가짜 종료/새 상태는 추가하지 않았다.
- 일정 소스는 SQL 최대 200 template 페이지와 최대 500개 결과/검사 예산·계속 조회 cursor를 사용한다.
  이동해 들어온 반복 회차를 포함하고 생성 없는 읽기 스냅샷에서 상태를 반영한다.
- 날짜/검색 요청 토큰, 취소/종료, 늦은 결과 차단. 일정/알림 실패를 분리해 다른 조회 성공이 실패 안내를 지우지 않는다.
- 재조회 후 선택한 일정/알림 상세도 최신 상태로 교체한다. 선택 대상이 사라지면 다른 항목으로 바꾸지 않고 선택을 해제한다.

### 설계의 실제 연결

기존 알림 preview worker를 복제하지 않고, 새 일정 worker와 각각 조회해 달력 본문에서 조합했다.
각 결과는 같은 선택 날짜/요청 세대를 확인하지만 두 조회를 DB의 완전히 같은 시점 스냅샷이라고 약속하지 않는다.
이후 쓰기 알림의 재조회가 최신 상태로 수렴시킨다. 조회가 업무/회차/delivery/이력을 새로 만들지 않는 계약은 유지했다.
계속 조회는 500개 결과 구간을 누적하지 않고 교체하며 이전 cursor로 돌아갈 수 있다. 시간표 복귀는 첫 구간을 다시 읽는다.
DST 날짜는 실제 23/25시간 길이를 사용하고 중복 시각의 UTC offset을 상세에 표시한다. 한국 시간대는 기존 24시간 축이다.

## 2. 검증 기록

최종 소스 전체 검사 **1,531개 통과, 실패 0개**(427.53초).
저장소 기본 offscreen parent에서 기존 Windows native child 검사도 그대로 수행했다.
근거: `artifacts/u30-u32-certified.xml`. 아래의 추가 실행 횟수는 이 1,531개에 더해 고유 검사 수로 합산하지 않는다.

- 새 기능·입력/메뉴/날짜 조회 관련 검사 통과, 합성 5,000업무 중 선택 날짜 20개와 LIMIT 조회를 검증했다.
  해당 로컬 합성 측정의 조회는 2.89ms였다(`artifacts/u31-bounded-measure.xml`). 실사용 PC의 성능 보장은 아니다.
- Windows 100/150/200%에서 관련 22개씩 통과. UI 격리 실행을 순차 수행했다.
- 첫 추가 native 검사에서 조회 종료 대기 중 finished slot이 thread 참조를 해제하는 경쟁을 발견했다.
  지역 thread 참조/유효성 확인으로 수정하고 같은 종료 경로를 회귀 검사에 추가했다.
- 초기 전체 native parent 실행은 1,515통과/6실패였다. 이전 키보드·드롭다운·기존 이력/첨부 child timeout·수명 검사가 포함된다.
  Enter 두 검사는 native 단독 재실행에서 통과했다. 드롭다운은 스크롤로 화면 밖인 콤보를 직접 showPopup하는 검사로,
  저장소 기본 offscreen에서 통과한다. 전체 기본 환경/별도 native 재검사 결과를 최종 집계에 사용한다.
  실패 조건을 삭제하거나 timeout/수명 assertion을 느슨하게 바꾸지 않았다.
- 선택 상세의 완료 상태 갱신 검사를 추가해 이전 값이 남는 문제를 수정했다. 관련 최종 검사 85개와
  별도 Windows native 상태/종료 검사 4개가 통과했다. 이 수정 전 시작한 전체 검사는 중단했고 최종 소스로 다시 실행했다.
- Ruff 코드 검사·mypy 150개 소스·변경한 Python 23개 파일의 format 검사·`git diff --check`가 통과했다.
  저장소 전체 format 확인에는 이번 변경 밖 기존 15개 파일의 차이가 남아 있어 무관한 일괄 재정렬은 하지 않았다.

## 3. 시각 검증과 미검증 환경

Windows Qt의 앱 밝은/어두운 팔레트 주입·760×560/대표 넓은 창·100/150/200%를 검사했다.
`artifacts/day-overview-*.png`, `day-alarms-*.png`, `management-menu-*.png`에 소형 캡처를 남긴다.
작은 창에서 종일 1행에 2행 높이를 예약하던 부분을 줄여 시간표 공간을 확보했다.
전체 offscreen 검사의 캡처는 최종 Windows native 150% 실행 5개 통과 후 다시 생성했다.
날짜 편집 캡처는 Qt 지연 레이아웃이 끝난 후 찍도록 보완했고, 입력 보호 Windows native 4개를 다시 통과했다.
하루 시간표·하루 알림·관리 메뉴·연도 저장 확인 캡처를 직접 확인했다. 한글·대비·버튼 잘림은 이 대표 환경에서 확인했다.
기능 검사와 캡처의 실제 확인을 구분하며 회사 PC의 보안 제품/실제 다중 모니터 전환을 검증했다고 간주하지 않는다.
실사용 데이터·폴더·설정을 테스트하지 않았다. 배포 EXE/설치/Python ZIP/새 릴리스 검증은 이번 범위 밖이다.

모든 검사 프로세스 종료 후 이번 작업의 합성 fixture 폴더 26개만 절대 경로·내부 junction 대상을 확인해 삭제했다.
검사 XML·소형 캡처는 보존했다. 실사용 DB·첨부·백업·이전 배포물은 정리 대상에 포함하지 않았다.

## 4. 사용 확인

기존 개발 실행을 완전히 종료하고 `run-officeflow-dev.cmd`를 다시 실행한다.

1. 메뉴 순서와 `관리 → 데이터 관리/설정/도움말`을 확인한다.
2. 날짜를 선택해 `하루 보기`와 `하루 알림 N건`을 확인한다. 일정 없는 알림, 다중 알림, 재알림도 확인한다.
3. 일정/알림 더블클릭, 우클릭, 밀집 +N·종일 +N, 월 복귀/다른 날짜 이동을 확인한다.
4. 연도만 바꿔 저장 확인→돌아가기/승인, 기존 업무 제목만 수정, 직접 지정 알림 유지 안내를 확인한다.
5. 68번 완료 요약 저장도 재확인한다. 입력을 유지한 DB 실패 경로는 격리 자동 검사로 별도 검증한다.

실사용 설치·Python 배포 폴더와 공개 3.0.12 배포물은 교체하지 않았다. 사용자 확인 뒤 별도 요청 때 Git/배포를 진행한다.

## 5. 2026-10-16 하루 시간 탐색 보완

사용자 검토 후 `개선해` 요청으로 69번 10절을 구현했다. 24시간(해당 시간대 DST는 실제 23/25시간) 축을
접거나 잘라내지 않고, 첫 일정/미처리 알림 부근에서 시작하며 시간 항목이 없으면 09시로 이동한다.
오늘도 첫 항목 기준이며 `지금`으로 현재 시각 1시간 전 부근을 볼 수 있다. 오늘이 아니면 이 버튼은 숨긴다.

- `↑ 이전 N건 / ↓ 이후 N건`은 화면에 전혀 보이지 않는 블록 안의 항목 수를 센다.
  일정/알림을 각각 유지한 합계이며 상세 건수·부분 조회 여부는 도움말에 표시한다.
  묶인 항목은 실제 수로, 화면과 일부라도 겹친 기간 블록과 종일·처리 알림 이력은 제외한다.
- 클릭하면 가까운 화면 밖 항목으로 스크롤만 한다. 선택/업무 보기/확인/완료/추가 DB 조회를 발생시키지 않는다.
- 최초 일정/알림 소스가 따로 도착하면 초기 위치를 보완한다. 사용자의 휠·키·스크롤바·이동 버튼 조작 뒤에는
  늦은 조회·새로고침·같은 날짜 목록 복귀로 강제 이동하지 않는다. 날짜를 바꾸면 다시 초기화한다.
- 건수는 기존 메모리 내 시간표 자료에서 읽고 스크롤/리사이즈 갱신을 이벤트 루프로 합친다.
  현재 시각/날짜 확인은 기존 1분 타이머를 재사용하며 종료 후 탐색 타이머가 재시작하지 않게 보호했다.
- 기존 시각 검증에서 놓친 검은 스크롤바는 해당 영역의 명시적 스타일 누락이었다.
  하루 시간표와 하루 목록에 밝은 트랙/파란 손잡이/hover 색을 지정하고 어두운 앱 팔레트의 실제 픽셀을 검사한다.

최종 관련 회귀 검사 **132개 통과**(19.53초, `artifacts/day-nav-final.xml`).
Windows 100/150/200%에서는 각 **22개 통과**(`artifacts/day-nav-verified-{1,1.5,2}.xml`).
이 실행은 서로 중복되므로 더해 고유 검사 수로 표시하지 않는다. 이번 작은 보완에서 전체 1,531개 검사를 재실행한 것은 아니다.
Ruff·mypy 150개 소스·변경 파일 format·diff 공백 검사를 통과했다.
`artifacts/day-nav-dark-*.png` 및 작은 주 창 캡처를 직접 확인해 버튼 글자/손잡이/밝은 본문을 확인했다.
회사 PC 보안 제품·실제 다중 모니터 전환 검증은 아니다.

검사용 합성 fixture 폴더 10개는 실행 종료·절대 경로·링크 여부 확인 후 정리하고 XML/캡처를 보존했다.
등록 폼 버튼/안내 배치·위험 날짜 강조·중요도/상태 통일·관리의 점 표시는 별도 후속 후보이며 이번 보완에 포함하지 않았다.
DB/사용자 자료/알림 처리 정책·버전·배포물·커밋·GitHub는 변경하지 않았다.
