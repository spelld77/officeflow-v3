# 운영 신뢰성 개선 1차 상세설계

작성일: 2026-10-10. 구현 전 설계. 상위 계약: [38번](38-reliability-common-design.md).

## 1. 백업 상태

- 자동/수동 백업의 시작·성공·실패·취소와 각 최근 성공 시각을 별도 상태 JSON에 보존한다.
  업무 DB/기존 전체 백업 형식/24시간 주기/자동 10개 보존 정책은 변경하지 않는다.
- 검증한 백업을 공개한 뒤에만 성공으로 기록한다. 취소는 실패 경고와 구분한다.
  공개 후 보존 개수 정리만 실패한 경우는 백업 성공 + 정리 확인 필요로 구분한다.
  대기 취소가 같은 종류의 다른 실행 중 백업 상태를 덮어쓰지 않게 한다.
- 남은 진행 상태는 다음 실행에서 '완료 미확인'으로 표시한다. 정상 백업으로 간주하지 않는다.
- 상태 기록 실패는 백업 파일의 성공 여부와 별도로 안내한다. 성공 파일을 실패로 지우지 않는다.
- 주 창에는 미확인 실패가 있을 때 작은 '백업 확인 필요' 버튼을 유지한다.
  데이터 → 내보내기·백업에서 최근 성공/시도/실패 원인과 '안내 확인'을 제공한다.
  확인은 경고 표시만 내리며 실패 기록/파일을 삭제하지 않는다. 재실패하면 다시 표시한다.
  같은 종류의 정상 백업 성공으로 해소한다. 자동 백업을 꺼도 기존 실패 이력은 보존한다.
- 자동 백업 주기 확인 실패도 비차단 안내한다. 반복 실패로 모달 창을 누적하지 않는다.
- 상태 파일은 로컬 운영 진단 정보이며 전체 백업에 넣지 않는다. 이전 PC의 백업 성공을
  복원 PC의 성공으로 오인하지 않는다. 최신 실행 중에는 데이터 화면이 주기적으로 갱신된다.

## 2. 수동 자료 검사

- 데이터 관리에 '자료 검사' 탭: 설명, 검사 시작/취소, 진행 건수, 요약, 문제 목록.
  검사 완료 팝업 없이 결과를 남긴다. 파일/DB 수정·삭제 버튼은 만들지 않는다.
- 현재/해제 첨부, 원본, 작업본, 개별 보관본, 중요 보관 파일, 휴지통 업무를 포함한다.
  보기 캐시/미확정 저널/외부 파일은 정상 자산 검사 범위가 아니다.
- 살아 있는 참조를 가진 active 자산을 시작 시 ID/rowid/생성 시각 상한까지 100개씩 keyset 조회한다.
  페이지 조회는 짧은 read-only DB 연결, 전체 파일 해시는 한 heavy-job slot과 파일별 pin/읽기 핸들.
  1MiB 단위 SHA-256, 블록마다 취소. 파일을 읽는 동안 DB 트랜잭션을 유지하지 않는다.
- 경로는 기존 checked_managed_path를 사용한다. junction/symlink/루트 밖/비일반 파일 거절.
- frozen은 고정 크기+SHA-256, 중요 보관 파일의 원장 기준도 대조한다.
  mutable은 최근 관측 기준 또는 최초 첨부 기준과 대조하되 '수정됨(편집 가능)'으로 안내한다.
  기준이 없는 mutable은 '비교 기준 없음'이지 손상이 아니다.
- 검사 전후 원장/참조 상태가 달라지면 '검사 중 변경/확인 불가'. 새 자료는 다음 검사 대상이다.
- 결과 건수는 실제 자산 수다. 문제 상세는 최대 500개이며 초과 개수와 전체 요약을 표시한다.
  정상 편집 정보가 누락/고정 불일치를 밀어내지 않도록 심각한 문제를 상세에서 우선한다.
  취소 시 검사한 부분만 표시하고 '전체 정상'으로 안내하지 않는다. SQL/파일 실패도 정상 완료로 위장하지 않는다.
- 모델리스 창과 queued signal로 알림 처리 유지. 닫기/앱 종료 시 cancel → native thread join → 자원 해제.

## 3. 종료/예외 진단

- 일반 로그 2MiB×현재 보존 정책 유지. native fault용 별도 로그는 비어 있지 않을 때만 시작 시 회전(최근 3개).
  faulthandler를 앱 실행 기간만 켜고 정상 종료에서 핸들을 해제한다.
- Python 미처리 예외는 오류 종류·traceback 코드 위치만 기록한다. 예외 메시지/locals를
  자동 기록하지 않는다. GUI에 비차단 안내를 전달하며 앱/알림 강제 종료를 하지 않는다.
  주 스레드와 일반 Python 작업 스레드 hook을 설치하고 원래 hook을 복원한다.
  주 창의 비차단 '오류 기록 확인'은 다른 일시적 상태 메시지로 사라지지 않는다.
- 데이터 화면에서 진단 폴더를 열 수 있게 한다. 기존 비정상 종료 안내에 진단 경로 동선을 설명한다.
- native 강제 종료/보안 제품/메모리 부족 시 기록되지 않을 수 있다. 종료 원인을 단정하지 않는다.
  sys hook 원래 값 복원·중복 설치 방지·재시작 로그 회전·실제 테스트 자식 프로세스 fault를 검사한다.

## 4. 수용 검사

백업 실패/성공/취소/재시작/확인 후 재실패/상태 파일 손상과 기록 실패;
공유 frozen 1회 검사, snapshot-only/해제/휴지통 자료, 정상 mutable 편집, frozen 변경·누락·잠금·보호,
기준 없는 파일, 검사 중 원장 변경, 취소/500개 상한/스트리밍/페이지 조회/DB 무변경;
알림 타이머 유지, 작업 중 닫기/안전 종료, 작은 창·밝은/어두운 palette 가독성;
비공개 문구가 진단 기록에 들어가지 않음, hook 복원, fault 자식 프로세스 기록.
결과는 별도 구현 보고에 실제 수행 범위/미검증 환경과 함께 기록한다.
