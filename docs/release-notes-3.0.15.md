# OfficeFlow 3.0.15

## 바뀐 점

- 업무 보기·첨부·이력·자료 관리 등의 창을 닫을 때 작업 종료를 비동기로 기다립니다.
- 닫기 도중 새 Qt 진행창/연결을 만들던 교착 경로를 제거했습니다.
- 작업 스레드가 실제로 종료하고 늦은 결과가 전달된 뒤 창을 정리합니다.
- 모든 작업과 최종 정리를 마친 뒤 DB를 닫고, 정리에 성공했을 때 정상 종료를 기록합니다.
- 미저장 입력 확인·협조적 취소·파일/DB 보존 규칙을 유지합니다.

## 업데이트

새 Python ZIP을 준비하는 동안 실행 중인 3.0.14를 계속 사용할 수 있습니다.
**새 버전으로 전환하기 직전** 기존 OfficeFlow에서 전체 백업을 만들고 트레이 메뉴에서 완전히 종료하세요.

1. `OfficeFlow-Python-3.0.15.zip`을 별도 폴더에 풉니다.
2. `setup-officeflow-python.cmd`를 한 번 실행합니다.
3. `run-officeflow-python.cmd`는 기존 `%LOCALAPPDATA%\OfficeFlow` 데이터를 사용합니다. DB/첨부를 새 프로그램 폴더로 복사하지 않습니다.

**DB0017·전체 백업 v3를 유지하며 3.0.14에서 새 DB 이행은 없습니다.**
0017 DB/백업에는 3.0.14 이상이 필요합니다. 더 이전 버전으로 돌아가려면 업데이트 전 자료를 사용하세요.
Python ZIP에는 Python/실행 라이브러리를 포함하지 않으므로 최초 setup에는 인터넷 연결이 필요합니다.

## 검증과 한계

최종 합성 종료 3,000회와 분할 회귀 고유 1,693개 통과·1개 환경 제외를 확인했습니다.
하나의 전체 실행 완주 수는 아닙니다. Windows 100/150/200%와 밝은/어두운 팔레트 주입 캡처를 확인했습니다.
실제 OS 테마 변경·회사 PC 장시간 사용·별도 native 자원 plateau는 검증하지 않았습니다.
모든 Qt/native 오류나 강제 종료를 방지한다고 보장하지 않습니다.

3.0.15부터 Python ZIP만 만듭니다. EXE·설치본·Windows ZIP은 다시 요청하실 때까지 만들지 않습니다.
이번 마감은 로컬 Python ZIP과 소스 커밋입니다. GitHub 공개·실사용 폴더 교체는 별도입니다.
