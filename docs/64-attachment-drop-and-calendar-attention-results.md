## 1. 반영한 사용자 흐름

- 첨부 목록 viewport·썸네일·빈 목록·stack·본문 여백·외부 scroll viewport에서 같은 수신기를 사용한다.
  파일 URL을 한 번 예약해서 기존 첨부 추가 명령으로 연결한다. 중복 전달·연속 드롭은 추가 작업을 중복 예약하지 않는다.
- 드롭은 Copy만 허용한다. 외부 파일 이동/삭제가 없고 Move만 가능한 드롭·웹 URL·버튼 위 드롭은 거절한다.
  휴지통·파일 작업/검증/외부 저장·이미지 처리 중에는 수신을 막으며 닫음/탭 전환 후 예약을 실행하지 않는다.
- 파일 선택·클립보드도 공통 추가 가능 조건을 확인한다. 경로 검사·부분 성공·중복/오류·큰 파일 확인은 기존 경로를 유지한다.
  신규 첨부 성공 후 전체 종류로 복귀하고 기존 살아 있는 선택/수동 순서를 유지한다.
- 본문 배경 스타일을 고유 objectName에 한정했다. 파일 추가는 파란 주요 버튼, 일반 행동은 밝은 공통 버튼으로 표시한다.
  비활성 파일 추가도 별도 색으로 구분한다. 첨부 탭이 없는 기록 창의 종료 경로도 검사·보완했다.
- 달력의 상태 판정은 업무와 원래 반복 회차 상태를 기준으로 한다. 알림을 모두 확인해도 미완료 업무는 회색이 되지 않는다.
  날짜 목록은 미완료 → 완료 순서이고 같은 상태 안에서는 시각순이다. 알림 전용 업무에도 같은 기준을 적용한다.
- 월 기간 막대는 주간 점유 마스크로 빈 줄을 재사용한다. 완료 막대가 겹치는 미완료보다 위에 배치되지 않는다.
  기존 기간 연속/주 경계·제목/첨부 표시·클릭·원래 회차 키를 유지한다.
- 저장소 LIMIT 전부터 미완료를 우선한다. 기존 날짜별 집계 쿼리에서 정확한 미완료 수도 함께 구한다.
  60개 상한과 120개 초과 요약 사이의 부분 조회에도 미완료/숨은 건수를 알 수 있다.
- 숨은 미완료는 강조색 `미완료 N개 더 / 남음 N`으로, 숨은 완료만 있으면 중립 건수로 표시한다.
  부분 DTO에서 집계를 모르면 `목록 확인`과 상태 일부 조회 안내를 사용하며 미완료 0으로 단정하지 않는다.
- 낮은 달력은 배지를 날짜 옆에 둬 막대와 겹치지 않는다. 막대 자체가 들어갈 수 없는 높이는 건수만 표시한다.
  아주 좁은 영역은 숫자와 툴팁/접근성 설명을 사용하고, 폭이 충분하면 `남음 N`을 표시한다.
- 조회/정렬은 알림 확인·업무 완료·파일 내용을 변경하지 않는다. 업무/원래 회차 선택과 보이는 기준 행을 유지한다.

새 화면·설정·DB 이행·파일 자산·디스크 캐시·외부 계정/의존성을 추가하지 않았다.

| 업무 서비스·저장소·알림 그룹·다중 알림·5,000건 성능 | 58 통과 | `artifacts/u24-u25-queries.xml` |

| 전체 Ruff, 변경 Python 12개 format, 전체 mypy | 통과 | mypy 139 source files |

주요 3묶음은 **중복 제외 230개 검사**, 실패/오류/건너뛰기 0이다.
25개 추가 회귀는 위 검사와 중복이므로 별도 고유 검사로 더하지 않는다.
전체 릴리스 게이트를 다시 실행했다는 뜻은 아니다. 파일 보존/생성/배포 정책을 바꾸지 않는 관련 범위 검사다.

특히 아래 조건을 확인했다.

- 실제 QWidget/viewport 이벤트 전달의 Enter → Move → Drop. 직접 list.dropEvent 호출 검사에만 의존하지 않음.
- 기존 첨부 0/1개·목록/썸네일·종류 필터 결과 0개·본문 여백의 한 번 추가, 복사 응답과 외부 원본 바이트 유지.
- 드롭 사용 불가/Move-only/웹 URL/컨트롤 거부, 처리 예약 중 중복과 소유자 종료/탭 전환 취소.
- 알림 확인한 미완료·완료/취소/건너뛰기 회차·일정/알림 묶음의 색/순서/선택 유지.
- 월~화 미완료 A / 화~수 미완료 B / 수~목 완료 C의 잘못된 빈칸 재사용 반례, 다른 날짜의 빈 줄 사용.
- 60/61/120/121개 일정, 검색·반복 회차 완료·사용자 지정 상한, 집계 조회의 INSERT/UPDATE/DELETE 없음.
- 날짜별 전체/미완료 집계는 한 UNION 쿼리로 유지. 5,000건 달력 조회의 기존 200ms 예산과 미리보기 상한 통과.
- 매우 낮은 창의 일정/알림 배지 비겹침, 좁은 창의 막대/숨은 건수 비겹침·일정 클릭/기록 연결.

## 3. 시각 검증과 중간 발견

Windows Qt에서 시스템 팔레트를 밝게/어둡게 주입하고 100/150/200% 배율을 각 별도 실행으로 확인했다.
첨부 최소 500×540의 다섯 행·기본/비활성 주요 버튼·정보창·메뉴/콤보와 달력 540/980폭을 검사했다.
대표 150% 첨부 최소 창과 150/200% 달력 캡처를 직접 열어 밝은 본문·파란 버튼·미완료 우선·잘림을 확인했다.

- 첨부 캡처: `artifacts/u23-captures/{light,dark}-{1,1.5,2}/`의 small-list 등.
- 달력 캡처: `artifacts/u24-u25-captures/calendar-{False,True}-{540,980}-{1,1.5,2}.png`.

자동 검사가 먼저 통과한 뒤 실제 캡처에서 낮은 달력의 배지가 막대를 가리는 경우를 발견했다.
날짜 옆 배치로 보완하고 hit 영역의 비겹침 검사를 추가했다. 정상 높이의 막대/클릭을 없애지 않았고 최종 회귀에서 건너뛰기도 없었다.

최초 격리 파일 복사 검사에서는 Qt worker의 `resolve(strict=True)`가 샌드박스 권한 거부를 받았다.
오류 안내 모달에서 대기한 **해당 pytest 명령의 프로세스만 식별해 종료**하고 경고 수집으로 원인을 확인했다.
일반 권한에서 동일 합성 자료 검사가 통과했다. 이 결과를 회사 보안 제품의 실패 원인과 동일하다고 단정하지 않는다.
처음의 미구현 모듈 수집 오류, 테스트 fixture/API/모듈명 충돌, 종료 경로 오류도 수정 후 재검증했다.

## 4. 남은 사용 확인과 한계

개발 소스의 `run-officeflow-dev.cmd`로 다음을 확인한다. 실사용 Python/설치 폴더는 아직 교체하지 않았다.

1. 첨부가 없는 업무와 기존 파일이 있는 업무에 탐색기에서 여러 파일을 드롭한다.
   목록/썸네일/흰 여백, 종류 필터 결과가 없는 상태에서 추가되고 외부 원본이 남는지 확인한다.
2. 파일 추가 버튼이 분명하게 보이고 파일 작업 중 추가가 비활성화되는지 확인한다.
3. 완료/미완료를 섞어 달력·하단 목록에서 미완료가 우선이고 숨은 건수로 남은 업무를 인지하는지 확인한다.
4. 알림만 확인한 미완료 업무가 정상 색으로 남고 반복 회차 완료가 다른 회차를 완료처럼 보이게 하지 않는지 확인한다.

**회사 PC 실제 탐색기 드래그, DRM/EDR, 다른 권한 프로세스, EXE/배포물**은 이번에 검사하지 않았다.
자동 전달 검사는 Windows 탐색기의 실제 OS 드래그와 같지 않다. 이벤트 자체가 막히면 권한/회사 정책을 별도 확인한다.
보안 비활성화·자동 관리자 실행·Windows 메시지 필터 우회는 하지 않는다.
시스템 팔레트 주입은 실제 Windows 테마 전환/모든 모니터 환경 검증과 구분한다.
hover/focus의 모든 실제 조합·모든 글꼴/다중 모니터도 완료했다고 주장하지 않는다.

Drop 이후 기존 GUI 스레드의 경로 사전 검사(resolve/stat)는 유지한다. Enter/Move에 파일 I/O를 추가하지 않았으나
접근 불가/느린 네트워크 경로의 사전 검사 지연까지 해결한 것은 아니다.
기간 연속 막대와 표시 줄 제한 때문에 모든 미완료 막대가 항상 보이지는 않는다. 정확한 숨은 미완료 수와 하단 목록이 보완한다.

검사 자료는 작은 합성 파일/격리 DB를 사용했다. 이번 실행 소유 `.test-tmp/u24-*`, `.test-tmp/u25-*` 중
명시적으로 생성한 24개 디렉터리만 절대 안전 경로·reparse point 검사 후 정리했다(190,795,175 bytes, 약 182 MiB).
정리한 합성 fixture는 검사로 다시 만들 수 있다. XML/소형 캡처는 보존했고 사용자/기존 배포 자료는 삭제하지 않았다.
