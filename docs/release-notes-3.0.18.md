# OfficeFlow 3.0.18

## 바뀐 점

- 새로 연결하거나 직접 다시 지정한 로컬 고정 NTFS 폴더는 이름이 바뀌었을 때 같은 상위 폴더에서 후보를 찾습니다.
  확인창의 **이 폴더 사용**을 눌러야 새 경로를 저장하고 엽니다. 기존 연결에는 소급 적용하지 않습니다.
- 전체·예정 탭의 일정순을 미래→과거로 바꿨습니다. 고정 업무 우선, 날짜 없는 업무 마지막은 유지합니다.
- 첨부 드래그의 상시 준비 안내를 제거해 목록과 버튼 공간을 복구했습니다.
  준비 전 드래그/시작 실패 때만 짧게 안내합니다.

폴더를 찾지 못했거나 권한/공유 연결/다른 PC 문제로 확인할 수 없으면 기존 연결을 유지하고 직접 지정을 안내합니다.
외부 폴더·파일을 이동하거나 수정하지 않으며 상시 감시/전체 드라이브 검색도 하지 않습니다.
별도로 붙인 표시 이름은 유지하고, 옛 폴더명 그대로였던 이름만 새 이름으로 바꿉니다.

## 업데이트와 DB 호환

새 ZIP을 준비하는 동안 기존 앱을 사용할 수 있습니다.
**새 버전을 처음 실행하기 직전 전체 백업을 만들고, 기존 앱을 트레이 메뉴에서 완전히 종료하세요.**

1. `OfficeFlow-Python-3.0.18.zip`을 별도 폴더에 풉니다.
2. `setup-officeflow-python.cmd`를 한 번 실행합니다.
3. `run-officeflow-python.cmd`로 실행합니다. 기존 `%LOCALAPPDATA%\OfficeFlow` 자료를 사용하므로
   DB/첨부를 새 프로그램 폴더로 복사하지 않습니다. 구버전과 동시에 실행하지 않습니다.

첫 실행에서 보호 사본을 만든 뒤 **DB0018**로 이행합니다. 기존 폴더 연결의 식별 정보는 빈 값으로 유지하며
기존 업무·첨부·일지는 보존합니다. 전체 백업의 파일 형식 v3는 유지하지만,
**0018 DB와 그 DB를 담은 백업은 3.0.18 이상에서만 사용합니다.**
구버전으로 돌아가려면 업데이트 전 백업이 필요합니다.

Python ZIP에는 Python/실행 라이브러리가 포함되지 않아 최초 setup에는 인터넷 연결이 필요합니다.
EXE·설치본·Windows ZIP은 만들지 않습니다. GitHub 자동 Source code ZIP 대신
릴리스 자산의 **OfficeFlow-Python-3.0.18.zip**을 받으세요.

## 검증과 한계

폴더 복구 관련 고유 66개·정렬 3개·안내 제거 3개 검사와 릴리스용 패키지/추출 검사를 확인했습니다.
단일 전체 회귀 실행 결과가 아닙니다. 실제 회사 공유 폴더/DRM·장시간 운영은 별도 확인입니다.
첨부의 실제 탐색기 드롭과 기존 응답 없음의 native 잠금 소유자도 미확인 상태를 유지합니다.
검증·추가 배율 검사·공개 결과는 [97번 체크리스트](97-release-checklist.md)를 따릅니다.
