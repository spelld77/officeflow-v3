# 달력 버튼·종일 목록 잘림 보완

2026-10-16 사용자 화면 보고: 작은 창의 `오늘` 글자 잘림과 같은 유형의 다른 화면 점검.

## 설계/수용 기준

- 기존 밝은 테마·작은 창·월/하루/알림 모드를 유지한다. 기능/데이터/알림 동작은 바꾸지 않는다.
- 이전/다음/오늘 버튼의 30px 고정 높이 대신 실제 스타일/글꼴의 권장 높이를 하한으로 삼는다.
  세 버튼은 같은 높이로 정렬하며 보통 창의 기준 높이도 유지한다.
- 하루 보기 종일 목록은 두 줄을 표시한다는 기존 계약을 유지하되 아이콘/텍스트/안쪽 여백을 포함한 실제 행 높이로 계산한다.
  3개 이상은 기존 `종일 +N개`로 확인하며, 두 번째 행을 일부만 보여 주거나 불필요한 스크롤을 만들지 않는다.
- 날짜 제목과 달력의 나머지 버튼(월/하루 전환·하루 알림·이전/이후 건수·일정 목록)을 함께 검사한다.
- 다른 고정 높이 컨트롤도 읽기 검토하며, 이미 글꼴/권장 높이를 반영하는 저장·취소/날짜별 목록은 불필요하게 바꾸지 않는다.
- 관련 회귀·Windows 100/150/200% 작은 화면·밝은/어두운 기본 팔레트를 검증한다. 결과는 아래에 추가한다.
- 실제 사용자 자료·버전·EXE/ZIP·커밋·GitHub는 변경하지 않는다. 이번 소유 fixture만 정리한다.

## 결과

개발 소스 구현·관련 검증 완료. 공개 버전/실사용 실행 폴더는 교체하지 않았다.

### 확인·수정한 부분

- 작은 창의 오늘/이전·다음 고정 높이에서 텍스트 영역이 부족함을 Windows native 검사로 재현했다.
  기본 창에서도 이전/다음 버튼의 글꼴 높이보다 텍스트 영역이 1px 작은 조건이 있었다.
- 달력 전용 이전/다음·오늘의 세로 여백을 정돈하고 실제 글꼴 + 스타일 내부 여백 + 안전 여백을 계산해 세 버튼 높이를 맞췄다.
- 월/하루/알림 모드의 `하루 보기 / 월 보기 / 돌아가기`와 알림 건수에 따라 버튼의 최소 폭을 다시 계산한다.
  날짜 제목도 표시한 날짜/요일의 실제 폭을 확보한다. 반복 갱신으로 크기가 계속 커지지 않음을 확인했다.
- 종일 기본 행이 Windows에서 49px로 잡히지만 두 줄 영역은 76px여서 두 번째 줄이 잘리는 조건을 재현했다.
  작은 중요도 아이콘과 글꼴/여백 기준 한 줄 높이를 명시하고 실제 행 수와 바깥 여백으로 영역 높이를 맞췄다.
  1/2/3개·글꼴 변경을 검사했고, 3개 이상은 기존 +N개 목록으로 모두 확인한다.
- 다른 고정 높이도 점검했다. 저장·취소는 이미 실제 권장 높이를, 월간 날짜별 목록·오늘 알림은 명시적 행 높이를 사용한다.
  편집 본문의 스크롤과 긴 미리보기의 의도된 생략은 잘림으로 오인해 확대하지 않았다.
