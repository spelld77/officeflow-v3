# U37/U38 업무 찾기 상세설계

작성일: 2026-10-26. [80번 공통설계](80-resource-and-task-finding-common-design.md)의 2차/3차 상세설계.
상태: **설계 완료, 실행 코드·DB 이행·동작 검증 전**. 1차 U36의 객체 정리/관측 검증을 선행한다.

후속 일괄 구현 승인으로 U37/U38 및 0017 색인 이행을 소스에 반영했다. 최신 결과는 [83번](83-resource-and-task-finding-results.md)을 따른다.
작은 완료 화면에서는 빠른 등록 영역을 숨겨 조회 공간을 확보하고 상단 `+ 업무`는 유지한다.
`전체 목록`은 월별 보기와 같은 완료 범위를 완료일순으로 보여준다. 다른 업무 탭의 기존 정렬은 유지한다.
사용자가 검토한 시안의 핵심은 검색창 옆 `최근`과 기존 `완료` 안의 월별 묶음이다.
이 문서가 실제 동작·상한·오류/호환 계약이며, 시안의 예시 업무/생략된 기존 컨트롤은 동작 명세가 아니다.

## 1. U37 최근·고정 바로 찾기

### 1.1 화면/기본 동작

- 검색창 옆에 `최근 ⌄` 버튼 하나를 둔다. 새 왼쪽 탭/태그/프로젝트/스마트 목록을 만들지 않는다.
- 메뉴는 위 `고정 업무`, 아래 `최근 본 업무`다. 고정이 없으면 그 구역을 생략한다.
- 기본 표시 상한은 고정 3행 + 최근 5행이다. 같은 업무가 위에 보이면 아래에서는 한 번 더 표시하지 않는다.
  다만 최근 기록 원장에서는 그 항목을 버리지 않는다. 고정 부분 밖의 항목을 잘못 중복 제거하지 않는다.
- 제목 1줄, 상태·열어 본 시각의 보조 1줄을 사용한다. 회차라면 원래 회차 날짜도 짧게 표시한다.
  긴 제목은 줄임과 전체 tooltip으로 확인하며 파일명·설명 전문·이미지는 메뉴에 적재하지 않는다.
- 작은 화면은 availableGeometry에 맞춰 행 수를 줄이거나 위로 펼친다. 일부만 보이는 행으로 개수를 오인하게 하지 않는다.
- `최근 더 보기…`는 최대 20개의 같은 기록을 보여주는 modeless 보조 창이다. 최대 한 개 재사용하고 닫으면 삭제한다.
  화면에 6~8행이 보이는 명시적 스크롤 목록과 `최근 기록 비우기`를 제공한다. 업무 삭제 버튼은 두지 않는다.
- `고정 전체 보기…`는 기존 전체 업무의 고정 필터로 명시적으로 이동한다. 다른 검색/필터를 지워
  숨긴 고정 업무가 없게 하며 현재 `고정` 조건/해제 버튼을 표시한다. 원래 메뉴 항목 선택과 다른 동작임을 라벨로 구분한다.
- 다른 탭을 새로 만들거나 기존 업무 목록의 정렬을 최근 조회순으로 몰래 바꾸지 않는다.

### 1.2 기록하는 시점

| 동작 | 최근 기록 |
| --- | --- |
| 목록/달력/알림/업무일지/첨부 검색에서 실제 업무 보기를 성공적으로 열기 | 갱신 |
| 이미 열린 동일 업무/회차 창을 명시적으로 다시 보여주기 | 갱신 |
| 최근 메뉴/고정 메뉴에서 기존 업무 보기 열기 | 갱신 |
| 행 단일 선택·마우스 hover·tooltip·백그라운드 갱신 | 기록하지 않음 |
| 수정창만 열기·빠른 등록 성공·일괄 작업으로 상태 갱신 | 기록하지 않음 |
| 파일만 외부 프로그램으로 열기·휴지통 업무 조회·열기 실패/취소 | 기록하지 않음 |

Application의 `record_viewed(ref)`는 업무 보기의 최종 진입 성공 경로 한 곳에서 호출한다.
단순한 창 Show 이벤트는 자동 복원/갱신에도 발생하므로 기록 근거로 사용하지 않는다.
같은 `task_id`는 하나만 남기고 최신 열람을 맨 앞에 옮긴다. 반복 여러 회차도 업무 하나의 최근 선택 회차만 기억한다.
시계가 뒤로 바뀌어도 MRU 순서는 실제 호출 순서로 유지한다. UTC 조회 시각은 표시용이며 정렬의 유일한 키가 아니다.
읽기는 `tasks.updated_at/completed_at`·완료 상태·알림·업무 이력·일지를 수정하지 않는다.

### 1.3 데이터와 저장

논리 타입 `RecentTaskRef(task_id, task_created_at, occurrence_start | None, viewed_at)`를 사용한다.
창/Task/ORM/description/파일 객체를 참조에 보관하지 않는다. UTC aware ISO 형식과 int ID만 직렬화한다.

`AppPaths.root/recent-tasks.json` envelope:

```text
version: 1
database_file_identity: 로컬 DB 파일의 지원되는 안정적 식별값(시각/내용 해시 아님)
entries: MRU 순서의 RecentTaskRef 최대 20개
```

- `database_file_identity`는 Windows의 파일 ID에 대응하는 stat dev/ino 등 정상 환경에서 안정적인 파일 식별값이다.
  수정 시각·DB 크기·WAL checkpoint로 매번 바뀌는 값이나 전체 DB hash를 쓰지 않는다.
  식별값을 신뢰할 수 없으면 현재 실행의 RAM 목록만 사용하고 재시작 복원은 하지 않는다.
- 파일은 최대 32KiB만 읽는다. 형식 버전/크기/객체 타입·ID/aware 시각/회차 키를 검증하고 잘못된 항목을 제외한다.
  JSON 순서대로 중복을 제거한 유효 20개만 수용한다. 손상 파일 때문에 전체 설정을 기본값으로 되돌리지 않는다.
- 원장/임시 파일은 검증된 앱 데이터 루트 아래의 지정 파일만 사용한다. 링크/우회 경로를 따라 외부 파일을 읽거나 지우지 않는다.
- 같은 루트의 검증된 작은 임시 파일 → atomic replace로 저장한다. 앱이 만든 임시 파일만 실패 시 정리한다.
- 쓰기는 300ms debounce로 합치며 진행 중 1개/대기 최신 1개다. 사용자 클릭마다 동기 fsync/새 thread를 만들지 않는다.
  저장 완료 revision을 비교해 옛 스냅샷이 최신 파일을 덮어쓰지 않게 한다. 기존 background의 안전 종료 계약을 따른다.
- 현재 실행의 MRU 갱신은 즉시 사용한다. 기록 쓰기 실패는 한 번의 비차단 안내 후 RAM 목록으로 동작한다.
  종료 직전/강제 종료·권한 실패 때 마지막 조회 기록이 일부 빠질 수 있지만 업무 데이터는 영향받지 않는다.
- `최근 기록 비우기`는 이 원장/표시만 비운다. 진행 중 옛 저장 generation을 폐기하고 빈 최신 스냅샷을 저장한다.
  업무/첨부/고정/일지/변경 이력/백업을 삭제하지 않는다. 실패 시 이번 실행에서는 비운 상태를 유지하고 저장 실패를 알린다.

### 1.4 복원·삭제·회차·현재 정보

- 지원되는 백업 복원 시작 전에 최근 상태를 무효화한다. 복원 여부는 bootstrap/BackupManager의 실제 진행 결과를 사용한다.
  파일 삭제/비우기가 실패하면 이번 실행에서 디스크 최근 기록을 읽지 않는다.
- 다음 시작도 DB 파일 식별값 불일치를 먼저 확인하므로 이전 파일이 남았다고 복원 전 ID를 그대로 신뢰하지 않는다.
  VACUUM/보안 드라이버 등으로 식별값이 달라져 최근 목록만 비는 것은 허용하며 업무 오류로 표시하지 않는다.
- 메뉴를 열 때 최대 20개 ID를 한 번에 조회하고 현재 `task.created_at`와 비교한다. 업무가 영구 삭제되어
  ID가 재사용돼도 생성 식별값이 다른 업무를 예전 기록으로 열지 않는다.
- 휴지통/없는 업무는 표시하지 않는다. 복구 시 자동으로 최근 목록을 되살리는 기능은 제공하지 않는다.
- 제목/상태/고정 여부는 현재 DB 값이다. 수정 전 제목이나 완료 전 상태를 원장 사본에서 보여주지 않는다.
- 고정은 기존 전체 업무의 고정 필터와 같은 범위다. 첫 4행까지 조회해 3행과 더 있음만 표시한다.
  기존 `is_pinned` 외에 새 즐겨찾기 컬럼/별도 순서를 만들지 않는다.
- 최근 조회/고정은 현재 주 화면의 검색·필터와 독립적이다. 선택 시 이를 해제하거나 캘린더를 이동시키지 않는다.
- 원래 회차 키가 현재 업무/저장된 회차에서 여전히 유효하면 그 회차의 기존 업무 보기를 연다.
  규칙 변경/회차 제거로 해석할 수 없으면 임의로 다른 회차를 고르지 않는다.
  `이 회차는 변경되어 확인이 필요합니다`와 명시적 `업무 공통 정보 열기`를 제시한다. 사용자가 선택한 공통 진입만 새 기록으로 남긴다.
- 항목 선택 직전 삭제/변경·열기 실패면 목록을 안전하게 갱신한다. 잘못된 대상에 편집·완료·알림 동작을 실행하지 않는다.
- 이미 열린 업무 보기의 미저장 결과/일지·선택 첨부·회차는 기존 재사용 규칙으로 보호한다.

### 1.5 서비스/UI 변경 위치

- 새 `application/recent_tasks.py`: bounded 참조 모델/MRU/검증·현재 조회 해석, `RecentTaskRepository` 읽기 port.
- 새 `infrastructure/recent_tasks.py`: 로컬 원장/atomic 저장. `database/task_repository.py`: ID 일괄 요약 읽기.
- 새 `presentation/recent_tasks.py`: 단일 버튼/menu/보조 창·최신 요청 controller.
- `main_window.py`의 `_show_task_records` 및 WorkLogBrowser의 독립 진입에서 같은 성공 통지를 연결한다.
  MainWindow가 찾은 WorkLogBrowser 내부 창을 재사용하는 경우도 중복 기록하지 않는다.
- AppPaths는 한 개의 최근 파일 property만 추가한다. AppSettings에는 필요 없는 업무 조회 스냅샷을 넣지 않는다.
- 업무 DB 이행은 없고 전체 백업 v3에 최근 파일을 추가하지 않는다.

## 2. U38 완료 기록 월별 보기

### 2.1 화면과 범위

- 기존 `완료` 화면의 보기 선택에서 `월별 묶음`을 기본으로 제공한다. 기존 평면 정렬 보기로 돌아갈 수 있다.
- `월별 묶음`은 TaskSort enum 값이 아닌 별도 presentation mode다. 기존 TaskSort 생성 경로에 잘못 넘기지 않는다.
  `view_preferences.completed`의 보기 값만 저장하고 다른 탭의 정렬/검색 동작은 유지한다.
- 상단에 `완료한 날짜 기준`을 표시한다. 월 헤더에 `2026년 10월 · 12건`, 펼친 행에 실제 완료일/요일을 표시한다.
  일반 일정 날짜·최근 조회일·수정일로 묶지 않는다.
- 기존 완료 상태의 일반 업무/업무 전체 완료와 완료된 반복 회차를 조회한다. 집계 단위는 **완료 기록 건수**다.
  반복 회차는 제목 옆에 회차 날짜를, 반복 업무 전체 종료는 `업무 전체 완료`를 표시해 같은 업무처럼 오인하지 않게 한다.
- 월별/평면 완료 보기의 읽기 범위와 건수를 통일한다. 지금의 단순 완료 상태 목록에서 안 보이던 완료 회차가
  표시될 수 있다는 변경을 도움말에 명시한다. 기존 업무일지의 완료 검색 범위/정렬은 임의로 바꾸지 않는다.
- 재개된 일반 업무는 현재 완료 목록에서 빠진다. 이것은 상태 기반 완료 탐색이지 과거 완료 이벤트 전체 원장이 아니다.
  과거 전환은 기존 업무 이력에서 확인한다. 회차는 현재 완료된 회차 상태를 따른다.
- 완료일이 NULL인 기존 완료 자료는 `완료일 미상`에 모은다. 수정일로 날짜를 꾸미거나 자료를 누락시키지 않는다.
- 검색·고정/중요도/첨부 필터를 적용한 월 헤더/행 건수는 동일한 조건을 사용한다. 검색/필터 상태를 기존 안내로 명확히 보인다.
  상태 필터가 완료와 모순되면 기존 조건 표시와 빈 결과를 유지하며 몰래 무시하지 않는다.

### 2.2 날짜/회차와 공통 조회 모델

새 읽기 모델 `CompletedEntryKey(task_id, original_occurrence_start | None, scope)`와
`CompletedEntry(summary, completed_at | None, key)`를 둔다. 월 헤더는 요약 건수만 갖는다.

- 일반/업무 전체 완료는 TaskRecord, 반복 회차는 TaskOccurrenceRecord에 실제 저장된 상태·completed_at을 사용한다.
- 완료 회차와 template 전체 완료가 함께 있으면 서로 다른 범위로 표시한다. 하나를 숨기거나 같은 회차로 합치지 않는다.
- task deleted_at이 있는 자료는 모든 branch에서 제외한다. 기존 공통/회차 결과·업무일지 FTS 검색 범위를 보존한다.
  한 회차의 결과/일지가 형제 회차까지 검색 일치시키지 않도록 기존 completed history 계약을 재사용한다.
- `CompletedReadScope`의 공통 predicates를 월 집계·행·평면 보기에 사용한다. 기존 completed_history_page의
  조건을 검토해 재사용하되 현재 무시되는 priority/pinned/attachment 조건을 그대로 복사하지 않는다.
  기존 업무일지 호출의 동작은 회귀로 고정하고 같은 조건인 부분만 공통화한다.
- 월 경계는 사용자 ZoneInfo의 월 첫날 00:00과 다음 월 첫날 00:00을 각각 UTC로 변환한 반열린 범위다.
  UTC 문자열 앞 7글자/OS localtime/고정 +9 offset으로 월을 판정하지 않는다. DST/연말/윤년을 포함한다.
- 펼친 행 더블클릭/Enter/우클릭은 기존 업무/회차 dispatcher로 연결한다. 완료일/이동 날짜를 회차 키로 넘기지 않는다.
- 클릭 직전 재개/삭제/규칙 변경이면 현재 상태를 다시 확인해 갱신/안내한다. 과거 상태를 현재 업무에 덮어쓰지 않는다.

### 2.3 헤더와 행 페이지

1. 유효한 완료 시각의 최신 값을 SQL MAX로 찾고 그 로컬 월부터 6개 달력 월 범위를 계산한다.
2. 이 범위의 COUNT 집계는 UTC 경계 조건으로 SQL 안에서 수행한다. CASE/범위 집계는 최대 6개이며
   모든 completed_at/Task 객체를 Python에 읽어 달을 나누지 않는다. 비어 있는 월 헤더는 생략한다.
3. 최신 비어 있지 않은 월 하나만 기본 펼침하여 첫 50행을 읽는다. 미상 포함 최대 2그룹까지 동시 펼침을 허용하고
   세 번째를 열면 가장 오래전에 연 그룹을 접고 그 행을 해제한다. 선택한 업무 보기 창은 닫지 않는다.
4. 한 월이 50건보다 많으면 `다음 50건 / 이전 50건`으로 그 월의 현재 페이지를 교체한다.
   화면에 현재 표시 범위/월 전체 건수를 보여준다. 끝없이 append하는 더 보기로 메모리를 늘리지 않는다.
5. `더 과거`는 현재 범위 이전의 다음 실제 완료 시각을 SQL MAX로 찾고 다시 6개월 범위로 교체한다.
   수년의 빈 달을 계속 눌러야 하지 않는다. `최근 기간`은 최신 범위로 돌아온다.
6. `완료일 미상` 헤더는 별도로 표시하고 같은 50행 페이지 계약을 쓴다. 완료 시각이 있는 결과가 없어도 이 자료에 접근할 수 있다.

- 상단 전체 건수는 필터를 적용한 **전체 완료 기록**의 SQL COUNT이고, 현재 6개월 범위/페이지 건수와 구분한다.
  헤더 응답은 total/기간 건수/미상 건수를 작은 숫자로 함께 전달하며 평면 보기의 전체 범위와 일치한다.
- 유효 시각의 MAX가 없고 미상만 있으면 미상 그룹을 기본 펼친다. 모두 0일 때만 진짜 빈 목록이다.
  월을 모두 접었거나 현재 페이지 일부만 불렀다는 이유로 `업무가 없습니다`를 표시하지 않는다.
  검색/필터로 0인 경우는 기존 조건 안내와 해제 동선을 유지한다.

- 정렬은 월 내 `completed_at DESC, task_id DESC, scope_rank DESC, occurrence_id DESC`의 안정적 키다.
  NULL bucket은 ID/범위 순서를 명시한다. next cursor는 이 키의 값만 저장하고 이전 페이지 cursor는 월당 최대 20개다.
  훨씬 오래된 구간으로 더 진행하면 최근 20개 cursor만 유지하고 가장 오래된 구간 이전은 `이 달 처음`으로 돌아간다.
- header counts와 현재 행은 같은 read snapshot 안에서 일치하도록 한다. 서로 다른 사용자 요청 사이에는 변경될 수 있음을 허용한다.
- 필터/검색·시간대/보기 방식·자료 generation이 바뀌면 cursor를 폐기한다. UTC 범위/원래 회차 키를 다시 계산한다.
- 변경 이벤트는 dirty/최신 요청으로 합치고, 숨김 상태는 조회하지 않는다. 대기 최신 1개·worker 1개를 유지한다.
- U34 복귀는 월 범위/펼친 그룹 최대 2개(미상 포함)/페이지 cursor/선택 키/스크롤 값만 기억한다.
  해당 페이지의 요약 텍스트 전체를 저장하지 않는다. 조건/자료가 달라지면 최신 월로 복귀하며 강제로 전부 fetch하지 않는다.
- 월 헤더와 데이터 행의 역할을 model에서 구분한다. 헤더 선택/더 보기 행이 다른 업무의 완료/삭제를 실행하지 않도록 한다.

### 2.4 DB·백업·내보내기 경계

- 기존 TaskRecord 완료일 색인을 사용하고, TaskOccurrenceRecord에 `(status, completed_at, task_id, id)` 복합 색인 하나를 추가할 계획이다.
  계획 revision `0017_completion_browse_index`는 **색인만 추가**하며 업무/회차/파일/이력 행은 변환하거나 삭제하지 않는다.
- migration 전 보호 사본, schema head 검사, 기존 0016 DB/백업에서 업그레이드·정상 시작·full backup/restore를 검사한다.
  전체 백업 v3는 유지하되 0017을 모르는 구버전의 사용은 보장하지 않고 기존 head 보호를 따른다.
- 최근 로컬 원장은 복원하지 않는다. 80번의 무효화/식별 계약을 유지한다.
- 월별 펼침은 조회 방식이지 내보내기 범위 선택이 아니다. 기존 데이터 관리의 Excel/ICS는 **업무 단위** 계약을 유지한다.
  반복 회차별 완료 목록/현재 펼친 월을 그대로 내보낸다고 표시하지 않는다. 선택 ID는 task_id로 중복 제거한다.
  데이터 관리 진입 시 `업무 단위 내보내기 · 완료 회차별/펼친 월 범위 아님`을 해당 범위 설명에 명시한다.
  기존 ICS의 회차 이동 예외 미반영도 그대로이며 이번 기능으로 동기화/내보내기를 확대하지 않는다.
