# 첨부 드래그·버튼 표시와 달력 미완료 우선 상세설계

작성일: 2026-10-14. 기준 소스/배포: 3.0.11.

상태: **후속 요청으로 개발 소스 구현·관련 검사 완료, 사용자 사용 확인 전.**
최초 설계 요청에서는 문서만 작성했다. 이후 `구현 및 테스트해` 요청으로 A(첨부) → B(달력)의 코드·검사·도움말을 반영했다.
[64번 결과](64-attachment-drop-and-calendar-attention-results.md)에 실제 수행/미검증 범위를 기록한다.
DB 스키마·사용자 파일/설정·실사용 프로그램·버전·EXE·설치본·ZIP·커밋·GitHub는 변경하지 않는다.

## 1. 목적과 확인 수준

오늘 다른 대화 `Officeflow 드래그 첨부 확인`의 사용 보고와 현재 소스를 함께 검토했다.

| 대상 | 확인한 내용 | 판단/설계 방향 |
| --- | --- | --- |
| 첨부 드래그 | 첨부가 이미 있어도 실패한다는 사용 보고. 현재 드롭 처리는 목록 위젯에 있고 빈 상태·상위 표면에는 없음 | 드롭 수신 경로를 통합한다. 회사 PC에서 실패한 정확한 원인은 아직 미확정 |
| 파일 추가 버튼 | 본문에 넓게 적용한 지역 스타일과 공통 버튼 스타일이 충돌. 검토 캡처에서 버튼 경계/강조가 약함 | 배경 스타일을 본문에만 제한하고 공통 기본/주요 버튼 스타일을 살림 |
| 날짜 하단 목록 | 일정/알림을 합친 결과에 업무 완료 기준 정렬이 없음 | 미완료 위, 완료 아래로 정렬 |
| 월 달력 막대 | 현재 배치에 완료 우선순위가 없어 회색 완료 막대가 먼저 보이고 미완료가 숨을 수 있음 | 미완료를 먼저 배치하고 숨은 미완료 건수 강조 |
| 알림을 모두 확인한 업무 | 하단 목록은 알림 그룹에 남은 알림이 없으면 회색 처리하는 조건이 있음 | 업무 미완료와 알림 확인을 분리. 확인만으로 업무를 회색 처리하지 않음 |

드래그의 상위 표면 누락은 확인된 취약점이지 모든 실패의 확정 원인이 아니다.
Windows 권한 차이·회사 보안 정책 때문에 앱에 이벤트 자체가 도착하지 않는 경우는 별도로 구분한다.
회사 보안 제품의 `zone.tab` 등 감지·암호화, Codex 런타임/캐시 삭제는 이 설계에서 다루지 않는다.

## 2. 바꾸지 않을 것

- 업무 완료와 알림 확인은 별개다. 이번 변경으로 알림을 확인·취소·소비하지 않는다.
- 반복 업무는 원래 `occurrence_start`를 식별자로 사용하고 회차 상태를 반영한다. 변경된 표시 날짜로 회차를 식별하지 않는다.
- 같은 업무/회차의 일정과 알림을 합치는 기존 규칙을 유지한다. 별도 중복 업무 행을 만들지 않는다.
- 첨부 수동 순서·종류 필터·원본/작업본/보관본·수정 보기 사본 보호·백업·삭제 정책을 유지한다.
- 파일 드롭은 기존 첨부 추가처럼 복사한다. 외부 원본을 이동·삭제하거나 내용을 바꾸지 않는다.
- 선택한 보이는 파일만 명령 대상으로 삼는다. 숨은 파일을 자동 선택하지 않는다.
- 창을 전체화면으로 만들거나 새로운 진행/완료 탭·설정 옵션·상시 설명 패널을 추가하지 않는다.
- DB0016·백업 v3를 유지한다. 새 스키마 이행·의존성·디스크 이미지 캐시를 추가하지 않는다.

## 3. 목표 화면

### 3.1 첨부

```text
[전체 파일 ▾]  [목록 | 썸네일]                 [＋ 파일 추가]
┌──────────────────────────────────────────────────────────┐
│ 원본   신청서.docx                                        │
│ 작업본 신청서 - 작성본.docx                               │
│ 일반   참고자료.pdf                                      │
│                                                          │
│  ← 목록·썸네일·빈 목록·아래 흰 여백으로 파일 드롭 가능     │
└──────────────────────────────────────────────────────────┘
```

주요 행동인 `파일 추가`는 파란 배경/흰 글자/분명한 버튼 경계로 표시한다.
드래그 중에는 수신 영역 경계를 잠깐 강조한다. 평소 긴 드래그 설명을 추가하지 않는다.
입력칸·종류 선택·버튼·다른 탭·파일 정보창은 새로운 드롭 대상이 아니다.

### 3.2 달력과 날짜 목록

```text
10월 14일
┌────────────────────────┐
│ 제출 자료 확인         │ ← 미완료
│ 계약 검토              │ ← 미완료
│ 미완료 1개 더          │ ← 전체 숨은 수는 툴팁에서도 확인
└────────────────────────┘

10월 14일 · 일정 5 · 미완료 3
  09:00  제출 자료 확인         진행
  11:00  계약 검토              대기
  16:00  최종 제출              진행
  08:00  ✓ 자료 수령            완료
  10:00  ✓ 초안 검토            완료
```

위 스케치는 동일 날짜 단일 일정 예시다. 기간 일정은 주간 연속 막대를 유지하므로
모든 날짜의 첫 줄을 항상 채우거나 모든 미완료 막대를 표시한다고 약속하지 않는다.
대신 완료 막대가 겹치는 미완료보다 위에 나오지 않고, 숨은 미완료가 있으면 건수로 알린다.
하단 목록의 기존 스크롤/크기 조절은 유지한다. 알림 전용 행이 있는 날짜에는 일정 수와 알림 수를 혼동하지 않는다.

## 4. A — 첨부 드롭 경로 통합

### 4.1 하나의 수신기와 하나의 추가 명령

`record_dialog.py`의 목록 전용 핸들러를 작은 공통 드롭 수신기로 통합한다.
구현 위치는 별도 `presentation/attachment_drop.py` 또는 같은 파일의 독립 helper로 하되,
표면마다 URL 해석·경고·파일 추가 코드를 복사하지 않는다.

- 명시적 참조로 목록 viewport, 빈 목록 안내, 첨부 stack, 본문 여백, 외부 scroll viewport에 연결한다.
- 앱 전체 이벤트 후킹·모든 자식 위젯 자동 탐색은 하지 않는다. 다른 탭과 조작 컨트롤은 제외한다.
- 한 drop은 수신기 한 곳에서만 처리한다. 이벤트를 처리하면 전파를 끝내고 기존 목록 핸들러의 중복 실행을 막는다.
- 목록/썸네일 전환·필터로 0개 표시·실제 첨부 0개 모두 같은 수신 계약을 사용한다.
- 수신 결과는 기존 `_add_attachment_sources`에 한 번만 전달한다. 새로운 저장소·파일 추가 서비스는 만들지 않는다.

### 4.2 이벤트와 권한

| 단계 | 처리 |
| --- | --- |
| Enter/Move | 로컬 파일 URL 후보와 허용 상태만 확인. 경로 조회·파일 읽기·DB 접근 없이 경계 강조 |
| Leave | 강조 해제. 파일/선택/순서 변경 없음 |
| Drop | URL 목록을 확보하고 명시적 CopyAction으로 수신. 한 번의 예약된 추가 명령으로 전달 |
| 닫음/탭 전환/거부 | 강조 해제. 닫힌 창의 예약 명령은 실행하지 않음 |

지원은 탐색기 등이 전달한 로컬 파일 URL이다. 텍스트 URL·웹 이미지·URL 없는 가상 첨부는 추가 지원하지 않는다.
클립보드 이미지는 기존 이미지 추가 기능을 사용한다. 폴더·없는 파일·지원 불가 경로는 기존 사전 검사에서 거른다.
Move가 제안되어도 Copy가 허용되면 Copy로 처리한다. Move만 가능한 드롭은 거부한다.
`acceptProposedAction()`만으로 외부 원본의 이동을 허용하는 응답을 하지 않는다.

창이 살아 있고 첨부 탭이 열려 있으며 읽기 전용이 아니고 다른 첨부 변경/검증/내보내기/이미지 처리가 없을 때만 허용한다.
DragMove마다 DB로 상태를 확인하지 않고 현재 창의 처리 상태를 사용한다. 실제 업무 유효성은 기존 추가 서비스에서도 확인한다.
예약 전달과 파일 추가 시작 사이에는 별도 pending 상태를 둬 연속 드롭이 여러 작업을 예약하지 못하게 한다.
버튼·파일 선택·클립보드 진입도 공통 사용 가능 조건을 확인해 드롭만 막히는 우회를 만들지 않는다.
처리 중/읽기 전용일 때 Enter/Move에서 모달 경고창을 반복 표시하지 않는다.
비활성 버튼·툴팁으로 이유를 알리고 나중에 자동 재실행하지 않는다.

### 4.3 기존 추가 흐름과 파일 보호

- 중복 경로 처리·복수 파일·부분 성공·실패 안내·큰 파일 확인·사용자 취소는 기존 흐름을 재사용한다.
- 실제 신규 첨부가 성공하면 U23처럼 전체 종류로 전환한다. 취소/전부 실패는 필터를 유지한다.
- 살아 있는 이전 선택은 유지하고 새 파일 전체를 자동 선택하지 않는다. 수동 순서와 기존 계열 연결을 유지한다.
- DragEnter/Move는 파일 I/O가 없다. Drop 이후 기존 경로 사전 검사에는 GUI 스레드의 resolve/stat가 있음을 구분한다.
  기존 import worker를 재사용하되 긴 네트워크 경로의 사전 검사 지연까지 해결했다고 주장하지 않는다.
  실제 지연이 재현되면 별도 worker 사전 검사 필요성을 검토하고 범위/닫음 보호를 갱신한다.
- 이번 수정으로 파일 내용 비교·썸네일 재생성·원본 보기 사본 생성·전체 첨부 재검증을 추가하지 않는다.
- 회사 PC에서 이벤트가 수신되지 않으면 탐색기/OfficeFlow 권한 차이와 보안 정책을 확인한다.
  자동 관리자 실행·보안 비활성화·Windows 메시지 필터 우회·확장자 위장은 하지 않는다.

## 5. A — 버튼과 밝은 본문 스타일

현재 첨부 본문의 넓은 지역 `color/background` 규칙을 본문/viewport의 고유 objectName에만 적용한다.
`theme.py`의 공통 QPushButton 스타일과 `primaryAction` 속성이 우선 적용되게 한다.

- 본문·빈 영역은 밝은 배경, 일반 글자는 어두운 색을 명시한다. 버튼까지 같은 배경색으로 덮지 않는다.
- `파일 추가`의 주요 행동 속성을 유지하고 기본/hover/focus/disabled 상태를 실제 표시로 확인한다.
- disabled와 주요 행동 규칙의 우선순위도 확인한다. 필요하면 첨부 버튼에 한정해 보완하고 다른 화면 테마를 일괄 변경하지 않는다.
- 일반 버튼·메뉴·콤보·선택 강조도 기존 공통 밝은 테마를 따른다. 시스템 다크 팔레트 상속으로 검은 글자/검은 배경이 만나지 않게 한다.
- 500~540 폭의 기존 5행 목록 공간을 줄이지 않는다. 굵은 안내 배너·큰 버튼으로 해결하지 않는다.

## 6. B — 달력용 업무 상태 계약

순서·완료 색·숨은 건수는 공통 달력 표시 helper에서 같은 기준으로 계산한다.
기존 `group_reminders`의 전체 앱 알림 우선순위나 `ScheduledTask`의 전역 의미를 바꾸지 않는다.

| 분류 | 판정 | 표시/순서 |
| --- | --- | --- |
| 미완료 | ACTIVE/PENDING인 업무. 반복은 해당 회차의 종료 상태까지 확인 | 위쪽, 기존 중요도 색/정상 글자 |
| 상태 미확정 | 부분 자료만 있고 확실한 업무/회차 상태가 없음 | 완료보다 앞, 완료로 단정하지 않음 |
| 완료 | 전체 업무 완료 또는 해당 반복 회차 완료 | 미완료 뒤, 회색·완료 표식 |
| 비활성 | 취소/보관/삭제, 해당 회차 건너뛰기/취소 | 마지막, 조회 대상에 있을 때 상태 표식 |

전체 업무의 종료 상태를 먼저 반영하고 그 다음 회차 상태를 본다.
일정과 합친 그룹은 ScheduledTask의 업무/회차 정보, 알림 전용 그룹은 대표 알림의 업무/회차 정보를 사용한다.
알림 pending/attention 수가 0인지로 업무 완료를 판정하지 않는다.
알림 확인/다시 알림/미확인 요약은 기존 별도 정보이며 이 분류를 변경하지 않는다.
원래 회차 시작값을 포함한 scope key는 정렬 후에도 유지한다.

## 7. B — 날짜 하단 목록

기존 `merge_day_reminders`가 일정과 알림을 합친 뒤 달력 화면에 한정해 정렬한다.

1. 미완료 → 상태 미확정 → 완료 → 비활성.
2. 같은 분류 안에서는 표시 시각 순. 일정은 시작 시각, 알림 전용은 대표 알림의 effective_at.
3. 동일 시각은 기존 순서를 안정적으로 유지하고 task ID/원래 회차 키로 재조회 시 흔들림을 막는다.

모든 알림을 확인한 미완료 업무도 정상 글자로 남는다. 회색 완료 표시는 업무/회차 완료에만 적용한다.
기존 제목 우선·첨부 보조 표시·알림 요약을 유지하고 동일 완료 표식을 중복으로 붙이지 않는다.
알림 전용 행의 업무도 실제 완료 상태를 표시한다. 취소/건너뛰기 등은 완료로 쓰지 않는다.

새로고침 후 선택은 행 번호가 아니라 업무/원래 회차 키로 복원한다.
완료로 바뀐 행이 아래로 이동해도 선택 대상이 다른 업무로 바뀌지 않아야 한다.
스크롤 기준 행을 가능한 한 유지하고 선택이 사라진 경우 안전하게 해제한다.
더블클릭·우클릭·업무 보기·수정의 대상 데이터와 기존 선택 날짜는 바꾸지 않는다.
기존 날짜 건수 영역에서 공간이 허용되면 미완료 수를 함께 표시하고 상세 범위는 툴팁으로 안내한다.

## 8. B — 월 달력 기간 막대 배치

현재 시작 열/기간 길이 중심 정렬에 완료 구분을 더한다.
정렬만 바꾸면 기존 `occupied_until` 방식은 앞 날짜의 빈칸을 다시 쓰지 못하므로 배치 방식도 함께 보완한다.

### 8.1 주간 점유 마스크와 완료의 최소 줄

- 주간 각 줄의 7개 날짜 점유를 비트 마스크로 기록한다.
- 미완료/미확정부터 배치한다. 같은 분류 안의 시작 열·긴 기간·고정·시각·안정 식별자 순은 유지한다.
- 이후 완료/비활성은 날짜 마스크가 겹치지 않는 빈 줄을 사용할 수 있다.
- 단, 완료/비활성 막대는 자기 날짜 범위와 겹치는 미완료/미확정의 가장 아래 줄보다 한 줄 아래부터 찾는다.
  겹치는 미완료가 전혀 없는 날짜에는 첫 줄의 빈칸도 사용할 수 있다.
- 기간 막대는 같은 주 안에서 연속이며 기존 주 경계 화살표·종료일 계산·표시/클릭 영역을 유지한다.

필수 반례: 미완료 A=월~화(0줄), 미완료 B=화~수(1줄), 완료 C=수~목.
단순 빈칸 재사용만 하면 C가 수요일 0줄에 올라 B보다 먼저 보인다.
위 최소 줄 조건으로 C는 2줄 이상에 배치한다. 목요일만의 다른 완료 일정은
겹치는 미완료가 없으므로 0줄을 쓸 수 있다. 주 전체의 빈 줄을 일괄 비워 두지는 않는다.

창 높이에 따른 기존 1~3줄 제한은 유지한다. 미완료끼리도 겹치면 숨길 수 있으며 다음 건수 규칙으로 알린다.
기간 연결을 깨면서 날짜별로 줄을 바꾸거나 완료를 날짜 밖에 표시하지 않는다.

### 8.2 부분 미리보기와 정확한 미완료 수

현재 기본 미리보기 상한은 60개, 요약 전환은 120개 초과다.
**61~120개에서도 막대 자료는 일부**이므로 화면에 받은 자료만 재정렬해서는 부족하다.

- 저장소의 일반 일정 미리보기는 LIMIT 적용 **전** 미완료를 우선한다.
- 반복 회차와 일반 일정의 합친 미리보기도 최종 상한 적용 전 동일 분류를 사용한다.
- 기존 날짜별 전체 수 조회에 ACTIVE/PENDING의 조건부 집계를 함께 넣는다.
  날짜마다 별도 미완료 SQL을 추가하거나 화면에서 DB를 조회하지 않는다.
- 반복 회차는 기존 확장/날짜 집계 과정에서 실제 회차 상태로 미완료 수를 더한다.
  미리보기에서 잘린 업무도 날짜별 집계에 포함한다. 취소/건너뛰기/보관/삭제는 미완료가 아니다.
- 읽기 DTO에 날짜별 미완료 수와 미리보기 완전 여부를 확장한다.
  후보 필드는 `regular_unfinished_day_counts`, `day_unfinished_counts`, `previews_complete`다.
  완전 여부는 실제 총수/조회 수로 정하며 summary_mode만 보고 추정하지 않는다.
- 예전 테스트 대역/부분 DTO의 미완료 집계는 None=미확정으로 받는다. 0으로 해석하지 않는다.
  실제 서비스 경로는 정확한 집계/완전 여부를 전달하도록 계약 테스트한다.
- 검색·시간대·기간 겹침·보관/삭제 제외 기준은 기존 전체 수와 같게 맞춘다.
  업무 상태 변경 후 막대·집계·하단 목록을 함께 새로고침하고 오래된 응답은 적용하지 않는다.

이 DTO는 조회용이다. SQL 조건/정렬/집계 변경은 필요하지만 DB 테이블·사용자 자료 이행은 없다.
월 건수는 일정/회차 기준이다. 일정 없는 날짜의 알림은 기존 별도 알림 표시에서 확인하고 월 일정 수에 중복 합산하지 않는다.

### 8.3 숨은 건수 표시

`숨은 미완료 = 정확한 날짜별 미완료 수 - 실제 그린 미완료 scope 수`로 계산한다.
전체 숨은 수도 같은 방식으로 구하고 한 업무/회차를 알림 개수만큼 중복 계산하지 않는다.

| 상황 | 날짜 셀의 표시 |
| --- | --- |
| 숨은 미완료 있음 | 강조색 `미완료 N개 더`; 좁으면 `남음 N`, 툴팁은 전체 숨은 수도 포함 |
| 숨은 것은 완료/비활성뿐 | 중립색 `+N개` |
| 요약/낮은 높이로 막대가 아예 없음 | `미완료 N개` 또는 `남음 N`. 막대가 없으므로 `더`라고 쓰지 않음 |
| 미완료 집계 없는 부분 자료 | 중립 건수와 `목록 확인` 안내. 툴팁/접근성 설명에 상태 일부 조회를 표시 |

매우 좁은 숫자 전용 영역에서는 강조색 숫자와 툴팁/접근성 설명으로 미완료/전체 수를 구분한다.
알림 배지와 일정 건수의 hit 영역이 겹치지 않게 한다. 긴 두 줄 배지를 추가하지 않는다.
집계가 없는 부분 자료에서 회색 막대만 보인다고 `미완료 0`이나 전부 완료라고 표시하지 않는다.
건수 영역 클릭은 기존 해당 날짜 목록 진입을 유지하고 숨긴 막대에 클릭 영역을 만들지 않는다.

## 10. 검증 계획과 완료 기준

아래는 최초 설계의 **검증 계획**이다. 후속 구현에서 실제 수행한 검사와 회사 PC/배포물 등 미검증 환경은 64번 결과에서 구분한다.

### 10.1 첨부

- 실제 등록된 수신 표면에 QApplication을 통한 Enter → Move → Drop을 전달한다.
  기존처럼 list.dropEvent를 직접 호출하는 검사만으로 이벤트 경로가 정상이라고 판단하지 않는다.
- 첨부 0개/기존 파일 있음/종류 필터 0개, 목록/썸네일, 목록 아래 여백/외부 viewport에서 한 번만 추가되는지 확인한다.
- 버튼/입력/다른 탭은 대상 제외. 읽기 전용/처리 중/연속 드롭/닫음 후 예약 호출을 검사한다.
- 여러 파일·중복·부분 실패·전부 실패·취소·큰 파일 확인과 선택/필터/수동 순서 회귀를 검사한다.
- Copy 응답과 외부 원본 바이트 보존, Move만 가능한 드롭의 거부를 검사한다.
- Windows 탐색기 → Python 모드와 EXE를 같은 일반 사용자 권한으로 수동 확인한다.
  이벤트 미수신은 권한/정책 확인 대상으로 따로 기록하며 자동 테스트만으로 회사 PC 성공을 단정하지 않는다.
- 밝은/어두운 시스템 팔레트, 100/150/200% 배율에서 버튼 기본/hover/focus/disabled,
  메뉴/콤보/빈 상태·선택·500~540 폭 5행을 실제 렌더링으로 확인한다. 색상 속성 검사만으로 끝내지 않는다.

### 10.2 달력

- 미완료/완료 혼합·전부 완료·알림 전부 확인한 미완료·알림 전용·반복 회차 완료/취소/건너뛰기를 검사한다.
- 선택/스크롤 복원, 원래 회차 식별자, 날짜 선택·업무 보기·수정·우클릭 대상이 바뀌지 않는지 확인한다.
- 기간 빈칸 재사용과 8.1의 월~화/화~수/수~목 반례, 고정 일정, 주/월/연 경계·자정 종료를 검사한다.
- 1/2/3줄 제한에서 숨은 미완료 강조, 숨은 완료만 있을 때 중립 표시, 요약 모드·숫자 전용 영역을 확인한다.
- 60개 이하/61~120개/120개 초과, 별도 상한/요약 기준, 일반+반복 혼합에서 집계와 미리보기 우선순위를 검사한다.
- 검색·시간대와 전체/미완료 집계 일치, 부분 DTO의 미확정 처리, 알림/일정 영역 비겹침을 확인한다.
- 조회만으로 DB 상태/알림 확인 기록이 바뀌지 않고 업무 상태 변경 후 오래된 조회가 되살아나지 않는지 검사한다.
- 기존 대량 합성 업무 성능 검사를 재사용한다. 미완료 집계 때문에 날짜별 추가 왕복이나 전체 첨부 읽기가 늘지 않아야 한다.

### 10.3 마감 경계

작은 합성 자료로 관련 unit/integration/UI·형식·정적 검사를 수행하고 실제 렌더링 결과를 별도로 기록한다.
새로 만든 임시 fixture만 안전 경로 확인 후 정리한다. 사용자 DB·첨부·실사용 프로그램을 테스트 대상으로 바꾸지 않는다.
기본 창과 좁은 창에서 첨부 수신/버튼 가독성, 달력 미완료 인지/완료 구분을 사용 확인한다.
미재현 회사 PC 문제·수동 확인 미완료는 남은 조건으로 명시한다. 설계만으로 기존 문제 해결을 선언하지 않는다.
