# 완료 요약 입력 후 완료: 대상 고정과 실패 보존

2026-10-15. 범위: 개발 소스의 버그 수정·격리 검증. 버전·배포·Git 작업은 포함하지 않는다.

## 재현 및 수용 기준

- 완료 입력창의 중첩 이벤트 루프에서 대기 중인 검색/목록 갱신이 실행되어 선택이 해제되면,
  기존 구현은 입력창을 닫은 뒤 현재 선택을 사용하므로 저장 없이 끝날 수 있다.
- 다른 업무/반복 회차로 선택이 바뀌어도 입력창을 연 업무 ID·원래 회차를 대상으로 한다.
- 완료 상태와 완료 요약은 기존 단일 명령/DB 트랜잭션으로 확정한다.
- DB 저장에 성공하기 전에는 입력창을 닫지 않는다. 실패 시 내용을 유지하고 창 안에서 재시도한다.
- 취소는 내용을 저장하거나 상태를 변경하지 않는다. 반복 업무는 선택 회차만 완료한다.
- 날짜 입력 실수 방지는 별도 검토 사항이며 이번 버그 수정에 섞지 않는다.

## 구현 방향

입력창을 열 때 업무/회차를 고정하고 독립 명령 ID 재시도 객체를 둔다.
완료 입력창은 저장 콜백이 성공한 뒤에만 닫는다. 다른 상태 전이와 같은 명령 실행 경로를 사용한다.
실패 안내는 공통 밝은 테마 안의 짧은 오류 문구이며 별도 중첩 오류창을 추가하지 않는다.

## 검증

- 수정 전: 실제 완료 입력창의 중첩 이벤트 루프에서 검색으로 대상을 제외시키면,
  완료 저장을 눌러도 결과가 빈 문자열로 남는 실패를 재현했다.
- 수정 후 새 회귀 12개 통과: 목록/달력 진입, 선택 해제·다른 업무·다른 반복 회차,
  DB 이력 쓰기 실패 시 상태/내용/이력 롤백과 동일 명령 ID 재시도, 빈 요약 완료·취소,
  밝은/어두운 앱 팔레트의 오류 표시·버튼 접근을 검사했다.
- 핵심 상태/달력/완료 조회/DB 이력/결과 서비스 109개 통과
  (`artifacts/completion-input-core.xml`).
- Windows Qt의 알림·기록창 상호작용 26개 통과
  (`artifacts/completion-input-native.xml`).
- Windows Qt의 새 회귀/기록창/DB 이력/완료 조회/결과 서비스 62개 통과
  (`artifacts/completion-input-native-final.xml`). 위 묶음과 중복 제외 **165개 통과**다.
- 전체 Ruff lint, 변경 Python 4개 format, 전체 mypy(144 source files), diff 공백 검사 통과.
- Windows Qt 500×320 DIP에서 밝은/어두운 앱 팔레트를 주입했다. 어두운 팔레트 캡처를 직접 열어
  입력 내용·빨간 실패 문구·완료 저장/취소 버튼이 밝은 배경에서 보이고 잘리지 않음을 확인했다.
  캡처는 `artifacts/completion-input-error-{light,dark}.png`에 보존한다.

초기 넓은 offscreen 검사에는 native 마우스 입력 대기와 별도 첨부 테스트의 파일 접근 거부가 있었다.
대기한 해당 테스트 세션만 중단했다. native 검사는 Windows Qt로 재실행했고, 첨부 테스트는
격리 fixture만 실행 제한 밖에서 재검사하여 통과했다. 제품 파일 접근 검사나 테스트 조건은 약화하지 않았다.
offscreen 캡처는 한국어 글꼴이 없어 시각 확인에 사용하지 않고 Windows Qt 캡처로 대체했다.

전체 테스트 스위트/모든 배율/회사 PC/EXE·ZIP은 이번에 재검증하지 않았다.
실제 사용자 DB·첨부·실행 폴더는 변경하지 않았고 버전·커밋·배포도 하지 않았다.
소스를 사용 확인하려면 기존 개발 실행을 종료한 뒤 `run-officeflow-dev.cmd`로 다시 실행한다.

검사 종료 후 이번 작업 소유 임시 fixture 10개(합성 DB/첨부)만 절대 경로와 링크 여부를 확인하고 정리했다.
XML 결과·두 Windows 캡처는 남겼다. 정리한 자료는 테스트 재실행으로 생성할 수 있다.
