# 자료 검색·백업 선택 저장 2차 구현·검증 보고

작성: 2026-10-10. 상태: 상세설계·소스 구현·격리 테스트 완료, 사용자 사용 확인 전.
후속 상태: 사용자 사용 확인 완료. 별도 요청으로 새 3차 상세설계·구현·테스트 진행(43/44번).
[41번 상세설계](41-reliability-phase-2-design.md) / [38번 공통설계](38-reliability-common-design.md).
1차 사용 확인을 받은 뒤 진행했다. 새 3차, 장기 정리 정책, 배포는 진행하지 않았다.

## 구현 결과

- 기존 첨부 검색을 현재 첨부·보관본·중요 보관 파일로 확대했다. 이름/최초 이름/보관명/메모를
  매개변수 검색하며 여러 단어 AND와 문자 그대로의 `%`/`_` 검색을 유지한다.
  자료 범위·종류·등록/보관 기간·휴지통/정리 대기 조건, 페이지/화면 상한·취소를 유지한다.
- 공유 자산도 논리 자료를 숨기지 않는다. `(시각, 종류, ID)` 커서로 같은 ID·시각이 섞여도
  페이지가 누락되지 않는다. 행/툴팁에 자료 종류와 보관명을 표시한다.
- 열기/외부 저장에 종류+ID를 전달한다. 고정 파일은 관리 원본이 아닌 기존 보기 사본으로 연다.
  보관본 관리 버튼은 검색한 항목부터 제한된 보관함 페이지를 보여준다.
  중요 보관 관리 버튼은 해당 업무의 이력 창을 연다(해당 파일 자체는 열기/저장 버튼으로 바로 사용).
- `데이터 → 내보내기·백업 → 백업 파일 꺼내기…`를 추가했다. 형식 1/2/3 백업 전체 검증 후
  임시 DB/목록만 읽는다. 운영 DB 복원·이행·예약·자동 연결을 하지 않는다.
  백업 당시 이름/보관명/메모/업무로 검색하고 100개씩 조회한다.
  연결 없는 복구 자료도 구분한다. 구형 백업의 누락 자료는 꺼낼 수 없다.
- Ctrl/Shift 다중 선택 → 외부 폴더 저장. 동명 번호·안전 대상/이름·준비 파일·검증·공개 저널은
  공통 외부 저장 기반을 재사용한다. 선택 파일을 1MiB씩 읽고 크기/SHA-256 검증한다.
  결과의 완료/실패/미처리/확인 필요, 실제 위치·복구 기록과 저장 폴더 열기를 제공한다.
  문서/탐색기를 자동 열거나 완료 파일을 취소 때문에 되지우지 않는다.
- 조회/저장은 공유 파일 작업 슬롯에서 수행한다. 비모달 창, 단일 worker, queued 전달,
  취소·응답 가능한 종료 대기·native thread join 후 임시 목록 정리를 연결했다.
  보안 제품 때문에 임시 자료 정리가 실패해도 출처/외부 완료 파일은 보존한다.
- 새 화면의 밝은 배경/선택/스크롤바와 검색 조건 체크박스를 명시했다.
  좁은 창의 날짜 조건 잘림과 긴 백업 이름/오류가 창을 과도하게 확장하는 경우를 보완했다.
  Markdown/HTML 도움말을 갱신했다.

| 검사 | 결과 |

| Ruff / mypy | 통과, 소스 122개 타입 검사 |
| git diff --check | 통과 |

광범위 회귀는 총 1,041개다. 이후 긴 오류/파일명 표시와 취소 정리 실패 안내를 보완하고
추가 케이스를 포함한 관련 34개를 재검사했다. 최초 이름을 검색하지 않는 이전 검사 두 개는
이번 검색 확대 계약에 맞춰 최초 이름/메모가 검색되는 기준으로 갱신했다.

2차 추가 검사는 실제 SQLite·파일·백업을 사용하는 격리 프로필이다.
현재/보관본/중요 보관, 당시 메모·이름 유지, 동시각-ID 커서, 문자/여러 단어, 휴지통,
snapshot-only/연결 없는 복구 자료, DB 무변경, 100개 페이지/ID 검증, 형식 1/2/3·구형 스키마,
중복 ZIP/위험 경로/손상 해시, 큰 DB/명세 preflight, 출처 변경, 관리 폴더 저장 거절,
동명 기존 파일 보존, 권한·공간·취소·재시도, 취소 정리 잠금 실패를 확인했다.
4MiB 실제 파일의 ZIP 읽기가 1MiB 요청만 사용하는 것도 계측했다.

별도 실제 테스트 프로세스를 외부 저장 `prepared` 시점에서 `os._exit(71)`로 중단했다.
출처 백업 재검증, 기존 DB 바이트 유지, 공개 전 최종 파일 없음, 완성된 준비 사본/소유 저널의
복구 목록 조회를 확인했다. 예외 주입만으로 강제 종료 검증을 대신하지 않았다.

Qt offscreen 별도 프로세스에서 Windows 글꼴과 밝은/어두운 palette, 100/150/200% scale을
사용하여 검색 648×470/백업 500×420 논리 크기를 렌더링했다. 핵심 버튼·날짜 조건 접근,
밝은 viewport, 선택 상태를 자동 검사했고 캡처를 직접 검토했다.
캡처는 Git 제외 `artifacts/reliability-phase2-visual/`에 있다. 실제 Windows 테마/DPI를 바꾼
실기 검사가 아니며 회사 DRM·모든 문서 앱·장기간 실행/용량 상한 스트레스는 미검증이다.

## 제한과 보존

- 문서 바이너리 본문/셀 검색, 전체 업무 상태 되돌리기, 자동 정리/삭제는 추가하지 않았다.
- 백업 전체 검증은 크기에 비례한 시간이 든다. 자동 시작에 이 검사를 넣지 않는다.
- ZIP 구성 및 논리 항목 100,000개, DB 512MiB, 명세 16MiB까지 선택 조회한다.
  한도 초과 시 해당 조회만 거절하고 자료를 삭제하지 않는다.
- 백업 목록 페이지 이동은 선택을 해제한다. 검색 결과 외부 저장은 한 항목씩 기존 동선을 유지한다.
- 정상 종료는 임시 DB/추출 파일을 정리한다. 강제 종료나 잠금 실패로 앱 소유 임시 폴더가
  남을 수 있으며 다음 시작에 위치를 추측해 자동 삭제하지 않는다. 외부 준비 자료는
  `데이터 → 첨부 정리 → 중단된 저장 확인`으로 검토한다.
- 버전 3.0.8, DB 0015, 백업 형식 v3는 변경하지 않았다.
  운영 프로필과 `.local-data`를 테스트에 사용하지 않았다. 배포물·커밋·업로드는 하지 않았다.
