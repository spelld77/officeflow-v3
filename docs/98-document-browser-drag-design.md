# U44 보관함의 선택 행 드래그 복사

2026-11-12 사용자 `그러면 해` 요청에 따른 구현 전 소형 설계.
06번 UI 기준·24번 17절/91번의 독립 사본·고정 자료 검증/임시 사본 수명을 그대로 따른다.

- 보관함의 현재 첨부/보관본에서 현재 페이지의 강조 선택 행만 드래그한다. 체크한 저장 목록과 분리한다.
- 기존 AttachmentDragController/DragCopyStore와 FileReference.attachment/version을 재사용한다.
- 300ms 준비·CopyAction만 전달·100개/1GiB/32배치·24시간/소유 잠금 정리·원본 보존 규칙은 바꾸지 않는다.
- 페이지/종류/가족/새로고침 때 ready를 무효화하고 현재 보이는 선택 payload로만 다시 준비한다.
  체크 상태만 바꾸면 드래그 선택은 바뀌지 않는다. 다른 페이지의 체크를 드래그에 포함하지 않는다.
- 파일 작업/외부 저장/종료 중 시작을 막고, 종료 때 controller를 기존 ShutdownScope 계층으로 정리한다.
- 새 상시 안내·버튼·DB/버전/배포/Git 변경은 없다. 보관함 보관본 이름은 기존 저장 규칙대로 표시 이름과 보관 이름을 사용한다.
- 작은 합성 자료로 첨부/보관본 MIME·강조/체크 분리·전환/갱신 무효화·준비 중 종료와 기존 관련 선택/저장 검사를 확인한다.
  실제 탐색기 드롭/회사 DRM·전체 회귀·배포 검증은 별도다.


## 구현·검증 결과 (2026-11-12)

개발 소스 구현 완료. 보관함에 공통 outgoing 리스트/AttachmentDragController를 연결했다.
첨부/보관본 참조는 기존 resolve/capture를 재사용하고, 강조 행 payload를 준비 토큰으로 사용한다.
새로고침/종류/페이지 전환에서 준비를 무효화하고 체크 저장 원장은 유지한다.
종료는 기존 ShutdownScope 소유 계층으로 취소·join한다. 상시 안내/새 버튼/DB 변경은 없다.
