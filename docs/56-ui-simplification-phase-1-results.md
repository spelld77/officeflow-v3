# 화면 문구·설명·상시 버튼 정돈 — 1~7번 구현·검증 결과

배포 후속 기록: 2026-10-11 사용자 요청으로 3.0.10에 포함한다. 이 문서의 미배포 표기는 작성 당시 기록이며
최신 검증·GitHub 공개 결과는 [3.0.10 릴리스 체크리스트](59-release-checklist.md)를 따른다.

작성일: 2026-10-10. 공개 3.0.9 이후 개발 소스, U22-1~U22-7.
[55번 상세설계](55-ui-simplification-phase-1-design.md) 이후 사용자의 `구현 및 테스트해` 요청으로 적용했다.
상태: 구현·자동 검증·사용자 사용 확인 완료. 배포는 아직 하지 않았다.

## 1. 반영한 화면

| 후보 | 실제 변경 |
| --- | --- |
| 1 | 업무 목록·선택 상세·달력·업무일지 진입을 `업무 보기`, 편집을 `수정`, 첨부 직접 진입을 `첨부`로 구분. 휴지통 복원, 마지막 탭, 반복 회차와 창 재사용, 화면별 더블클릭은 유지 |
| 2 | 체크리스트의 상시 위로/아래로 제거. 오른쪽 메뉴에 수정·위로 이동·아래로 이동·삭제. 첫/끝 경계·읽기 전용·실패 후 기존 순서/선택 유지 |
| 3 | 보관함 선택 정보는 1~2줄 요약. 전체 이름·출처·메모는 비모달 읽기 전용 `파일 정보…`. 긴 이름은 생략 표시하고 전체 툴팁/정보 확인 유지 |
| 4 | 보관함 기본 행동 `열기 / 체크한 파일 저장… / 더보기`. 현재 페이지 강조 선택과 페이지 간 저장 체크 개수를 별도 표시. 삭제는 강조 선택만, 모두 해제는 모든 저장 체크만 대상으로 함 |
| 5 | 임시 사본 기본 행동 `작업본으로 저장… / 더보기`. 검사·문서 닫음 확인·외부 저장·선택 사본 버리기·미수정 사본 정리를 메뉴로 이동. 한 페이지에서는 이동 영역 숨김 |
| 6 | 업무 이력 기본 행동 `상세 / 비교 / 새로고침`. `시점 보관…`은 상단, 중단된 보관 확인은 상단 ⋯ 메뉴. 비교 모드에서만 두 시점 체크·선택 요약·개별 해제·취소·비교하기 표시 |
| 7 | 업무 입력의 알림 요약은 실제 개수/다음 시각을 한 번 표시. 저장 전 변경과 외부 실제 갱신 구분. 새 업무에는 `저장 전 · 예상`, 상세 설정 버튼에는 `알림 설정…` 표시 |

기능을 삭제하거나 자동 정리/알림 처리 규칙을 바꾸는 작업이 아니다.
정식 첨부 다중 저장과 임시 사본 단일 외부 저장은 서로 다르며, 사본 다중 외부 저장을 새로 구현하지 않았다.

## 2. 안전·부하 경계

- 보관함 요약/전체 정보는 메타정보 한 건만 조회하며 파일 본문이나 해시를 읽지 않는다.
  비동기 응답은 선택 ID/세대를 확인하여 예전 선택의 응답으로 새 선택을 덮지 않는다.
  확인된 출처 상태는 체크/행동 활성 상태 변경에도 유지한다. 보관 출처의 이름과 장식 라벨을 구분한다.
- `DocumentEntry`에 현재 출처의 실제 파일명 필드를 추가했다. DTO만 확장했으며 DB 스키마·저장 형식 변경은 없다.
- 사본 페이지는 인덱스 키 100+1건으로 다음 페이지를 판정하고 최대 100건의 상태 JSON만 읽는다.
  읽기 실패 개수를 표시하며 실패를 정상적인 빈 목록으로 숨기지 않는다. 기존 `page()` 호출 계약은 유지한다.
- 문서 닫음 확인은 저장/종료 동의 확인란이 필요하다. 창을 연 뒤 재열람한 사본의 오래된 토큰은 거절한다.
  다중 확인·미수정 정리는 완료·보호/보류·실패·미처리를 구분한다. 미수정 정리는 재검사하며 변경 사본을 삭제하지 않는다.
- 원본 보존, 사본 작업본 저장, 변경 버리기, 독점 파일 확인, 잠금·재열람·승인 후 변경 보호는 기존 서비스로 처리한다.
  조회/요약만으로 파일 복사·삭제·자동 이력·알림 처리를 하지 않는다.
- 이력 비교 선택은 현재 페이지 최대 50건과 선택 시점 최대 2건만 보관한다.
  페이지·필터·새로고침에도 비교 선택을 유지하고 화면 밖 선택을 표시한다. 다른 업무/회차 범위 비교는 거절한다.
  실제 비교는 과거→최근 순서이며 `현재와 비교`의 기존 업무 정보 6항목 범위는 유지한다.
- 알림 요약 변경 판단은 화면 문자열이 아니라 일정/상태/규칙 값과 기존 규칙 ID를 비교한다.
  제목·설명·규칙 정렬만으로 미저장 알림 변경이라고 표시하지 않는다. 외부 완료/재알림은 실제 상태만 갱신하고 초안을 보존한다.

## 3. 검증

모든 자료는 `.test-tmp`의 합성 DB/파일이다. 실제 사용 자료와 회사 DRM 환경은 테스트하지 않았다.

| 검사 | 결과 |
| --- | --- |
| 단위·통합 전체 | 765개 통과 (204.37초) |
| UI 전체 최종 재실행 | 519개 통과 (211.42초) |
| 대량 자료 성능 전체 | 5개 통과 (6.34초) |
| Ruff / mypy | 통과 / 소스 135개 통과 |
| Windows 실제 Qt 렌더링 | 밝은/어두운 팔레트·작은/일반 창 × 100/150/200%, 12개 조합 통과 |

기본 전체 테스트 합계는 1,289개다. Windows 렌더링 12개는 동일한 화면 테스트를
배율별 별도 프로세스에서 실행한 추가 검증이며 전체 테스트 합계에 다시 더하지 않는다.
이번 범위의 신규 테스트는 기능/실패 경로 19개와 화면 조합 4개이며 기본 전체 테스트에 포함된다.
개발 중 테스트의 이전 버튼 이름/제거된 버튼 기대치를 갱신했고, 레이아웃·상태 안내 문제를 보완한 뒤 위 최종 결과를 얻었다.

추가 자동 검증은 이름/행동 구분, 체크리스트 경계·읽기 전용·저장 실패,
보관함 강조/체크 분리·긴 메모·전체 정보·늦은 응답,
사본 1/100/101건 페이지·동의·재열람 토큰·부분 실패·상태 읽기 실패,
이력 선택 0/1/2/3건·범위 거절·페이지 간 유지,
알림 실제/초안/외부 완료·미저장 예측을 다룬다. 기존 파일 보호·백업·알림 회귀 테스트도 함께 실행한다.

실행 환경의 제한으로 한글 파일 경로 관련 테스트를 샌드박스 안에서 실행하면 권한 오류가 발생했다.
테스트 경로를 격리한 승인된 실행으로 검증했으며 그 권한 오류를 기능 성공/실패 판정에 포함하지 않았다.

### 화면 검증에서 추가 보완한 부분

- 작은 이력 창에 비교 선택과 기간을 함께 펼치면 버튼 높이가 줄어드는 문제를 확인했다.
  목록의 최소 높이와 레이아웃에 필요한 창 최소 높이를 확보했다. 필요한 경우 작은 창의 높이만 늘어난다.
- 체크 목록을 캡처할 때 마지막 행의 글자가 viewport 바깥 요약에 겹치는 문제를 확인했다.
  밝은 배경/체크 배치는 유지하고 행 텍스트와 체크의 그리기 영역을 목록 안으로 제한했다.
- 좁은 업무 입력창에서 저장 전 알림 변경 안내가 요약 아래로 잘리는 것을 확인했다.
  필수 상태는 생략하지 않고 현재 폭에 필요한 높이를 확보하도록 보완했다.
  정상 요약은 짧게 유지하지만 실제 시각·미저장 안내가 함께 필요한 좁은 창은 여러 줄로 보인다.
- 테스트는 버튼의 위치뿐 아니라 텍스트를 수용할 너비/높이도 검사한다.
  파일 정보·메뉴·목록·이력 비교·알림 변경 상태의 실제 캡처를 검토한다.
- 캡처는 `artifacts/ui-simplification-captures/`에 남긴다. 빌드/배포 자료가 아니며 Git 제외 대상이다.
  시스템 테마 자체를 전환한 검증이 아니라 Windows Qt 위젯에 밝은/어두운 팔레트를 주입한 검증이다.

## 4. 변경하지 않은 것과 사용 확인

기존 미커밋 변경을 보존했다. 실제 사용자 DB/첨부/백업, 버전, 새 DB 이행,
EXE·설치 파일·ZIP 재생성, Git 커밋·GitHub 업로드는 하지 않았다.
사용자는 `괜찮네. 복잡함이 줄었네`라고 1~7번의 사용 확인을 했다.
이어 요청한 U22-8~U22-14의 상세설계는 [57번 문서](57-ui-simplification-phase-2-design.md)에
정리했다. 이후 요청으로 반영한 8~14번의 결과는 [58번 보고](58-ui-simplification-phase-2-results.md)를 따른다.
처리 필요 분류, 자동 삭제 정책, 전체 테마 재설계는 계속 보류한다.

추가 사용 확인은 저장소의 `run-officeflow-dev.cmd`로 실행한다. `.local-data`의 개발용 자료를 사용한다.
이미 실행 중인 개발 프로그램이 있으면 완전히 종료하고 다시 실행해야 변경된 코드를 읽는다.

1. 업무 목록·달력에서 `업무 보기`/`수정`과 체크리스트 오른쪽 순서 메뉴 확인.
2. 보관함의 파일 체크·강조 선택, `파일 정보…`, 여러 파일 저장/삭제의 대상 구분 확인.
3. 임시 사본의 작업본 저장/사본 버리기/닫음 확인 동선과 이력의 두 시점 선택·해제 확인.
4. 업무 편집에서 날짜·알림 변경 시 실제 시각과 저장 전 안내가 구분되는지 확인.

회사 문서 편집기·보안 프로그램·시스템별 배율 조합에서의 사용 확인은 별도다.
