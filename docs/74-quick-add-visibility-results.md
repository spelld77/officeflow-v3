# 빠른 등록 결과 가시성 구현·검증

2026-10-16. 73번 설계의 개발 소스 구현/관련 검증 완료. 사용자 사용 확인 전이다.
이전 가독성 보완은 사용자가 확인했으며 기존 미커밋 변경을 보존했다.

## 반영

- 예정의 빠른 등록: 내일 종일·알림 없음, 예정 탭 유지. 오늘/전체의 기존 등록 기준은 유지했다.
- 입력 아래 한 줄에 등록 기준을 미리 알린다. 기타 탭의 전체 이동도 사전에 표시한다.
- 성공 후 같은 줄에 등록됨/제목/일정을 남기며 다음 입력·탭 변경 전까지 유지한다.
  긴 제목은 말줄임/전체 도움말/접근성 이름으로 처리한다. 한 줄 최소 높이를 고정해 성공 버튼 표시로 본문이 점프하지 않는다.
- 로드된 새 행은 그룹 펼침·선택·스크롤로 보여주고 입력 포커스는 유지한다.
  검색/필터 또는 첫 조회 50행 밖에서는 전체를 끝까지 읽지 않고 목록 밖 안내와 직접 업무 보기를 제공한다.
- 직접 보기는 현재 선택과 독립된 실제 저장 ID로 재조회하고 삭제된 업무는 안내한다.
  보기로 새 알림/완료/저장/회차를 생성하지 않는다. 모델 재설정/추가 조회 후 목록 밖 안내도 갱신한다.
- 저장 실패는 입력과 요청 식별을 유지하며 저장 직후 응답 실패 재시도에서도 중복 생성을 막는다.
  같은 제목의 정상 별도 등록은 금지하지 않는다. 주 화면의 날짜/저장 시각은 같은 시계를 사용한다.

## 검증

- 선행 실패 검사 12개로 누락 동작을 확인한 뒤 구현했다(`artifacts/quick-visibility-red.xml`).
- 최종 관련 회귀 **106개 통과**(`artifacts/quick-visibility-final-gate.xml`).
  빠른 등록/주 화면/업무 서비스/목록/실제 SQL 저장소를 포함한다. 중간 85/104개 실행을 중복 합산하지 않는다.
- Windows 100/150/200% **각 32개 통과**(`artifacts/quick-visibility-native-1.xml`,
  `quick-visibility-native-1.5.xml`, `quick-visibility-native-2.xml`). 밝은/어두운 앱 팔레트·760×560 DIP의
  긴 제목/사전 안내/성공 버튼·Enter/숫자 Enter·연속 입력/Tab을 포함한다. 생성된 대표 캡처를 직접 확인했다.
- 검색 밖/조회 구간 밖에서 조회를 제한하고 성공을 표시하는지, 정렬을 유지하며 새 행을 보여주는지 검사했다.
  실제 저장된 ID의 업무 보기/삭제 뒤 보기 방지/저장 직후 응답 실패의 동일 요청 재시도/알림 없음도 확인했다.
- 자정/연말/23시간 DST 날짜와 공급된 시계의 날짜·생성 시각을 검사했다.
- Ruff·mypy 151개 소스·수정 Python format·diff 공백 검사 통과.
- 이번 작업의 합성 fixture 폴더 8개만 종료 후 제거했다. 절대 경로/직계 artifacts 폴더/재분석 지점 없음이
  확인된 대상만 정리했고 실제 자료와 기존 배포물은 건드리지 않았다. 검사 XML·작은 캡처는 보존했으며 fixture는 재실행으로 재생성된다.
- 전체 검사/EXE/설치/ZIP/회사 PC/실제 다중 모니터 검사는 이번에 실행하지 않았다.
  앞선 72번의 1,573개 전체 통과를 이번 수정 후 전체 통과라고 재사용하지 않는다.

## 첨부 창 조사: 구현 전 제안

사용자는 창을 크게 만들거나 상시 필터를 늘리는 것을 원하지 않았다. 현재 첨부는 목록/썸네일·종류 콤보·
수동 순서·보관함/출처가 이미 있으므로 이를 새 기능처럼 중복 제안하지 않는다. 일반 첨부 목록은 여전히
원본/작업본을 각각의 행에 표시한다. 아래는 공식 문서에서 확인한 방식과 OfficeFlow 적용에 대한 추론이다.

- Adobe Bridge는 여러 파일을 대표 썸네일 하나와 개수로 묶고 펼침/접기를 제공한다.
  [공식 파일 스택 문서](https://helpx.adobe.com/uk/bridge/desktop/organize-and-find-files/organize-files-and-folders/stack-files.html)
- Zotero는 항목의 첨부를 부모 아래 펼쳐 보고 노드를 접을 수 있다.
  [공식 사용 팁](https://www.zotero.org/support/tips_and_tricks)
- VS Code는 필요할 때 Quick Open을 열어 파일 이름으로 찾고, 탐색기 트리도 이름 찾기를 지원한다.
  [공식 UI 문서](https://code.visualstudio.com/docs/editing/getting-started/userinterface)

적용 후보는 두 가지다. 원본-작업본 관계가 있는 파일은 기존 계열 ID를 활용한 접힌 묶음으로 중복 행을 줄이고,
서로 관계없는 파일은 요청할 때만 이름 검색을 열어 찾는다. 이름으로 임의 계열을 추측하거나 새 태그 입력을 요구하지 않는다.
작업본이 여러 개면 최신이라는 이유만으로 다른 활성 작업본을 조용히 숨기지 않고 개수/펼침을 명시해야 한다.
묶음은 구조이지 삭제할 파일이 아니므로 접힌 묶음 클릭을 전체 선택/삭제로 해석하지 않는다.
필요할 때의 검색은 닫으면 해제하고 적용 중임을 분명히 표시해 업무 검색의 이전 혼동을 반복하지 않게 한다.
현재 추천일 뿐 상세설계·실행 코드·저장 필드·첨부 순서/보존/삭제 방식은 바꾸지 않았다.

## 사용 확인

기존 OfficeFlow를 완전히 종료한 뒤 `run-officeflow-dev.cmd`로 개발 소스를 실행한다.
예정 탭 빠른 등록 아래 내일 날짜/알림 없음을 확인하고 제목을 입력해 Enter를 누른다.
예정 유지·등록됨/새 행 선택·계속 입력·업무 보기를 확인한다. 공개된 3.0.12 배포물은 바뀌지 않았다.
