# 매시 알림 구현·검증 보고서

- 날짜: 2026-10-01
- 기준: OfficeFlow 3.0.3 작업 소스 (버전·배포본 변경 없음)
- 후속: 사용자 테스트 확인 후 3.0.4 배포 승인. 실제 배포 검증·게시 결과는 [릴리스 체크리스트](../16-release-checklist.md)를 따른다.
- 결과: 설계의 시간 규칙·실행 상태·설정·화면·시작/종료 연동 구현 및 자동 검증 완료

## 구현

- 매시 35분 기본값, 대상 시간의 시작 안내, 같은 시각 구간 중복 방지.
- 실제 프로세스 실행마다 ON. 트레이/두 번째 실행 요청은 기존 OFF 상태를 유지.
- 이번 시간 닫기/X/Escape, 건너뛰기/취소, 같은 구간 안의 5분 다시 알림.
- 평일 제외 시간·주말 전체, 날짜 한정 오늘 휴일근무, 모든 요일의 추가 제외 시간.
- 08시 이후 첫 실행 제외, 05시/07:59/전날 ON의 자동 08시 연속, 예외적인 아침 재개.
- 아침 연속 상태의 오늘 09시 만료와 재실행 보존. 저장 실패 시 RAM 안내 유지, 매 검사 재저장 없음.
- 독립된 비차단 최상위 단일 알림창, 업무 알림과 위치 조정, 트레이/상태바/별도 설정창.
- 문구 1~200자·분 0~59·추가 제외 최대 8개 검증, 기본/추가 설정 분리 및 스크롤.
- 최신 AppSettings에 편집한 항목만 병합. 일반 설정창도 비차단으로 전환.
- 종료 타이머/창 정리, 설정 저장 실패 중에도 정상 종료 정리 계속 수행.
- 새 설정의 잘못된 필드는 개별 보정. 기존 DB 스키마·업무/알림 처리 이력 변경 없음.
- 5초 검사는 DB·파일·네트워크 조회를 하지 않으며 처리 키는 최대 48개, 창은 하나로 제한.

긴 알림 문구가 잘리지 않도록 본문 높이를 확보했고, 고급 설정은 본문 스크롤 안에 둔다.
테스트용 글꼴은 검사 후 해제하여 기존 UI 테스트에 영향을 주지 않는다.

## 남은 실제 사용 확인

### 사용 확인 후 UI 정돈

하단 상태의 긴 `매시 알림 · 이번 시간...` 문구로 발생한 잘림을 수정했다.
현재 구간 처리 여부는 툴팁/메뉴에서 보여주고, 상태 버튼은 `다음 20:35` / `재알림 19:45` 등
짧은 문구와 실제 내용에 맞는 너비로 표시한다. 알림 팝업은 기본 420×220으로 줄이고
`5분 뒤 알림 / 닫기 / ...` 한 행으로 정리했다. 긴 사용자 문구의 줄바꿈/높이 보장은 유지한다.

모호한 `평일 08시 연속 조건 적용` 체크 항목은 긍정형 `늦게 켜도 08시 알림 받기`(기본 끔)로
표현하고 평일 08:00~08:59 첫 실행에도 받을지 선택한다는 설명을 추가했다.
체크 여부와 기존 저장 플래그는 반대로 연결하며 기존 설정/시간 판정 호환을 유지한다.
예외적인 하루 재개 항목도 `오늘 08시 알림 받기`로 표시한다.
좁은 메인 창의 닫힘/건너뜀 표시와 옵션 저장·다시 열기의 회귀 테스트를 추가했다.

### 실제 Windows 검증 범위

Offscreen 테스트는 OS 포커스·회사 보안 정책 검증을 대신하지 않는다.
Excel/메모장 입력 중 매시 창이 나타날 때 포커스와 Enter 대상 유지,
네이티브 파일 선택창과의 클릭, 절전/잠금 복귀, 다중 모니터와 150%/200% 배율은 실제 Windows에서 확인해야 한다.
WA_ShowWithoutActivating·비모달·최상위 플래그와 activateWindow 미사용은 자동 검사 및 소스에서 확인했다.
Windows 보안 화면·독점 전체화면·강제 종료 중 표시를 보장하지 않는다.

인사랑은 연결/조작하지 않는다. 출근·업무기록 성공·초과근무 인정은 검사하지 않으며 사용자에게도 그렇게 표시하지 않는다.

## 사용·배포 경계

작업 폴더의 `run-officeflow-dev.cmd`는 `.local-data`를 사용하는 개발 실행이고,
`run-officeflow-python.cmd`는 기존 설치형과 같은 실제 사용자 데이터 경로를 사용하는 실행이다.
테스트 시 기존 OfficeFlow를 트레이에서 완전히 종료하고 목적에 맞는 실행기를 사용한다.
조정 경로는 `트레이 → 매시 알림` 또는 `설정 → 매시 알림 설정...`이다.

테스트 파일·화면 캡처·smoke DB는 Git에서 제외된 `artifacts` 안에 만들었다.
최초 구현 요청 단계에서는 실제 사용자 DB·설치 파일·Python ZIP·버전 번호·Git 커밋·GitHub 릴리스를 변경하지 않았다.
이후 별도 배포 승인에 따라 3.0.4 파일을 검증했으며 사용자 DB·첨부는 계속 변경하지 않는다.
