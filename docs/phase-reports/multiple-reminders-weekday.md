# 여러 알림·요일 표시 구현·검증 보고서

- 날짜: 2026-10-06
- 기준: OfficeFlow 3.0.6에서 개발한 개선, 3.0.7 릴리스 대상
- 설계: [한 업무의 여러 알림과 요일 표시](../21-multiple-reminders-weekday-design.md)
- 결과: 소스 구현·자동 검증 완료. 2026-10-07 요청에 따라 3.0.7 배포 검증·공개를 진행하며 결과는 [릴리스 체크리스트](../22-release-checklist.md)에 기록한다.

## 구현 내용

- 한 업무에 최대 20개 규칙. 날짜 직접 지정은 한 번, 시작·종료 기준은 업무 일정과 연동하며 반복 업무의 회차마다 적용한다.
- 기존 시작/종료/직접 지정 알림을 하나의 목록으로 편집한다. 새 업무의 기본 시작 시각 알림은 유지한다.
- 새 항목은 날짜 직접 지정이 기본이다. 기준 알림은 빠른 선택 또는 일·시간·분과 전/후로 입력하며 실제 예정 시각을 보여준다.
- 업무 편집창은 요약과 설정 버튼만 둔다. 설정의 적용은 임시 초안이며 업무 저장이 최종 저장이다. 취소는 DB를 바꾸지 않는다.
- 모델리스 입력·설정·항목 편집과 저장 실패 시 입력 보존. 열린 입력을 덮어쓰지 않고 확인·재알림의 발생 상태만 갱신한다.
- 오늘 알림은 업무 일정일·검색·필터와 독립적으로 표시한다. 기본 3행, 낮은 창 2행, 총 개수·숨은 개수·전체 보기를 제공한다.
- 달력 셀에 별도 알림 건수를 표시하고 기존 하단 목록에 업무/알림 행을 합친다. 건수를 누르면 첫 미처리 알림으로 선택·스크롤한다.
- 달력과 오늘 알림의 기록·첨부 동작은 원본 업무에 연결한다. 회차가 없는 직접 지정 알림에 임의 회차를 부여하지 않는다.
- 확인·재알림은 delivery 하나만 처리한다. 업무 전체 완료·취소·휴지통은 관련 미처리 알림을 정리하며 반복 회차 완료는 해당 회차만 처리한다.
- 알림창은 `이번 알림 확인`을 기본 동작으로 먼저 배치한다. 모든 업무 완료는 남은 알림 중단 범위를 별도 확인하며 반복 업무의 직접 지정은 `업무 전체 완료…`로 구분한다.
- 조회용 미리보기는 읽기 전용 계산과 실제 발생 이력을 합친다. 과거 날짜의 실제 발생을 추정하지 않으며 재알림/복구의 원래 예정일과 실제 날짜를 구분한다.
- 미리보기는 최대 42일, 후보 묶음 200개, 기본 결과 예산 5,000개/2초다. 일부 조회를 0건/전체 결과로 오해하지 않도록 표시하고 추가 조회를 제공한다.
- 오늘/월과 선택 날짜의 조회를 분리하고 오래된 요청 취소·낡은 결과 무시·종료 시 작업/전체 보기 창 정리를 적용한다.
- 날짜 표시 공통 함수와 입력칸 내부 읽기 전용 요일을 적용한다. 시간대 변환 뒤 한국어 요일을 계산하고 입력의 Tab 순서는 유지한다.
- 도움말 Markdown/HTML과 Python 패키지 필수 파일 검사 목록을 갱신했다.

## 데이터 보호

업무 본문·규칙 변경·다음 예약·관련 delivery 정리는 SQLite의 같은 `BEGIN IMMEDIATE` 작업 단위에서 저장한다.
실패 시 전체를 롤백하며 다른 창의 업무/규칙 변경을 감지해 작성 중인 입력을 보존한다.
변경하지 않은 규칙의 ID·확인 이력·재알림·예약 캐시는 유지하고 수정한 규칙도 ID를 보존한다.
기존 task-update 트리거가 모든 예약 캐시를 초기화하는 경우에도 영향을 받지 않은 캐시를 같은 트랜잭션 안에서 복구한다.
발생 검사와 예약 변경 사이에는 최신 규칙/업무/캐시 비교를 적용해 낡은 후보의 저장·발생을 막는다.

기존 20개 초과 규칙은 자르지 않으며 수정·삭제는 가능하고 새 규칙 확장만 막는다.
휴지통 복원은 지난 재알림을 다시 활성화하지 않고 유효한 미래 예약부터 다시 계산한다.
미리보기 조회 전후 DB 행·다음 예약·발생 키가 바뀌지 않는 것을 검사했다.

여러 알림 자체에는 새 DB 열·테이블이 필요하지 않다. 이전 첨부 수동 순서 작업의 0011 마이그레이션은
별개이며 기존 변경을 보존했다. 실제 사용자 DB·첨부·설정은 이번 검증에서 열거나 변경하지 않았다.

## 사용 확인·배포 경계

### 후속 화면 수정: Windows 어두운 테마

사용자 화면에서 업무 수정창의 본문이 어두워 항목명이 보이지 않는 문제를 재현했다.
`QScrollArea`의 콘텐츠는 시스템 Window 팔레트를 따라 자동 배경을 채우며, 창 자체의 밝은 QDialog 스타일만으로는
본문까지 밝게 지정되지 않았다. 시스템 팔레트를 어둡게 바꾼 네이티브 테스트에서 본문 픽셀이 `#202020`으로 나오는 것을 확인했다.

스크롤 영역·뷰포트·본문에 별도 이름과 밝은 배경 `#F4F6FA`를 지정하고 스크롤바도 밝은 색으로 통일했다.
일반 일정·기간 일정 모두 본문 실제 렌더링과 제목/설명/상태 글자색, 알림 설정·항목 편집창 배경을 검사했다.
Windows 125%와 200%에서 관련 편집/알림 UI 검사 각 35개가 통과했다.
이 수정도 소스만 반영했으며 실제 사용자 DB·배포 파일은 변경하지 않았다.

### 후속 화면 수정: 요일을 입력칸 내부로 통일

칸 바깥에 별도 라벨로 붙였던 요일을 모든 날짜 입력의 테두리 안으로 옮겼다.
연·월·일 세 구간만 편집하며 한국어 요일은 따옴표 리터럴로 표시한다.
날짜 변경 시 활성 구간·선택·커서를 유지하며 날짜 자체와 저장/검색/ICS 값은 바꾸지 않는다.
글꼴·스타일 변경 시 최소 입력 폭도 다시 계산해 두 날짜를 나란히 놓는 화면에서 잘림을 방지한다.

등록/수정의 시작·종료·반복 종료, 알림 설정, 업무별 일지 날짜, 일지 조회의 일일/기간 날짜,
첨부 검색 기간, ICS 내보내기 기간에 공통 적용했다. 직접 타이핑·화살표·달력 팝업·Tab과
윤년 날짜, 실제 표시 폭을 검사했다. Windows 125%·200%에서 관련 검사 각 44개가 통과했다.

### 후속 알림 UX 수정: 알림 확인과 업무 완료 구분

기존 파란색 `완료`는 업무 자체를 완료해 남은 예약이 중단되는 동작이었다.
`이번 알림 확인`을 파란색 기본/Enter 동작으로 먼저 배치하고 다시 알림을 같은 행에 둔다.
`업무 완료…`·`업무 대기로`는 별도 보조 행에 두고 적용 범위를 툴팁과 처리 메시지에 표시한다.

일반 업무·반복 회차·반복 업무 전체 모두 완료 전 남은 알림·재알림의 중단 범위를 확인받는다.
확인창은 알림창 위의 비차단 창이며 기본/Enter/Esc는 취소다. 중복 확인창을 만들지 않고,
확인 중 반복 범위가 바뀌거나 알림이 먼저 처리되면 이전 동의로 완료하지 않는다.
취소 후 다시 열기·알림 확인·종료 때 확인창의 연결을 정리해 삭제된 창을 다시 참조하지 않는다.

이번 알림 확인 뒤 프로그램 서비스를 다시 시작해도 다음 예약은 울리며 다른 예약의 재알림도 유지된다.
업무 대기는 다음 예약을 끄지 않는다. 일반 완료는 확인 후 남은 예약·재알림을 중단하고,
회차 완료는 해당 회차의 남은 예약만 중단하며 다음 회차는 유지되는 것을 검사했다.
기록·첨부 창이 열린 상태에서 실제 QWindow 입력으로 완료 확인을 처리하고,
작은 알림창의 버튼 표시를 Windows 125%·200%에서 검사했다. 각 배율의 관련 검사 58개가 통과했다.
알림 저장 구조·업무 상태 정책·기존 사용자 자료는 변경하지 않았다.

기존 OfficeFlow를 트레이에서 완전히 종료한 뒤 작업 폴더의 `run-officeflow-dev.cmd`를 더블클릭해 확인한다.
이 실행기는 격리된 `.local-data`를 사용한다. 새 업무 또는 기존 업무의 `알림 → 설정…`에서 여러 예약을 추가하고,
오늘 알림·달력 날짜별 알림·각 예약의 확인/재알림을 확인한다.

`run-officeflow-python.cmd`는 실제 사용자 데이터 경로를 사용하므로 개발 실행과 구분한다.
구현·화면 수정 단계에서는 소스만 변경했으며 기존 3.0.6 공개 파일은 변경하지 않았다.
2026-10-07 후속 요청에 따라 버전을 3.0.7로 올리고 EXE·설치파일·Python ZIP을 다시 생성해 별도 릴리스로 공개한다.
기존 3.0.6 실행 파일·배포 ZIP에는 이 기능이 없으므로 새 3.0.7 배포본을 사용해야 한다.
`처리 필요`의 분류 기준 변경은 사용자 요청으로 보류했으며 현재 기준을 유지한다.
