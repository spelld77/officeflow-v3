# 첨부 호환·입력 편의와 업무 보기 통합 상세설계

작성일: 2026-10-14. 상태: 후속 구현 요청으로 개발 소스에 반영. 구현·검증 결과는
[66번 결과](66-attachment-and-task-view-combined-results.md)에 기록한다. 사용자 사용 확인·배포 전.

사용자 요청: 최근 제안한 1차(이미지·첨부 입력 보완)와 2차(업무 보기·조회 동선)를
한 번에 설계한다. 최초 요청은 설계이며 구현·버전 변경·배포·커밋·업로드 승인이 아니었다.
후속 `이제 테스트까지 진행해` 요청으로 실행 코드 구현과 격리 검증을 승인받았다.
과거 1~3차 개발 문서의 차수와 구분하여 **이번 통합 묶음**으로 부른다.

기준: [후속 목록](23-follow-up-improvements.md), [파일 보존 공통 계약](24-follow-up-common-design.md),
[품질·밝은 테마 기준](06-development-process.md), [운영 신뢰성 계약](38-reliability-common-design.md).
이미 구현한 U24/U25는 [64번 결과](64-attachment-drop-and-calendar-attention-results.md)를 유지한다.

  자연어 등록·음성 인식·이미지 편집·PDF 가공·외부 서비스는 제외한다.
- 기존 미커밋 소스와 문서는 보존한다. 실제 사용자 파일·DB·실행 폴더로 설계 검사를 하지 않는다.

## 2. 확인한 현재 구조

- `presentation/main_window.py`: 목록 doubleClicked는 `_open_task_from_index`에서 수정창으로 연결한다.
  Enter도 `_activate_selected_task`에서 목록/달력을 다르게 처리한다. 달력은 `_open_selected_records`로 연결한다.
- `_show_task_records`는 업무 ID·원래 회차·휴지통 읽기 전용 상태가 같은 열린 기록창을 재사용한다.
  기본 진입 탭은 세션의 마지막 탭이다. 이 재사용 계약을 별도의 새 상세창으로 대체하지 않는다.
- `presentation/record_dialog.py`: `TaskRecordsDialog` 상단은 제목·기록 범위이며 업무 설명이 없다.
  메인의 설명 상세 패널은 좁은 창에서 숨겨진다. 첨부 탭에서는 짧은 제목으로 목록 공간을 확보한다.
- `presentation/task_list.py`: 첨부 배지는 그리기만 하며 클릭 행동은 없다.
  완료 원과 더보기는 delegate가 클릭을 처리한다. 이들의 클릭 영역과 첨부 영역은 분리해야 한다.
- `application/image_attachments.py`와 `presentation/image_attachments.py`의 허용 형식은 PNG/JPEG/BMP다.
  실제 WebP를 Qt가 읽을 수 있어도 앱이 거절한다. 썸네일의 일반 실패는 넓게 축약된다.
- `AttachmentMetadataDialog`는 입력 뒤에 기존 확장자를 붙인다. 전체 파일명을 붙여넣으면 중복될 수 있다.
- 파일 추가 대화상자의 초기 폴더는 빈 문자열이다. `AppSettings`에는 외부 저장 폴더만 있다.

현재 코드 관찰은 설계의 근거이며 아래 목표 동작이 이미 구현되었다는 뜻은 아니다.

## 3. U28: 업무 확인과 수정 분리

### 3.1 진입 동작

| 진입 | 새 창의 목표 상태 |
| --- | --- |
| 오늘/예정/중요/대기/완료/전체의 업무 더블클릭·Enter | 업무 보기, 설명 펼침, 기본 체크리스트 탭 |
| 달력 막대/날짜 하단 업무 활성화·Enter | 동일한 업무 보기, 선택한 원래 반복 회차 유지 |
| 업무 보기 메뉴/버튼 | 동일한 일반 조회 진입 |
| 목록 첨부 배지/첨부 버튼·메뉴 | 같은 창의 첨부 탭, 설명 접힘 |
| 완료 요약·업무일지·폴더 등 목적이 명확한 기존 진입 | 요청한 탭 우선. 그 기능을 체크리스트로 바꾸지 않음 |
| 휴지통의 일반 조회 | 읽기 전용 업무 보기. 더블클릭으로 복원/수정을 실행하지 않음 |
| 수정 메뉴/버튼 | 기존 업무 수정창. 조회창을 자동 저장·수정창으로 전환하지 않음 |

일반 조회로 새 창을 만들 때는 마지막 첨부 탭을 무조건 상속하지 않는다.
이미 열린 같은 창이 있으면 새로 만들지 않고 현재 탭·선택·스크롤·미저장 기록 초안을 유지한다.
일반 조회 요청은 설명만 펼쳐 보여준다. 첨부 등 명시적 요청은 탭만 전환하며 초안을 버리지 않는다.
탭 전환으로 설명을 자동 접었다가 펼치는 규칙을 추가하지 않는다. 접힘은 진입 목적과 사용자의 행동으로 결정한다.
체크리스트 기본 탭은 기존 탭 재사용을 위한 결정이며 새로운 필수 체크를 요구하지 않는다.

### 3.2 기존 창의 최소 보완

- 사용자 문구는 `업무 보기`로 통일한다. 제목 옆에 `수정` 하나를 두고 기존 편집 명령을 호출한다.
  휴지통에서는 비활성화하고 복원은 기존 휴지통 동선을 사용한다.
- 제목 아래 일정·상태를 짧게 표시한다. 반복 회차의 경우 해당 회차임을 표시하고
  설명·체크리스트는 업무 공통 자료, 결과/일지는 기존 회차 범위라는 구분을 유지한다.
- 설명은 읽기 전용 plain text로 표시한다. 글자 선택/복사가 가능하고 HTML이나 URL을 자동 실행하지 않는다.
  공백뿐인 설명은 빈 영역·`설명 없음` 문구 없이 생략한다.
- 일반 진입은 실제 줄바꿈·너비에 따른 처음 3줄까지 표시한다. 나머지는 `더 보기`로 펼친다.
  펼친 본문도 약 6줄 높이의 스크롤 영역으로 제한한다. 긴 설명을 영구 잘라 저장하지 않는다.
- 첨부 직접 진입은 설명 본문을 접고 필요할 때 `설명 보기`로 펼친다.
  설명이 없는 업무는 이 버튼도 만들지 않는다. 설명 접힘 상태를 새 사용자 설정으로 저장하지 않는다.
- 제목·일정의 폭을 제한하고 기존 제목 줄임/전체 확인 방식을 재사용한다.
  500×540 DIP 창에서 첨부 직접 진입은 기존 목록 영역을 설명 높이만큼 빼앗지 않아야 한다.
- 기존 5개 탭·창 크기 기억·넓게 보기·다중 선택·기록 작성·첨부 작업을 재사용한다.
  메인 목록의 표시 줄 수나 행 높이를 이 기능 때문에 늘리지 않는다.

### 3.3 최신 정보와 편집 보호

- 조회 정보의 키는 `(task_id, original_occurrence_start 또는 None)`이다.
  반복 이동 후 표시 날짜로 회차를 새로 식별하지 않는다.
- 설명/제목은 현재 저장된 업무 공통 값, 일정·상태는 선택 범위의 유효 값을 사용한다.
  선택 회차의 표시 일정 projection을 이용하되 기본 업무 DTO를 수정용 값으로 덮어쓰지 않는다.
- 반복 업무에서 수정 버튼은 기존 기본 업무 수정 동작을 유지한다. 회차 확인창의 이동 날짜가
  반복 전체 수정창에 저장할 기본 날짜로 잘못 전달되지 않아야 한다.
- 열린 수정창은 기존 업무 ID 재사용 정책을 따른다. 수정 취소는 보기창 내용을 바꾸지 않는다.
- 편집·상태 변경 성공 뒤 영향받은 열린 보기창의 **조회 헤더만** 새 저장 값으로 갱신한다.
  기존 결과메모/일지 입력기, 파일 선택/작업, 비교 중인 과거 내용은 재생성하거나 덮어쓰지 않는다.
- 일반 목록에서 반복 항목을 활성화할 때 실제 선택 행의 원래 회차 값을 넘긴다.
  이전에 선택했던 다른 업무/회차의 상태를 그대로 사용하는 경로를 없앤다.
- 보기만으로 알림 확인·업무 완료·일지/이력 추가를 실행하지 않는다.
  창은 modeless이며 알림 창이나 다른 파일 창을 막는 최상위/모달 정책을 추가하지 않는다.
- 새 요청/닫힌 창 뒤의 늦은 결과는 요청 토큰과 Qt 객체 생존 확인으로 배제한다.
- 헤더 재조회 실패는 기존 화면과 초안을 유지하고 짧게 알린다. 영구 삭제된 업무는 더 이상
  쓰기/수정할 수 없게 안내하되 미저장 기록을 조용히 없애지 않는다. 상태 오류로 새 회차를 만들지 않는다.

### 3.4 첨부 배지 클릭

- 기본/간결 보기에서 그리기와 클릭 판정이 같은 DIP 좌표의 배지 사각형을 사용한다.
  왼쪽 버튼만 처리하며 완료 원·상태 배지·더보기·행 선택과 겹치지 않는다.
- 클릭한 행의 업무/회차를 먼저 확정하고 기존 첨부 열기 경로로 연결한다.
  가상 그룹 헤더·추가 불러오기·첨부 없는 행은 첨부 명령을 실행하지 않는다.
- 배지 더블클릭의 두 번째 이벤트가 일반 업무 활성화로 전달되어 설명을 펼치거나 수정창을 열지 않도록 한다.
  연속 클릭해도 같은 창을 재사용한다. 마우스 누름 위치와 놓음 위치가 다른 경우를 구분한다.
- `첨부파일 보기` 도움말/접근 가능한 안내를 제공한다. 기존 첨부 버튼·오른쪽 메뉴는
  키보드 접근 경로로 유지한다. 첨부를 보기 위해 파일을 자동으로 열거나 복사하지 않는다.
- 파일명 검색의 `일치` 배지는 같은 첨부 진입을 사용한다. 첫 출시에서는 임의의 첫 파일을
  자동 실행/선택하지 않는다. 검색 결과의 기존 일치 이름 안내는 유지한다.

## 4. U29: 날짜 도움말

공통 표시 함수는 일정의 유효 시작/종료, 종일 여부, 시간대와 주입된 현재 시각을 받는다.
시계/파일/DB를 함수 안에서 조회하지 않는다. 화면은 tooltip 요청 때 현재 시각을 전달한다.

| 조건 | 상대 날짜 문구 |
| --- | --- |
| 시작 날짜가 미래 | `시작일은 N일 후입니다.` |
| 시작 시각 전이지만 같은 날짜 | `오늘 시작 예정입니다.` |
| 시작 후, 종료 전인 기간 일정 | `종료일은 N일 후입니다.` / `오늘 종료 예정입니다.` |
| 종료 시각이 지남 | `종료일로부터 N일이 지났습니다.` / `종료 예정 시각이 지났습니다.` |
| 종료 없는 일정의 시작 시각이 지남 | `시작일로부터 N일이 지났습니다.` / `오늘 시작 예정 시각이 지났습니다.` |
| 일정 없음 | `일정 없음`. 상대 기간을 계산하지 않음 |
| 완료/취소·건너뛴 회차 | 저장된 상태·정확한 날짜 표시. 남은 작업이나 지연을 요구하는 문구는 생략 |

- N은 업무 시간대의 **달력 날짜 차이**다. 24시간 나눗셈이나 영업일/공휴일 계산이 아니다.
  같은 날 미래 시각을 `1일 후`로 표시하지 않는다.
- 항상 연도·월·일·요일·시각(종일은 종일)을 함께 표시한다. 기간은 시작/종료를 모두 보여준다.
- 종일의 저장 종료는 배타 경계다. 종료 날짜 문구에는 마지막 포함 날짜를 사용하고,
  기간이 끝났는지는 저장 종료 경계로 판단한다. 하루 종일 일정을 다음 날까지 남은 것으로 표시하지 않는다.
- `시작일이 지남`을 `마감 초과`로 바꾸거나 업무 상태를 자동 수정하지 않는다.
- 유효 회차 일정/상태를 아직 확인하지 못한 경우 기본 반복 업무의 옛 시작일로 상대 기간을
  추측하지 않는다. 확인된 정확한 정보만 보여주고 조회/확인 전임을 구분한다.
- 첫 범위는 메인 업무 목록의 일정 부분, 달력의 실제 업무 항목/날짜 하단 목록,
  업무 보기의 일정 라벨이다. 날짜 입력칸·월 달력의 날짜 요약/숨은 건수 tooltip은 바꾸지 않는다.
- 목록은 paint와 같은 일정 영역을 이용해 도움말을 구분한다. 다른 영역의 설명·첨부 일치·재알림
  tooltip을 없애지 않는다. 달력의 알림 항목은 업무 일정과 알림 예정 시각을 별도 문구로 유지한다.
- 매 초 전체 행을 다시 계산하거나 새 타이머/예약을 추가하지 않는다. 자정 뒤 새 tooltip 요청은
  새 시각으로 계산하고 다음 UI 갱신에서도 오래된 상대 날짜 문자열을 재사용하지 않는다.

## 5. U27-1/2: WebP와 오류 구분

### 5.1 읽기 범위

- 이미지 후보 확장자에 `.webp`를 추가한다. 실제 decoder 허용 형식은 PNG/JPEG/BMP/WebP다.
  `.png` 파일의 실제 내용이 WebP여도 안전한 decoder가 읽을 수 있으면 표시한다.
  비이미지 확장자까지 모든 파일을 탐색/디코딩하는 자동 판별 기능은 추가하지 않는다.
- 파일은 기존 `image_preview_stream`의 보호된 읽기 핸들로 읽는다.
  frozen의 크기·SHA-256 검증, 사용 예약, 변경 중/취소 검사 뒤에만 이미지를 공개한다.
- 기존 1,600만 픽셀·64 MiB 파일/이미지 상한, 32 MiB·64개 LRU,
  32개 큐·보이는 항목만 요청·한 reader worker를 유지한다. 상한을 높이지 않는다.
- WebP 애니메이션은 첫 표시 프레임만 대상으로 한다. 재생 타이머·전체 프레임 캐시는 만들지 않는다.
- 원본을 PNG로 변환하거나 확장자·자산·최초 해시를 바꾸지 않는다. 클립보드 캡처 저장 형식은 PNG 그대로다.
- decoder plugin이 없는 환경은 지원 기능 실패로 안내한다. 추후 EXE/ZIP 릴리스 때 Qt WebP plugin 포함을
  별도로 확인한다. 지금 설치본을 만들거나 모든 환경의 지원을 이미 검증했다고 기록하지 않는다.

### 5.2 실패 분류

문자열에 `크`가 있는지 또는 원본 역할인지만으로 상태를 추정하지 않는다.
서비스/reader는 기존 예외 계층과 호환되는 명시적 오류 코드/세부 원인을 전달하고,
썸네일과 확대 미리보기는 같은 분류를 표시한다. 실제 클래스명은 구현 시 기존 예외를 재사용해 정한다.

| 원인 | 짧은 표시 | 유지할 처리 |
| --- | --- | --- |
| 미지원 실제 형식/decoder 없음 | `형식 미지원` | 구체적 지원 범위 tooltip. 고정 내용 이상으로 취급하지 않음 |
| 파일 용량/픽셀/디코딩 메모리 상한 | `크기 제한` | 기존 제한으로 거절. 출처 내용 변경 없음 |
| 파일 누락 | `파일 없음` | 자동 삭제/재연결 없음 |
| 권한·파일 잠금·복구 보호 | `읽기 불가` | 정책 우회/자동 복사 없음 |
| 실제 frozen 검증값 불일치 | `고정 내용 불일치` | 이미지 공개 거절, 파일/기준 보존 |
| 읽는 중 변경 | `다시 확인 필요` | 오래된 화면 공개하지 않음. 요청 재검사 동선 유지 |
| 해석 실패/알 수 없는 오류 | `미리보기 실패` | decoder 실패만으로 손상·무결성 깨짐을 단정하지 않음 |

취소/다른 항목 선택/닫힘은 사용자 오류로 남기지 않는다. 긴 기술 원인은 tooltip/상세에 두고
파일 본문·개인 경로를 로그에 넣지 않는다. 전체 자료 검사/백업 오류 체계를 이 작업으로 재작성하지 않는다.

## 6. U27-3: 표시 이름 입력

- 기존 본문 입력칸 + 고정 확장자 구조를 유지한다. 입력/붙여넣기 뒤 **완성 이름 한 줄**을 보여준다.
- 입력칸은 전체 파일명도 받을 수 있도록 원래 파일명 길이 상한을 사용하고, 확장자 정규화 뒤
  최종 이름을 다시 검증한다. 기존처럼 상한에서 확장자 길이를 먼저 빼서 붙여넣은 이름을 잘라내지 않는다.
- 기존 확장자와 같은 끝부분 하나를 대소문자 무시로 제거한 뒤, 기존 확장자를 한 번 붙인다.
  본문 속 점/버전 번호/다른 접미사는 삭제하지 않는다. 이미 중복된 끝 확장자가 여러 개면
  자동으로 여러 번 지우지 않고 입력 오류로 안내한다. 초기 기존 이름 자체는 열기만으로 바꾸지 않는다.
- 기존 이름이 이미 중복 확장자를 포함하더라도 입력을 바꾸지 않고 닫기/저장하는 것은 무변경 처리한다.
  명시적으로 이름을 편집한 경우에만 새 정규화/오류 안내를 적용한다. 메모 편집에는 이 규칙을 적용하지 않는다.
- 앞뒤 공백/금지 이름/문자/경로/길이 검증을 기존 `validate_display_name`으로 유지한다.
  정규화 전에 잘못된 끝 공백·마침표를 확인해 조용히 정상 입력으로 바꾸지 않는다.
- 다른 확장자를 입력해도 형식 변환은 하지 않는다. 최종 이름에 기존 확장자가 유지됨을 표시한다.
  확장자가 없던 파일에 임의의 확장자를 붙이는 요청은 기존 도메인 정책대로 거절한다.

| 기존 확장자 | 입력 | 완성 이름/결과 |
| --- | --- | --- |
| `.docx` | `수정 보고서` | `수정 보고서.docx` |
| `.docx` | `수정 보고서.DOCX` | `수정 보고서.docx` |
| `.docx` | `수정 보고서.docx.docx` | 중복 입력 안내, 저장 안 함 |
| `.docx` | `보고서.v2.0` | `보고서.v2.0.docx` |
| `.docx` | `보고서.pdf` | `보고서.pdf.docx` 미리보기. 파일 형식이 바뀌지 않음 |

확정은 기존 메타데이터 명령·경쟁 토큰·검색 갱신을 사용한다. 첨부 ID/실제 경로/내용·출처 연결·
이전 작업본의 자체 이름/과거 보관 당시 이름은 변경하지 않는다. DB 저장 실패는 창과 입력을 유지한다.

## 7. U27-4: 파일 추가 시작 폴더

- `AppSettings.attachment_import_directory: str | None = None`을 추가하고 기존 JSON 저장을 사용한다.
  타입/빈 문자열/NUL/절대 경로 형태를 확인하며 잘못된 새 값만 기본값으로 복구한다.
  다른 창 크기·알림·백업 설정을 초기화하지 않는다. 설정 없음/구형 설정은 기본 폴더 동작이다.
- 파일 추가 picker에서 명시적으로 파일을 선택했을 때 첫 선택 파일의 부모 폴더를 기억한다.
  여러 파일 가져오기의 실패/중복 여부와 독립이다. 선택 취소·드롭·클립보드 캡처·열기/내보내기는 바꾸지 않는다.
- 최초 시작 위치는 Windows 문서 폴더를 사용한다. 로컬 폴더 누락/접근 실패를 확인하면 같은 기본 위치로 복귀한다.
  폴더 삭제/권한/공유 접속 실패를 파일 가져오기 실패나 첨부 삭제로 해석하지 않는다.
- 시작 시 저장한 경로를 전수 검사/탐색하지 않는다. picker 요청 시 필요한 확인만 한다.
  네트워크/매핑 드라이브를 GUI 스레드에서 동기 `exists/resolve`로 사전 탐색하지 않는다.
  native picker가 시작 위치를 처리하도록 하며 접근 실패 시 기본 위치로 다시 선택할 수 있게 한다.
  Windows의 접속 시간 제한까지 앱이 즉시 복귀하도록 보장하는 별도 네트워크 탐색 서비스는 추가하지 않는다.
- MainWindow가 단일 최신 설정의 소유자다. 일반 보기·업무일지에서 연 자식 보기창·알림 경유 창에
  현재 폴더를 전달하고 변경 신호/저장 callback으로 열린 창에도 반영한다.
  오래전에 열린 창의 설정 사본 전체를 저장하여 다른 설정 변경을 덮어쓰지 않는다.
- 설정 저장 실패여도 파일 선택/가져오기는 계속 가능하다. 이번 실행의 기억은 유지하고
  `선택 폴더를 저장하지 못했습니다.`를 비차단으로 알린다. 사용자가 처리해야 하는 성공 팝업은 추가하지 않는다.
- 전체 백업에서 설정을 보존하는 기존 계약을 재사용한다. 다른 PC에서 외부 경로가 달라도
  파일이 자동 이동/복원되는 기능은 아니다. 개인 경로를 테스트 fixture/문서에 넣지 않는다.

## 8. 코드 경계와 구현 순서

1. 이미지 읽기 허용 형식과 명시적 오류 분류를 공통 reader/service에 먼저 반영한다.
2. 이름 정규화/최종 이름 표시, 선택 폴더 설정·signal을 기존 입력 동선에 연결한다.
3. 기존 기록창에 읽기 전용 설명·일정·상태와 수정 요청 signal을 추가한다.
4. MainWindow/업무일지의 창 생성·재사용, 헤더 갱신·회차 projection·휴지통 조회 경로를 연결한다.
5. 목록/달력 활성화와 첨부 배지 클릭을 같은 진입 계약으로 정리하고 날짜 도움말을 연결한다.
6. 통합 회귀·시각 확인 뒤 도움말/변경 기록/검증 보고를 갱신한다. 사용 확인용 개발 실행을 안내한다.

외부 도구/새 패키지를 설치하지 않는다. 현재 Qt decoder를 사용한다. 하나의 설계·구현 묶음이지만
단위별 관련 검사를 중간에 실행한다. 전체 구현 뒤 한 번에만 실패를 발견하는 방식으로 진행하지 않는다.
새 공통 조회 데이터는 Qt widget이나 ORM session을 섞지 않는 작은 DTO/함수로 표현하고
화면마다 별도 SQL·반복 날짜 산술·파일 읽기를 복제하지 않는다.
