# 첨부파일 검색 설계

- 작성일: 2026-09-30
- 기준: OfficeFlow 3.0.2
- 상태: 2026-10-01 구현 및 테스트 완료, 3.0.3 배포 대상으로 반영
- 목표: 업무 제목이나 날짜를 몰라도 원래 파일명으로 첨부를 찾고 바로 열 수 있게 한다.

## 1. 범위와 제품 결정

첫 구현은 파일명 검색, 검색된 파일 열기, 연결 업무 확인까지 완결한다.
PDF·Excel·Word의 본문, 이미지 문자 인식, 압축파일 내부, 원본 PC 경로는 검색하지 않는다.
검색 안내에는 항상 '파일명 검색'이라고 명시한다.

별도 사이드바 메뉴를 추가하지 않고 상단 검색창 옆에 작은 검색 대상 선택을 둔다.
일반 화면에서는 '업무 / 첨부파일', 캘린더에서는 '일정 / 첨부파일'로 표시한다.

| 검색 대상 | 조회 범위 | 결과 단위 |
|---|---|---|
| 업무 | 현재 탭과 업무 필터 유지, 기존 검색 대상에 연결된 첨부파일명 추가 | 업무 1개 |
| 일정 | 현재 캘린더 범위 유지, 연결된 첨부파일명도 검색 | 기존 일정 표시 |
| 첨부파일 | 모든 날짜·업무 상태, 완료·보관·취소 업무 포함 | 첨부파일 1개 |
| 업무일지 | 기존 완료 업무·기록의 검색 규칙과 선택 기간 유지, 파일명도 검색 | 기존 업무 그룹 |

업무일지 검색에 파일명을 추가해도 기록이 없고 완료하지 않은 업무를 새로 끼워 넣지 않는다.
파일을 전체 기간에서 찾으려는 경우 상단 첨부파일 모드를 사용한다.
반복 업무의 첨부는 현재 모델처럼 업무에 연결된다. 발생일마다 같은 파일을 중복 표시하지 않는다.

## 2. 화면과 이동

### 2.1 업무 모드

기존 검색창 안내를 '업무·내용·첨부파일명 검색'으로 바꾼다.
검색 상태 표시에는 현재 범위를 함께 적는다. 예: '오늘에서 견적 검색 중 · 2개 업무'.
현재 범위에서 결과가 없으면 '전체 기간의 첨부파일 찾기'를 제공한다.
이 동작은 검색어를 유지하며 첨부파일 모드로 전환한다.

검색에 일치한 파일이 있는 업무에는 '파일명 일치' 표시를 제공한다.
일반 보기의 보조 줄에 첫 일치 파일명을 보여주고, 간결 보기에서는 제목 줄을 늘리지 않고
표시와 툴팁으로 안내한다. 여러 파일이 일치하면 첫 파일명과 '외 N개'를 표시한다.
선택 업무의 상세 영역에는 일치 파일과 열기 동작을 제공한다.
일치 파일 정보는 현재 업무 페이지에 필요한 것만 일괄 조회한다.

### 2.2 첨부파일 모드

메인 콘텐츠 영역을 파일 검색 페이지로 전환한다. 캘린더나 업무 목록 위에 창을 겹치지 않는다.
제목은 '첨부파일 찾기', 범위는 '전체 기간 · 완료/보관 포함'으로 명시한다.
업무 전용 상태·중요도·고정 필터와 빠른 등록은 이 페이지에서 숨긴다.
파일 종류 선택은 '전체 / Excel / PDF / Word / 이미지 / 기타'를 제공한다.
파일 종류는 확장자 기준이며 내용 검증 또는 악성 파일 판별 기능으로 표현하지 않는다.

검색어가 없으면 최근 첨부 50개를 보여주고 '최근 첨부파일'로 표시한다.
검색어가 있으면 '파일명 검색 중'과 표시한 결과 수를 보여준다.
전체 건수 계산이 끝나지 않았다면 '50개 표시 · 더 있음'처럼 표현한다.
파일 결과 수와 연결 업무 수는 구분하며, 첫 페이지 수를 전체 건수처럼 표시하지 않는다.

```text
[첨부파일 v] [ 견적                         x ]

첨부파일 찾기                    [업무로 돌아가기]
전체 기간 · 완료/보관 포함
[파일 종류: 전체 v] [추가 조건]
"견적" 파일명 검색 중 · 2개 파일        [검색 해제]
-------------------------------------------------
📄 9월_장비견적서.xlsx
   장비 구매 검토 · 완료 · 9/14 첨부 · 42 KB
📄 수정견적서.pdf
   거래처 계약 · 진행 · 9/22 첨부 · 180 KB
-------------------------------------------------
선택: 9월_장비견적서.xlsx
[파일 열기] [연결 업무] [첨부 관리]
```

각 파일은 파일명 한 줄과 업무·상태·첨부일·크기 한 줄로 표시한다.
행마다 버튼을 넣지 않고 선택 파일에 대한 하단 액션 3개를 둔다.
긴 파일명은 말줄임하고 툴팁 및 선택 상세에서 전체 이름을 확인한다.
작은 창에서 메타데이터는 줄이되 파일명과 주요 동작이 잘리지 않도록 한다.

추가 조건을 펼쳤을 때만 첨부일 기간과 '휴지통 업무 포함', '정리 대기 파일 포함'을 보여준다.
기간은 업무 시작일·완료일이 아니라 파일을 등록한 날짜이며 양 끝 날짜를 포함한다.
검색 모드를 다시 들어오면 추가 조건은 기본값으로 초기화한다.

### 2.3 검색 상태 전이

- 검색 대상을 바꾸면 입력한 검색어는 유지하고 선택·페이지·이전 결과를 초기화한다.
- 파일 모드 진입 전 업무 탭, 필터, 캘린더 월·선택 날짜를 복귀 문맥으로 보존한다.
- '업무로 돌아가기' 또는 '캘린더로 돌아가기'는 해당 문맥으로 돌아가며 검색어를 지운다.
- 사이드바 업무 메뉴와 캘린더를 누르면 해당 기본 모드로 이동하고 검색어를 지운다.
- 파일 모드의 '검색 해제'는 파일명과 추가 조건을 초기화해 최근 첨부 목록을 표시한다.
- 모드는 실행을 종료할 때 저장하지 않는다. 다음 실행은 기존 기본 업무 화면을 사용한다.
- Ctrl+K는 현재 모드의 검색창에 포커스를 둔다. Esc로 검색어를 삭제하지 않는다.
- 목록에서 Enter와 더블클릭은 선택 파일을 연다. 단순 선택은 파일을 열지 않는다.
- 추가 조건을 접어도 활성 조건 수와 기간 요약을 표시해 숨은 필터를 알 수 있게 한다.

## 3. 결과와 파일 상태

| 상황 | 기본 검색 | 결과 동작 |
|---|---|---|
| 정상 연결 파일 | 포함 | 파일 열기, 연결 업무, 첨부 관리 |
| 완료·보관 업무의 파일 | 포함 | 상태 표시 후 동일 동작 |
| 휴지통 업무의 연결 파일 | 제외 | 포함 옵션 선택 시 표시, 업무/첨부는 기존 읽기 전용 규칙 |
| 연결 해제된 정리 대기 파일 | 제외 | 포함 옵션 선택 시 표시, 파일 열기와 정리 화면 이동 |
| 휴지통 업무의 정리 대기 파일 | 제외 | 두 포함 옵션을 모두 켠 경우만 표시 |
| 누락이 확인된 파일 | 포함 | '파일 누락' 표시, 업무 확인 가능, 열 때 다시 존재 여부 확인 |
| DB 연결 정보 없는 고아 파일 | 제외 | 기존 데이터 관리의 첨부 정리에서 확인 |
| 검색 후 파일이 영구 삭제됨 | 조회 시 없으면 제외 | 열기 직전 재조회, 삭제 안내 후 해당 행 갱신 |

같은 이름의 파일도 첨부 ID가 다르면 별도 결과다. 소속 업무를 함께 표시해 구분한다.
정리 대기 파일의 '연결 업무'는 원래 업무 확인을 뜻하며 파일이 연결된 상태처럼 표현하지 않는다.
파일 검색 페이지에서 영구 삭제·완료 처리를 직접 제공하지 않는다. 기존 관리 화면을 이용한다.

파일 열기는 기존 AttachmentService.path_for_open과 경로 검증을 사용한다.
저장소 내부 경로를 파일명에서 새로 만들지 않는다. 탐색기 이동이 필요하면 기존 관리 동작을 재사용한다.
파일이 없거나 접근이 거부됐을 때는 검색 화면을 유지하고 해결 가능한 오류 메시지를 표시한다.
검색 시 파일 존재 확인·체크섬 검사를 전체 파일에 수행하지 않는다. 누락 상태는 확인된 정보만 표시한다.

## 4. 검색 의미

- 파일명 중간의 문자열을 찾는다. '9월업무보고서_최종.xlsx'는 '보고서', '보고', '최종', 'xlsx'로 찾는다.
- 영문 대소문자를 구분하지 않는다. 한글 초성·오타 보정·띄어쓰기 제거 검색은 첫 범위에 넣지 않는다.
- 앞뒤 공백은 제거하고 공백으로 구분된 여러 검색어는 모두 같은 파일명에 있어야 한다.
- '견적 최종'은 두 단어가 한 파일명에 있는 경우에만 파일 결과가 된다.
- 파일명 검색은 2글자 이상부터 실행한다. 한 글자는 '파일명은 2글자 이상 입력해 주세요'로 안내한다.
- 기존 업무/일정/업무일지의 한 글자 본문 검색은 유지한다. 이때 파일명 매칭은 수행하지 않고
  안내에 '첨부파일명은 2글자부터 검색'을 표시한다.
- '%', '_', 따옴표와 하이픈은 검색 문법이 아니라 입력한 글자 그대로 처리한다.
- 업무 통합 검색은 기존 제목/내용 조건 OR 파일명 조건이다. 서로 다른 파일이나 본문에 나뉜
  단어를 합쳐 매칭하는 새 규칙은 도입하지 않는다.
- 제목만 일치한 경우 '파일명 일치' 표시는 붙이지 않는다.

## 5. 데이터와 구현 경계

### 5.1 조회 계약

애플리케이션 계층에 AttachmentSearchQuery, AttachmentSearchHit, AttachmentSearchPage를 둔다.

- Query: 검색어, 파일 종류, 첨부일 범위, 휴지통/정리 대기 포함 여부, 페이지 커서, limit=50.
- Hit: 첨부 ID, 업무 ID·제목·상태·휴지통 여부, 원래 이름, 크기, 첨부 시각, 누락/정리 대기 상태.
- Page: 결과, 다음 커서, has_more, 선택적인 정확한 total, 요청 식별자.

검색 결과는 읽기 전용 DTO로 전달하고 실제 파일 경로는 사용자가 열 때만 서비스에서 구한다.
정렬은 첨부 시각 내림차순, ID 내림차순이다. 파일명으로는 정렬하지 않는다.
다음 페이지는 마지막 created_at/id를 커서로 사용하고, 같은 시각의 파일도 안정적으로 구분한다.
첨부 변경·업무 이동·복원·삭제 알림을 받으면 조회를 무효화하고 첫 페이지부터 갱신한다.
선택 파일이 남아 있다면 선택을 유지하며 제거됐으면 선택과 액션을 해제한다.

### 5.2 파일명 색인

attachments.original_name은 그대로 보존하고 별도 FTS5 trigram 색인을 추가한다.
기존 unicode61 업무 색인은 유지한다. 일반 접두어 검색을 파일명 검색에 그대로 적용하지 않는다.

3글자 이상 검색어는 trigram 후보 검색과 실제 부분 문자열 일치 검사로 처리한다.
2글자 검색어나 색인으로 좁힐 수 없는 조건은 DB 파일명 문자열 비교로 처리한다.
여러 단어가 있으면 긴 단어로 후보를 좁히고 짧은 단어를 포함한 모든 조건을 최종 검증한다.
FTS 표현은 입력을 안전하게 인용해 구성하고 SQL 값은 바인딩한다.
부분 문자열 비교에는 instr 등을 사용해 '%'/'_'가 와일드카드가 되지 않도록 한다.
LIKE의 ESCAPE 절이 trigram 색인 사용을 막는 점을 고려해 구현 시 실행 계획을 확인한다.

3글자/2글자 경로의 영문 대소문자·특수문자 일치 의미가 같아야 한다.
trigram은 일부 검색을 빠르게 만들지만 모든 짧은 검색의 성능을 보장하지 않는다.
DB 조회·후보 검증을 워커에서 수행하고 파일 바이트를 읽지 않는다.

새 마이그레이션에서 기존 파일명을 색인하고 첨부 추가·이름 변경·삭제에 대한 동기화 트리거를 둔다.
휴지통/정리 대기 여부는 검색 시 attachments/tasks와 결합해 판정한다.
해제된 파일도 색인에는 남겨 복원 시 검색에서 누락되지 않게 한다.
영구 삭제 시 색인 행을 삭제하며 고아 색인 및 색인 누락을 검증한다.

업무 검색은 파일명 일치 첨부의 task_id를 EXISTS/IN으로 결합한다.
여러 파일이 일치해도 업무 결과 개수와 페이지에 같은 업무가 중복되지 않아야 한다.
업무일지의 파일명 매칭 위치 표시는 검색 조건과 같은 판정 함수를 사용한다.
Python 필터링만으로 페이지를 걸러 total/has_more가 틀어지게 하지 않는다.

### 5.3 주요 변경 위치

| 계층 | 변경 |
|---|---|
| Application | 첨부 검색 계약·서비스, 업무별 매칭 파일 요약 |
| Infrastructure | 첨부 검색 repository, 파일명 검색 조건 공통화, 색인 마이그레이션 |
| 기존 Repository | 업무·캘린더·업무일지 검색에 첨부 조건 결합 |
| Presentation | 검색 대상 선택, 파일 검색 페이지·모델, 업무 매칭 표시 |
| 기존 첨부 화면 | attachment_id로 특정 파일을 선택해 열 수 있도록 확장 |
| Bootstrap | 검색 서비스 연결, 워커와 DB 연결 수명 관리 |

메인 창에 SQL 또는 파일 검색 로직을 추가하지 않고 별도 페이지/모델로 분리한다.
첫 구현에 외부 검색 서비스나 새로운 상주 프로세스를 추가하지 않는다.

## 6. 응답성·알림·메모리

- 입력 디바운스는 기존 메인 검색과 같은 250 ms로 한다.
- 전용 검색 워커를 한 개만 사용하고 진행 중 요청 뒤에는 최신 요청 하나만 대기시킨다.
- 요청 ID를 비교해 오래된 검색 결과가 새 검색어나 이동한 페이지에 적용되지 않게 한다.
- 검색 취소와 쿼리 시간 제한은 워커 전용 SQLite 연결에서 지원한다.
- 취소/시간 제한은 '검색이 완료되지 않았습니다'로 구분하며 '결과 없음'으로 표시하지 않는다.
- limit+1 조회로 더 있음 여부를 얻는다. 첫 구현은 별도의 전체 건수 쿼리를 실행하지 않고
  실제 표시 결과 수와 더 있음 여부만 유지한다. 정확한 전체 건수는 탐색에 필수적이지 않아 보류한다.
- 모델에는 메타데이터만 담고 한 검색에서 최대 500개까지만 유지한다.
  50개씩 추가로 읽고 500개에 도달하면 이전/다음 500개 결과 구간으로 이동한다.
  구간 이동 시 이전 행을 해제하고 화면에 현재 구간을 표시한다.
- 파일 내용·썸네일·전체 업무 설명을 검색 결과에 캐시하지 않는다.
- 검색 페이지에 모달/최상위 창을 추가하지 않는다. 알림 폴링과 처리를 계속 허용한다.
- '첨부 관리'로 연 기존 대화상자와 알림의 클릭 우선순위는 별도 UI 회귀 기준으로 확인한다.
- 창 종료 시 검색 취소와 워커 종료 후 DB 연결을 정리한다.

성능 목표는 수용 기준이지 현재 측정 결과가 아니다.
합성 데이터 업무 5,000건/첨부 50,000건에서 3글자 검색 첫 페이지 조회 p95 300 ms,
2글자 검색 p95 1초 이내를 목표로 하며 디바운스와 렌더링 시간은 별도로 측정한다.
추가 검색 데이터의 메모리는 500행 유지 시 20 MB 이하를 목표로 한다.
초기 색인 작성 시간·DB 증가량, 결과 없음/흔한 단어/기존 업무의 전체 건수 포함 쿼리도 함께 측정한다.
목표 미달 시 쿼리/색인을 먼저 조정하고 사용자에게 부분 결과를 전체 결과처럼 표시하지 않는다.

## 7. 업데이트·백업·복구

첫 실행의 기존 DB 업그레이드에서 파일명 색인을 자동 생성한다. 사용자는 DB를 옮기지 않는다.
원래 파일명, 파일 경로, 첨부 바이트와 연결 업무는 변경하지 않는다.
색인은 재생성 가능한 파생 데이터다. 재색인은 실패 시 롤백하고 원본 첨부 데이터를 보존한다.

실제 구현 시 스키마 변경 전 SQLite 온라인 백업으로 DB 보호 사본을 만든다.
파일 바이트를 변경하지 않는 마이그레이션이므로 보호 사본 작성에 전체 첨부 복사를 요구하지 않는다.
업그레이드 전 사용자가 만드는 기존 .ofbackup은 DB·첨부·설정 전체 복구 수단으로 유지한다.
대량 DB의 초기 색인은 진행 상태를 표시하고 성공 후 검색을 활성화한다.
새 색인 생성에 필요한 디스크 공간과 실패 시 다음 실행의 재시도 동작을 검증한다.

기존 백업 복원은 DB 복원 후 스키마 업그레이드가 실행되는 현재 순서를 사용한다.
이미 이전한 업무 및 최신 백업 복원에서도 첨부 검색과 파일 열기가 유지되는지 시험한다.
새 스키마에서 예전 앱 실행 가능 여부는 별도 확인하며, 검증 없이 다운그레이드를 안내하지 않는다.
검색어·파일명·업무 제목을 진단 로그에 기록하지 않는다.

## 8. 수용 기준

1. 업무 제목에 없는 파일명으로 완료 업무와 연결 파일을 전체 기간에서 찾을 수 있다.
2. '9월업무보고서_최종.xlsx'가 '보고서', '보고', '최종', 'XLSX'에 일치한다.
3. 두 검색어가 서로 다른 파일에 나뉘어 있으면 파일명 조건에 일치하지 않는다.
4. '%'/'_'/따옴표 입력은 문자 그대로 검색되고 SQL/FTS 오류가 발생하지 않는다.
5. 기존 업무 필터·오늘 그룹·캘린더 날짜·업무일지 기간 규칙이 유지된다.
6. 같은 업무의 파일 여러 개가 일치해도 업무 결과는 한 개, 파일 결과는 각 첨부별 한 개다.
7. 휴지통/정리 대기 포함 옵션과 읽기 전용 동작이 표의 규칙과 일치한다.
8. 누락·삭제·접근 거부 상황에서 프로그램이 종료되지 않고 검색 화면이 유지된다.
9. 추가·연결 해제·복원·업무 이동·영구 삭제 직후 결과가 갱신된다.
10. 빠른 타이핑·화면 전환·앱 종료 시 오래된 응답과 워커가 남지 않는다.
11. 검색 및 첨부 관리 중 알림이 표시되며 양쪽 창의 동작을 클릭할 수 있다.
12. 760×560, 960×640과 100%/150%/200% 배율에서 컨트롤이 잘리지 않는다.
13. 3.0.2 DB 업그레이드, 기존 백업 복원, 이미 이전한 데이터에서 검색과 첨부 열기가 정상이다.
14. 대량 데이터 성능·추가 메모리·색인 용량 측정이 기록된다.

## 9. 구현 순서

1. 검색 계약·부분 문자열 판정·파일명 색인과 마이그레이션 검증.
2. 첨부파일 모드와 전체 기간 검색·선택 파일 열기·연결 업무 흐름 완성.
3. 기존 업무/일정/업무일지 검색 연동과 매칭 위치 표시.
4. 대량 데이터·작은 창·알림 동시 사용·백업/복원 회귀 검증.
5. 사용자 도움말과 변경 기록 갱신 후 배포 여부 결정.
