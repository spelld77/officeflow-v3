# 보관함 페이지 이동·여러 파일 삭제 상세설계

2026-10-09. 구현 전 작성. 운영 자료·배포·버전·커밋/업로드는 포함하지 않는다.

## 1. 페이지 이동

- 보관본 50개, 현재 첨부 100개를 유지하되 조회 시 다음 존재 확인용 한 행만 더 가져온다.
- 첫 페이지이며 다음 자료가 없으면 이동 영역 전체를 숨긴다.
- 여러 페이지면 `이전 페이지 / n페이지 / 다음 페이지`를 별도의 작은 영역에 표시한다.
  첫 페이지 이전, 마지막 페이지 다음은 비활성화한다. 빈 페이지로 이동하지 않는다.
- 종류/계열 변경 시 첫 페이지로 초기화. 마지막 페이지 자료 삭제/외부 변경으로 비었으면
  직전 유효 페이지로 돌아온다. 파일 전체 조회/COUNT·전체 바이너리 적재는 하지 않는다.
- 기존 체크 저장 선택은 페이지 이동 후에도 유지한다.

## 2. 여러 파일 선택 삭제

- 현재 첨부의 Ctrl/Shift 선택 → 오른쪽 클릭/더보기 `선택 N개 삭제…`.
- 보관함의 Ctrl/Shift 선택 → `선택 항목 삭제…`. 현재 페이지에서 파란색으로 선택한 항목만 대상이다.
  보관함의 체크는 기존의 페이지 간 외부 저장 선택이며 삭제에 자동 포함하지 않는다.
  툴팁/도움말 및 삭제 대상 목록에서 이 구분을 명확히 한다.
- 읽기 전용/휴지통 업무, 진행 중 작업은 변경할 수 없다. 빈 선택은 실행하지 않는다.
- 확인창에는 선택한 파일명 목록(스크롤), 총 첨부/보관본 수, 중복 제거한 실제 삭제/유지 파일 수,
  남는 보관본·외부 사본/백업 유지·되돌릴 수 없음 안내를 표시한다. 확인 체크와 취소를 제공한다.
- 선택 단위는 한 업무의 attachment/version ID 최대 100개다. 중복 ID·다른 업무·없는 ID는 거절한다.
  한 개 선택은 기존 단일 삭제 계약을 그대로 사용한다.

## 3. 공통 삭제 명령 보완

- 기존 DeleteTarget(kind,id)는 구조/직렬화/지문을 바꾸지 않는다.
- 별도의 DeleteSelection(kind=selection,id=업무ID,items=선택 DeleteTarget tuple)을 추가한다.
  DB 이행은 없다. 같은 DeletePlan/Command/Receipt와 격리/복구 엔진을 재사용한다.
- repository의 selection 계획은 선택 항목 전체와 해당 자산의 모든 보존 참조를 하나의 스냅샷에서 읽는다.
  공유 자산은 한 번만 격리하고 선택 밖의 참조가 있으면 물리 파일을 유지한다.
- 모든 대상이 현재 업무에 속하며 살아 있는지 확인한다. 이름/역할/revision/참조가 확인 후 바뀌면 거절한다.
- 선택의 모든 물리 파일 준비 후 첨부/보관본 연결 삭제·자산 상태·영수증을 한 트랜잭션으로 확정한다.
  한 파일 잠금/격리 실패/취소/DB 실패 시 확정 전 선택 전체를 복구한다. 부분 완료를 성공으로 알리지 않는다.
- 확정 후 정리 실패는 기존 pending 표시·재시작 정리로 처리한다. 같은 작업 ID는 중복 삭제하지 않는다.
- 기존 저널 target(kind,id)와 새 selection target을 명시적으로 분리하여 읽는다.
  알 수 없는 종류/키/중복/중첩 selection/task 포함은 보존 후 거절한다.

## 4. 검증

- 0/2/정확히 50·100/경계+1 항목의 페이지 이동 표시, 다음/이전·필터 초기화·끝 페이지 삭제.
- 첨부 두 개 삭제, 첨부+보관본 혼합, 원본/작업본과 보관 내용 유지, 공유 frozen의 선택 안/밖 참조.
- 선택 파일 하나 잠금/내용 메타데이터 변경/취소/DB 실패 시 전체 유지, 단일 형식 지문 호환.
- 실제 별도 프로세스 종료 후 확정 전 복원/확정 후 정리, 같은 명령 재시도.
- 두 화면에서 다중 선택과 메뉴/확인창/취소/휴지통 보호, 체크 저장 선택이 삭제에 섞이지 않음.
- 영향 화면의 밝은 스타일, 어두운 palette/좁은 창/배율별 목록·버튼 확인.

## 5. 실제 구현·검증 결과

### 구현

- Catalog의 keyset 조회에서 한 행만 추가 조회하여 `has_next`를 전달한다.
  기존 `page()` 반환 형식은 유지한다. 보관함의 페이지 영역을 액션 버튼과 분리했다.
- 첨부 화면의 오른쪽 클릭/더보기와 보관함 삭제를 공통 `delete_many`로 연결했다.
  확인창에 일반/원본/작업본/보관본 구분과 전체 파일명을 스크롤 목록으로 표시한다.
  취소하면 선택과 파일을 그대로 유지한다. 한 개는 기존 단일 명령을 사용한다.
- `DeleteSelection`을 기존 단일 대상과 별도로 추가하고 DB 확정/저널 읽기/중단 복구가
  선택을 한 단위로 취급하도록 했다. 기존 `DeleteTarget(kind,id)` 직렬화와 지문은 그대로다.
  선택 밖의 공유 참조가 있으면 파일을 지우지 않는다. DB 스키마 변경은 없다.
- 사용자 안내에 페이지 크기, 저장 체크와 삭제 선택 구분, 잠금/충돌 시 전체 보류를 추가했다.

### 검사

운영 프로필/실제 편집기 대신 ignored `.test-tmp`와 합성 자료만 사용한다.

- 수정 전 관련 17개 회귀가 실패하는 것을 확인한 뒤 구현했다. 중간 실패 실행은 통과로 계산하지 않는다.
- 첫 관련 범위 검사 98개 / 74.26초 통과, 추가 경계·혼합 선택·체크 저장 구분까지 21개 / 40.22초 통과.
  두 실행은 중복 범위가 있으므로 합산하지 않는다. 이후 확인 취소/읽기 전용 검사도 추가했다.
- 실제 별도 프로세스를 9개 중단 시점에서 종료한 단일/다중 삭제 복구를 검증한다.
  선택 파일 모두 확정 전 복구, 확정 후 남은 정리, 같은 명령 재시도를 포함한다.
- 실제 Windows renderer, 밝은/어두운 Window/Base·검은 Text palette, 100%·150%·200% 배율 6조합에서
  작은 보관함/첨부 창·두 파일 선택·긴 이름 확인창·첫/마지막 페이지를 캡처했다.
  목록 viewport 150 logical px 이상, 버튼 좌표 접근, 한 페이지 이동 숨김·마지막 다음 비활성,
  확인 취소 후 두 파일 유지 검사를 통과했다. 대표 캡처를 직접 확인했다.
  캡처/재현 실행기는 `.test-tmp/paging-delete-visual-*`와 `.test-tmp/paging-delete-visual.py`에 있다.
- Ruff 전체 검사, mypy 101개 소스, `git diff --check` 통과.
- 확인 취소/읽기 전용 추가 검사 3개 / 0.56초 통과.
- 최종 분리 전체 검사: UI **302개 / 112.15초**, integration+unit **610개 / 137.39초**,
  performance **4개 / 3.08초** — 합계 **916개 통과**. 같은 소스 상태에서 모든 검사 디렉터리를 포함한다.
- 단일 프로세스 전체 검사는 기존 `test_today_reminders_independent_of_task_filters_and_overflow`
  부근에서 장시간 대기하여 정확히 확인한 테스트 프로세스만 중단했다. 이 실행은 전체 통과로 계산하지 않는다.
  해당 검사 단독 **1개 / 0.45초**, 진단 타임아웃을 켠 UI 전체 302개에서는 정상 종료했다.
  연속 전체 실행의 일시 대기 원인은 재현/확정하지 못했으며 분리 통과로 원인이 해결되었다고 하지 않는다.
  같은 현상 재발 시 타임아웃 stack/실행 순서를 수집하는 별도 점검 항목으로 남긴다.
- 이번 실행이 생성한 `paging-delete-full`, `paging-delete-non-ui-final` 두 대용량 fixture만
  절대 경로·reparse 부재를 재확인하고 정리했다(합계 약 16.4GiB). 테스트 재실행으로 재생성할 수 있다.
  UI 검증 자료·캡처·실행기 및 운영 자료는 유지했다.

회사 DRM/실제 한글·Excel 편집기의 저장/잠금, 시스템 테마 live 전환, 장기간 운영까지
이번 합성 자료 검사로 확인했다고 하지 않는다. 운영 첨부·DB·배포물·커밋/원격 업로드는 변경하지 않는다.

### 사용 재확인

프로그램을 트레이에서도 종료한 뒤 `run-officeflow-dev.cmd`로 다시 실행한다.
공개 EXE/ZIP에는 아직 이 수정이 없다. 중요한 운영 파일 대신 불필요한 시험 첨부로 확인한다.

1. 보관함에 첨부 두 개만 있으면 이전/다음이 표시되지 않는지 확인한다.
2. 첨부 목록에서 Ctrl/Shift로 두 개 선택 → 오른쪽 클릭/더보기 `선택 2개 삭제…`.
   확인창에서 두 이름/범위를 확인하고 취소하면 그대로 남는지, 확인하면 둘 다 사라지는지 확인한다.
3. 보관함은 현재 페이지의 강조 선택 → `선택 항목 삭제…`를 사용한다.
   외부 저장용 체크는 삭제 대상이 아니다. 선택하지 않은 보관본은 유지된다.
