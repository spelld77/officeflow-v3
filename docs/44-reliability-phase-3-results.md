# 달력·오늘 알림 묶음 3차 구현·검증 보고

작성: 2026-10-10. 상태: 상세설계·소스 구현·격리 테스트 완료, 사용자 사용 확인 전.
[43번 상세설계](43-reliability-phase-3-design.md) / [38번 공통설계](38-reliability-common-design.md).
2차 사용 확인 뒤 승인받은 U1 표시 개선이다. 기존 파일/알림 처리 계약은 유지한다.

## 반영한 동작

- 달력 하단에서 같은 업무·원래 반복 회차의 일정과 다중 알림을 한 줄로 합친다.
  그날 일정이 없으면 `[알림만]`으로 노출한다. 일정 없는 업무의 선택 상세에 가짜 날짜를 넣지 않는다.
- 오늘 알림도 업무·회차별 한 줄이다. 2~3행의 미리보기를 한 업무가 독점하지 않는다.
  오늘 업무 목록과 알림 영역은 역할이 달라 둘 다 유지하며 업무 검색/필터로 알림을 숨기지 않는다.
- 업무 묶음 수와 실제 알림 건수를 구분한다. 미확인/예정/발생 기록 확인 필요/처리 이력의
  원래 상태를 보존하며 완료한 업무와 확인한 개별 알림을 같은 상태로 합치지 않는다.
- 선택한 묶음의 `알림 시각 보기`에서 개별 날짜·요일·시각·상태를 확인한다.
  각 행 툴팁은 원래 예정·재알림·최근 발생을 보여 준다. 알림 시각 창과 오늘 전체 보기는
  비모달이며 100행씩 페이지로 표시한다. 부모 종료 때 연결 창도 닫는다.
- 더블클릭·기록·첨부·오른쪽 메뉴·알림 설정은 원래 업무/정확한 회차로 연결한다.
  반복의 공통 날짜 지정 알림과 특정 회차, 서로 다른 업무 ID는 제목이 같아도 합치지 않는다.
- 일정이 늦게 도착해 알림만 행이 일정+알림으로 바뀌어도 선택 키를 유지한다.
  열린 시각 창은 최신 결과를 반영하고 알림이 사라지면 행동 버튼을 비활성화한다.
- 긴 제목은 한 줄 생략/툴팁을 사용하며 첨부 표시는 행 앞에 남긴다.
  새 창·목록·선택·스크롤 색을 밝은 스타일로 명시했다.
- 실제 캡처에서 좁은 달력의 세 번째 행과 하단 안내가 겹치는 것을 발견해 보완했다.
  하단 최소 높이를 실제 레이아웃으로 계산하고 낮은 창의 달력 도구줄/격자를 줄인다.
  작은 셀의 일정/알림 개수는 서로 다른 클릭 영역으로 배치한다. Markdown/HTML 도움말도 갱신했다.

## 실제 수행한 검사

| 검사 | 최종 결과 |
| --- | --- |
| 단위·통합·성능 전체 | 709개 통과, 153.29초 |
| UI 전체 재검사 | 365개 통과, 150.05초 |
| Ruff / mypy | 통과, 소스 123개 타입 검사 |
| git diff --check | 통과 |

최종 광범위 회귀는 총 **1,074개**다. 중간·관련 재검사는 중복이므로 합산하지 않는다.
신규 3차 단위/통합/UI는 27개(그중 렌더링 6개)다. 기존 여러 알림 UI의 세 검사에서
5개 알림=5행이었던 기대를 1개 업무 묶음=1행으로 갱신했다. 알림별 확인/재알림/회차 완료
검사는 기존 처리 계약 그대로 통과했다.

격리 SQLite에서 상대+절대 알림 혼합, 같은 날 서로 다른 반복 회차/공통 알림, 기간 일정,
다른 날 재알림과 원래 날 이동 이력, 완료/확인 이력 분리, 조회 전후 delivery 행의 무변경을 확인했다.
UI는 일정 지연 도착/선택 유지, 검색 독립성, 기록/첨부/알림 설정 연결, 열린 창 갱신/종료,
긴 제목, 부분 조회, 250건/250묶음의 100행 페이지와 작은 셀 hit 영역 분리를 확인했다.
날짜/월 경계·반복 일정·대량 업무의 기존 회귀도 전체 검사에 포함했다.

Qt offscreen 별도 프로세스에서 Windows 글꼴과 밝은/어두운 palette,
100/150/200% scale로 주창 760×560 및 시각 창 460×340을 렌더링했다.
밝은 viewport, 버튼 접근, 달력 최소 3행, 하단 범위/안내 비겹침을 검사하고 캡처를 직접 검토했다.
결과는 Git 제외 `artifacts/reliability-phase3-visual/`에 있다.
실제 Windows 테마/DPI 설정을 변경한 실기 검사는 아니다.

최종 전체 UI 첫 재실행에서 기존 첨부 정보 테스트 부근에 한 번 대기가 발생했다.
해당 검사 실행은 중단했고 기존 첨부 정보 9개는 별도 재실행에서 모두 통과했다.
진단 타임아웃을 켠 전체 UI 재실행도 365개 통과했다. 간헐 대기의 원인은 확정하지 않았으며
이를 새 묶음 기능의 오류 또는 해결된 프로그램 버그로 단정하지 않는다.

## 제한과 보존

- 알림 팝업은 묶지 않는다. 개별 확인/재알림과 업무/회차 완료는 기존 동작 그대로다.
  미리보기/시각 조회 자체로 알림을 발생·확인·완료 처리하지 않는다.
- 오늘 전체 보기/개별 시각 창은 표시 100행 상한이다. 읽기 전용 조회의 예산/상한은 기존대로다.
  달력 선택 날짜는 기존 전체 일정 조회/스크롤을 유지한다. 같은 날 매우 많은 **고유 업무/회차**가
  쌓이면 그룹화만으로 행 수를 줄이지 못한다. 이 경우의 달력 페이지화는 이번에 추가하지 않았다.
- 실제 회사 DRM, 실제 알림 발생 시각의 장시간 실기, 모든 문서 앱/OS 환경은 별도 확인 대상이다.
- DB 0015, 백업 v3, 버전 3.0.8과 파일 보존/삭제/백업 계약은 변경하지 않았다.
  운영 프로필과 `.local-data`를 테스트에 사용하지 않았다.
  EXE/설치파일/ZIP 재생성·커밋·GitHub 업로드도 하지 않았다.

## 사용자 확인

개발본을 완전히 종료하고 `run-officeflow-dev.cmd`로 다시 실행한다.

1. 같은 업무에 오늘 일정과 여러 알림이 있으면 달력 하단이 한 줄인지 확인한다.
2. 일정이 다른 날인 업무도 오늘 알림/달력에 `알림만`으로 보이는지 확인한다.
3. 묶음 선택 → `알림 시각 보기`에서 개별 시각·상태와 기록/첨부 동선을 확인한다.
4. 좁은 창에서 달력 아래 세 행·스크롤 안내·목록 확대가 보이는지 확인한다.

사용 확인 뒤 마감/커밋/배포가 필요하면 별도 요청으로 진행한다. 다음 차수를 자동 시작하지 않는다.
