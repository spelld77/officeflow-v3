# 첨부 썸네일 구현·검증 결과

배포 후속 기록: 2026-10-11 사용자 요청으로 3.0.10에 포함한다. 이 문서의 미배포 표기는 작성 당시 기록이며
최신 검증·GitHub 공개 결과는 [3.0.10 릴리스 체크리스트](59-release-checklist.md)를 따른다.

작성일: 2026-10-10. 대상: 공개 3.0.9 이후 개발 소스.
사용자의 `구현 및 테스트를 진행해` 요청으로 [53번 상세설계](53-attachment-thumbnail-design.md)를 적용했다.
기존 미커밋 변경을 보존했고 실제 사용자 DB/첨부/클립보드, 버전, EXE/설치 파일/ZIP,
Git 커밋·GitHub 업로드는 변경하지 않았다. 이후 사용자가 확인했으며 상단 순서 버튼의 제거를 요청했다.

## 1. 실제 반영

- 기존 업무 보기의 첨부파일 탭에서 `목록 / 썸네일`로 전환한다. 기본/최소 창에서 보통 2열,
  넓으면 최대 4열이다. 카드 폭 176~240 DIP, 그림 높이104 DIP, 파일명/역할 각1줄이다.
- 같은 QListWidget의 ID·순서·현재 선택·다중 선택을 유지한다. 전환/갱신은 보이는 첨부 ID로
  위치를 복원하며 기존 더블클릭 외부 열기·오른쪽 메뉴의 순서 변경·끌어놓기·저장/삭제를 유지한다.
- 일반/원본/작업본, 필요한 짧은 상태/메모 여부를 표시한다. 긴 이름은 가운데 생략하며
  전체 정보/읽기 실패 이유는 툴팁·정보에서 확인한다. 세로 스크롤바는 항상 표시한다.
- 상시 미리보기 버튼은 표시하지 않는다. 단일 사진의 오른쪽 메뉴/더보기 `이미지 확대…`는
  비모달 읽기 전용 창이다. 새 업무의 클립보드 사진 확인 동선은 유지한다.
- 마지막 보기 방식은 공통 설정에 저장한다. 이미 열린 다른 창은 바꾸지 않는다.
  새 설정만 손상되면 목록으로 복구하고 기존 백업/위치 설정을 보존한다.
  저장 실패는 이번 선택을 유지하며 주 화면에 비모달로 알린다.

## 2. 파일·자원·종료 계약

- PNG/JPG/JPEG/BMP 후보만 실제 형식/크기를 확인한다. 문서는 종류 표시만 그린다.
  파일64 MiB/16,000,000픽셀 제한과 Qt 자체 할당 제한을 유지한다.
- 공통 소유자의 지속 worker 하나로 저장 첨부 썸네일/확대를 순차 처리한다.
  GUI가 결과를 처리한 뒤 다음 읽기를 시작한다. 동일한 동시 요청은 합치고 확대를 우선한다.
- 자동 썸네일은 파일 서비스의 background 슬롯을 사용하여 명시적인 파일 작업에 양보한다.
  선택 자산의 읽기가 실행 중이면 취소/종료 후 선택을 재확인하고 요청을 실행한다.
  기다리는 동안 다른 화면/알림을 모달로 막지 않는다. 예약/보호 핸들은 우회하지 않는다.
- 작은 그림 최대640×400 물리 픽셀. 공통 LRU는 실제 QImage32 MiB/64개 이내다.
  확대 출력도 같은 예산으로 관리하며 확대 창에 표시 중인 한 장/Qt 내부 버퍼는 별도다.
  목록 항목은 QImage/QWidget을 각각 소유하지 않는다.
- 대기32개, 한 창 대기 후보24개, 현재 가시 상태256개 이내다. 완료 뒤 가시 후보를 보충한다.
  부분 노출된 카드도 포함하는 공통 가시 헬퍼는 `O(log n + 보이는 수)`로 조회한다.
  스크롤/리사이즈는100ms 묶는다. 시작/목록/다른 탭/숨김/최소화에서는 새 사진을 읽지 않는다.
- 자산/상대 경로/고정 정책/목표 크기/확인 세대를 검사하고 늦은 결과를 버린다.
  같은 핸들의 stat 변화는 캐시 갱신 힌트다. 고정 원본은 재확인마다 해시를 검증한다.
  원본이 바뀌면 `원본 확인 필요`이며 수정된 보기 사본을 원본 사진으로 대체하지 않는다.
- 탭 재진입/포커스 복귀 시 가시 사진을 재확인한다. `썸네일 새로고침`은 해당 확인 세대의
  가시 사진 캐시를 무시한다. 일반 파일의 같은 stat로 저장된 변경은 자동 판별을 보장하지 않는다.
- 마지막 조회 창이 닫히면 큐/캐시를 해제한다. 앱 종료는 취소 후 native thread 종료까지
  소유권을 유지한다. 강제 terminate하지 않는다. 파일/DB/보기 사본/디스크 캐시를 생성하지 않는다.

## 3. 자동 검사와 수정한 문제

- 썸네일 기능24개: 선택·순서·외부 열기, 화면 밖 미읽기, 다음 창/재시작 설정,
  잘못된 설정6종/저장 실패, 원본/수정 보기 사본 구분/고정 해시,
  변경 후 재읽기/강제 갱신/이름만 변경 시 decode 재사용,
  누락/손상/권한의 인라인 오류와 무한 재시도 방지, 파일 명령 전 취소/GUI 타이머,
  큐/캐시 바이트·개수 상한,100/1,000첨부 가시 범위, 공유 요청 합치기/재확인,
  늦은 결과/창 종료, 다른 탭·숨김·최소화, 위치 기준/다중 선택/외부 드롭 설정을 검사했다.
- 새 시각/Windows 반복 검사5개와 기존 클립보드/확대37개를 함께 실행해 **66개 통과**했다.
- 150%/200% 각각4개 통과. 기본620×650/최소500×540와 밝음/어둠 제어 팔레트,
  긴 이름/투명·세로·가로 사진/문서/선택/버튼 경계/스크롤을 캡처했다.
  직접 확인한 최소100%와 기본200% 캡처에서 밝은 글자/배경과 카드 경계를 확인했다.
- 원본 변경 오류가 `없습니다`라는 문구 때문에 `파일 없음`으로 분류되는 실패를 발견해 수정했다.
  경로·원본 고정 정책을 요청 당시 값과 비교하도록 강화했다. 다중 선택 확대는 이전 사진을 지운다.
  명시적 파일 명령 재개가 확대 읽기를 먼저 재시작하지 않도록 했다.
- Ruff 전체 검사, 변경 파일 형식 검사, mypy134개 소스, `git diff --check` 통과.

전체 기본/화면 회귀의 최종 집계는 **1,250개 통과**다.

최종 결과 신호에서 구독 해제가 일어나도 안전하도록 통지 순서를 정리한 뒤

한꺼번에 실행한 화면 회귀는 기존 알림 확인창 검사에서 대기하여 정확한 격리 pytest 프로세스만 중지했다.

## 4. 실제 Windows 반복·메모리 측정

회사 자료가 아닌 합성 이미지/격리 프로필/별도 프로세스와 Windows Qt backend를 사용했다.
각 시험은 PNG/JPEG/BMP12개를 준비하고 두 창에서 보기 전환·복수 선택·스크롤·확대를6회 반복했다.
매회 종료 후 캐시0, worker 취소/마무리, 종료 코드0과 `NATIVE_THUMBNAILS_OK`를 확인했다.

| 합성 사진 크기 | 프로세스 시작 관측 | 프로세스 최고 working set | 전체 종료 직전 | 표시 시 캐시 | 시험 전체 최대 GUI 타이머 간격 |
| --- | --- | --- | --- | --- | --- |
|1920×1080|127.7 MiB|263.0 MiB|241.3 MiB|약3.16 MiB/2개|379.2ms|
|4000×4000(1,600만 픽셀)|128.5 MiB|369.2 MiB|240.7 MiB|약3.13 MiB/2개|891.5ms|

최고값은 파일 준비·decode/변환·창 생성·Qt 자원·테스트 자체가 포함된 **별도 프로세스 전체**의 관측값이다.
GUI 간격도 빠른 전환/창 생성/종료가 포함되며 decode만의 지연으로 분리하지 않았다.
창 닫은 뒤 QImage 캐시는0이지만 OS working set이 시작값으로 즉시 돌아오지는 않았다.
캐시 제한만으로 프로그램 전체를32 MiB라고 설명하거나 장기 메모리 누수가 없다고 단정하지 않는다.
큰 사진에서 순간 지연이 관측되었다. 회사PC 보안 제품·실제 모니터 DPI·다른 무거운 프로그램과의
동시 사용/장기 실행/OS 강제 종료는 이 시험으로 보장하지 않는다.

100/1,000개 검사에서는 실제 파일/SQLite 행을 격리 생성했다. UI 전용 fixture는 저장소/원장으로
준비하여 기존 추가 서비스의 누적 중복 검사를 시험 준비 시간과 분리했다.
최초 실제 추가 서비스로 준비한1,000개 검사도 가시 읽기/스크롤 검사는 통과했지만 전체 파일 생성이 오래 걸렸다.
썸네일은 전체 메타데이터 조회/모델 생성이 여전히 있다는 점을 숨기지 않는다.

## 5. 확인 방법·미포함

`run-officeflow-dev.cmd`로 격리 `.local-data`를 사용하는 개발 소스를 실행한다.
업무 보기 → 첨부파일 → 썸네일에서 여러 사진/문서를 확인하고 Ctrl/Shift 선택,
목록 전환·스크롤·더블클릭·다른 이름으로 저장·정보/메뉴·알림 독립 조작을 확인한다.
원본을 편집하면 보기 사본/작업본과 구분되며 원본 그림 자체는 바뀌지 않아야 한다.

배포/ZIP/설치 파일/버전/Git 작업, 전체 검색/보관함/외부 HTML 썸네일,
문서 본문 decode·OCR·디스크 캐시·추가 파일 자동 삭제는 범위에 포함하지 않았다.

## 6. 사용 확인 후 상단 버튼 간소화

사용자의 요청에 따라 `목록 / 썸네일` 아래의 상시 `위로 / 아래로` 버튼을 제거했다.
`파일 추가 / 클립보드 이미지`와 보기 전환은 유지한다.
첨부 하나를 오른쪽 클릭하면 `위로 / 아래로 / 맨 위로 / 맨 아래로`로 순서를 바꿀 수 있다.
순서 저장·다른 창 동기화·휴지통/작업 중 제한과 파일 처리 규칙은 변경하지 않았다.

- 관련 순서·썸네일·시각/Windows 반복·클립보드 시각 검사 **39개 통과**.
  이후 네 가지 오른쪽 메뉴 이동의 실행 검증을 강화해 순서 검사 **8개를 재실행해 통과**했다.
- 최소/기본 창과 밝음/어둠 제어 팔레트의 offscreen 캡처를 갱신했다.
  한글 글꼴을 적용한 최소500×540 캡처에서 버튼 제거와 글자/목록 경계를 직접 확인했다.
  회사PC의 실제 배율·보안 환경을 이번 시험으로 다시 검증한 것은 아니다.
- Ruff 전체 검사, 변경4개 파일 형식 검사, mypy134개 소스, `git diff --check` 통과.
- 이번 소규모 수정에 전체1,250개 회귀·150/200% 배율 검사를 다시 실행하지 않았다.
  이전 결과와 이번39개 검사를 합쳐 전체 회귀 재통과라고 계산하지 않는다.
- 실행 파일·배포 ZIP·버전·커밋·업로드는 변경하지 않았다.
