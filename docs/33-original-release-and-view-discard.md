# 원본 지정 해제·보기 사본 버리기 보완 상세설계

2026-10-09. 사용자 승인 후 구현 전에 작성. 상태: 소스 구현·검증 완료, 사용자 재확인 대기.
공통 계약 및 2차 상세설계와 함께 갱신한다. 운영 데이터/배포/Git 작업은 포함하지 않는다.

## 1. 원본 지정 해제

- 첨부 한 개의 오른쪽 메뉴/더보기 `원본 지정 해제…`. 살아 있는 업무의 현재 원본에만 허용한다.
- 확인창: 같은 첨부를 편집 가능한 일반 첨부로 전환하며 해제 전 내용을 보관함의
  `원본 해제 전 내용`으로 남긴다고 안내한다. 수정된 보기 사본은 별도 보존/버리기 대상이다.
- `release_original` 명령은 현재 원본의 fixed 크기/해시를 확인하며 독립 mutable 파일을 캡처한다.
  고정 파일에 쓰기 권한을 주거나 제자리에서 역할만 바꾸는 명령이 아니다.
- 기존 내부 저널/사용 예약/작업 스레드/취소/새 경로 공개/완료 영수증 절차를 재사용한다.
- 한 DB 트랜잭션: 새 mutable 자산 생성, 이전 frozen 자산을 같은 계열의 새 보관본에 연결,
  같은 첨부 ID를 새 자산 + general 역할로 전환, revision 증가, 보관 순번 증가, 완료 영수증 저장.
- 현재 표시명/최초 이름/메모/순서/계열/최초 첨부 해시·크기와 출처 링크는 유지한다.
  보관본에는 해제 당시 파일명·메모·원본 출처 payload를 남긴다. 기존 작업본/보관본을 바꾸지 않는다.
- 결과는 현재 attachment_id와 retained_version_id를 가진다. 기존 영수증에는 새 선택 필드가
  없어도 읽을 수 있다. 같은 작업 ID 재시도는 보관본/편집 파일을 중복 생성하지 않는다.
- 잠금/손상/취소/DB 충돌 시 원본과 보기 사본을 유지한다. 중간 종료는 기존 미확정 복구 정책을 따른다.
- 해제 전 원본 보관본은 일반 보관함에서 조회/보기/작업본 생성/외부 저장 가능하다.
  편집 파일을 삭제해도 유지하며 명시적인 보관본 삭제나 업무 영구 삭제만 별도로 처리한다.
- 새 DB 테이블/이행은 없다. 전체 백업은 기존 자산 참조 수집으로 두 파일을 보존한다.

## 2. 선택 보기 사본 버리기

기존 문제는 실제 문서를 닫아도 프로그램의 닫음 확인 상태가 갱신되지 않는다는 것이다.
보호 조건을 없애는 대신 확인 흐름을 합친다.

1. `변경 버리기/정리` 선택 시 worker에서 선택 사본의 실제 내용을 관측한다.
2. 같은 선택 ID/use_token을 유지한 확인창에 파일명과 되돌릴 수 없음·원본 유지 안내를 표시한다.
3. `편집기에서 문서를 닫았습니다` 체크 전 삭제 버튼은 비활성화한다. 저장을 강요하지 않는다.
4. worker의 `discard_after_close`는 사용자 동의·현재 세대·use_token·승인 관측값을 확인한다.
   닫음 재관측 값이 승인 값과 다르면 삭제하지 않고 다시 확인하라고 안내한다.
5. 닫음 상태를 저장하고 기존 독점 읽기·최종 해시/identity·편집기 임시 파일·삭제 저널 검사를 실행한다.
   파일을 다시 열었거나 바뀌었거나 잠겨 있으면 남긴다. 취소는 실제 삭제 전까지만 가능하다.
6. 성공 시 선택 사본만 삭제하고 목록/해당 업무의 변경 표시를 갱신한다.
   다음 원본 열람은 그대로인 고정 내용으로 보기 사본을 준비한다.

## 3. 수용 검사

- 원본 해제 후 같은 ID/메타데이터, 일반 파일 독립 편집, 보관함 이전 내용, 기존 작업본 출처 유지.
- 수정 보기 사본은 해제 후에도 남아 작업본으로 보존 가능. 편집 파일 삭제 후 보관본 유지.
- 비원본/휴지통/해제 첨부/오래된 revision/손상/Windows 파일 잠금/취소/DB 실패 거절.
- 동일 ID 재시도, 실제 별도 프로세스 중단 전후 복구, 전체 백업/복원.
- 사본 버리기 한 창 처리, 미체크 거절, 승인 후 수정/재열람/잠금/sidecar/취소 시 보존.
- 해당 확인창 밝은 스타일, 어두운 시스템 palette 및 좁은 창의 문구/버튼 접근 확인.

## 4. 실제 반영·검증

- `release_original`, 선택 결과의 `retained_version_id`, 같은 첨부 ID의 일반 전환과
  이전 원본 보관본 연결을 구현했다. 새 이행 없이 0013을 유지한다.
- 현재 첨부의 오른쪽 메뉴/더보기에서 해제 확인을 열고, 원본일 때만 활성화한다.
- 사본 버리기는 worker 관측 후 확인창을 열고 문서 닫음 체크와 취소를 제공한다.
  승인한 내용/use_token과 닫음 재관측을 비교한 뒤 기존 독점 확인/삭제 저널을 사용한다.
  승인 후 내용 변경은 파일을 보존하고 확인창을 새로 열어 재시도하도록 안내한다.
- 관련 회귀 **142개 / 58.99초**, 전체 회귀 **879개 / 184.99초** 통과.
  이 전체 검사에는 해제 명령의 실제 별도 프로세스 종료 7개 지점,
  독립 파일 편집·수정 cache 유지/보존·삭제 후 이전 원본 유지·전체 백업/복원이 포함된다.
- 전체 검사 이후 오류 안내 문구를 더 구체화하고 기존 영수증의 선택 필드 누락 호환,
  DB 실패 후 같은 명령 재시도, 확인 후 수정의 UI 재확인 흐름 검사를 추가했다.
  최종 변경 관련 **24개 / 5.25초** 통과. 879개 결과를 이후 추가된 네 검사까지 포함한 결과로 표기하지 않는다.
- 실제 Windows renderer로 밝은/어두운 palette 주입, 100%·150%·200% 배율에서
  400×260 확인창의 문구/버튼 접근과 긴 이름을 확인하고 캡처했다.
  사본 버리기 후 원본 유지와 원본 해제 후 일반/보관함 내용도 검사했다.
  캡처는 ignored `.test-tmp/original-release-visual-{light,dark}-{100,150,200}`에 남겼다.
- Ruff 전체, mypy 101개 소스, `git diff --check` 통과. 외부 편집기는 실행하지 않았고
  실제 회사 DRM/보안 제품·Office/HWP의 닫힘 동작까지 검증했다고 간주하지 않는다.
- 운영 DB/첨부, 버전, EXE/ZIP/설치파일, Git 커밋/원격 업로드는 변경하지 않았다.
