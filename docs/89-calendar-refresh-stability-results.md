# U40 달력 자동 갱신·선택 유지 구현 결과

2026-11-11 사용자 `구현해` 요청으로 [88번 설계](88-calendar-refresh-stability-design.md)를 개발 소스에 반영했다.
상태: **구현·관련 격리 검증 완료. 후속 3.0.16 공개 결과는 [90번](90-release-checklist.md)을 따른다. 사용자 사용 확인은 별도다.**

## 구현

- CalendarPage에서 행 payload·문구·툴팁·색과 표시 맥락을 계산해 마지막 적용 값과 비교한다.
  같은 결과면 Qt setter/목록 재생성/선택 복원과 상위 선택 신호를 생략한다.
- 같은 논리 키 순서이면 QListWidgetItem을 재사용하고 달라진 속성만 반영한다.
  같은 문구라도 업무/알림 동작 데이터가 달라지면 UserRole·선택 상세를 최신화한다.
- 실제 구성 변경 때만 목록을 재생성하고 모든 행 생성 후 선택을 최대 한 번 복원한다.
  기존 키가 사라지면 첫 항목을 임의로 선택하지 않는다. 배치가 달라지면 위쪽 행/오프셋을 복원한다.
- 업무 직접 클릭 요청, 알림 포커스, overview→day 조회의 논리 선택 의도를 분리했다.
  중간 preview/재알림 갱신이 선택 의도를 지우지 않고 최종 빈 결과에서 상세/버튼을 정리한다.
- 재진입 요청은 한 개의 사전 연결된 타이머로 다음 GUI turn에 최신 원장을 처리한다.
  적용 시작 시 계산한 스냅샷만 완료 캐시로 기록한다. 실패 시 캐시 무효화·예약 중단으로
  자동 재시도 루프를 막고, 다음 정상 입력에서 명시적 선택 요청도 재시도할 수 있다.
  shutdown에서 타이머를 중단하고 후속 실행을 막는다.

설계 구체화: 원장 비교만으로 입구에서 생략하는 별도 캐시는 두지 않았다.
현재 적재 행의 projection을 매번 비교하는 한 경로로 통합해 자정·표시 맥락·동작 데이터의
무효화 누락을 피한다. 같은 원장에서도 Qt 변경은 생략된다. 입력 dict는 기존처럼 복사한다.
변경 번호 대신 캡처한 불변 signature와 pending 플래그를 사용하며, 도중 도착한 입력은
그 signature에 포함되지 않아 다음 반영에서 비교된다. DB 조회/파일 I/O는 추가하지 않았다.

## 검증

관련 검사는 서로 다른 노드 기준 **91개 통과**다. 전체 제품 회귀를 실행한 결과가 아니다.

| 범위 | 통과 | 증거 (`artifacts/u40-calendar/`) |
| --- | ---: | --- |
| 새 갱신 안정성 회귀 | 15 | new-final-retry.xml |
| 기존 달력 주의/알림 포커스/렌더링 | 10 | attention.xml |
| 달력 업무 보기 연결 | 22 | records.xml |
| 알림 묶음·달력 계산·주의 정렬 단위 | 34 | unit.xml |
| 정기 알림/재알림 동작·시간 갱신 통합 | 10 | integration.xml |

새 회귀에는 변화 없는 입력 200회 시나리오, dict 복사, 재알림 추가/해제,
동일 문구의 새 payload, 직접 선택 신호 중복 방지, 임시→최종 빈 결과,
일반 업무↔알림 묶음, 선택 삭제, 재진입 최신 값, 실패 후 재적용,
종료 예약 취소, 지역 자정 문구 변경, 구조 변경의 스크롤 앵커, 보기 복귀를 포함한다.

Windows native 추가 검사는 100% 24개, 150% 10개, 200% 10개 통과했다.
이는 위 검사 재실행이며 고유 검사 수에 더하지 않는다. native 검사는 마지막 실패 복구 경로의
보완 전 실행이며, 최종 실패 복구 회귀는 offscreen에서 확인했다.
밝은 제품 스타일에 어두운 팔레트를 주입한 환경과 일반 팔레트, 좁은/넓은 창을 검사했다.
실제 Windows 시스템 테마를 전환한 검사는 아니다.
기존 캡처는 `artifacts/u24-u25-captures/`에, 별도 200% 선택/재알림 캡처 2개는
`artifacts/u40-calendar/captures/`에 있다. 200% 어두운 주입 팔레트의 좁은 창 캡처를
직접 열어 밝은 본문·선택 문구·버튼·스크롤 표시가 읽히고 잘리지 않는지 확인했다.
기존 렌더링 fixture의 월 제목/직접 날짜 설정 불일치는 제품 동작 증거로 쓰지 않고,
별도 캡처에서는 실제 날짜 전환 경로로 월 제목과 날짜를 일치시켰다.

Ruff check·format check와 변경 소스 mypy 검사 통과.
처음 여러 파일을 묶은 실행은 60초 제한으로 종료되어 완료 결과에 포함하지 않았다.
해당 범위를 파일별 제한 프로세스로 나누어 모두 완료했다. mypy 초기 변수 타입 오류 3건은
변수 이름을 분리해 수정했다. 중간 11/14개 실행은 최종 15개와 중복이므로 합산하지 않는다.
200회 시나리오는 새 파일 재검사와 native 100%에도 포함되어 총 4번(800회) 실행했다.
설계의 1회 계획보다 재실행이 많았으며 별도 장시간/stress 검사는 추가하지 않았다.

## 보존과 한계

테스트 DB는 tmp_path, 앱 캡처는 별도 OFFICEFLOW_DATA_DIR을 사용했다.
캡처 실행 전 AppPaths.root가 지정한 격리 경로인지 확인했다. 운영 실행 cmd는 사용하지 않았다.
운영 앱/DB/첨부/설정·DB0017/백업 v3·버전·배포물·커밋/원격은 변경하지 않았다.
사용자가 지금 앱을 종료할 필요는 없다. 합성 fixture는 이번 작업 소유 경로만 확인 후 정리한다.

실제 응답 없음의 native 잠금 소유자는 미확정이며 재현 시험으로 원래 정지를 재현하지 못했다.
변화 없는 갱신의 위험 호출을 제거한 결과이며 전체 native 정지 해결이나 실사용 무재발의 증거가 아니다.
회사 Excel/보안 제품과의 인과·장시간 사용 확인·전체 제품 회귀는 미검증이다.
구조 변경과 명시적 사용자 선택에는 필요한 Qt 선택 호출이 남는다.
