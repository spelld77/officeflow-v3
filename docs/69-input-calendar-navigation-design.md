# 입력 실수 방지·하루 일정/알림·메뉴 정돈 통합 상세설계

작성: 2026-10-15. 대상: U30, U31-1/2, U32.
상태: **설계 완료, 실행 코드 구현·동작 검증 전**. 이번 요청은 개선목록 기록과 설계다.
이 문서의 수치·동작은 첫 구현의 설계 기준이며 테스트 통과나 배포를 뜻하지 않는다.

후속 `구현 및 테스트까지 진행해` 요청으로 아래 설계의 개발 소스 구현·격리 검증을 진행했다.
위 문구는 설계 작성 당시 상태이며 최신 실제 결과는 [70번 구현·검증](70-input-calendar-navigation-results.md)을 따른다.
이하 본문은 설계 계약으로 유지하고 배포/Git 작업은 이번에도 포함하지 않는다.

2026-10-16 후속 입력/하루 가독성 보완은 [71번 설계](71-input-and-day-readability-design.md)를 따른다.
이후 합의로 일반 날짜/내일 안내는 제거하고 위험 날짜는 입력칸 가까이 강조하며, 하루 중요도·상태와 관리 표기를 보완했다.

## 1. 목적·범위·기존 변경 보호

1. 유효한 날짜지만 의도와 다른 연도/시각을 저장하는 실수를 줄인다.
2. 특정 업무가 아닌 선택한 하루 전체의 일정/알림 흐름을 볼 수 있게 한다.
3. 작은 창에서 업무 탐색과 프로그램 관리 메뉴를 구분한다.

기존 밝은 테마, 전체 시각 입력, 최소 한 시간 뒤 정각 기본값, 휠 보호, 알림 최대 20개,
기록·첨부 보존, 월 달력 미완료 우선, 업무 완료와 알림 확인의 구분을 유지한다.
완료 요약 버그 수정은 [68번](68-completion-input-fix.md)의 별도 미커밋 변경으로 보존한다.
사용자 DB/첨부/실행 폴더·DB0016·백업 v3·버전·배포물·Git 작업은 이번 요청에서 변경하지 않는다.

U26 날짜 간편 이동, 주간 보기, 달력 드래그 편집, 새 마감일, 오늘 탭 분류 변경,
매시 업무기록 알림 변경, 새 관리 설정, 자동 자료 정리는 포함하지 않는다.

근거 문서: [개발 지침](06-development-process.md), [공통 계약](24-follow-up-common-design.md),
[운영 신뢰성](38-reliability-common-design.md), [일정/알림 묶음](43-reliability-phase-3-design.md),
[기존 입력 계약](49-task-input-and-reminder-design.md), [달력 미완료 우선](63-attachment-drop-and-calendar-attention-design.md).
이 문서는 그 보존/쓰기 계약을 바꾸지 않고 조회·입력 확인·탐색을 보완한다.

## 3. 공통 식별·시간·조회 계약

- 업무 범위 키는 `(task_id, original_occurrence_start 또는 None)`다. 이동된 표시 시각은 키가 아니다.
  반복의 날짜 직접 지정 공통 알림은 `None` 범위로 유지하고 임의 회차에 귀속시키지 않는다.
- 개별 알림은 기존 `ReminderPreviewItem.key`를 사용한다. 같은 업무의 다른 알림 ID는 다른 알림이다.
  동일 원소의 중복 전달만 제거한다. 일정 수와 알림 수를 더해 업무 수라고 하지 않는다.
- 화면의 날짜 경계는 앱 시간대의 `[해당 날짜 00:00, 다음 날짜 00:00)`를 UTC로 변환해 계산한다.
  종일 종료의 배타 경계·DST·원래 회차와 실제 이동 일정은 기존 서비스 계약을 따른다.
  DST 중복 시각은 UTC 식별자를 유지하고 동일 HH:mm에 offset을 함께 표시해 구분한다.
  하루를 항상 UTC 24시간 길이라고 계산하지 않는다.
- 새 조회는 알림을 poll/claim/acknowledge하거나 회차/delivery/이력을 쓰지 않는다.
- 실제 상태 갱신은 조회 결과만 교체한다. 열린 수정/완료/기록창의 대상 키와 미저장 내용을 바꾸지 않는다.
- 요청 토큰에 날짜·검색·화면 모드·generation을 넣는다. 오래된 결과·닫힌 화면 결과는 버린다.
  선택 보존은 ID 키로 하며 다른 행으로 대체하지 않는다.

## 4. U30: 입력 실수 방지

### 4.1 기준값과 적용 범위

업무 등록/수정의 시작일·활성 종료일·활성 반복 종료일, 알림 추가/수정의 직접 지정 날짜에 적용한다.
단순 조회/검색/내보내기 기간에는 저장 위험 경고를 적용하지 않는다.

- 수정 기준은 창을 열 때의 저장값이다. 새 업무는 현재 기본값/명시적으로 고른 달력 날짜의 초기값이다.
  초기값 배치와 종료 자동 제안을 마친 뒤 기준을 잡아 프로그램 초기화를 사용자 수정으로 오인하지 않는다.
- 입력 텍스트를 확정해 최종 draft를 만든 뒤 활성 값만 비교한다. 숨겨진 비활성 날짜의 임시값은 경고하지 않는다.
- 기존 과거/미래 업무를 열어 제목만 수정하면 날짜 경고 없음. 날짜를 바꿨다가 원래 값으로 돌려도 없음.
- 연도 차이는 업무 시간대의 달력 날짜로 계산한다. 종일의 종료일은 사용자에게 보이는 마지막 포함일이다.

### 4.2 표시와 첫 경고 조건

아래 기준은 설정 항목을 늘리지 않고 순수 함수의 상수/조건으로 관리한다.

| 상황 | 입력 중 표시 | 최종 저장 확인 |
| --- | --- | --- |
| 기준 대비 연도가 달라짐 | `연도 변경: 2026 → 2025` | 아래 위험 조건일 때만 |
| 같은 월일인데 연도만 달라짐 | 이전→이후 전체 날짜·요일 | 필요 |
| 연도를 넘으며 기준 대비 180일 이상 이동 | 이전→이후와 이동 일수 | 필요 |
| 새 업무/새 직접 지정 알림이 현재 날짜에서 366일 초과로 떨어짐 | `현재 기준 1년 이상 전/후` | 초기 명시 선택에서 다시 바꾼 날짜일 때 필요 |
| 12월 31일→다음 해 1월 1일 등 짧은 이동 | 전체 날짜·요일, 연도 변경 문구 | 이것만으로는 필요 없음 |
| 기본 정각 또는 ±시간 조정으로 자정을 넘김 | `내일 2026-10-16(금) 01:00` 또는 `날짜 변경` | 이것만으로는 필요 없음 |

180일/366일은 사용자 의도를 판정하는 법칙이 아니라 첫 구현의 주의 기준이다. 유효한 장기/과거 업무는
확인 후 저장할 수 있다. 윤년은 실제 date 차이를 사용하며 `1년=365일`로 변환하지 않는다.
반복 종료일에는 장기간 반복이 정상일 수 있으므로 새 업무의 366일 규칙을 적용하지 않는다.
활성 반복 종료일을 직접 바꾼 경우에는 기준 대비 연도 위험 조건만 적용한다.
새로 활성화해 과거 기준이 없는 날짜는 유효한 현재 초안의 초기 제안값을 기준으로 삼는다.

일반 입력에는 빈 주의 영역을 만들지 않는다. 변경 항목 옆 짧은 문구와 필요한 경우 접히는 상세만 둔다.
시각은 확정 후 `11:24`처럼 정규화한 값으로 표시한다. 오전/오후 의도를 추측해 09시를 21시로 바꾸지 않는다.
업무 시각이 과거인 것과 과거 새 알림이 금지되는 것은 구분한다. 후자는 기존 검증 오류를 따른다.

### 4.3 확인·재시도 경계

- 필수 입력/도메인/알림 유효성 오류를 먼저 검사한다. 오류가 없는 최종 초안의 위험 항목만 한 번에 모은다.
- 확인 문구는 `연도가 바뀝니다. 이 날짜로 저장할까요?`, 실제 이전→이후 날짜/요일,
  `이 날짜로 저장 / 돌아가기`다. 모든 정상 저장마다 팝업을 띄우지 않는다.
- 확인은 DB 트랜잭션 전에 한다. 열린 확인창 동안 알림 스케줄러/다른 창 조작을 멈추지 않는다.
  비모달 확인을 쓰고 대상 업무·회차·초안 지문을 캡처한다. 확인창 중복 열기는 막는다.
- 확인 중 초안이 바뀌면 예전 승인으로 저장하지 않는다. 새 초안을 재검증한다. 현재 선택 업무를 재사용하지 않는다.
- 업무 편집 내부 알림창은 초안만 넘기고 업무 최종 저장에서 통합 확인한다.
  단독 알림 설정창은 최종 적용에서 확인한다. 동일 초안에 이중 확인을 요구하지 않는다.
- 승인한 동일 초안의 저장 실패 재시도는 다시 묻지 않되 입력을 보존한다. 수정된 초안은 새 확인 대상이다.
  동시 수정 충돌과 명령 ID/이력 원자성은 기존 저장 서비스의 검증을 그대로 사용한다.

### 4.4 날짜 이외 함께 줄일 실수

- 시작/종료 변경 시 활성 직접 지정 알림이 있으면 `직접 지정 알림 N개는 날짜를 바꿔도 유지됩니다`를 표시한다.
  상세에서 해당 시각/요일을 확인한다. 상대 알림은 기존 규칙대로 재계산하며 실제 예약과 저장 전 예상을 구분한다.
  자동으로 절대 알림을 이동/삭제하거나 과거 새 알림 금지를 우회하지 않는다.
- 추가 설정을 접어도 활성 종료/반복은 남는 현재 동작을 유지한다.
  접힌 토글 문구에 `종료 18:00 · 매주 반복`처럼 활성 항목만 짧게 붙인다. 해제하려면 실제 옵션을 변경한다.
- 범위 일정은 추가 설정이 강제로 펼쳐지는 기존 동작을 유지한다. 시간 변경/종일 전환 때 몰래 값 삭제하지 않는다.
- 상태에 따른 이후 알림 중단 안내는 기존 것을 재사용한다. 새로운 업무 완료 규칙/중복 확인은 추가하지 않는다.

## 5. U31: 월 보기·하루 보기·하루 전체 알림

### 5.1 화면 전환과 기본 동작

왼쪽 `캘린더` 하나 안에 세 표시 상태를 둔다. 새 왼쪽 메뉴/별도 스마트 목록은 만들지 않는다.

1. 월 보기: 기존 월 격자와 날짜 목록. 미완료 우선·목록 확대·알림 건수 배지는 유지한다.
2. 하루 보기: 월 격자와 하단 목록 대신 **같은 달력 본문 전체**를 시간표로 사용한다.
3. 하루 알림: 같은 본문에서 시간순 목록을 표시하고 `돌아가기`로 이전 월/하루 상태를 복원한다.

상단에 `하루 보기↔월 보기` 전환과 `하루 알림 N건` 진입을 둔다. 업무를 선택하지 않아도 사용한다.
기존 업무별 `알림 시각 보기`는 `선택 업무 알림`으로 구분해 선택 업무의 상세 범위를 유지한다.
하루 보기에서는 선택 업무 오른쪽 메뉴로 접근해 상시 버튼을 늘리지 않는다.

월에서 고른 날짜를 하루 보기에 그대로 전달한다. 이전/다음은 월 모드에서 월, 하루/하루 알림에서 날짜 이동이다.
`오늘`은 모드를 유지하고 오늘로 이동한다. 제목에 전체 연도·월일·요일을 표시한다.
월로 돌아오면 같은 날짜가 선택되고 이전 분할 비율/목록 스크롤을 복원한다.
재진입 시 현재 실행의 마지막 모드를 유지하되 재시작 기본은 기존 월 보기다. 새 설정 저장은 추가하지 않는다.
전체화면으로 전환하거나 창 크기를 강제로 늘리지 않는다.

### 5.2 하루 알림의 범위·상태·순서

- 선택 날짜의 **전체 업무 알림**을 다룬다. 업무 검색/상태 필터 때문에 알림을 감추지 않는다.
  일정 검색 중이면 `일정 검색 결과 N개 · 알림은 하루 전체`로 범위를 알린다.
  매시 업무기록 알림은 업무에 등록한 알림과 다른 기능이므로 이 건수/시간표에 합산하지 않는다.
  버튼 도움말은 `선택 날짜에 등록된 모든 업무의 알림`으로 범위를 명시한다.
- 기본 목록은 `예정/재알림/미확인`과 `시각 지남·발생 기록 없음`이다. 각각 기존 pending/attention 판정을 사용한다.
  상단은 `예정·재알림 N · 미확인 M · 확인 필요 K`로 구분한다. 하나의 항목을 두 범주에 중복 집계하지 않는다.
- 확인함·처리됨·업무 완료/취소·다른 날로 미룸 등의 원래 날짜 기록은 접힌 `처리 이력 N`에서 조회한다.
  완료 후 앞으로 울리지 않는 것을 예정/재알림에 포함하지 않는다. 기존 자료가 없는 미래 중단 기록을 새로 만들지 않는다.
- 시간순은 실제 `effective_at` → 업무/원래 회차 키 → reminder ID → scheduled_at 순으로 안정 정렬한다.
  재알림은 실제 다시 울릴 시각, 처리 이력은 기존 날짜 투영의 상태/원래 예정 시각을 함께 표시한다.
- 같은 시각에 다른 알림 ID가 있으면 모두 유지한다. 같은 업무의 두 알림도 별도 시각 행이다.
  행은 `시각 / 업무 제목 / 상태`이고 전체 날짜·요일·원래 예정·재알림은 선택 상세/툴팁으로 확인한다.
- 과거에 프로그램이 실행되지 않아 기록되지 않은 모든 알림을 사후 복원한 목록이라고 약속하지 않는다.
  기존 preview가 돌려준 실제 이력·예상·발생 기록 없음의 구분을 유지한다.
- 읽기/업무 보기/설정 진입만 제공한다. 이 화면 자체에서 새 확인·재알림·완료 명령을 만들지 않는다.
  설정 변경과 업무 보기는 기존 서비스/창 재사용으로 연결한다.

### 5.3 하루 시간표의 표현

공통 세로 시간축에 `업무 일정`과 `알림` 두 열을 둔다. 파랑/주황의 색뿐 아니라 열 이름·시각·상태로 구분한다.

| 대상 | 표현 | 주의할 점 |
| --- | --- | --- |
| 시작·종료가 있는 일정 | 실제 길이에 비례하는 블록 | 표시 최소 높이를 위해 실제 종료를 바꾸지 않음 |
| 시작만 있는 업무 | 해당 시각의 시점 표시와 짧은 카드 | 임의 한 시간 종료/작업량 추정 금지 |
| 종일·여러 날 종일 일정 | 위쪽 종일 영역 | 최초 2행, 나머지 `종일 +N`으로 조회 가능 |
| 날짜를 넘는 시간 일정 | 해당 날짜 구간만 자름, 이어짐 표시 | 날짜 전체를 종일 업무로 변환하지 않음 |
| 알림 | 오른쪽 열의 시각 표시/짧은 카드 | 기간 블록으로 알림 지속 시간을 만들지 않음 |
| 일정 없이 오늘 알림만 있는 업무 | 오른쪽 알림만 표시 | 왼쪽에 가짜 일정을 추가하지 않음 |

하루 보기의 시간 순서를 위해 월 목록의 미완료 우선 정렬을 시간축에 적용하지 않는다.
완료 일정은 같은 실제 위치에서 `완료`와 연한 표시를 사용한다. 알림 확인만으로 업무를 회색 완료로 만들지 않는다.
같은 업무의 일정/알림을 선택하면 해당 범위의 연결 항목을 강조하되 서로 다른 반복 회차는 같이 강조하지 않는다.
검색으로 왼쪽 일정이 숨겨진 알림을 눌러도 검색을 몰래 해제하거나 다른 날짜로 이동하지 않는다.

### 5.4 24시간·겹침·작은 창

- 실제 시간표는 **00:00~24:00 전체**에 접근한다. 예상 화면의 09~18시는 설명용 예시이며 근무시간 제한이 아니다.
- 한 시간 기본 높이 56 DIP, 30분 중간선, 날짜/열 제목과 종일 영역은 고정하고 시간 본문을 세로 스크롤한다.
  수평 스크롤은 기본적으로 만들지 않는다. 오늘 첫 진입은 현재 시각 1시간 전 부근, 다른 날짜는 첫 일정/알림 부근,
  항목이 없으면 09시 부근으로 이동한다. 앞뒤 시간으로 스크롤할 수 있고 갱신 때 현재 시각으로 강제 점프하지 않는다.
- 밀도 조정 슬라이더 등 새 상시 옵션은 첫 구현에 넣지 않는다. 예상 화면의 디자인 조절은 제품 기능 승인이 아니다.
- 같은 열의 시간 구간 겹침은 안정적인 lane 배치다. 시점 카드/짧은 블록의 글자 영역 겹침도 별도로 처리한다.
  좁은 칸에 글자를 억지로 넣지 않고 제목 생략+전체 보기 도움말을 제공한다.
- 일정 동시 겹침은 최대 3 lane까지 직접 표시, 나머지는 `+N 일정`으로 정확한 시각/제목 목록을 연다.
  알림이 같은 시각/짧은 구간에 밀집하면 `14:00 · 알림 N건` 표시를 누르면 개별 시각 목록으로 펼친다.
  묶음은 표시만 합치며 실제 알림 수/ID/시각을 변경하지 않는다. 숨은 항목을 조용히 버리지 않는다.
- 주 창 최소 760×560 DIP에서 읽을 수 있게 메뉴를 줄인 공간을 활용한다. 도구줄은 필요하면 두 줄로 배치한다.
  종일/선택 설명을 높이 제한 없이 늘리지 않고 시간표 본문의 스크롤 공간을 우선한다.
- 한 번 클릭은 선택/짧은 정보, 더블클릭·Enter는 기존 업무 보기, 우클릭은 기존 업무/정확한 회차 메뉴다.
  선택 자체로 수정/확인/완료하지 않는다. 드래그로 시간 변경, 빈 칸 더블클릭 등록은 첫 구현에서 제외한다.
  새 일정은 기존 등록 버튼과 선택 날짜 초기값을 사용한다.

### 5.5 조회·성능·갱신

표시 모델은 저장 테이블이 아니라 읽기 전용 투영이다.

- `DayOverviewService`에서 날짜 일정과 알림 preview를 조합한다. 날짜 일정은 화면 worker의 독립 읽기 session에서 조회한다.
  현재 `calendar_schedule()`의 전체 tuple을 GUI에서 읽은 뒤 500개로 자르는 방식은 새 경량화로 인정하지 않는다.
- 첫 조회는 일정 투영 최대 500개, 알림은 기존 기본 5,000개/2초 조회 예산을 유지한다.
  일정에는 bounded reader/반복 전개 예산을 추가해 원본 template 페이지(최대 200개)와 전개 결과를 모두 제한한다.
  시간 예산은 취소 확인 기준이지 DB/OS가 어떤 경우에도 정확히 2초 안에 끝난다는 보장이 아니다.
- `DayOverviewResult`는 날짜·검색 범위·일정 tuple·알림 결과·일정 조회 완전성·확인된 건수 범위를 가진다.
  정확한 전체 수가 없으면 `조회된 N개·일부 조회`라고 하고 전체 건수인 것처럼 말하지 않는다.
- 개별 알림 목록은 100행 단위 페이지다. 추가 알림 조회는 기존 단계적 상향과 최대 100,000개 상한을 재사용한다.
  이 수만큼 QWidget을 만들지 않는다. 시간표는 viewport에 보이는 도형과 hit 영역 중심으로 그린다.
- 일정 상한 초과는 명확한 안내와 페이지 조회 가능한 `일정 목록`으로 연결한다.
  모든 일정을 그래픽으로 끝없이 추가하는 대신 같은 read-only reader의 다음 페이지를 사용한다.
  부분 조회에서 겹침 없음/알림 없음/전부 완료를 단정하지 않는다.
- 파일 내용·이미지·첨부 해시는 조회하지 않는다. 첨부 있음 표시는 기존 metadata만 사용한다.
- 분 경계/명시적 저장/재알림/완료 통지에서 필요한 하루만 갱신한다. 매초 전체 일정/이력을 읽지 않는다.
  1분 단위 현재 시각선은 화면만 갱신하고 새 예약을 만들지 않는다.
- 날짜 변경·화면 닫음·앱 종료 시 worker 취소/정리와 늦은 결과 차단을 적용한다.
  실패는 마지막 정상 화면에 `갱신 실패·이전 결과`를 표시하며 빈 일정/0건으로 덮어쓰지 않는다.

## 6. U32: 왼쪽 메뉴

```text
오늘
예정
캘린더
전체 업무
──────────
중요
대기
──────────
완료
업무일지

  (남는 공간)
휴지통
관리 ⋯  → 데이터 관리 / 설정 / 도움말
```

- 상시 12개 진입을 10개로 정돈한다. `관리 ⋯` 아래 세 기능은 기존 동작/서비스를 유지한다.
  관리 화면들을 합치거나 실제 내보내기/백업/복원 기능을 삭제하지 않는다.
- 위쪽은 업무 탐색, 중간은 중요/대기와 완료/일지, 아래는 삭제 자료/관리다.
  큰 섹션 제목을 새로 넣지 않고 NoFocus 구분선/짧은 간격을 쓴다.
- `휴지통/관리/버전`은 아래 고정한다. 높이가 부족할 때만 위쪽 탐색 영역을 스크롤하고 하단 진입은 남긴다.
  기존 작은 창 높이의 짧은 버튼·88 DIP 사이드바와 `전체/달력/일지` 표기를 재사용한다.
- 관리 메뉴의 full label은 `데이터 관리`, 도구 설명은 `백업·복원·내보내기·자료 검사·첨부 정리`다.
  기존 직접 호출 메서드와 활성/비활성 조건을 QAction에 연결한다. 데이터/백업 서비스가 없을 때 비활성 이유를 보인다.
- 캘린더/업무 목록은 현재 화면 선택 강조, 업무일지/관리 진입은 기존 창을 여는 행동이다.
  관리 메뉴 열기/닫기나 도움말 호출 때문에 주 화면 선택을 옮기지 않는다. 첫 시작은 기존 오늘이다.
- 관리 메뉴는 Tab·Enter/Space·화살표로 접근 가능하고 메뉴 Esc는 닫기만 한다. 검색 Esc 삭제는 추가하지 않는다.
- 백업 실패/자료 이상 상태바 버튼과 트레이의 기존 직접 진입은 그대로 유지한다.
  도움말에는 `관리 → 데이터 관리`와 새 하루 보기 동선을 구현 시 갱신한다.
- 사용자별 메뉴 정렬·끌어서 이동·접는 트리·새 스마트 목록·메뉴 개수 배지는 추가하지 않는다.

## 8. 수용 기준·검증 계획

### U30

- 같은 월일의 연도 오입력·180일 경계·366일 경계·윤년·연말 정상 이동·과거 업무 제목만 수정.
- 달력에서 명시적으로 선택한 과거/미래 날짜·알림 직접 날짜·비활성 종료/반복·반복 종료 장기 설정.
- 자정 기본값과 ±시간 이동·직접 지정 알림 유지·상대 알림 예상·접힌 설정 요약과 Tab 경로.
- 확인 취소·확인 중 재편집/선택 변경·동일 초안 DB 실패 재시도·다른 창 변경 충돌·미저장 내용 유지.
- 예외 날짜 안내가 실제 저장값을 바꾸지 않고 기존 오류 검증/알림 예약을 우회하지 않음.

### U31

- 일정만/알림만/같은 업무 다중 알림/같은 제목 다른 ID·다른 반복 회차·공통 알림.
- 재알림 날짜 이동/실제 시각 변경·원래 날짜 이력·업무 완료/취소·알림 확인 분리·기록 없는 과거 날짜.
- 종일 배타 종료·야간/자정·월/연도/윤년/DST·종료 없는 시점·짧은 일정·동시 겹침·밀집 +N.
- 월 미완료 우선과 하루 시각 순서의 차이·업무 검색 중 전체 알림 범위·표시/업무/알림 건수 구분.
- 월↔하루↔하루 알림의 날짜·스크롤·선택/분할 복원, 갱신 중 다른 날짜 선택, 종료 후 결과 도착.
- 조회만으로 DB 이력/회차/delivery가 생기지 않음. 보기/수정/우클릭은 원래 대상, 완료 내용 버그 회귀 포함.
- 0/10/100개 하루 자료와 합성 대량 자료(업무 5,000·한 날짜 밀집·다중 반복)에서 조회/전개/paint 상한,
  부분 조회/추가 조회·취소·첫 화면/알림 조작 응답을 실제 측정한다. 대용량 첨부 fixture는 만들지 않는다.

### U32 및 공통 UI
