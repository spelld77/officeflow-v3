# 달력에서 업무 기록을 우선하는 동작

설계일: 2026-10-03. 범위: 달력의 조회 동작, 주 창 소유 기록 창 재사용, 사용자 안내와 회귀 검사.

## 목적

등록 이후 수정하기보다 첨부·체크리스트·업무일지를 확인하는 사용 흐름을 우선한다.
달력의 월·선택 날짜·목록 확대 상태를 유지하고, 수정 화면이나 날짜별 업무일지 전체 화면으로 이동하지 않는다.
DB 구조·기존 데이터·설정 파일 형식·배포 버전은 변경하지 않는다.

## 동작

| 입력 | 결과 |
| --- | --- |
| 일정 한 번 클릭 | 일정만 선택. 창은 열지 않는다. |
| 일정 막대/날짜별 목록 더블클릭 | 선택한 업무의 비모달 기록 창. 처음은 체크리스트, 이후 이번 실행의 최근 탭. |
| 하단 공통 `기록` | 더블클릭과 같은 동작. |
| 선택 일정 Enter | 달력에서는 기록 열기, 일반 업무 목록의 기존 열기 동작은 유지. |
| 하단 공통 `첨부` | 해당 업무의 첨부 탭. 파일 선택창은 열지 않는다. |
| 하단 `⋯`/일정 오른쪽 클릭 | 기록·체크리스트·업무일지·첨부를 먼저 표시하고, 완료·수정·휴지통 등 기존 기능 유지. |
| 빈 날짜 더블클릭 | 기존처럼 선택 날짜의 새 일정 등록. |

버튼은 일정마다 반복하지 않고 하단 목록 위에 한 세트만 배치한다. 선택 없이는 비활성화한다.
넓은 창의 오른쪽 상세에서도 달력의 수정 버튼은 숨기고 기존 기록 버튼을 주 동작으로 강조한다.
일반 업무 목록으로 돌아가면 기존 수정 버튼과 스타일을 복원한다.
첨부가 없더라도 첨부 목록을 열 수 있고, 화면에는 `첨부파일이 없습니다`와 추가 버튼이 있다.
일정의 기존 첨부 표시와 목록 확대/남은 일정 안내는 유지한다. 좁은 창에서는 짧은 버튼과
툴팁을 사용하며 긴 스크롤 안내는 목록 아래에 두어 동작 버튼을 밀어내지 않는다.
목록 행은 글꼴 높이와 여백에 맞춰 한 줄 높이를 지정하고 최소 3행 공간을 확보한다.
작은 창의 달력 셀에 막대가 들어갈 높이가 없으면 개수만 표시해 다음 날짜/하단 버튼 영역을 가리지 않는다.

## 기록과 선택의 정체성

- 일반 업무는 업무 ID, 반복 업무는 업무 ID와 원래 발생 시각을 사용한다.
- 같은 반복 업무라도 다른 회차의 창은 별도이다. 같은 회차는 재사용한다.
- 달력 목록 갱신도 같은 정체성으로 선택을 복원한다. 업무 ID만으로 다른 회차를 선택하지 않는다.
- 날짜 변경/필터 결과에서 사라진 일정은 선택을 해제하고 버튼을 비활성화한다.
- 더블클릭은 신호에 담긴 일정을 기준으로 기록을 열어 이전 선택의 회차를 열지 않는다.

## 창 재사용과 탭

주 창에서 여는 목록·달력·첨부 검색의 기록 창은 `(업무 ID, 발생 시각, 읽기 전용 여부)`로
찾아 재사용한다. 다시 열 때 입력 내용을 다시 불러오거나 덮어쓰지 않는다. 명시적 탭 바로가기는
해당 탭으로 이동하지만 일반 기록 열기는 이미 열린 창의 현재 탭을 유지한다.
새 창을 일반 기록 열기로 만들 때는 이번 실행의 최근 탭을 사용한다. 재실행하면 체크리스트부터
시작하며 조회 때문에 설정 파일을 새로 쓰지 않는다.

업무일지 검색 창 내부의 기록 창은 기존 부모 소유·회차별 재사용 정책을 유지한다. 서로 다른 부모의
창을 넘겨 재사용하지 않아 업무일지 창 종료 시 정리와 알림 비모달 정책을 깨뜨리지 않는다.
프로그램 종료 시 기존 취소·안전한 대기·창 정리 정책을 따른다.

## 검증

단일 클릭/더블클릭/공통 버튼/오른쪽 메뉴/수정/빈 날짜 등록, 첨부 유무, 최근 탭,
창 재사용과 미저장 입력, 반복 회차 분리·갱신·날짜 변경, 좁은 창과 최소 3행/남은 개수,
알림 클릭과 기존 휴지통 읽기 전용, 부모 종료의 회귀 검사를 수행한다.
설치형 HTML과 Markdown 도움말의 더블클릭 안내를 함께 갱신한다.
