# ADR-0001: Windows 데스크톱 기술 스택

- 상태: 승인 제안
- 날짜: 2026-09-12

## 상황

OfficeFlow v3는 Windows 시스템 트레이, 알림, 단축키, 로컬 파일과 SQLite를 사용하는 개인용 데스크톱 앱이다. 현대적인 3패널 UI, 대량 목록, 여러 날 일정 캘린더와 설치 프로그램이 필요하다.

## 결정

- 언어: Python
- UI: PySide6 / Qt Widgets
- 저장소: SQLite
- 데이터 접근: SQLAlchemy 2 계열
- 스키마 변경: Alembic
- 테스트: pytest 기반
- 패키징: PyInstaller를 우선 검증하고 설치 프로그램 계층을 별도로 구성
- 구조: 계층형 모듈러 모놀리스

정확한 패키지 버전은 프로젝트 부트스트랩 시 호환성을 확인하고 lock 파일에 고정한다.

## 이유

- 기존 Python 업무 규칙과 내보내기 코드를 선택적으로 참고할 수 있다.
- Qt 모델/뷰는 많은 업무를 개별 Tk 위젯으로 생성하지 않고 표시하기 적합하다.
- Qt의 시스템 트레이, 로컬 IPC, 스레드 신호와 고해상도 화면 지원을 활용할 수 있다.
- SQLite는 단일 사용자 로컬 앱의 배포와 백업에 적합하다.
- SQLAlchemy와 Alembic은 스키마 변화와 테스트용 저장소 구성을 명시적으로 관리하게 해준다.

## 검토한 대안

### 기존 Tkinter 유지

초기 개발은 빠르지만 현재 UI 결합도를 해소하면서 현대적인 목록과 기간 캘린더를 구현할 때 얻는 이점이 적다.

### 웹 앱 또는 Electron

화면 구성은 유연하지만 로컬 알림, 트레이, 설치 용량과 파일 시스템 통합 부담이 커진다. 클라우드·협업이 핵심 요구가 아닌 현재 범위에는 과하다.

### .NET 데스크톱 앱

Windows 통합성과 배포는 좋지만 기존 Python 코드 재사용성이 낮고 전체 기술 전환 비용이 커진다. 장기적으로 Windows 전용 제품화가 최우선이 되면 다시 평가할 수 있다.

## 결과

- 기존 Tkinter UI 코드는 직접 재사용하지 않고 동작 참고 자료로 사용한다.
- 기존 DB 접근 코드는 쿼리와 규칙을 검증하는 참고 자료로만 사용한다.
- 첫 개발 단계에서 PySide6, SQLAlchemy, Alembic과 PyInstaller의 최소 실행·패키징 실험을 수행한다.
- 패키징 또는 캘린더 구현의 중대한 기술 문제가 확인되면 Phase 1 종료 전에 ADR을 재검토한다.
