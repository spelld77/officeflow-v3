# ADR-0002: OfficeFlow v2.6 데이터 변환 규칙

- 상태: Accepted
- 결정일: 2026-09-16

## 배경

v2.6의 `tasks.content`에는 제목과 설명이 분리되어 있지 않고, `deadline`은 UI에서 항상 빈
문자열로 저장됐다. `file_path`는 첨부 테이블과 별개로 사용자가 연결한 파일 또는 폴더
경로다. 이 값을 추측해 v3의 기간 일정으로 바꾸면 실제 의미와 다른 일정이 만들어질 수
있다.

## 결정

- `content`의 첫 번째 비어 있지 않은 줄 최대 80자를 제목으로 사용하고 전체 원문은 설명에
  보존한다.
- `target_date`와 유효한 `alarm_time`은 시간 일정의 시작으로 바꾼다. 종료 시각은 추정하지
  않는다.
- 날짜는 유효하지만 시각이 없거나 잘못됐으면 해당 날짜의 하루 종일 일정으로 바꾼다.
- `deadline`은 `ends_at`으로 바꾸지 않고 `기존 마감일`이라는 표식과 함께 설명에 보존한다.
- `file_path`가 실제 파일이면 관리 첨부파일로 복사하고, 폴더이거나 찾을 수 없으면 원래
  경로를 설명과 보고서에 보존한다.
- `Once`, `Daily`, `Weekly`은 각각 반복 없음, 매일, 지정 요일 매주 RRULE로 변환한다.
- 반복 업무의 과거 `history_logs` 날짜가 반복 규칙에 맞으면 완료 발생 이력과 업무일지를
  함께 만든다. 규칙에 맞지 않으면 업무일지만 보존한다.
- `active`, `pending`, `done`과 `보통`, `관심`, `중요`, `긴급`은 v3 상태와 중요도에 직접
  대응한다. 알 수 없는 값은 안전한 기본값으로 변환하고 보고한다.
- 찾을 수 없는 첨부파일은 메타데이터를 유지하고 `missing_at`으로 표시한다.

## 안전성

원본 DB는 읽기 전용으로 열고 SQLite 온라인 백업으로 별도 안전 사본을 만든다. 현재 v3
DB와 첨부를 임시 영역에 복제한 후 변환하며, SQLite 무결성·외래키·개수 검증을 통과한
결과만 다음 실행용 복원 파일로 예약한다. 동일한 원본 체크섬과 `legacy_id`는 다시
가져오지 않는다.

## 결과

모호한 값을 추정해 일정 의미를 바꾸지 않으면서 v2.6 원문과 추적 ID를 보존한다. 기간
일정이 필요하면 사용자가 가져오기 후 v3 편집기에서 명시적으로 종료일을 지정한다.
