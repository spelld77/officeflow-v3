설치 파일 생성은 하지 않았다. U1 일정/알림 중복 표시와 실제 Git 연동은 계속 보류한다.

## 1. 사용 동선

업무/달력 오른쪽 메뉴의 **이력·보관…** 또는 업무 기록 창 하단의 **이력·보관**으로 연다.
새 탐색 탭을 추가하거나 기존 업무 화면에 전체 이력을 펼치지 않는다.

- 저장된 변경: 한 줄 시간순 목록 → 상세에서 실제 변경 전/후 확인.
- 중요 자료: **현재 상태 보관…** → 이름 → 선택 파일(선택하지 않아도 됨) → 보관.
- 비교: 항목 선택 → **비교에 추가**를 두 번 → **선택 2시점 비교**.
  한 항목을 현재와 비교할 때는 **현재와 비교**.
- 당시 파일: 중요 보관 상세 → **파일 보기 / 선택 저장… / 새 작업본…**.
- 중단된 캡처: **중단된 보관 확인…** → 해당 업무의 작업 확인·안전 정리.

화면은 모델리스이며 동일 업무/회차의 이력 창을 재사용한다. 미저장 설명·결과메모를
이력 갱신 신호로 덮어쓰지 않는다. 상세를 별도 창으로 열어 목록 높이를 유지한다.
도움말의 기록/첨부 항목에 범위·사용법·보관/삭제/백업 주의사항을 추가했다.

## 2. 자동 변경 이력

제목·설명·일정·중요도·상태·결과메모의 여섯 그룹을 저장한다. 글자별 입력,
같은 값 저장, 실패/취소, 알림 확인·다시 알림, 첨부 관측, 고정/체크리스트/일지 편집은 제외한다.
업무/회차 완료·대기와 완료 실행 취소는 실제 상태 변경이므로 포함한다.

새 업무는 생성 기록을 남기고 기존 업무/회차는 첫 실제 변경에서 변경 직전 기준과 변경을
함께 남긴다. 과거 변경을 소급 생성하지 않는다. 반복 회차는 이동된 표시 날짜나 행 ID 대신
원래 발생 시각의 UTC 키로 구분한다. 공통 변경을 미래 회차마다 복제하지 않는다.

`TaskSaveService`, 빠른 등록/편집, 상태/완료/결과메모, 회차 이동/건너뛰기/재개,
알림의 완료/대기 경로를 명시적인 명령 경계로 연결했다. 한 트랜잭션에 업무·회차·필요한
알림 처리·이력·처리 영수증을 확정한다. 이력/영수증/알림 저장 실패는 전체 롤백한다.
완료+결과메모, 대기였던 업무의 완료 취소 중간 단계는 각각 한 사용자 변경으로 표시한다.

입력창은 실패 때 초안과 명령 ID를 유지한다. 같은 요청 재시도는 기존 처리 영수증을 확인하고
현재 상태를 다시 읽으며, 같은 ID에 다른 요청이면 거절한다. 이미 처리된 요청임을 UI에 구분한다.
다른 창이 결과메모/업무 정보를 수정했으면 예상 값 검증으로 오래된 초안의 덮어쓰기를 거절한다.
커밋 전에는 성공/갱신 신호를 발행하지 않는다.

## 3. 중요 시점 보관

기본 이름은 `업무 보관 N`, 이름은 자유 입력이다. 당시 저장된 여섯 그룹·공통 고정/생성 정보·
체크리스트 상태와 선택 파일을 고정한다. 전체 업무일지·알림 규칙/실행 상태는 복제하지 않는다.
미저장 결과메모는 돌아가서 저장하거나 DB에 저장된 내용만 보관하도록 명시적으로 구분한다.

현재 첨부와 개별 보관본을 페이지당 최대 100개, 선택 전체 최대 100개로 조회/선택한다.
페이지/종류 변경에도 체크를 유지하고 초과 선택은 거절한다. 파일 선택 0개는 업무 정보만 보관한다.
파일을 선택하면 저장하고 문서를 닫았다는 확인이 필요하다. 이 확인만으로 안전한 파일 읽기
검증을 대체하지 않으며 외부 편집기의 미저장 내용은 보관할 수 없다.

변경 가능한 첨부는 독립 고정 자산으로 스트리밍 복사한다. 기존 고정 자산은 크기·해시를
검증해 재사용한다. 같은 자산의 논리 선택 두 개는 파일 정보 두 행을 유지하되 bytes는 하나다.
파일명·역할·메모·출처 정보는 당시 값으로 저장하여 현재 첨부의 이름 변경/삭제가 과거를 바꾸지 않는다.

모든 출처의 보호 읽기/사용 예약을 먼저 확보한다. 복사/검증 중에는 긴 DB 쓰기 트랜잭션을
유지하지 않고, 확정 시 업무/회차 이력 ID·실제 값·체크리스트·선택 파일 메타데이터 토큰을
재검증한다. 중간 A→B→A 업무 변경도 이력 ID로 감지한다. 파일 하나라도 누락/잠금/검증 실패,
캡처 중 대상 변경이면 보관 전체를 성공으로 확정하지 않는다.

UI 보관 재시도도 같은 승인 요청 ID를 유지한다. 커밋 후 응답만 실패한 경우 기존 묶음을
반환하고 중복 생성하지 않는다. 확정되지 않은 준비 작업은 자동 재실행하지 않는다.

## 4. 통합 조회와 비교

자동 이력과 중요 보관을 한 DB 읽기 스냅샷에서 조회한다. 시간/종류/ID 복합 커서로 50+1행만
읽고 목록에는 50행만 유지한다. 동일 시각의 혼합 항목도 페이지 사이 중복/누락 없이 조회한다.
필터는 공통/선택 회차/모든 회차, 종류, 여섯 변경 그룹, 선택 기간이다. 기간 종료일은
업무 시간대 다음날 0시의 배타 경계로 변환한다. 최초 조회는 기간 제한이 없다.

요약 목록에서 큰 본문 payload를 읽지 않는다. 각 UNION 분기에 필터/커서/정렬/51행 제한을
먼저 적용해 최대 102행만 최종 정렬한다. 첫 페이지는 새 기록에 갱신하고 과거 페이지는
`새 기록 있음`으로 위치를 유지한다. 오래된 비동기 결과는 요청 세대로 폐기한다.

비교 두 항목도 한 DB 읽기 스냅샷에서 확보하고 공통끼리/같은 원래 회차끼리만 허용한다.
현재와 비교는 현재 조회 시각을 표시한 **업무 정보 여섯 그룹** 비교다. 두 중요 보관끼리는
당시 체크리스트/파일 정보도 표시하며 여섯 그룹이 같아도 보관 정보 변경을 별도로 안내한다.
자동 이력에 없는 체크리스트/파일을 마치 함께 보관한 것처럼 표시하지 않는다.

넓은 창은 좌우, 좁은 창은 위아래로 전/후 원문을 표시한다. 자유 문장은 실제 문구만 비교하며
`100만원`과 `100(천원)`의 의미가 같다고 추정하지 않는다. 한글/줄바꿈/이모지의 위치를
Qt UTF-16에 맞춰 강조한다. 100,000자/10,000줄/0.2초 예산 초과는 강조를 생략하고 원문을 유지한다.
HWP/Excel 내부 의미 비교나 과거 상태/알림의 자동 복원은 제공하지 않는다.

## 5. 파일 보존·삭제·백업 연결

`snapshot_files`를 실제 자산 보존 참조로 연결했다. 출처 첨부/개별 보관본을 지워도 묶음 파일은
남고 열기·단일/다중 외부 저장·독립 작업본 생성이 가능하다. 묶음 삭제도 다른 참조가 쓰는
고정 자산은 유지하며 일부 파일만 따로 삭제하는 메뉴는 제공하지 않는다.

휴지통에서 조회/외부 저장은 허용하고 새 보관/작업본/묶음 삭제는 거절한다. 업무 영구 삭제는
기존 보관본에 더해 자동 이력·중요 보관·파일 개수를 계획/확인창에 표시하고 별도 범위 승인을
받는다. 업무일지는 기존 연결 해제/보존 정책을 유지한다. 새 삭제 완료 payload는 v2,
기존 v1 영수증은 새 개수를 0으로 읽으며 기존 명령 지문 형식을 바꾸지 않았다.

전체 백업 형식 v3의 DB/자산/manifest 검증과 복원에 새 테이블/참조를 포함했다.
snapshot만 참조하는 고정 파일도 포함되고 공유 bytes는 중복 저장하지 않는다. 사용량에 이력/
중요 보관/파일 참조 개수를 추가했다. 보관 파일 열기/외부 저장/전체 백업은 고정 내용 검증을
사용한다. 개별 첨부 화면의 검사를 모든 중요 보관 파일의 새 일괄 전수검사로 확장한 것은 아니다.

새 스키마는 0013 → 0014(이력/명령 영수증) → 0015(중요 보관/파일)다. 기존 파일의 경로/내용을
움직이거나 다시 원본 지정하지 않는다. 이행과 전체 백업/복원은 격리 자료에서 검증했으며
새 DB/백업을 지원하지 않는 공개 구버전으로 되돌려 열면 안 된다.

## 6. 실제 중단·실패 검사

단일 파일 문서 저널과 구별되는 `.operations/snapshot-<job_id>` 부모 원장을 사용한다.
출처와 자기 소유 준비/공개 파일을 구분하며 fsync·검증 후 자산/묶음/모든 파일 참조/영수증을
한 DB 트랜잭션에 확정한다. 확정 전 중단이면 자동 등록하지 않고 자료를 보호한다.

- 실제 자식 프로세스를 보관의 journal/copied/prepared/published/committed/finished 6경계에서 종료했다.
  확정 전 묶음 없음, 원본 유지, 준비 자료 확인 후 정리, 확정 뒤 영수증 재인식/중복 방지를 확인했다.
- 업무 변경도 이력/영수증 INSERT·커밋 후 통지·반환 4경계에서 실제 자식 프로세스를 종료했다.
  확정 전 전부 롤백, 확정 후 재시도 중복 없음과 현재 값 반환을 확인했다.
- 캡처 중 체크리스트/파일명/결과 변경, 두 번째 파일 누락·Windows 잠금, 같은 값으로 돌아온
  업무 변경, 고정 공유 참조와 업무 삭제 범위 승인, 수정/지원 불명 저널 보존을 검사했다.
- 준비 파일 정리는 승인 후 모든 대상의 소유/등록 여부·경로·읽기 핸들·고정 검증값을 확인한다.
  출처/재사용 frozen, 변경된 준비 파일, 검증값 없는 복사 중단 자료/불명 자료는 자동 삭제하지 않는다.
  확인 가능한 prepared/published 자기 소유 파일만 정리하고 나머지는 점검 대상으로 보존한다.
- 미확정 자료는 전체 백업의 recovery 영역으로 분리하며 복원 후 자동 등록/재실행하지 않는다.

## 7. 검사 결과

검사는 Python 3.12.4 / Windows / PySide6·Qt 6.11.2에서 격리된 임시 프로필로 수행했다.
중간 실패/중단, 반복 실행과 아래 집중 검사를 최종 고유 검사 수에 더하지 않는다.

| 최종 분리 범위 | 결과 |
| --- | --- |
| unit + integration | 657개 통과 / 159.08초 |
| UI | 318개 통과 / 128.16초 |
| performance | 5개 통과 / 5.76초 |
| Ruff / mypy | 통과 / 소스 113개 |
| diff 공백 검사 | 통과 |

최종 분리 검사는 같은 최종 소스에서 모든 검사 디렉터리를 포함하며 합계 **980개 통과**다.
UI만 표시 문구/스트레스 검사를 마지막에 보완했으므로 전체 UI와 영향 범위를 다시 실행했다.

최종 회귀 실행에는 `-o addopts= -o faulthandler_timeout=30 --tb=short`를 사용했다.
UI 진단 재실행은 `-vv --capture=tee-sys --log-file=.test-tmp/phase3-final-ui.log`로 시험 위치도 남겼다.
이력/보관 화면 최종 영향 검사 16개는 28.80초에 통과했다.

실측 집중 검사(2개 재실행, 7.31초):

- 업무 5,000개 + 자동 이력 50,000건 + 중요 보관 50,000건: 첫 50행 **5.05ms**, 다음 **3.19ms**.
  요약 조회 SQL에 before/after/info 본문이 없는 것과 50행 제한/중복 없음도 검증했다.
- 1GiB 변경 가능한 파일 중요 보관: peak RSS 증가 **2,600,960 bytes (약 2.48MiB)**,
  처리 **1.906초**, 경고 없음. 실제 Windows 별도 프로세스의 메모리를 측정했다.
  디스크/보안 검사/파일 내용에 따라 시간은 달라지며 모든 PC의 속도를 보장하지 않는다.
- 이력/상세 창 100회 열기·닫기: worker/QThread·이벤트 구독·Python 객체 참조 잔존 없이 해제.
- 20,000줄 한글 원문 비교: 강조 생략 안내와 전/후 전체 내용 유지, 닫기 정상 동작.

## 8. 가독성 검사와 이번에 바로잡은 부분

설치된 맑은 고딕/Segoe UI를 사용한 Windows Qt offscreen renderer에서 새 목록·보관 입력·보관 상세·
비교·중단 작업 5화면을 480×520 logical px로 렌더링했다. 밝은/어두운 Window/Base와 검은 Text
palette, 100%·150%·200% 6조합에서 버튼/날짜 좌표·창 폭·DPR을 검사하고 대표 PNG를 직접 확인했다.
대표 캡처는 ignored `.test-tmp/phase3-visual/final-review-scale2-dark`에 남겼다.

- 공통 밝은 스타일 외에 내부 viewport/글자·배경 쌍과 읽기 창 palette를 명시했다.
- 날짜 내부 QLineEdit에 일반 입력 padding이 겹쳐 요일이 잘리는 문제를 수정했다.
- 좁은 목록의 필터/기간/버튼을 정돈해 상세를 열어도 목록 공간을 유지했다.
- 긴 본문 비교는 UI thread에서 계산하지 않고 강조 예산/원문 보존을 분리했다.
- 저장/보관 후 응답만 실패한 재시도, 상태 완료 취소, 결과메모 충돌의 실제 처리 경계를 보완했다.
- UNION 전체 정렬 조회 병목을 분기별 제한으로 바꾸고 큰 보관 header의 파일별 반복 로딩을 제거했다.
- 기존 스키마 전용 시험 fixture는 이력 연결을 명시적으로 끄며, 프로덕션에서 새 테이블 누락을
  무시하고 기록 없는 저장을 성공시키는 fallback은 넣지 않았다.

OS 다크 모드/배율 설정 자체의 live 전환, 실제 업무 PC의 DRM·보안 정책,
실제 한글/Excel 편집기의 저장/잠금, 장기간 사용까지 검사했다고 하지 않는다.
보관 내용 고정은 앱의 관리 경계이며 운영체제 밖에서 내부 폴더를 임의 변경해도 항상 복구할 수 있다는
보장이 아니다. 전체 백업과 필요한 외부 사본 보관은 계속 필요하다.

최종 UI 재검사 한 번은 48개 내외 진행 뒤 요약/stack 없이 exit 1로 종료했다.
이를 통과로 계산하지 않았다. 원인/실패한 시험 위치는 당시 출력만으로 확정하지 못했고
Qt/native 또는 외부 종료로 단정하지 않는다. 위 진단 전체 재실행은 318개가 정상 종료했고
같은 중단은 재현되지 않았다. 앞선 전체 315/316개, 영향 16개와 최종 318개 통과가 원인 해결
증거라고 설명하지 않는다. 재발 시 시험 위치/stack/프로세스 종료 기록을 수집할 점검 항목으로 남긴다.

## 9. 사용자 사용 확인과 다음 단계

공개 실행 파일이 아닌 현재 개발 소스를 사용한다. 실행 중인 OfficeFlow를 트레이에서도 종료하고
저장소의 `run-officeflow-dev.cmd`로 실행한다. 중요한 실제 첨부 대신 시험 파일로 먼저 확인한다.
이 실행은 저장소의 ignored `.local-data` 개발 프로필을 사용한다. 실제 설치/Python 운영 프로필인
`%LOCALAPPDATA%/OfficeFlow`를 이번 자동 검사와 섞지 않았다. 개발 실행을 사용자가 직접 하면
개발 프로필은 새 스키마로 이행하므로 지원하지 않는 옛 개발 소스로 되돌려 열지 않는다.

1. 업무 설명 수정 → 이력·보관 → 변경 전/후. 같은 내용 저장 시 새 변경이 없는지 확인한다.
2. 완료+결과메모 → 하나의 변경, 실행 취소 → 별도 상태 변경을 확인한다.
3. 파일 없이 현재 상태 보관 → 나중에 설명 수정 → 당시 내용/현재와 비교.
4. 시험 첨부 둘을 선택해 보관 → 현재 작업본 수정 → 보관 파일의 내용이 그대로인지 확인한다.
5. 중요 보관 상세에서 파일 여러 개 외부 저장, 파일 하나로 새 작업본 생성.
6. 이력·보관 두 시점 비교, 기간/범위 필터, 좁은 창의 원문 스크롤·한 페이지 이동 숨김.
7. 휴지통 조회/외부 저장과 새 보관 금지. 영구 삭제는 불필요한 시험 업무에서만 확인한다.

사용 확인 후 필요하면 버튼 문구/기본 위치를 조정하고 별도 요청으로 중간 커밋한다.
배포 전에는 개발 소스의 새 스키마/백업 호환과 실제 PC 가독성을 확인한다.
이번 작업만으로 기존 EXE/배포 ZIP/설치 파일/GitHub가 업데이트되지 않는다.

## 10. 사용 확인 후 체크박스 가독성 보완 (2026-10-09)

사용자가 보관 입력의 파일 체크박스를 발견하지 못했다고 보고했다. 목록의 체크 표시는
QCheckBox 위젯이 아니라 delegate가 그리는 item-view indicator라서 기존 QCheckBox 테마가
적용되지 않고 시스템의 연한 기본 표시를 사용하고 있었다.

- 보관 입력/보관 상세의 체크 가능한 목록에 한정해 20px 표시 영역, 2px 파란 테두리와
  체크 시 파란 배경/흰색 ✓를 직접 렌더링한다. 비활성도 체크 표시를 유지한다.
- 최소 34px 한 줄 행으로 클릭 영역을 확보하고 긴 이름 생략/세로 스크롤은 유지한다.
  `CompactFileDelegate`를 쓰는 기존 첨부/보관함 화면에는 새 delegate를 적용하지 않았다.
- 보관 입력에는 `첨부파일도 보관하려면 왼쪽 □를 체크하세요`, 보관 상세에는
  `여러 파일을 저장하려면 왼쪽 □를 체크하세요`를 표시한다.
- 파일 행 강조 선택과 체크를 합치지 않는다. 기본 0개 선택·100개 제한·다른 페이지의 체크
  유지·문서 저장/닫음 확인·당시 내용 고정 정책은 그대로다. 상세의 체크 개수도 즉시 갱신한다.
- 기존 클릭 동작과 선택 행에 Space로 체크/해제하는 동작을 유지한다. 저장·복사·DB 구조·버전은 바꾸지 않는다.

수정 전 4개 회귀가 행 높이 조건에서 실패하는 것을 확인했다. 수정 후 관련 22개
(보관 8 / 이력 6 / 배율·palette 6 / 테마 2)가 **29.89초에 통과**했다.
Ruff 전체 검사·mypy 소스 113개·`git diff --check`도 통과했다.
확인은 격리된 자료로 수행하며 앞선 전체 980건과 중복 합산하지 않는다.
100%·150%·200%/밝은·어두운 palette 6조합에서 미체크/체크/비활성 PNG와 버튼 좌표를 검사했다.
200% 어두운 환경의 대표 캡처를 직접 확인했고 `.test-tmp/phase3-check-visibility/scale2-dark`에 남겼다.
