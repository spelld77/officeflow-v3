# 외부 폴더 바로가기와 업무 묶음 외부 보관: 공통설계

승인: 2026-10-10 사용자 구현 요청. 버전 3.0.9 이후 소스 개선이며 배포/커밋은 별도다.

## 목적과 경계

- 업무에 사용자가 관리하는 외부 폴더를 연결한다. URL/파일 바로가기는 제외한다.
- 짧은 업무 여러 개를 연도/기간별로 HTML·Excel·첨부 사본으로 묶어 앱 없이 읽는다.
- 내부 업무·첨부·이력 삭제, 자동 정리, DB 축소, 외부 폴더 내용 수집은 하지 않는다.
- 외부 보관은 읽기용 스냅샷이다. 전체 백업/복원 및 재가져오기 기능이 아니다.

## 소유권과 데이터

폴더 연결은 업무 공통 ID에 소속된다. 반복 회차마다 복제하지 않는다.
새 DB 테이블에 ID·업무 ID·이름·절대 경로·순서·등록 시각을 저장한다.
휴지통에서는 조회/열기만, 영구 업무 삭제 시 연결 행만 cascade 삭제한다.
DB 전체 백업에는 연결이 포함되지만 외부 폴더 내용은 포함되지 않는다.
0015 → 0016 이행은 테이블 추가만 하고 기존 업무/파일을 이동하거나 바꾸지 않는다.
스키마 보호 사본/구버전 차단은 기존 migration 계약을 따른다.

외부 보관은 새로운 전용 폴더를 예약하여 기존 자료를 덮어쓰지 않는다.
미완료 표식으로 시작하고 HTML·Excel·파일·manifest를 모두 검증한 후 완료 표식을 만든다.
오류/취소/전원 중단은 미완료 폴더로 남긴다. 사용자 폴더를 자동 청소하지 않는다.
선택 자료 하나라도 읽지 못하면 정상 완료로 표시하지 않는다.
HTML/XLSX에는 선택 범위, 제외 대상, 생성 시각, 각 업무 캡처 시각을 남긴다.
서로 다른 업무/파일 전체를 정확히 같은 순간에 동결했다는 의미는 아니다.

## 안전과 성능

UI → Application → Repository/Storage 경계를 유지한다. Qt worker는 별도 DB session을 쓴다.
외부 경로 검증/열기 전 존재 확인/복사/해시는 worker에서 한다. 시작할 때 외부 경로를 조사하지 않는다.
관리 데이터/첨부/캐시 내부 폴더는 연결/출력 대상으로 거절하며 junction의 실제 경로도 검사한다.
폴더가 없거나 접근이 막혀도 연결을 지우지 않는다. 이름/위치 변경은 수동 재지정한다.
파일 복사는 기존 ExternalExportStorage의 안정적인 읽기·청크 복사·해시·무덮어쓰기 저널을 재사용한다.
공통 heavy-job 슬롯, 파일 pin을 사용한다. 긴 복사 중 DB write transaction을 열어두지 않는다.
파일 준비 전 캡처한 메타데이터를 해당 업무 복사 후 재검사한다. 변경 시 묶음 완료를 거절한다.
HTML은 텍스트를 escape하고 외부 네트워크 자원을 쓰지 않는다. 검색은 접힌 상세도 포함한다.
Excel은 문자열을 수식으로 실행하지 않으며 셀 길이 제한을 초과한 내용은 분할 시트로 보존한다.
한 묶음 최대 업무 5,000개, 업무별 각 자료 종류 5,000개. 초과 시 기간을 나누도록 안내한다.
파일 내용은 메모리에 통째로 읽지 않는다. 업무 한 개씩 문서를 기록한다.
알림/주 화면은 보관 중에도 작동한다. 닫기/종료는 취소 요청과 안전한 worker 종료를 따른다.

## UI 계약

기존 업무 기록 창에 `폴더` 탭, 목록/달력 오른쪽 메뉴에 `폴더 바로가기…`를 추가한다.
새 업무 입력 Tab 동선에 연결 설정을 끼워 넣지 않는다.
데이터 → 내보내기·백업 → `업무 묶음 보관…`에서 연도/기간/선택 업무를 고른다.
밝은 배경/글자색을 명시하고 좁은 창, 긴 이름, 스크롤, 선택/비활성 색을 검사한다.

상세 및 검증은 [47번 설계](47-folder-and-external-archive-detail.md)를 따른다.
구현·회귀 검사 결과와 배포 전 사용자 확인은 [48번 보고](48-folder-and-external-archive-results.md)에 기록한다.
