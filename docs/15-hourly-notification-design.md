# 매시 정기 알림 설계

- 작성일: 2026-10-01 (Asia/Seoul)
- 기준 버전: OfficeFlow 3.0.3
- 상태: 실행 코드·자동 테스트·도움말 반영 및 사용자 개발 실행 확인. 3.0.4 릴리스 검증·GitHub 공개 완료 (2026-10-02).
- 목적: 실제 근무 중 인사랑의 시간대별 업무기록을 잊지 않도록 독립적으로 안내한다.
- 확장 용도: 알림 문구와 제외 시간을 바꿔 매시간 확인·휴식 등의 안내에 사용한다.
- 보완: 평일 공휴일 설정, 늦은 오전 실행 제외, 05시 등 이른 사용·전날 실행의 08시 자동 연속 안내 반영.

### 구현 후 UI 정돈 (2026-10-01)

사용 확인 후 하단 상태는 `다음 20:35` / `재알림 19:45`처럼 짧게 표시하고 구간 처리 상태는
툴팁·메뉴로 옮겼다. 팝업은 `5분 뒤 알림 / 닫기 / ...` 한 행으로 정리하고 중복 문구를 줄였다.
아래 초안의 `평일 08시 연속 조건 적용`은 UI에서 `늦게 켜도 08시 알림 받기`(기본 끔)로 표현한다.
체크하면 저장된 morning_continuation_required를 false로 적용한다. 이름을 쉬운 긍정 표현으로
바꾼 것이며 이전 설정값과 시간 판정 규칙은 유지한다. 수동 예외 재개는 `오늘 08시 알림 받기`로 표시한다.

## 1. 제품 원칙과 범위

1. 기록 단위는 마지막 기록 후 60분이 아니라 `18:00~18:59`, `19:00~19:59` 같은 시각 구간이다.
2. 앱을 새로 시작하면 항상 활성화한다. 켜기를 잊어서 안내를 놓치지 않도록 한다.
3. 알림을 꺼도 현재 실행에만 적용한다. 다음 프로세스 실행에는 꺼짐을 복원하지 않는다.
4. 인사랑의 연결·로그인·자체 알림과 무관하게 로컬 시각으로 작동한다.
5. 인사랑을 자동 클릭하거나 업무기록을 전송·조회하지 않는다. 근무 인정이나 기록 완료를 보장하지 않는다.
6. 업무·반복 일정·업무일지·알림 처리 이력을 생성하지 않는다.
7. 사이드바나 업무 목록에 새 관리 화면·행별 버튼을 추가하지 않는다.
8. 공휴일 캘린더·근무요일 편집·날짜별 예외 목록·외부 API·새 상주 프로세스는 도입하지 않는다.
9. 앱 실행 시각은 실제 출근 시각의 증거가 아니다. 앱의 ON 구간은 알림을 이어주는 기준으로만
   사용하고 실제 출근·업무기록·초과근무 인정이 확인된 것으로 표현하지 않는다.

사용자가 승인한 핵심은 자동 활성화, 평일/주말 기본 시간, 알림 분 변경, 이번 시간 제외,
실행 동안만 끄기, 대상 시간의 시작 알림, 평일 공휴일 낮의 알림, 08시 이후 처음 실행의 아침 안내 제외,
05시 등 이른 사용에서 08시까지 추가 선택 없는 연속 안내다.
이 문서의 아침 연속 상태 보존·예외적인 재개 UI·5분 미루기·시각 변경·창 갱신 등은
그 핵심을 일관되게 구현하기 위한 권장 세부 규칙이며 실제 구현 전 수정할 수 있다.

## 2. 용어와 기본값

제품 이름은 **매시 알림**으로 통일한다. 설정 제목은 `매시 알림 설정`, 기본 문구는
`인사랑 업무기록을 확인하세요.`다. `완료`, `기록 완료`, `근무 인정` 같은 표현을 사용하지 않는다.

| 항목 | 기본 동작 |
|---|---|
| 실행 상태 | 새 프로세스마다 ON |
| 정기 알림 시각 | 매시 35분, 0~59분 변경 가능 |
| 평일 | 월~금, 09:00~18:00 제외; 08:00~09:00는 이전부터의 알림 흐름을 자동으로 이어주는 경우만 대상 |
| 주말 | 토·일, 하루 전체 대상 |
| 평일 공휴일 | `오늘 휴일근무` 선택 시 하루 전체 대상 |
| 시작 알림 | 대상이면 현재 구간 즉시 안내; 평일 08시 이후 첫 실행은 기본 아침 안내 없음 |
| 알림 소리 | OFF, 원하는 경우 설정에서 ON |
| 이번 시간 제외 | 현재 시각 구간만 제외, 실행 중에만 기억 |
| 전체 끄기 | 이번 프로세스 실행 동안만 OFF |

35분은 시험 사용을 위한 기본값이지 인사랑의 공식 마감 시각이 아니다.
사용자가 정한 시간대 규칙을 적용하며 법령상 초과근무 대상 여부를 판정하지 않는다.
아침 인정 조건은 사용자가 제공한 운영 규칙을 설계 전제로 사용한다. 인사랑이나 기관의 실제
인정 결과를 검증한 것으로 표현하지 않는다. 아침 연속 상태는 알림 유지 조건이지 출근 인증이 아니다.

## 3. 대상 시간 판정

### 3.1 기본 시간

앱 설정의 시간대(`AppSettings.timezone`, 기본 `Asia/Seoul`)로 요일과 시각을 계산한다.
모든 시간 구간은 시작 포함·끝 제외다.

- 월~금: `[00:00, 09:00)` 및 `[18:00, 다음 날 00:00)`.
- 토·일: `[00:00, 다음 날 00:00)`.
- 정확히 평일 09:00부터 제외, 정확히 18:00부터 대상이다.
- 자정에는 날짜와 요일을 다시 평가한다. 금요일 밤→토요일, 일요일 밤→월요일도 같은 규칙이다.

위 목록은 기본 시간표이며 평일 08:00~09:00는 3.4의 연속 안내 조건을 적용한다.
`오늘 휴일근무`를 선택한 날짜는 평일 기본 제외와 아침 연속 조건을 적용하지 않는다.

판정 순서는 다음과 같다.

```text
이번 실행 OFF                     -> 모든 매시 알림 중지
추가 제외 시간에 해당             -> 제외
평일 업무시간이고 오늘 휴일 아님  -> 제외
평일 08시이고 오늘 휴일 아님,
  앞선 알림 흐름/예외 재개 없음   -> 제외
현재 구간을 닫음/건너뜀           -> 현재 구간만 제외
그 외                            -> 알림 가능
```

### 3.2 설정 가능한 제외 시간

기본 화면에는 `평일 제외 시간 [09:00] ~ [18:00]` 한 행만 둔다.
토·일은 이 평일 제외를 적용하지 않는다. 주말용 별도 시간표는 만들지 않는다.

접힌 `추가 설정`에서 모든 요일에 적용할 추가 제외 시간(최대 8개)을 등록할 수 있다.
이는 점심·휴식·야간 무음 등 범용 활용을 위한 옵션이며 기본은 빈 목록이다.
같은 시작/끝은 모호하므로 오류로 안내하고, 중복·겹침은 정규화한다.
자정을 넘는 구간은 내부에서 두 구간으로 나누되 화면에는 입력한 한 구간으로 보여준다.

설정한 매시 분이 제외 시간에 들어가면 그 시각의 정기 알림은 생략한다.
제외 구간을 피해 임의의 다른 시각으로 옮겨 울리지 않는다.
사용자 지정 제외 시간 때문에 일부 시각 구간에 정기 알림이 없을 수 있으며 다음 알림 예시로 안내한다.
48시간 안에 정기 알림 후보가 없으면 `현재 설정에서는 다음 48시간 알림 없음`을 표시한다.

### 3.3 평일 공휴일의 간단한 대응

공휴일을 자동 판단하지 않는다. 트레이의 매시 알림 하위 메뉴와 설정창에
`오늘 휴일근무` 체크 항목을 제공한다. 추석 등 평일 공휴일에 선택하면 그 날짜를 주말과 같은
하루 전체 대상으로 취급한다. 따로 공휴일 목록이나 달력 관리 화면을 만들지 않는다.

이는 오늘 날짜의 평일 기본 제외와 08시 아침 연속 조건만 해제한다.
추가 제외 시간·이번 실행 OFF·이번 구간 건너뛰기는 해제하지 않는다.
선택 날짜 하나만 설정 파일에 보존하여 같은 날 재실행해도 낮의 알림이 다시 제외되지 않게 한다.
날짜가 바뀌면 효력을 잃고 다음 실행/설정 저장에서 만료 값을 제거한다.
여러 날 연휴는 해당 날짜마다 선택하며 날짜 예외 목록은 쌓지 않는다.
토·일에는 이미 같은 규칙이므로 선택을 비활성화하고 `주말은 기본 하루 전체`라고 안내한다.

적용하면 실행이 ON이고 현재 구간이 미처리인 경우 즉시 안내한다.
이는 저장된 매시 분을 바꾸는 동작과 구분되는 명시적인 대상 시간 확장이다.
되돌려 현재가 제외되면 열린 창과 미루기를 취소한다.
재실행 시 OFF를 해제하는 규칙과 날짜 유형 설정 보존은 별개다.

### 3.4 평일 아침의 연속 알림

사용자가 제공한 전제는 다음과 같다.

- 정상 평일에는 08:00 전에 인사랑 출근과 필요한 업무기록을 해야 08:00~08:59 기록 안내가 의미 있다.
- 08:00 이후 출근한 경우 08시 구간에 초과근무용 출근·기록 안내를 하지 않는다.
- 토·일 및 사용자가 지정한 `오늘 휴일근무`에는 이 조건을 적용하지 않는다.

매번 조기출근 조건을 선택하게 했던 초안을 대체한다. 이른 시각부터 알림이 작동하고 있다면
08시도 자동으로 이어야 하며, 05시에 사용을 시작한 사람에게 07시에 추가 버튼을 누르게 하지 않는다.

1. **08시 전에 시작된 ON 구간이면 08시를 자동 포함한다.**
   실제 초기화 또는 OFF→ON 전환 시각을 `active_since`로 메모리에 둔다.
   해당 날짜 08:00보다 이전에 시작한 ON 구간이 이어지면 그 날짜의 아침 연속 상태를 자동 설정한다.
   실제 자동 설정은 현재 시각이 그 날짜 09:00 이전일 때만 수행한다. 09시 이후에는 만료한 값을
   검사마다 다시 만들지 않는다. 미래 다음 시각 계산에서도 설정 파일을 쓰지 않는다.
   05시 실행은 시작 안내→06시→07시→08시로 이어지고, 07:59 실행도 08시를 포함한다.
   마지막 알림을 닫거나 특정 구간을 건너뛰는 것은 뒤 구간 전체를 중지한 것이 아니므로 연속 상태를 취소하지 않는다.
2. **전날부터 실행 중이고 ON이 이어진 경우도 포함한다.**
   자정에 실제 출근 날짜를 추정하지 않고 새 날짜의 08시까지 알림을 이어주는 규칙을 적용한다.
   날짜가 바뀐 뒤 첫 검사가 절전 복귀로 08시 이후가 되어도, 이전부터 이어진 ON 구간이면 연속 상태를 적용한다.
   앱이 켜진 PC만 남아 있어도 안내가 올 수 있다. 이는 자동 알림의 알려진 한계이며
   실제 근무하지 않을 때 `이번 실행 동안 끄기` 또는 해당 구간 건너뛰기로 중지한다.
3. **08:00~08:59에 처음 실행하고 유효한 아침 연속 상태가 없으면 아침 안내를 하지 않는다.**
   시작·정기·복귀·창 갱신 모두 동일하게 제외한다. 08:30 늦은 출근자에게 출근·기록을 요구하지 않는다.
   08시 이후 ON으로 바꾼 것만으로 새로운 조기출근 조건을 충족한 것처럼 안내하지 않는다.
4. **이미 시작한 아침 알림 흐름은 재실행으로 잃지 않는다.**
   아침 연속 상태는 날짜 하나만 설정 파일에 보존하고 해당 날짜 09:00에 만료한다.
   05시 실행 후 08:30에 재실행하면 새 실행 ON 및 현재 구간 안내를 적용한다.
   저장하는 것은 알림 연속 조건이지 출근 시각·업무 내용·기록 성공·완료 이력이 아니다.
5. **실제 조기출근했지만 앱만 늦게 켠 예외는 수동 재개한다.**
   트레이/설정에 `아침 알림 재개`를 평일 08:00~09:00에만 노출한다.
   안내는 `08시 전에 인사랑 출근·업무기록을 했는데 앱을 늦게 켠 경우`로 명확히 한다.
   선택하면 같은 날짜의 연속 상태를 설정하고, ON이며 현재 구간이 미처리이면 즉시 안내한다.
   OFF·이번 구간 건너뛰기·추가 제외는 자동으로 해제하지 않는다. 선택으로 인사랑이 처리되지 않는다.
   이미 연속 상태가 있거나 주말/오늘 휴일근무이면 별도 선택이 불필요하므로 숨긴다.
6. **08시 이전 안내에는 조건부 문구만 보조로 둔다.**
   `조기출근 초과근무라면 08시 전에 인사랑에서 출근과 업무기록을 직접 해주세요.`
   이를 닫는 행위를 기록 성공 확인으로 취급하지 않는다. 자동 연속에 추가 확인은 요구하지 않는다.
7. **09:00에 기본 업무시간 제외로 돌아간다.**
   아침 연속 값과 관련 미루기는 만료하고 다음 아침에 같은 값을 자동 승계하지 않는다.
   단, 같은 프로세스의 ON이 다음 날에도 이어지면 그날의 연속 상태를 새로 계산할 수 있다.
8. **사용자가 지정한 제외는 항상 우선한다.**
   기본 평일 제외 시간 또는 추가 제외 시간에 해당하면 아침 연속 상태로 그 제외를 해제하지 않는다.
   연속 흐름을 만든 날짜에 명시적으로 OFF였고 연속 상태도 없는 경우, OFF 상태로 오래
   프로세스만 켜져 있었다는 이유로 08시 이후 다시 ON할 때 연속 상태를 만들어서는 안 된다.

08시 이전 실행을 출근 사실로 인증하는 것은 아니며, 알림을 이어주는 자동 기준으로만 사용한다.
프로그램 시작과 실제 출근이 다른 예외는 위의 재개 경로로 처리한다. 아침 알림 전용 확인 버튼을
매일 눌러야 하는 설계는 사용자가 원하는 자동 누락 방지와 맞지 않아 채택하지 않는다.
범용 확인/휴식 알림으로 사용할 때는 접힌 추가 설정에서 `평일 08시 연속 조건 적용`을
해제할 수 있다. 기본은 ON이며 인사랑용 안내 조건임을 표시한다.

## 4. 시각 구간과 스케줄

### 4.1 구간 식별

한 구간은 해당 지역 시각의 정각부터 다음 정각 직전까지다.
DTO에는 `hour_key`, `starts_at`, `ends_at`을 시간대가 있는 시각으로 전달한다.
키는 지역 날짜·시각·UTC 오프셋을 포함하여 서로 다른 실제 구간을 구분한다.
이 문서의 기본 사용자 시각은 한국 시각이며 다른 시간대도 앱의 기존 설정을 따른다.

일정은 지역 시각으로 만들고 UTC 시각으로 비교한다. 존재하지 않는 지역 시각은 제외하며,
오프셋 변경으로 같은 시각이 두 번 생기는 경우 실제 구간 키로 중복을 구분한다.
알림 간격을 `확인한 시각 + 60분` 또는 `타이머 시작 + 60분`으로 계산하지 않는다.

### 4.2 시작

- 데이터 준비·복원·단일 인스턴스 확보·시작 경고 처리가 끝난 후 초기화한다.
- 새 실행의 상태는 항상 ON이다. 이전 프로세스의 OFF·닫힘·건너뛰기·미루기는 읽지 않는다.
- 오늘 휴일근무/아침 연속의 유효한 날짜 한정 설정을 읽고 자동 연속 조건을 계산하되 출근 사실은 추론하지 않는다.
- 현재 시각이 대상이면 현재 구간을 1회 즉시 안내한다. 다음 정기 알림은 그 다음 구간이다.
- 현재가 제외 시간이면 시작 알림도 없고 다음 허용 정기 시각만 계산한다.
- `--background`로 실제 새 프로세스를 실행한 경우도 동일하다.
- `--smoke-test`와 기본 UI 테스트는 명시적으로 매시 알림을 비활성화하여 시험 중 실제 알림을 막는다.

예: 매시 35분 설정에서 19:10 또는 19:45에 새 실행하면 19시 구간을 즉시 안내한다.
그 구간을 닫은 뒤 다음 정기 알림은 20:35이며 19:35를 중복 생성하지 않는다.
평일 17:50에 시작하면 즉시 안내하지 않고 첫 정기 알림은 18:35다.
평일 08:30 최초 시작은 아침 연속 상태가 없으면 안내하지 않고 다음 알림은 18:35다.
앞서 05시부터 사용해 유효한 아침 연속 상태가 있거나 오늘 휴일근무이면 현재 구간을 즉시 안내한다.
18:00 진입 자체로 별도 알림을 추가하지 않는다.

### 4.3 정기 알림

짧은 타이머는 현재 시각과 해당 구간의 예정 시각만 비교한다.
정기 시각을 지난 첫 검사에서 해당 구간을 1회 안내한다. 같은 구간의 시작 알림·복귀 알림이
이미 열려 있거나 닫힘/건너뛰기 상태라면 정기 시각을 지나도 추가 생성하지 않는다.
최초 안내와 미루기의 재안내는 구분한다.

백그라운드 타이머의 검사 주기는 5초로 제안한다. 검사당 DB·파일·네트워크 접근을 하지 않는다.
타이머의 정확한 초 단위 발화를 보장하지 않고 정상 응답 중 예정 시각 후 5초 내 표시를 목표로 한다.
UI 스레드가 막힌 경우 밀린 구간을 순회하지 않고 다음 검사에서 현재 구간만 판정한다.

### 4.4 분 변경

저장 성공 후 다음 정기 시각과 표시를 즉시 재계산한다. 꺼진 상태를 자동으로 켜지 않는다.
이미 닫거나 건너뛴 현재 구간은 분을 바꿔도 해제하지 않는다.

- 19:20에 35분→45분: 현재 구간 미처리라면 19:45.
- 19:20에 35분→15분: 지난 19:15를 소급 안내하지 않고 20:15.
- 시작 알림을 처리한 19시 구간: 어느 분으로 변경해도 다음 구간부터 적용.
- 열려 있는 알림은 유지하고 다음 정기 시각만 갱신. 대기 중인 5분 미루기는 유지한다.
- 제외 시간 변경으로 현재가 제외되면 창과 미루기를 취소한다.
- 설정 변경으로 지난 시각을 새 알림처럼 만들지 않는다. `지금 확인`이라는 별도 동작도 추가하지 않는다.

59분 설정은 금지하지 않되 `기록할 여유가 짧고 표시가 지연될 수 있습니다`를 안내한다.

## 5. 실행 중 행동

| 행동 | 결과 | 재실행 후 |
|---|---|---|
| 이번 시간 알림 닫기 | 현재 구간 추가 안내 중지 | 기억하지 않음 |
| 이번 시간 건너뛰기 | 알림 전에도 현재 구간 제외 | 기억하지 않음 |
| 건너뛰기 취소 | 현재 구간 제외 취소 | 기억하지 않음 |
| 5분 후 다시 알림 | 현재 구간 안에서만 재안내 | 기억하지 않음 |
| 이번 실행 동안 끄기 | 매시 알림·창·미루기 중지 | 반드시 ON |
| 다시 켜기 | 대상인 현재 구간을 즉시 재평가 | 새 실행은 ON |
| 오늘 휴일근무 | 오늘 평일 기본 제외·08시 연속 조건 해제 | 오늘 날짜에 한해 유지 |
| 아침 알림 자동 연속 | 08시 이전부터의 ON 구간을 08시까지 이어줌, 사용자 선택 불필요 | 오늘 09:00까지 유지 |
| 아침 알림 재개 | 실제 조기출근했지만 앱을 늦게 켠 예외의 현재 구간 안내 | 오늘 09:00까지 유지 |

재실행 때는 알림 처리 일시 상태를 초기화하므로 대상 시간에는 이미 기록한 구간에도 시작 안내를 다시 볼 수 있다.
날짜 한정 대상 설정은 유효할 때만 보존하며 꺼진 상태나 기록 처리 이력을 보존하는 것은 아니다.
이는 기록 여부를 추정하지 않고 누락 방지를 우선하는 명시적인 제품 선택이다.
트레이로 숨기기·최소화·기존 프로세스 다시 열기는 재실행이 아니므로 상태를 초기화하지 않는다.
두 번째 실행 요청이 기존 프로세스를 활성화하는 경우에도 OFF를 강제로 ON으로 바꾸지 않는다.

### 5.1 닫기와 건너뛰기

알림 닫기는 인사랑 기록 완료가 아니라 그 시간대의 안내를 종료한다는 뜻이다.
알림의 X와 Escape도 `이번 시간 알림 닫기`와 같으며 업무 알림의 강제 처리 규칙을 가져오지 않는다.
트레이·상태 메뉴의 `이번 시간 건너뛰기`는 현재 지역 시각 구간에 적용한다.
같은 구간의 열려 있는 창과 미루기도 취소한다. 건너뛰기 취소는 해당 구간만 되돌린다.
취소 시 대상이고 정기 시각이 지났으면 1회 즉시 안내하며, 아직 전이면 정기 시각을 기다린다.

### 5.2 5분 미루기

미루기는 사용자 편의를 위한 명시적 재안내이고 다음 구간의 정기 시각을 변경하지 않는다.
`현재 시각 + 5분`이 현재 구간 끝보다 앞이고 대상 시간인 경우에만 허용한다.
다음 구간·제외 시간으로 넘어가면 버튼을 비활성화하고 `이번 시간 안에 5분 뒤 재알림 불가`를 표시한다.
예: 19:54→19:59 가능, 19:55→20:00 불가. 앱 지연으로 이미 구간이 끝났으면 취소한다.
버튼 클릭 시에도 시각을 다시 확인해 오래된 활성 상태를 믿지 않는다.

### 5.3 다시 켜기

이번 실행 OFF 동안에도 시각 구간 경계를 추적하되 알림을 만들지 않는다.
다시 켜도 현재 구간을 명시적으로 건너뛴 상태라면 존중한다.
OFF→ON 시 `active_since`를 현재 시각으로 설정한다. 이전 ON 구간을 무조건 이어진 것으로 취급하지 않는다.
유효한 아침 연속 날짜가 있으면 존중하되, 없다면 08시 이후 재개만으로 자동 생성하지 않는다.
OFF로 숨긴 미처리 안내는 다시 켤 때 현재 구간에서 한 번 재개할 수 있다.
이미 닫은 구간은 자동으로 다시 열지 않는다. 완전히 새 실행만 모든 일시 상태를 초기화한다.

## 6. 절전·지연·시각 변경

- 시계 주입 인터페이스에서 벽시계(실제 날짜/시각)와 단조 시계를 함께 제공한다.
- 마지막 검사와 현재 검사의 간격이 90초 이상이면 복귀/지연으로 보고 현재 구간만 평가한다.
- OS 복귀 이벤트를 받을 수 있으면 즉시 검사하되 타이머 검사와 같은 키로 중복 제거한다.
- 현재가 대상이고 그 구간이 미처리라면 알림 분 이전이어도 현재 구간을 한 번 안내한다.
- 평일 08시에는 아침 연속 조건을 적용한다. 이전부터 ON이었다면 이어주고 08시 최초 실행은 제외한다.
- 절전은 사용자의 OFF가 아니므로 `active_since`를 초기화하지 않는다. 출근 사실을 인증하지 않는다.
- 같은 구간을 이미 닫거나 건너뛰었다면 다시 띄우지 않는다.
- 기다리던 미루기가 같은 구간 안에서 지났다면 한 번 재안내하고 과거 구간이면 취소한다.
- 시계가 앞으로 바뀌면 과거 알림을 몰아서 복구하지 않는다.
- 시계가 뒤로 바뀌어도 최근에 처리한 동일 키는 재안내하지 않는다.
- 시간대 변경 시 현재 구간을 재판정하고 이전 시간대의 창·미루기를 취소한다.

기존 업무 알림의 `놓친 알림 확인 범위`와 DB 복구 로직은 이 기능에 적용하지 않는다.
최근 구간 처리 키는 메모리에 최대 48개만 유지하고 과거 키를 제거한다.
일반 시간 이동의 중복을 막는 작은 실행 상태이며 사용자에게 기록 목록으로 제공하지 않는다.
임의의 큰 시각 역행·수동 시간대 변경 전후의 무제한 중복 방지는 보장하지 않는다.

## 7. 표시 중 시간대가 바뀌는 경우

표시된 창과 버튼은 항상 최신 구간 식별자를 가진다. 오래된 버튼 신호는 무시하고 상태를 갱신한다.

- 다음 구간도 대상이고 이전 창이 미처리로 남아 있으면 그 한 창을 현재 구간 안내로 갱신한다.
  이미 보이는 안내를 최신화한 것이므로 그 구간의 안내로 취급하며 정기 분에 별도 창을 추가하지 않는다.
  구간 경계 갱신 자체에는 소리를 내거나 창을 다시 활성화하지 않는다.
- 다음 구간이 제외 시간이면 창을 숨기고 이전 구간의 미루기를 취소한다.
- 같은 구간 안에서는 시간 경과만으로 창을 자동 닫지 않는다.
- 이전 시간대의 기록을 지금 처리할 수 있다고 안내하지 않는다. 이전 구간 미처리 목록도 만들지 않는다.

이 예외는 고정 시각에 새 창을 반복 생성하는 것보다 최신 시간대 안내와 방해 최소화를 우선한다.

## 8. UI와 접근 경로

### 8.1 트레이

기존 트레이 메뉴에 `매시 알림 >` 하나만 추가한다.

```text
OfficeFlow 열기
빠른 업무 등록
매시 알림 >
    다음 알림 20:35                 (상태, 클릭 불가)
    이번 시간 건너뛰기              (건너뛴 경우에만 취소로 변경)
    이번 실행 동안 끄기             (OFF일 때 다시 켜기)
    [ ] 오늘 휴일근무                (토·일에는 선택 불필요)
    아침 알림 재개                   (평일 08시 최초 실행 등의 예외에만 표시)
    알림 설정...
완전히 종료
```

다음 시각에는 날짜가 다르면 `내일 00:35`처럼 날짜 문맥을 표시한다.
이미 알림을 닫은 구간에는 `이번 시간 알림 닫힘`을 표시하고 건너뛰기/취소 항목을 비활성화한다.
상태를 클릭한 경우와 트레이 메뉴에서 동일한 QAction/컨트롤러 동작을 사용한다.
트레이가 없거나 Windows에서 숨겨져도 접근할 수 있도록 기존 `설정` 창에
`매시 알림 설정...` 진입 버튼을 제공한다. 사이드바 메뉴는 늘리지 않는다.

### 8.2 작은 상태 표시

메인 창 상태바의 짧은 버튼 하나와 트레이 툴팁으로 현재 상태를 전달한다.
일반적인 평일 업무시간 또는 08시 연속 흐름 없는 제외 중에는 상태바에서 숨기고 메뉴/툴팁에는 이유를 남긴다.
대상 시간에는 다음 시각, 미루기, 현재 구간 제외를 표시한다.
실행 OFF일 때는 작은 회색 `매시 알림 꺼짐` 표시를 남겨 켜졌다고 착각하지 않게 한다.

우선순위는 `꺼짐 > 추가/평일/08시 조건 제외 > 미루기 > 열려 있는 현재 안내 > 이번 구간 제외 > 다음 시각`이다.
다른 기능의 `statusBar().showMessage()`와 독립된 위젯으로 두어 백업·저장 안내에 지워지지 않게 한다.
작은 창에서는 `다음 20:35`처럼 줄이고 툴팁에 전체 규칙을 표시한다.
완료 실행 취소 버튼 등 기존 영구 위젯과 겹치지 않도록 너비를 제한한다.

### 8.3 설정

기본 필드는 문구, 매시 분, 평일 제외 시간 세 개다. 문구는 공백 제외 1~200자다.
저장 버튼에 `설정은 기억하지만 끄기는 이번 실행에만 적용됩니다` 안내를 붙인다.
오늘 휴일근무는 트레이 및 설정에서 직접 접근하게 한다. 아침은 자동으로 이어주며
실제로 조기출근했는데 앱을 늦게 켠 경우에만 아침 알림 재개를 노출한다.
평소 업무 화면에는 관련 버튼을 상시 추가하지 않는다.
추가 제외·소리·평일 08시 연속 조건 적용 여부는 접힌 추가 설정에 배치한다.
영구 ON/OFF, 켜기 예약, 자동 종료 시각, 근무요일·공휴일 편집은 넣지 않는다.
자동 종료 시각은 수동으로 매번 켜는 설계에서 나온 항목이므로 이번 자동 활성화 설계에서 제외한다.

설정창은 별도 modeless 대화상자로 열어 업무/파일/매시 알림을 동시에 처리할 수 있게 한다.
같은 설정창을 중복 생성하지 않으며 저장 직전에 최신 AppSettings에 해당 필드만 병합한다.
설정창이 열린 동안 변경된 창 크기·백업 설정·업무 보기 상태를 오래된 스냅샷으로 덮어쓰지 않는다.

### 8.4 알림창

```text
+----------------------------------------------+
| OfficeFlow · 매시 알림                     X  |
|----------------------------------------------|
| 인사랑 업무기록을 확인하세요.                |
|                                              |
| 현재 시간대: 19:00 ~ 19:59                    |
| 이미 기록했다면 이번 시간 알림을 닫으세요.    |
|                                              |
| 다음 정기 알림: 20:35                        |
|                                              |
| [ 5분 후 다시 알림 ] [ 이번 시간 알림 닫기 ] |
| [ 더 보기 v ]                                |
+----------------------------------------------+
```

더 보기에 이번 실행 동안 끄기와 설정을 둔다. 잘못 눌러 실행 전체를 끄는 것을 줄인다.
키보드 포커스를 받은 뒤에는 Tab 이동과 명시적 클릭/키로 동작한다.
표시만으로 Enter 입력을 가로채거나 어떤 버튼을 자동 실행하지 않는다.

## 9. 창 표시와 기존 업무 알림 공존

기존 `ReminderDialog`는 DB delivery를 받고 완료·대기·다시 알림·확인을 처리한다.
`present()`에서 중앙 배치와 `activateWindow()`를 사용하며 미처리 상태에서는 X 닫기를 거부한다.
그 클래스를 그대로 재사용하면 기록 없는 안내, 닫기 허용, 포커스 유지 요구와 충돌한다.
별도 `HourlyNotificationDialog`를 modeless 최상위 창으로 두되 아이콘·라이트 테마 등 스타일만 재사용한다.

- `WindowStaysOnTopHint`, `WA_ShowWithoutActivating`, 표시 경로에서 `activateWindow()` 금지.
- 다른 앱의 입력 포커스를 유지하고 실제 버튼 클릭 때만 일반 활성화를 허용한다.
- 첫 표시 때 작업 영역 중앙 근처에 배치하여 트레이 풍선만 놓치는 문제를 줄인다.
- 실행 중 사용자가 옮긴 위치는 같은 창 갱신에 유지한다. 화면이 사라지면 유효 작업 영역으로 보정한다.
- 소리 ON이어도 새 안내/사용자 미루기 재안내에만 1회, 매 검사·구간 갱신에는 소리 없음.
- 트레이 풍선을 동시에 띄워 이중 알림을 만들지 않는다.
- 표시용 창은 하나만 유지한다. 파일·검색 결과·업무 목록을 다시 조회하지 않는다.

기존 업무 알림은 우선순위를 유지하되 새 매시 창과 같은 자리에 겹치지 않도록 작은
NotificationCoordinator가 위치·표시 가능 여부만 조정한다. 업무 처리 로직은 이동하지 않는다.
업무 알림이 열려 있으면 매시 창을 같은 화면의 다른 유효 위치에 배치한다.
공간이 부족하면 상단 창을 계속 번갈아 올리는 대신 서로 접근 가능한 위치/표시를 유지한다.

실제 OS 네이티브 파일 선택창·Windows 보안 화면·독점 전체화면은 최상위 표시도 보장하지 않는다.
네이티브 대화상자로 Qt 이벤트 처리가 지연되면 복귀 검사로 현재 구간만 안내한다.
modeless 보장이 필요한 화면에서 부적절한 parent/modal 연결을 피하고 실제 Windows에서 확인한다.

## 10. 설정 저장과 실행 상태

### 10.1 영구 설정

기존 `%LOCALAPPDATA%\OfficeFlow\settings.json` 또는 사용자 지정 데이터 루트의 설정 파일을 사용한다.
권장 키는 평평하게 추가하여 기존 AppSettings/JsonSettingsStore와 통합한다.

```json
{
  "hourly_notification_minute": 35,
  "hourly_notification_message": "인사랑 업무기록을 확인하세요.",
  "hourly_notification_weekday_exclusion_start": "09:00",
  "hourly_notification_weekday_exclusion_end": "18:00",
  "hourly_notification_extra_exclusions": [],
  "hourly_notification_sound": false,
  "hourly_notification_morning_continuation_required": true,
  "hourly_notification_holiday_date": null,
  "hourly_notification_morning_continuation_date": null
}
```

`enabled`, `paused`, `last_recorded_at`, `last_delivery`, `skipped_hour`는 저장 키에 넣지 않는다.
기존 백업에는 설정만 포함되며 복원 후 실행 상태는 항상 ON이다. DB 스키마 변경은 필요 없다.
holiday_date는 선택한 하루가 지나면, morning_continuation_date는 해당 날짜 09:00에 만료한다.
두 키는 현재 유효한 날짜 또는 null 하나만 가지며 지난 날짜 목록을 누적하지 않는다.
백업 복원에서도 만료를 현재 시각 기준으로 검사한다. 출근 시각·기록 내용·기록 성공 상태를 뜻하지 않는다.
아침 연속 값은 해당 날짜 처음 설정될 때 한 번 저장하고 같은 날짜의 매 검사에서 다시 쓰지 않는다.
사용자 선택/취소·만료 정리도 원자적으로 저장하며 오래된 날짜 목록이나 주기적인 파일 쓰기를 만들지 않는다.
이 보존은 이전 초안의 `오늘 제외 해제는 재실행 시 초기화` 제안을 대체한다.
아침 연속의 자동 저장 실패는 현재 실행의 알림을 멈추지 않고 메모리 상태를 유지한다.
같은 실패로 검사마다 재저장하지 않고 재실행 보존이 안 될 수 있음을 상태/오류로 안내한다.

현재 설정 로더는 AppSettings 검증 실패 시 전체 기본값으로 돌아간다.
추가 필드의 잘못된 값은 필드별 기본값으로 보정하여 기존 자동 시작·백업·창 설정까지
초기화되지 않게 한다. 알림 분에서 bool을 int로 받아들이지 않는 등 타입과 범위를 함께 검사한다.
기존 설정 파일에 새 키가 없어도 새 기본값을 적용하고 기존 키는 보존한다.
사용자 설정/날짜 선택 저장 실패 시 실행 설정도 되돌리고 오류를 표시한다. 성공한 것처럼 적용하지 않는다.
자동 연속 값 저장 실패의 예외는 위 규칙을 따른다.

### 10.2 메모리 상태

- 실행 ON/OFF, 현재 구간 상태(대기/열림/닫힘/건너뜀/미루기).
- 미루기 시각 하나, 유효한 오늘 휴일근무·아침 연속 상태의 메모리 사본, 현재 ON 구간의 `active_since`.
- 최근 구간 중복 방지 키 최대 48개.
- 이전 검사 시각과 단조 시각, 알림창 참조 하나, 마지막 상태 DTO.

상태는 종료 시 폐기하며 백업·진단의 업무기록처럼 내보내지 않는다.
오류 로그에는 기술적 오류만 기록하고 매시간 문구·처리 시각·근무 기록을 누적하지 않는다.

## 11. 구현 계층과 변경 위치

| 위치 | 책임 |
|---|---|
| `domain/hourly_notification.py` (신규) | 시간 구간·제외 시간·순수 판정 및 검증 |
| `application/hourly_notifications.py` (신규) | 실행 상태·시작/검사/닫기/미루기/건너뛰기와 상태 DTO |
| `infrastructure/settings/store.py` | 저장 필드·호환성·필드별 보정 |
| `presentation/hourly_notification_controller.py` (신규) | 5초 QTimer, clock 주입, 상태/표시 신호 |
| `presentation/hourly_notification_dialog.py` (신규) | 비차단 단일 알림창과 명시적 동작 |
| `presentation/hourly_notification_settings.py` (신규) | 작은 설정창, 고급 설정 접기 |
| `presentation/notification_coordinator.py` (신규) | 기존 업무 알림과 새 창의 위치 충돌만 조정 |
| `presentation/main_window.py` | 트레이·상태 버튼·설정 진입·종료 연동 |
| `main.py` | 실제 앱 구동 시 주입, smoke/test 비활성화 |

서비스의 `start(now)`, `tick(now, monotonic_now)`, `dismiss(hour_key)`, `skip_current(now)`,
`cancel_skip(now)`, `snooze(hour_key, now)`, `set_session_enabled(enabled, now)`,
`set_today_holiday(enabled, now)`, `resume_morning_notifications(now)`,
`update_settings(settings, now)`, `shutdown()`은 명시적인 입력을 사용한다.
휴일 선택 및 예외적인 아침 재개는 저장 성공 후 상태에 반영하고 실패 시 변경 전 상태를 유지한다.
자동 아침 연속은 별도 사용자 호출 없이 start/tick/복귀/ON 전환에서 공통 판정 함수로 계산한다.
서비스 결과는 표시/갱신/숨김 이벤트와 상태 DTO이며 Qt 객체와 DB 세션을 갖지 않는다.
컨트롤러가 이벤트를 UI에 적용한 뒤 표시 성공/실패를 반영한다. 창 생성 실패를 처리 성공으로
기록하지 않고 오류 상태로 표시하며 매 5초 무한 재생성하지 않는다.

상태 DTO는 실행 ON/OFF, 대상 여부/제외 이유, 현재 구간, 다음 정기 시각, 미루기 시각,
현재 표시 여부, 가능한 버튼을 포함한다. 화면·트레이가 각각 날짜 계산을 구현하지 않는다.
제외 이유에 `morning_without_continuation`을 추가하고 알림 가능 시각 계산도 같은 판정을 사용한다.
미래 다음 시각은 현재 ON이 이어진다는 전제로 아침 연속을 계산하되 실제 근무가 확인됐다고 표시하지 않는다.
`next_regular_at`과 `snoozed_until`을 구분하여 `다음 정기 20:35 · 다시 알림 19:45`처럼 정확히 표시한다.

## 12. 시작·종료·오류 안전성

- 실제 프로세스의 bootstrap 후에만 start한다. 단일 인스턴스 메시지마다 start하지 않는다.
- DB 업그레이드 실패로 앱이 시작하지 못하면 이 기능도 실행하지 않는다.
- 비정상 종료 경고는 기존 순서를 유지하고 처리 후 시작 알림 1개만 연다.
- 종료 시 컨트롤러를 먼저 shutdown하고 타이머 중지·창 해제 후 기존 DB/워커 정리를 한다.
- shutdown은 여러 번 호출해도 안전하며 종료 후 대기 신호로 새 창을 만들지 않는다.
- 하나의 알림 오류가 기존 업무 알림·앱 실행을 중지시키지 않도록 예외 경계를 분리한다.
- OFF는 업무 알림을 끄지 않는다. 업무 알림 완료/확인은 매시 알림 상태를 바꾸지 않는다.
- 프로그램/PC 종료 중 알림, 강제 종료 전 안내, 수당 인정·인사랑 기록 성공은 보장하지 않는다.

추가 워커·주기적 DB 쓰기·네트워크 폴링·타이머마다 설정 저장을 만들지 않는다.
설정 저장은 명시적 저장/날짜 선택, 날짜당 최초 아침 연속 설정, 만료 값의 한 번 정리에만 수행한다.
24시간 실행해도 창 수와 상태 크기는 증가하지 않는다.

## 14. 시험과 수용 기준

### 순수 규칙·상태 테스트

1. 모든 요일의 00:00, 07:59:59, 08:00, 08:59:59, 09:00, 17:59:59, 18:00, 23:59:59 경계.
2. 금→토, 일→월, 월말·연말·자정 전이와 시간대/오프셋 처리.
3. 알림 분 0/35/59, invalid bool/음수/60, 문구/시간 범위 검증.
4. 시작 알림의 분 이전/이후, 제외 시간 시작, 같은 실행 두 번 start 방어.
5. 정기 검사 반복·동일 시각·늦은 검사에서 최대 하나의 최초 안내.
6. 현재 구간 닫기/건너뛰기/취소·분 변경·새 구간으로의 상태 전이.
7. 5분 미루기·경계 불가·시각 이동·제외 진입·설정 변경 및 OFF 취소.
8. OFF→트레이 복귀는 유지, 실제 재실행은 ON과 새 시작 안내.
9. 절전 복귀·여러 날 검사 지연·시계 역행에서 과거 구간 복구 없음.
10. 오늘 휴일근무의 자정 만료·주말 무효·재실행 보존·추가 제외 존중.
11. 상태 최대 48개, 단일 창·단일 미루기, 기존 업무/알림 DB 변화 없음.
12. 설정 변경으로 지난 분의 알림을 만들지 않고 next_regular_at과 미루기를 구분.
13. 08시 최초 실행·연속 없음이면 시작·정기·미루기·복귀·창 갱신 경로 모두 아침 안내 없음.
14. 05시/07:50/07:59 실행과 전날부터의 ON에서 추가 선택 없이 08시 포함, 09시 제외.
15. 자동 아침 연속의 날짜 한정 저장·09:00 만료·재실행 보존·휴일 우회와 범용 조건 해제.
16. 전날부터 ON인 절전 복귀와 OFF인 프로세스만 남은 경우 구분, ON 전환 시 `active_since` 갱신.
17. 예외적인 아침 재개는 08시 구간에만 제공하며 기록 성공/출근 사실로 표현하지 않음.
18. 자동 아침 연속의 날짜당 한 번 저장, 저장 실패 시 메모리 안내 지속·무한 재저장 없음.

### 설정·UI·연동 테스트

- 구 설정 파일 로드·잘못된 새 키 보정·저장 round-trip·저장 실패 원상 복구.
- 별도 일반 설정창 저장 후에도 매시 필드 보존, 그 반대 방향도 보존.
- 하루 한정 설정 선택/만료 시에도 OFF·미루기·닫힘 이력을 저장하지 않음, 저장 실패 시 원상 복구.
- 760×560 메인 창과 100%/150%/200% 배율에서 상태 버튼·기존 실행 취소 버튼 겹침 없음.
- 문구 200자·긴 날짜/시간대·고급 설정에서 폼 잘림 없음. 필요하면 설정 본문만 스크롤.
- 파일/기록/첨부/검색 창과 기존 업무 알림 중 새 창 버튼을 클릭할 수 있음.
- 열려 있는 오래된 구간 버튼 클릭이 새로운 구간에 잘못 적용되지 않음.
- 모든 정상 경로와 오류 중 OFF가 기존 업무 알림에 영향을 주지 않음.
- background 실제 시작·트레이 미지원·두 번째 실행·smoke·종료 중 pending 신호 검증.
- 시간은 fake clock으로 진행시켜 1시간 실제 대기 없이 테스트한다.
- 48시간 이상의 합성 진행에서 상태/창 수 고정, SQLite 쓰기와 로그 시간별 누적 없음.

### 실제 Windows 검증

포커스는 offscreen Qt 검사만으로 확인 완료로 판단하지 않는다.
Windows에서 Excel/메모장에 입력하는 동안 새 창이 표시되어도 입력 포커스와 Enter 대상이
유지되는지, 기존 업무 알림·네이티브 파일 선택창과의 위치/클릭을 확인한다.
다중 모니터·작은 작업 영역·절전 복귀·잠금 해제·회사 보안 환경도 지원 범위를 기록한다.
외부 인사랑 기록 성공 여부를 자동 테스트 결과로 표현하지 않는다.

## 15. 구현 순서와 릴리스 경계

1. 순수 시간 판정·상태 서비스와 fake-clock 테스트를 먼저 완성한다.
2. 영구/일시 설정을 분리하고 기존 설정 파일 호환성을 검증한다.
3. 단일 비차단 창·설정창·컨트롤러와 트레이/상태 표시를 연결한다.
4. 시작·단일 인스턴스·절전·설정 변경·종료와 기존 업무 알림 공존을 검증한다.
5. 전체 회귀 및 실제 Windows 포커스 검증 후 도움말·변경 기록을 갱신한다.
6. 사용자 확인 후 버전·Python ZIP·설치본·GitHub 배포 여부를 결정한다.

설계 작성 뒤 사용자 요청에 따라 실행 코드를 구현했고, 사용자 테스트 확인 후 별도 승인으로
3.0.4 배포 및 커밋·릴리스 업로드를 진행한다. 결과는 `16-release-checklist.md`에 기록한다.
자동 활성화라는 동작 변경은 실제 배포 시 도움말과 릴리스 노트에 명확히 안내한다.

## 16. 후속 대화 반영 요약

- 평일 공휴일은 오늘 휴일근무로 직접 설정하며 09~18시 및 아침 제한을 해제한다.
- 08:30에 처음 앱을 켜는 일반 평일 출근자에게 아침 출근·기록 안내를 요구하지 않는다.
- 05시부터 사용하거나 전날부터 ON인 경우 08시까지 자동으로 알림을 이어준다.
- 매번 `08시 알림도 받기`를 선택해야 했던 초안을 폐기하고, 늦게 앱을 켠 예외에만 재개 경로를 둔다.
- 앱 사용 흐름은 알림 유지 기준일 뿐 실제 인사랑 출근·기록을 인증하지 않는다.
- OFF는 다음 실제 실행에 보존하지 않으며 날짜 한정 대상 설정과 구분한다.
- 후속 구현으로 실행 코드·자동 테스트·도움말을 반영했고, 사용자 승인으로 3.0.4 설치본·Python ZIP·GitHub 릴리스를 준비했다. DB 스키마는 변경하지 않았다.
