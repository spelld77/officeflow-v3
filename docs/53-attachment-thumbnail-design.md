# 첨부 목록·썸네일 전환 상세설계

작성일: 2026-10-10. 상태: 개발 소스 구현·격리 검증 및 사용자 사용 확인 후 상단 순서 버튼 간소화.
실제 구현·검증 결과와 제한은 [54번 보고](54-attachment-thumbnail-results.md)를 따른다.

사용자가 썸네일 예시를 확인한 뒤 검토·설계를 요청했다. U21의 후속 설계다.
[51번 설계](51-clipboard-image-and-preview-design.md)와 [52번 결과](52-clipboard-image-and-preview-results.md)는
당시 개발 소스의 별도 미리보기 동작을 기록한다. 아래는 구현 전 확정한 설계다.
클립보드 첨부 U20과 기존 미커밋 작업은 보존한다.
설계 작성 당시에는 실행 코드도 변경하지 않았다. 후속 구현은 소스와 격리 시험 자료만 변경한다.
실제 사용자 자료·DB·버전·EXE·설치 파일·ZIP·Git·GitHub는 변경하지 않는다.

## 1. 검토 결론과 범위

썸네일은 **여러 이미지를 열기 전에 구분하고 찾는 용도**로 유용하다.
외부 프로그램으로 한 장을 크게 보거나 편집하는 기존 열기와 역할이 다르다.
파일마다 미리보기 버튼을 누르거나 마우스를 올리는 방식은 한 장씩 확인해야 하므로 주 동선으로 채택하지 않는다.
목록 옆/아래 큰 그림을 상시 표시하면 좁은 창에서 첨부 목록이 줄어드는 기존 불편이 재발할 수 있다.

권장안은 같은 첨부 목록의 `목록 / 썸네일` 전환이다. 문서 중심·파일명 중심 작업은 목록으로 돌아갈 수 있다.
작은 글자가 모두 읽히는 기능은 아니다. 자세한 확인에는 기존 열기 또는 선택적 확대를 사용한다.
화면과 비동기 읽기 변경이 있어 단순 버튼 추가보다 검증 범위가 크지만, 저장 구조나 전체 업무 UI를 바꿀 필요는 없다.

- 첫 적용: `업무 보기 → 첨부파일`의 현재 일반·원본·작업본. 목록·달력·업무일지·알림에서 같은 창으로 진입한다.
- 반복 업무의 첨부/수동 순서 공유, 휴지통 읽기 전용, 기존 파일 명령의 권한 규칙을 유지한다.
- 최초 기본값은 기존 `목록`. 한 번 `썸네일`을 선택하면 다음 업무/재시작에서 그 선택을 기억한다.
  파일 종류/개수로 자동 전환하지 않는다. 이미 열린 다른 창은 강제로 바꾸지 않고 다음 진입의 기본값만 공유한다.
- 보관함·중요 시점 파일 목록·전체 첨부 검색 결과·외부 HTML 묶음은 이번에 바꾸지 않는다.
- 새 업무의 미저장 클립보드 사진 영역은 기존 작은 미리보기/확대/제거를 유지한다.
- OCR·문서 첫 페이지 생성·이미지 편집·추가 이미지 형식·디스크 썸네일 저장·자동 정리/전역 감시는 제외한다.

## 2. 화면과 조작

### 2.1 배치

기존 첨부 개수/안내 영역을 짧은 개수와 보기 전환으로 정돈한다.
추가 버튼과 하단 파일 명령을 유지한다. 순서 변경은 오른쪽 클릭 메뉴에만 남긴다.
사용 확인 후 요청에 따라 상단 `위로 / 아래로` 버튼은 제거한다.
크기 조절 도구막대나 새 관리 탭은 만들지 않는다.

```text
첨부 6개                                 [목록] [썸네일]
[파일 추가] [클립보드 이미지]
┌────────────────────────┬────────────────────────┐ ↑
│   [접속 오류 사진]      │      [예산 표 사진]     │ │
│ 캡처_…_14-30-25.png     │ 캡처_…_14-32-10.png     │ │
│ 일반                   │ 일반                   │ │
├────────────────────────┼────────────────────────┤ │
│   [점검 안내 사진]      │      [점검 완료 사진]   │ │
│ 캡처_…_15-05-00.png     │ 캡처_…_15-08-00.png     │ │
│ 원본                   │ 작업본 · 메모 있음      │ ↓
└────────────────────────┴────────────────────────┘
선택 1개 · 캡처_2026-10-10_15-08-00.png
[열기] [다른 이름으로 저장…] [정보] [보관함] [더보기]
```

배치 예시이며 실제 창에서 항상 네 장을 보여준다는 뜻은 아니다.

- 그림은 비율을 유지해 맞춘다. 자르거나 늘리지 않고 작은 그림을 과하게 확대하지 않는다.
- 파일명 1줄＋역할/짧은 상태 1줄을 기본으로 한다. 이름은 가운데 생략하여 끝의 시각·확장자를 남긴다.
  전체 이름은 tooltip/정보와 선택 요약으로 확인한다. 긴 메모/경로/해시는 상시 늘어놓지 않는다.
- `일반 / 원본 / 작업본`, 필요한 `메모 있음`을 표시한다.
  누락/읽기 오류를 먼저, 이후 기존 `수정본 있음 / 보관 n / 메모 있음`을 짧게 표현한다.
  여러 상태의 전체 설명은 tooltip/정보에 남기고 카드 높이를 늘리지 않는다.
- 문서는 종류별 아이콘＋이름을 표시한다. Excel/Word/HWP/PDF 본문을 읽어 작은 그림을 만들지 않는다.
- 세로 스크롤바를 항상 표시하고 총 개수를 남긴다. 하단 선택 요약은 기존 최대 2줄로 제한한다.

### 2.2 동작 계약

| 동작 | 결과 |
| --- | --- |
| 한 번 클릭 | 선택만 한다. 자동 열기/확대/첨부 상태 변경 없음 |
| Ctrl/Shift·Ctrl+A | 기존 다중 선택. 별도 체크박스 선택 체계를 추가하지 않음 |
| 방향키/Home/End/Page 키 | 표준 이동과 선택이 보이도록 스크롤 |
| 더블클릭·열기 | 기존 외부 프로그램 열기. 고정 원본은 기존 서비스의 보기 사본 사용 |
| 오른쪽 클릭 | 기존 저장/삭제/이름/메모/보관 명령. 다중 선택 유지 |
| 보기 전환 | 첨부 ID·순서·선택 집합을 그대로 유지하고 표현만 변경 |
| 오른쪽 메뉴의 위로/아래로·맨 위로/맨 아래로 | 순서상 이전/다음·처음/끝. 썸네일은 왼쪽→오른쪽, 위→아래 순 |
| 외부 파일 드롭 | 기존 다중 첨부. 카드 자체의 자유 이동/드래그 정렬은 추가하지 않음 |

전환 전 현재 항목·선택 ID 집합·맨 위의 보이는 첨부 ID를 저장하고 전환 뒤 가능한 한 같은 위치를 유지한다.
높이가 다른 두 방식에 동일 스크롤 숫자를 그대로 사용하지 않는다.
갱신/이름 변경/순서 변경에도 ID로 복원하며 삭제된 항목만 선택에서 제거한다.

첨부 탭의 상시 `미리보기` 버튼은 제거하는 설계다.
기존 읽기 전용 확대 창은 단일 이미지의 오른쪽 메뉴/`더보기 → 이미지 확대…`에 보조 기능으로 남긴다.
클립보드 입력의 확인/확대 버튼은 유지한다. 단일 선택/호버가 확대 창을 자동으로 열지 않는다.
확대 창을 사용자가 열어둔 경우에만 기존 단일 선택 연동을 유지하며, 복수 선택이면 이전 그림을 지운다.

## 3. 작은 창·테마

- 현재 기본 620×650, 최소 500×540 업무 창을 기준으로 한다. 기본 창은 보통 2열,
  실제 첨부 viewport의 폭에 따라 1~4열로 배치한다. 고정 열수 때문에 가로로 밀어내지 않는다.
- 카드 폭의 초기 목표는 176~240 DIP, 그림 높이는 약104 DIP다. 이름/상태 높이는 실제 글꼴로 계산한다.
  최종 치수는 구현 시 100/150/200% 배율과 좁은 창을 확인해 조정한다. 그림 크기 변경 옵션은 첫 범위에 없다.
- 최소 높이/긴 업무 제목에서는 적은 줄이 보일 수 있다. 아래 파일은 스크롤로 접근하며 이름 중심이면 목록으로 전환한다.
- 기존 밝은 공통 스타일을 적용한다. viewport·선택/비활성/오류·메뉴·확대 창의 글자/배경색을 함께 지정한다.
  사진 자체를 반전시키지 않는다. 투명 이미지와 읽는 중의 바탕은 중립색으로 하고 영역 높이는 고정한다.
- 상태를 색만으로 표현하지 않는다. 선택/키보드 포커스와 파일명·역할·상태의 접근성 정보를 제공한다.

## 4. 표시 내용과 파일 안전

[24번 공통설계](24-follow-up-common-design.md)의 보존·삭제·백업 계약을 유지한다.

1. 현재 지원하는 PNG/JPG/JPEG/BMP만 자동 읽기 후보로 삼고 실제 형식도 확인한다.
   SVG/HTML/PDF/문서/영상 읽기와 애니메이션 재생은 추가하지 않는다.
2. `AttachmentService.image_preview_stream()`의 접근 예약·보호 핸들을 재사용한다.
   썸네일을 봤다는 이유로 DB의 최초 정보/관측값/원본 상태를 변경하지 않는다.
3. **원본 그림은 고정된 원본 내용이다.** 수정된 보기 사본을 원본 그림으로 대신 보여주지 않는다.
   보기 사본의 `수정본 있음`은 별도 상태다. 작업본으로 보존하면 새 작업본 항목의 저장 내용을 보여준다.
4. 고정 원본은 같은 핸들에서 고정 크기/SHA-256을 확인한 뒤 읽는다.
   불일치면 이전 그림을 지우고 `원본 확인 필요`로 표시한다. 실제 파일/DB는 유지한다.
5. 일반·작업본은 디스크에 저장된 내용만 보여준다. 외부 편집기의 미저장 내용은 인식하지 못한다.
   잠금/읽기 중 변경 등은 보류하고 저장 후 다시 확인하도록 안내한다.
6. 썸네일은 메모리상의 작은 그림일 뿐이다. 첨부/보기 사본/작업본/보관본/이미지 파일을 생성하지 않는다.
   첨부 개수·검색·외부 저장·백업·외부 HTML의 파일 대상에 추가하지 않는다.
7. 작은 그림을 못 읽어도 이름/역할/기존 파일 명령은 남긴다.
   읽기 실패와 저장/삭제의 실제 허용 여부는 분리하여 기존 서비스에서 판단한다.

## 5. 필요한 만큼만 읽기

### 5.1 요청과 자원 예산

썸네일 모드의 첨부 탭이 보일 때 viewport에 걸치는 이미지부터 읽는다.
시작 시·목록 모드·다른 탭·최소화/닫힌 창에서는 새 이미지 읽기를 하지 않는다.
화면 밖 선행 읽기는 첫 범위에서 하지 않는다. 전체 첨부를 열거나 해시하지 않는다.

| 대상 | 초기 설계 예산 |
| --- | --- |
| 저장 이미지 읽기/decode | 썸네일과 첨부 확대가 공유하는 큐에서 동시에 1개. 명시적 확대 우선 |
| 원본 이미지 제한 | 기존 파일64 MiB·16,000,000픽셀. 읽기 전후 검사 |
| 작은 그림 출력 | 표시 영역×DPR, 최대640×400 물리 픽셀. 원본 크기 이미지를 항목에 보관하지 않음 |
| 축소 캐시 | 앱 공통 LRU, 실제 이미지32 MiB 또는64개 중 먼저 도달하는 상한 |
| 기다리는 요청 | 앱 전체32개, 한 창의 후보 배치24개. 완료 뒤 남은 보이는 항목을 보충; 가시 상태는 한 창256개 이내 |
| 화면 변경 | 스크롤/크기 변경100ms 묶기. 화면 밖 대기 요청 폐기 |
| 오류 | 작은 상태만 개수 제한해 저장. paint마다 재시도/반복 팝업 금지 |

32 MiB는 **썸네일 캐시 예산**이지 프로그램 전체/일시적인 decode 메모리 상한이 아니다.
형식에 따라 원본 크기 이미지/변환 버퍼가 필요하다. 클립보드 대기 사진·PNG 생성·Qt 내부 표현·확대 출력도 별도로 측정한다.
Qt의 기존 이미지 할당 제한을 해제/상향하거나 읽기마다 전역 값을 바꾸지 않는다.
큰 PNG/JPEG/BMP와 여러 창에서 실제 최고 사용량을 검사하며 절대 종료하지 않는다는 보장은 하지 않는다.

GUI가 아직 받지 않은 큰 이미지 결과를 쌓지 않도록 한 결과의 처리 후 다음 읽기를 진행한다.
각 목록 항목에는 이미지/QWidget을 붙이지 않는다. 그리기 담당자가 캐시 키로 조회해 그리므로,
캐시에서 제거했는데 모든 항목이 그림을 계속 보유하는 구조를 피한다.

기존 `_sample_visible_files()`는 세로1열을 전제로 하므로 그대로 사용하지 않는다.
고정 셀/viewport와 `indexAt / visualRect`로 보이는 후보를 좁히는 공통 헬퍼를 작성한다.
매 스크롤마다 모든 항목의 사각형을 검사하지 않는다. 선택 파일 상태 확인의 기존 최대100개 제한은 별도로 유지한다.

### 5.2 캐시와 업데이트

- 키: 자산ID/안전한 상대 경로, 실제 파일 관측 특성, 출력 크기/DPR, 읽기 정책 버전.
  고정 원본에는 고정 크기/해시 기준도 포함한다. 이름을 식별자로 쓰지 않는다.
- 캐시 그림은 **마지막에 정상적으로 읽은 저장 내용**이다. 실시간 추적/현재 파일의 무결성 인증 표시가 아니다.
  크기/mtime 등의 stat는 변경 후보 힌트이지 내용이 같다는 증거는 아니다.
- 원본 지정/해제·작업본 생성·대상 삭제·복원/데이터 루트 변경은 영향받은 키를 무효화한다.
  이름/메모/순서만 바뀌면 글자/배치를 갱신하고 동일 그림을 다시 decode하지 않는다.
- 첨부 탭 재진입·창 포커스 복귀·외부 열기 후 복귀는 보이는 사진을 재확인한다.
  고정 원본은 재확인 단위마다 해시 검증을 수행하며 예전 캐시만으로 정상 판정하지 않는다.
- 일반/작업본의 관측 특성이 변하면 이전 그림을 지우고 다시 읽는다.
  동일한 크기/시각으로 저장된 외부 변경은 자동 판별을 보장하지 않는다.
  `더보기 → 썸네일 새로고침`은 보이는 이미지의 캐시를 무시하고 재읽기한다.
  목록 모드에서 누르면 다음 썸네일 표시 때 새로 읽도록 한다. 전체 파일 스캔은 하지 않는다.
- 마지막 저장 이미지 조회 창이 닫히면 캐시/대기 요청을 해제한다. 재시작용 캐시 파일은 없다.
  기존 원본 보기 사본의 보존·정리와 썸네일 메모리 해제는 서로 다른 처리다.

## 6. 비동기·경쟁 처리

- MainWindow 수명의 명시적 공유 `AttachmentImageCoordinator`를 두고 각 업무 보기/일지 자식 창에 전달한다.
  숨은 전역 상태를 만들지 않는다. 여러 창의 같은 요청은 묶고 보이는 창을 공정하게 처리한다.
- worker는 보호 읽기/검증/decode 후 작은 불변 QImage와 첨부·자산·요청 토큰을 반환한다.
  DB session은 공유하지 않는다. GUI 반영·캐시/선택 처리는 GUI 스레드에서 한다.
  읽기 직전에 실제 해석한 자산/경로가 요청의 기준과 같은지 확인하고, 결과에는 실제 읽은 기준을 담는다.
  큐에 넣은 첨부ID가 같다는 이유로 그 사이 바뀐 원본/작업본 연결을 같은 파일이라고 취급하지 않는다.
- 창/보기 세대·첨부ID·자산ID/경로·목표 크기를 확인하고 늦은 결과를 버린다.
  삭제/원본 지정/보기 전환/종료 뒤 결과가 다른 카드나 이전 선택을 덮어쓰지 않는다.
- 선택만 바뀌었다고 다시 decode하거나 이미지/클릭마다 native thread를 만들지 않는다.
  확대한 창이 열린 경우의 단일 선택 연동은 최신 요청만 남기는 기존 계약을 적용한다.
- 명시적 수정/삭제 명령 직전에는 해당 자산의 자동 읽기 요구를 중단한다.
  실행 중 보호 읽기 종료 후 ID/상태를 다시 확인해 기존 명령으로 진행하며 읽기/쓰기 잠금을 우회하지 않는다.
  기다리는 중에도 주 창/알림은 동작한다. 이 대기는 비모달로 안내하고 자동 읽기가 사용자 명령을 굶기지 않게 한다.
- 창 닫기는 그 창의 요청/구독을 해제한다. 실행 중 worker는 공유 소유자가 계속 보유한다.
  앱 종료는 취소 후 `finish_thread()`로 native 종료까지 소유권을 유지하며 강제 terminate하지 않는다.
- 취소는 해시 청크/읽기 전후에서 확인한다. OS 읽기나 decode를 즉시 중단할 수 있다고 약속하지 않는다.
  이미지 읽기를 별도 프로세스로 완전히 격리하는 확장은 첫 범위가 아니다.

## 7. 실패 표시

| 상황 | 표시/처리 |
| --- | --- |
| 읽는 중 | 같은 크기 틀＋`읽는 중`. 선택/스크롤 가능 |
| 비지원 문서/형식 | 종류 아이콘. 정상 문서를 오류 취급하지 않음 |
| 파일 없음 | `파일 없음`. 기존 참조/삭제 판단 유지 |
| 권한·잠금·보안 제품 거절 | `읽기 불가`. 이유/재시도 방법은 tooltip/정보 |
| 고정 원본 불일치 | `원본 확인 필요`. 그림을 지우고 원장/파일 보존 |
| 너무 큰 사진/크기 판정 불가 | `크기 제한` 또는 `이미지 확인 불가` |
| 손상/형식 위장 | `이미지 확인 불가`. 파일 수정/삭제 안 함 |

한 파일 실패로 연속 팝업을 띄우거나 다른 이미지/알림을 중단하지 않는다.
같은 확인 단위에서는 실패를 한 번 처리하고 다음 재진입/포커스 복귀/명시적 갱신에서 재시도한다.
반복 paint/스크롤만으로 무한 재시도하지 않는다. 이미지 내용/관리 경로를 로그에 남기지 않는다.
기존 외부 열기와 파일 명령은 각자 원래 안전 검증을 계속 사용한다.

| `application/attachments.py` | read-only 스트림 재사용. 필요하면 읽기용 관측값만 추가, DB 갱신과 분리 |

| 안내/테스트 | 구현 후 실제 동작·결과로 갱신. 지금부터 사용 가능하다고 쓰지 않음 |

설정 저장 실패 시 이번 실행의 선택은 유지하고 다음 시작에 기억되지 않을 수 있음을 비모달 안내한다.
기존 위치/백업/알림 설정을 함께 초기화하지 않는다. 기존settings JSON 저장/백업 계약을 사용한다.
DB migration·첨부 이동·새 의존성·백업 형식 변경은 필요 없는 설계다.

구현 순서:

1. 동일 목록의 모드/그리기와 문서 아이콘 → 선택/순서/스크롤/드롭 검증.
2. 제한된 공통 큐/보호 읽기/취소/캐시 → 원본/작업본/오류/종료 검증.
3. 설정/갱신/여러 창/알림/가독성·배율·성능 회귀 → 사용 안내/실제 결과 작성.

같은 개선의 내부 작업 순서이며 별도 공개 릴리스 세 번을 뜻하지 않는다.
설계 작성 당시에는 시작 요청을 기다렸다. 이후 사용자 요청으로 구현·테스트를 진행했으며 배포는 하지 않는다.

- 캐시의 실제 바이트/개수, 저장 이미지decode 동시1개, 여러 창/닫기/종료에서 구독/worker/이미지 참조 해제.

- 큰 PNG/JPEG/BMP·빠른 선택/전환·취소/닫기를 별도 프로세스에서 반복해 native 종료 회귀 검사.
  파일 창/알림의 독립 조작과 명시적 명령 우선 처리 검사.
- 기본/최소 창, 100/150/200%, 밝음/어둠 제어 팔레트와 직접 캡처에서 텍스트/배경/선택/스크롤/버튼 경계 확인.
  offscreen과 실제 Windows/회사PC 검증을 구분해 미검증 환경 명시.
- 보기만으로 DB행/첨부수/파일 내용/원본/보기 캐시/보관/백업에 변화 없음. 기존 클립보드·확대·백업/복원 관련 회귀.
  기존 미리보기 버튼을 직접 누르는 UI 검사는 새 확대 메뉴 진입으로 갱신하되, 읽기 전용/원본 검증/종료 기준은 약화하지 않는다.

구현 결과에는 캐시 데이터량, GUI 응답, 전체 프로세스의 최고 메모리와 창 닫은 뒤의 회수를 별도로 기록한다.
캐시 상한 테스트만으로 프로그램 전체 메모리 안전성과 회사 보안 제품 호환을 단정하지 않는다.

## 10. 현재 코드 확인과 설계 근거

현재 AttachmentListWidget은 QListWidget/ExtendedSelection과 외부 파일 드롭/더블클릭 외부 열기를 사용한다.
CompactFileDelegate는1줄·상시 세로 스크롤·FileRow 이름/역할/상태를 제공한다.
기존 preview_stream은 보호 핸들 내 원본 해시 검증을 제공하며 보기 사본/DB 관측값을 만들지 않는다.
read_preview의1200×900 출력은 전체 아이템에 그대로 저장하지 않는다.
가시 상태 확인의 세로1열 전제와 worker 종료의 native 경쟁 보호가 이번 변경의 필수 점검 지점이다.

Qt가 목록/아이콘 표시, 고정 배치/재배치/동일 크기 항목을 지원하므로 기존 QListWidget을 재사용하는 설계다.
모드 기본값에 맡기지 않고 Static 배치와 외부 드롭을 전환 후 명시한다.
근거: [Qt QListView](https://doc.qt.io/qt-6/qlistview.html).

축소 읽기의 메모리 절감은 형식 지원에 따라 다르다. setScaledSize만으로 원본decode 회피를 보장하지 않으므로
동시 처리 제한·사전/사후 크기 검사·실측을 함께 적용한다.
근거: [Qt QImageReader](https://doc.qt.io/qt-6/qimagereader.html).

Qt의 전역 QPixmapCache는 주 스레드에서만 사용할 수 있고 다른 기능과 공유하므로 독립 예산의 원장으로 삼지 않는다.
명시적 소유자의 축소 QImage LRU와 GUI 그리기를 사용하는 설계다.
근거: [Qt QPixmapCache](https://doc.qt.io/qt-6/qpixmapcache.html).

위 내용은 현 코드와 공식 자료에서 도출한 설계 판단이며 구현 성능을 측정한 결과가 아니다.
공통 보존/삭제/백업 계약을 바꾸지 않고 U21의 표시/읽기만 구체화했다.
