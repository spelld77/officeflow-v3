# 첨부 화면 공간·종류 필터·출처 표시 상세설계

작성일: 2026-10-13. 상태: 후속 요청으로 개발 소스 구현·관련 자동/시각 검증 완료, 사용자 사용 확인 전.
기준 버전: 공개 3.0.10 / DB0016 / 전체 백업 v3.

2026-10-14 후속 요청으로 3.0.11 마감·배포를 진행한다. 최신 결과는 [62번 릴리스 체크리스트](62-release-checklist.md)를 따른다.

대상은 `업무 보기 → 첨부파일`이다. 최초 설계 요청 후 `구현 테스트해` 요청으로 실행 코드·설정 지원·도움말을 반영했다.
실제 사용자 설정/DB/첨부·DB 스키마·버전·EXE/설치본/ZIP·커밋·GitHub는 변경하지 않았다.
[61번 구현·검증 결과](61-attachment-space-and-source-results.md)에서 실제 반영과 미검증 범위를 확인한다.
[24번 공통설계](24-follow-up-common-design.md)의 보존·명령·출처 계약과
[53번 썸네일 설계](53-attachment-thumbnail-design.md)의 선택·순서·메모리 계약을 유지한다.

## 1. 목적과 현재 상태

원본 3개와 작업본 2개부터, 작은 창에서 파일을 구분하고 선택하기가 불편해질 수 있다.
파일이 5개면 반드시 화면이 잘린다는 의미는 아니다. 실제 표시 수는 글꼴·창 크기·보기 방식에 따라 다르다.

현재 업무 기록 창은 기본 620×650, 최소 500×540 DIP다. 첨부 목록에는 세로 스크롤과
최소 높이 180 DIP가 있으나 위의 추가/보기 전환, 아래의 선택 정보·파일 행동·공통 닫기 영역이 공간을 나눈다.
문서도 썸네일 보기에서는 큰 카드로 표시된다. 현재 파일 목록은 일반·원본·작업본이 섞인 수동 순서다.
보관본은 별도 보관함에 있으며 현재 첨부 수에 포함하지 않는다.

개선 목표:

- 같은 작은 창에서 목록에 더 많은 세로 공간을 준다.
- 필요한 파일 종류만 고르되 숨긴 파일을 없는 것으로 오해하거나 잘못 삭제하지 않는다.
- 작업본의 직접 출처를 한 줄로 확인한다. 출처를 무조건 원본이라고 부르지 않는다.
- 관련 첨부/보관본을 기존 보관함에서 확인한다. 문서 관리 창을 새로 늘리지 않는다.
- 필요할 때 같은 창을 넓히며 전체화면 사용을 요구하지 않는다.

## 2. 확정 범위와 제외

포함:

1. 첨부 탭의 2줄 상단 도구 영역·넓은 단일 목록·짧은 하단 요약/행동.
2. `전체 파일 / 원본 / 작업본 / 일반` 드롭다운과 전체/표시 개수, 필터 해제.
3. 선택 파일의 직접 출처 및 전체 정보를 확인하는 비차단 정보 창.
4. 현재 업무 창의 `넓게 보기 / 이전 크기`와 업무 보기 창의 크기 기억.
5. 선택 파일 기준 보관함의 관련 자료 범위 표시, 기존 현재 첨부/보관본 전환 재사용.
6. 조회 실패·수정 사본·휴지통·작업 중·다중 선택·목록/썸네일 전환의 안전 처리.

제외:

- 원본별 접힌 트리, 자동 묶기/정렬, 최신 작업본 선정, 즐겨찾기/추가 작업 상태.
- 파일명 유사도로 관계 추측, 관계를 자동 수정하거나 파일을 이동/복제하는 기능.
- 별도 첨부 전용 창, 상시 큰 미리보기, 썸네일 크기 조절, 문서 표지 생성.
- 첨부 안의 새 검색창/본문 검색, 보관함의 선택 체계·페이지·삭제 정책 전면 개편.
- DB 이행, 파일/백업 형식 변경, 내부 자료 정리, 실사용 데이터 자동 삭제.

앞서 ASCII의 여러 종류 버튼/별도 확대 창은 검토 예시다. 본 설계는 작은 드롭다운과 같은 창 크기 조절을 채택한다.

## 3. 목표 배치

### 3.1 기본 첨부 탭

```text
업무 보기 · 예산 검토
체크리스트 | 완료 요약 | 업무일지 | [첨부파일] | 폴더

[파일 추가] [클립보드 이미지]                 [넓게 보기]
[전체 파일 (5) ▾]                       [목록] [썸네일]
┌────────────────────────────────────────────────────┐
│ 원본    예산서식.xlsx                   보관 2      │
│ 원본    검토서식.docx                               │
│ 원본    참고자료.pdf                               │
│ 작업본  예산서_작성중.xlsx                          │
│ 작업본  검토서_수정안.docx                          │
│                                             스크롤 │
└────────────────────────────────────────────────────┘
작업본 · 출처: 예산서식.xlsx
[열기] [다른 이름으로 저장…] [보관함] [더보기]

[이력·시점 보관]                                 [닫기]
```

행의 공간/개수는 예시다. 보관 개수는 파일 상태 칸의 기존 문구이며 현재 첨부 개수와 합산하지 않는다.

- 파일 추가와 클립보드 이미지는 각각 한 번 클릭으로 기존 대화상자를 연다. 추가 메뉴에 숨기지 않는다.
- 첫 줄은 추가/크기, 둘째 줄은 종류/보기 방식이다. 매 파일마다 별도 버튼을 만들지 않는다.
- 하단 `정보` 상시 버튼은 `더보기 → 파일 정보…`로 옮기고 오른쪽 메뉴에도 제공한다.
  전체 파일명·출처·메모·기준/현재 파일 정보는 그 창에서 확인·복사한다. 기존 읽기 전용 정보 창을 재사용한다.
- 단일 선택 요약은 평상시 한 줄로 제한한다. 현재처럼 메모/용량/출처를 모두 상시 여러 줄로 늘이지 않는다.
  긴 출처는 가운데 생략하고 전체 텍스트를 툴팁/정보 창에 남긴다. 글자를 작게 줄이지 않는다.
- 첨부 탭에서 긴 업무 제목은 한 줄로 생략하고 툴팁/창 제목에 전체 값을 유지한다.
  반복 회차/휴지통 범위 안내는 남기며 다른 탭의 입력 내용·배치는 바꾸지 않는다.
- `수정본 있음`, 파일 누락, 확인 불가와 파일 작업 오류는 평상시 요약과 별도로 짧게 노출할 수 있다.
  수정 사본의 `수정본 저장…` 접근은 유지한다. 경고를 출처 텍스트 때문에 덮거나 더보기 안에만 숨기지 않는다.
- 목록은 남는 높이를 전부 사용한다. 항목은 기존 한 줄, 썸네일은 기존 크기·이미지 정책을 유지한다.
  필터 결과가 적어도 목록의 높이를 줄여 하단 정보를 늘리지 않는다. 세로 스크롤은 계속 표시한다.

### 3.2 종류 선택과 빈 결과

```text
[작업본 (2) ▾]  2개 표시 / 전체 5개  [전체 보기] [목록] [썸네일]
┌────────────────────────────────────────────────────┐
│ 작업본  예산서_작성중.xlsx                          │
│ 작업본  검토서_수정안.docx                          │
└────────────────────────────────────────────────────┘

선택 종류가 0개이면:
이 종류의 첨부파일이 없습니다. 전체 첨부는 5개입니다.
[전체 보기]
```

좁으면 `전체 보기`/표시 개수 안내를 같은 도구 영역의 한 줄 아래에 배치한다.
필터 활성 표시는 기본 노출이며 hover에만 의존하지 않는다. 전체 0건과 필터 0건은 서로 다른 안내다.

## 4. 종류 필터와 선택 계약

- 드롭다운 항목은 `전체 파일 (N) / 원본 (N) / 작업본 (N) / 일반 (N)`이다. 0개 항목도 표시한다.
- 대상은 현재 업무에 연결된 현재 첨부만이다. 해제 첨부·보관본·중요 시점 파일을 합산하지 않는다.
  파일이 누락됐어도 현재 연결된 첨부면 개수에 포함하고 누락 상태를 유지한다.
- 새 업무 보기 창은 항상 `전체 파일`로 시작한다. 종류 필터는 설정에 저장하거나 다른 창으로 공유하지 않는다.
  같은 열린 창에서 다른 탭에 갔다 오거나 기존 창을 재활성화하면 필터는 유지하고 상태 안내를 표시한다.
- 필터 적용은 기존 수동 순서의 부분 집합을 보여준다. 원본/작업본 순으로 다시 정렬하거나 DB 순서를 변경하지 않는다.
- 전체 메타데이터와 현재 표시 목록을 분리한다. 화면에는 필터에 맞는 항목만 구성한다.
  숨긴 QListWidgetItem의 선택을 남겨두는 방식은 피한다.
- 필터 변경 시 선택은 `이전 선택 ID ∩ 현재 표시 ID`만 남긴다. 현재 항목이 사라지면 단일 대상/출처를 비운다.
  남은 항목을 자동 선택하거나, 전체로 돌아올 때 예전 숨은 선택을 자동 복구하지 않는다.
- Ctrl+A, Shift 범위 선택, 저장·삭제·해제·이름·메모·원본/작업본 명령은 현재 보이는 선택만 대상으로 한다.
  파일 명령 대상 수/이름을 같은 선택 수집 함수에서 구하고 실행 직전 서비스에서도 유효성을 확인한다.
- 필터 중에는 순서 이동을 비활성화하고 `전체 파일 보기에서 순서를 바꿀 수 있습니다`를 안내한다.
  전체 보기의 기존 위/아래/맨 위/맨 아래 이동과 순서 계약은 그대로 유지한다.
- 종류가 바뀌는 명령 후에는 현재 필터를 유지한다. 항목이 사라지면 `원본으로 지정됨 · 현재 필터에서 제외`처럼
  성공과 표시 제외를 구분하고 `전체 보기`를 제공한다. 삭제된 것으로 표현하지 않는다.
- 파일 추가·드롭·클립보드 추가·새 작업본 생성 성공으로 새 첨부가 생길 때만 전체 보기로 전환해 결과를 보인다.
  기존 선택 중 살아 있는 ID를 유지하되 새 파일들을 전부 자동 선택하지 않는다. 새 파일 위치를 안내/스크롤한다.
  취소·전체 실패·보관본 생성은 필터를 바꾸지 않는다. 일부 추가 성공이면 실제 성공 파일만 표시한다.
- 파일 검색에서 특정 첨부 ID로 진입하면 전체 보기에서 해당 파일을 선택한다.
  기존 창 재사용 때문에 종류 필터에 가려진 결과를 선택 불가능하게 만들지 않는다.
- 파일 명령이 진행 중이거나 썸네일 사용 예약 해제를 기다리면 종류 변경을 잠시 막는다.
  크기 조절·목록 스크롤·알림 처리는 막지 않는다. 기존 보기 전환의 작업 보호 계약을 유지한다.

## 5. 출처 표시

### 5.1 사용자 문구

| 선택 상태 | 요약 예시 |
| --- | --- |
| 선택 없음 | 파일을 선택하세요 |
| 직접 추가한 일반 첨부 | 일반 첨부 · 120 KB |
| 원본 | 원본 · 내용 고정 |
| 원본에서 만든 작업본 | 작업본 · 출처: 예산서식.xlsx |
| 다른 작업본에서 생성 | 작업본 · 출처: 예산서_검토중.xlsx |
| 보관본에서 생성 | 작업본 · 출처: 검토 반영 · 예산서.xlsx (보관본) |
| 중요 시점 파일에서 생성 | 작업본 · 출처: 제출 전 · 예산서.xlsx (시점 보관) |
| 수정한 보기 사본을 보존 | 작업본 · 출처: 수정 보기 사본 · 예산서식.xlsx |
| 출처 항목 삭제됨 | 작업본 · 출처 삭제됨: 생성 당시 이름 |
| 과거 출처 정보도 없음 | 작업본 · 출처 정보 없음 |
| 메타데이터 조회 실패 | 작업본 · 출처 확인 불가 |
| 여러 파일 선택 | 3개 선택 |

- 직접 출처만 보여준다. 원본까지의 전체 조상 트리·자동 최신 파일 판단은 하지 않는다.
- 현재 출처가 살아 있으면 현재 표시 이름을 쓴다. 생성 당시 이름은 정보 창에서 별도로 보여준다.
  원본 이름을 바꿔도 작업본의 자체 이름이나 과거 출처 payload를 자동 변경하지 않는다.
- 출처 삭제는 작업본 파일 누락/손상을 뜻하지 않는다. 출처 ID가 없어도 작업본/보관본의 파일은 독립적으로 유지한다.
- 일반 첨부/원본도 출처 기록이 있으면 정보 창에서 확인 가능하다. 평상시 한 줄은 역할·보호 상태를 우선한다.
- 읽는 중이면 `출처 확인 중`을 표시한다. 이전 선택의 출처를 새 선택 아래에 남기지 않는다.
- 문서 내용, 파일 경로, 이름 유사도, 파일 해시로 출처를 추측하지 않는다.
- 출처 FK가 둘 다 비었다는 이유만으로 직접 첨부/출처 삭제로 판단하지 않는다.
  현재 구현은 `snapshot_file`/`cache`에서 만든 작업본의 출처를 payload에 보존하므로 이 두 경우도 구분한다.
  보기 캐시가 정상 정리되어도 그 작업본을 `출처 삭제됨` 경고로 표시하지 않는다.

### 5.2 조회·실패·동시성

- 현행 `source_attachment_id`, `source_version_id`, `source_payload`, `family_id`와
  lifecycle의 `DocumentCatalog.get('attachment', id)`가 제공하는 메타데이터를 재사용한다.
  Presentation에서 새 SQL을 실행하거나 이 조회를 위해 파일을 열거나 해시하지 않는다.
- 현행 catalog.get의 현재 출처 이름은 첨부/개별 보관본 중심이다. 시점 파일/수정 보기 사본까지의
  출처 종류·현재 이름·당시 이름·생존 상태는 catalog의 읽기 전용 출처 요약 projection으로 보완한다.
  `snapshot_file`은 해당 업무/묶음의 연결을 확인해 이름을 조회하고, `cache`는 저장 당시 payload만 표시한다.
  첨부/보관본의 v1 provenance, 시점 파일의 기존 state, 수정 사본의 decode_cache_source 형식을 각각 검증한다.
  모든 payload에 공통 kind/version이 있다고 가정하지 않는다. ID/계열/업무 범위를 검사하고
  잘못된 값으로 다른 업무 자료를 노출하지 않는다.
  조회 실패/자산 상태 불명과 실제 출처 항목 삭제는 구분하며 DB/JSON을 읽기 과정에서 고치지 않는다.
- 단일 선택의 출처만 지연 조회한다. 모든 행마다 get을 호출하거나 매 스크롤마다 조상 조회를 반복하지 않는다.
- 명령/파일 읽기와 분리된 제한된 metadata worker 채널을 사용한다. 요청은 실행 1개 + 최신 대기 1개로 병합한다.
  창 수명 동안 worker를 재사용하고 클릭마다 native thread를 만들지 않는다. 종료 시 기존 안전 종료 방식을 따른다.
- 구현 검증에서 정보 창을 연 직후 선택을 바꾸면 출처 조회가 사라지는 경쟁을 발견했다.
  명시적으로 연 정보 창 1개에는 고정된 조회 요청 1개를 추가로 보존한다. 실행은 여전히 한 번에 1개이며
  목록용 최신 대기 1개와 정보창용 대기 최대 1개만 둔다. 정보창 요청은 먼저 완료하고 목록의 최신 요청을 처리한다.
  정보 창을 다시 열면 같은 창/요청을 교체하며, 정보용 결과가 현재 목록 선택을 덮지 않게 토큰을 별도로 검사한다.
- 캐시는 현재 선택의 결과 1개만 둔다. 재선택/포커스 복귀·첨부 갱신 때 재검증하며 전체 첨부별 캐시를 늘리지 않는다.
- 요청 토큰에는 소유자·업무·첨부 ID·메타데이터 revision·화면 generation을 포함한다.
  다중 선택/선택 해제/필터 변경/소유자 닫힘 뒤 결과는 적용하지 않는다.
  표시 이름 변경/파일 명령 후 generation을 바꾸어 이전 이름 결과가 새 화면을 덮지 않게 한다.
- 현재 표시용 메타데이터와 생성 당시 payload를 별개로 유지한다. 원장/백업/보관 파일에는 쓰지 않는다.
- 잘못된 payload·삭제 경쟁·DB 오류는 출처 안내 실패로 다룬다. 파일 자체가 누락됐다고 단정하지 않는다.
  정보 창도 일관된 실패 상태를 표시하고 알림/목록을 계속 사용할 수 있게 한다.

## 6. 넓게 보기와 크기 기억

- `넓게 보기`는 현재 `TaskRecordsDialog`의 크기만 조절한다. 같은 목록·선택·서비스·worker를 사용한다.
  새 창 생성·전체화면·최대화·다른 탭 제거·파일 재조회는 하지 않는다.
- 목표는 최소 현재 크기 이상에서 940×720 DIP 정도다. 이미 더 큰 창이면 축소하지 않는다.
  실제 최대값은 현재 창이 있는 모니터의 availableGeometry(작업표시줄 제외)와 창 테두리를 고려해 제한한다.
- 확대 전 geometry를 이번 실행의 되돌림 기준으로 기억하고 버튼을 `이전 크기`로 바꾼다.
  수동 크기 조절은 허용하며 이전 크기는 화면 밖으로 돌아가지 않도록 다시 제한한다.
- 창 크기는 업무 보기 전체에 공통으로 기억한다. 다른 탭으로 가도 자동으로 줄이지 않으며 모든 창을 동시에 조절하지 않는다.
  다음 신규 창은 최근 정상 크기로 열고, 현재 열린 창은 사용자가 직접 조절한다.
- 폭/높이만 설정에 저장한다. 모니터 좌표·최대화 여부·종류 필터·이전 크기 토글 상태는 재시작에 복원하지 않는다.
  재시작 후 버튼은 `넓게 보기`이고 최근 크기를 기본으로 사용한다.
- 저장은 안전한 창 닫힘 때 한 번 전달한다. 종료/복사 취소 대기 중간에 크기를 수십 번 기록하지 않는다.
  여러 창이 있으면 마지막 정상 종료 창의 크기가 다음 기본값이다.
- 설정 필드는 `record_window_width`, `record_window_height`(nullable int)로 계획한다.
  각 값은 bool이 아닌 int, 200~8192 DIP 또는 None으로 검증하고 실제 사용 크기는 레이아웃/작업 영역에 다시 제한한다.
  누락은 기존 620×650으로 처리한다. 잘못된 타입/0/과도한 값은 해당 새 필드만 복구하고 기존 알림/백업 설정은 유지한다.
- 정상 close/accept/reject와 앱의 안전 종료 완료 경로는 같은 1회 저장 훅을 사용한다.
  최소화/사용자의 수동 최대화 상태에서는 normalGeometry의 유효 크기를 쓰고 최소화된 치수·최대화 상태는 저장하지 않는다.
- 주 창이 최신 AppSettings에 크기 필드만 합쳐 저장한다. 업무 창이 오래된 설정 전체를 덮어쓰지 않는다.
  저장 실패는 비차단 안내로 구분하며 파일/업무 저장 실패로 표시하지 않는다.
- 목록·달력·알림·첨부 검색·업무일지에서 만드는 업무 보기 창에 같은 크기 초기값/저장 콜백을 주입한다.
  기존 창 재사용/업무·원래 회차/휴지통 식별은 유지한다. 단독 테스트 생성자는 콜백 없이 기존 기본값을 사용한다.
- 목표 최소 크기는 기존 500×540이다. 작업 영역이 이보다 작은 환경은 도구 줄 재배치·세로 스크롤로
  핵심 행동을 접근 가능하게 하고 화면 밖 배치를 피한다. 그 경우 5행 표시를 보장하지 않는다.

## 7. 관련 자료와 기존 보관함

- 하단 `보관함`은 유지한다. 단일 선택이면 선택 파일의 family, 선택 없거나 다중이면 업무 전체를 대상으로 한다.
  버튼 tooltip은 `선택 파일의 관련 첨부·보관본` 또는 `이 업무의 보관함`으로 범위를 구분한다.
- 오른쪽 메뉴/더보기에 `관련 파일 보기…`를 제공한다. 단일 선택·유효한 family에서만 사용하며
  기존 DocumentBrowser를 `현재 첨부`로 초기화한다. 상단은 `선택 파일의 관련 자료`로 범위를 분명하게 표시한다.
- 보관함 버튼의 기본은 기존 `보관본`이다. 오른쪽 메뉴의 관련 파일과 같은 클래스/서비스를 재사용하며
  선택 family/업무 전체와 현재 첨부/보관본 전환을 유지한다. 혼합 타임라인을 새로 만들지 않는다.
- 기존 `이 업무 전체 보기`로 범위를 확장한다. 원래 선택 파일이 없거나 family가 무효면 업무 전체 안내로 연다.
  직접 추가한 독립 파일은 관련 목록에 자신만 나올 수 있다. 이름이 비슷한 다른 파일을 자동 연결하지 않는다.
- 현재 첨부 수와 보관본 수를 따로 표현한다. 중요 시점 묶음은 기존 이력·시점 보관에서 조회한다.
- 보관함의 페이지당 제한·체크한 저장 대상과 강조 삭제 대상의 구분·다중 삭제 계획은 변경하지 않는다.
  주 첨부 종류 필터/선택을 보관함의 체크 목록에 자동 이식하지 않는다.
- 보관함의 활성 창 재사용이 필요하면 `(업무, family/전체, 종류, 읽기전용)`으로 범위를 맞춘다.
  작업 중인 기존 보관함을 다른 family로 돌리지 않는다. 수정/저장 명령 대상과 보기 범위를 혼동하지 않는다.

## 8. 안전·성능·호환

- DB0016·파일 경로·자산·출처·순서·파일 수·백업 v3는 유지한다. 새 DB 이행은 없다.
  새 설정 크기 값은 선택 사항이며 구버전 설정 읽기/설정 포함 백업에서도 기존 허용 키 방식을 따른다.
- 종류 필터·출처·크기 조절만으로 파일 생성·보기 사본 생성·관측 해시 갱신·업무 완료/알림 확인은 하지 않는다.
- 휴지통에서도 종류 선택·출처·전체 정보·넓게 보기·외부 저장·보관 조회는 가능하다.
  추가/드롭/원본 지정/작업본/보관본 생성/이름·메모/순서/해제/삭제는 현재 읽기 전용 규칙으로 막는다.
- 목록/썸네일 전환은 현재 보이는 선택 ID·수동 순서·맨 위 보이는 항목을 유지한다.
  사진/문서 종류와 개수로 자동 전환하거나 문서가 많은 업무의 썸네일 기억을 임의 변경하지 않는다.
- 샘플/썸네일 요청은 표시 항목·유효한 선택만 대상으로 한다. 필터 변경 시 요청 epoch/generation을 올리고
  숨은 항목의 지연 결과가 현재 선택/사진을 덮지 않게 한다. 앱 공통 32 MiB/64개 메모리 캐시 등 기존 상한을 유지한다.
- 현재 첨부 메타데이터를 읽는 기존 범위는 유지하되 이번 작업에서 별도 전체 캐시·보관 파일 본문 적재를 추가하지 않는다.
  첨부 자체의 대규모 페이지화는 별도 범위다. 종류 필터를 전체 첨부 성능 문제의 해결로 보고하지 않는다.
- 삭제/저장/생성의 최초 선택 ID와 명령 진행 상태를 유지한다. 다른 화면에서 변경되면 최신 서비스 검증으로 보호한다.
  경로 기반 직접 삭제나 새 파일 명령 구현으로 기존 저널·참조·사용 예약을 우회하지 않는다.
- 업무/매시 알림은 계속 응답해야 한다. 출처 정보·보관함·파일 정보는 비모달이며 작업 중 전체 앱을 비활성화하지 않는다.

## 10. 수용 기준과 검증 계획

### 10.1 기능·실패

- 0개 / 원본 3+작업본 2 / 혼합 20개 / 100개의 합성 첨부에서 전체·종류 개수와 순서 일치.
- 전체 0과 종류 0 구분, 새 창 전체 시작, 재활성화 필터 안내, 외부 검색 ID 진입.
- 전체에서 3개 선택 후 원본/작업본 전환: 숨긴 ID는 선택·저장·삭제·해제·메타데이터 명령에 포함되지 않음.
  Ctrl+A·범위 선택·현재 항목 삭제·전체 복귀·다중 선택 우클릭 모두 같은 보이는 선택을 사용.
- 종류 전환/전체 복귀·목록/썸네일 전환/스크롤 중 기존 ID와 순서 유지, 필터 중 이동 비활성.
- 필터 중 새 첨부/드롭/클립보드/작업본 성공·일부 실패·취소·역할 변경 후 표시 계약 확인.
- 원본·다른 작업본·보관본·중요 시점 파일·수정 보기 사본 출처, 현재 이름 변경/삭제 후 당시 이름,
  캐시 정상 정리 후 출처 표기, 잘못된 JSON/타 업무 payload/출처 없음/조회 실패.
- 빠른 단일/다중 선택·새로고침·다른 창의 이름/역할 변경·조회 중 창 닫힘에 stale 결과/worker 누수 없음.
- 넓게 보기·되돌림·수동 크기 조절·탭 변경·창 재사용·다중 모니터 이동·재시작 크기 기억.
  손상된 크기 설정은 나머지 알림/백업 값을 보존하고 크기 저장 실패는 비차단 안내.
- 관련 자료/업무 전체/현재 첨부/보관본 범위, 직접 추가 파일·유효 family 없음·0 보관본·휴지통 조회.
- 다중 저장/삭제, 수정 보기 사본 보존/버리기, 클립보드 실패 재시도, 파일 사용 예약과 종료·알림 상호 조작 회귀.

### 10.2 가독성·좁은 창

- 기본 620×650·최소 500×540·넓힌 창과 작은 작업 영역, 밝은/어두운 시스템 팔레트·100/150/200%에서 검증한다.
- 일반 최소 크기·기본 글꼴·평상시 목록 보기에서는 원본 3+작업본 2를 최소 5행 보이게 하는 것을 목표로 한다.
  실제 글꼴과 경고 상태에서 가용 공간이 줄면 스크롤·총/표시 개수로 남은 항목을 명확히 안내한다.
- 긴 업무 제목/출처/파일명/보관명·수정본 경고·읽기 전용·동시 오류에서도 버튼과 드롭다운이 잘리지 않아야 한다.
- 입력/비활성/선택/메뉴/viewport/사진 배경은 공통 밝은 스타일로 확인한다. 제목/버튼을 축소 글꼴로 맞추지 않는다.
- 썸네일에서는 항상 다섯 장이 보인다고 약속하지 않는다. 목록 전환과 스크롤·필터로 접근 가능성을 검증한다.
- Tab 순서: 추가 → 클립보드 이미지 → 넓게 보기 → 종류 → 전체 보기(활성 필터만) → 목록/썸네일 →
  파일 목록 → 열기/외부 저장/보관함/더보기 → 기존 공통 하단 행동. 비활성/숨은 항목은 건너뛴다.
  목록의 Enter/더블클릭·원본 보호 열기, 입력칸 Enter를 가로채지 않는 범위 단축키도 회귀 검사한다.

### 10.3 디스크 사용과 검사 기록

- 이번 화면/출처/필터 검사는 수 KB 파일·작은 이미지 중심으로 만든다. 1 GiB 파일 스트리밍 검사는 매 단계 반복하지 않는다.
- 변경 범위 중심 검증 후 릴리스 때 전체 게이트를 실행한다. 각 실행의 합성 fixture는 소유한 임시 디렉터리에서 정리한다.
- 실패 시 필요한 로그/XML/소형 캡처만 보존한다. 큰 파일 fixture를 매 실행의 이름으로 영구 누적하지 않는다.
  명시적 테스트 소유권/안전 경로 확인 없이 사용자 자료나 기존 다른 작업 폴더를 청소하지 않는다.
- 기능 테스트, 시각 캡처, 실제 회사 DRM/문서 편집기 사용 확인을 구분해 결과 문서에 기록한다.

## 11. 완료 판단과 다음 단계

설계 문서·후속 후보 기록을 마쳤다는 것이 구현/테스트 완료나 배포 승인을 뜻하지 않는다.
후속 구현·관련 테스트는 완료했고 다음은 개발용 소스에서 사용자 사용 확인이다.
이번 범위는 파일 저장 구조를 바꾸는 개선이 아니므로 별도 자료 이행/정리 없이 진행하는 것이 목표다.
버전 변경·EXE/ZIP/설치본·Git 작업은 이후 별도 요청 때 진행한다.
