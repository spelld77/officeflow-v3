# 외부 폴더 바로가기·업무 묶음 보관 구현 및 검증

배포 후속 기록: 2026-10-11 사용자 요청으로 3.0.10에 포함한다. 이 문서의 미배포 표기는 작성 당시 기록이며
최신 검증·GitHub 공개 결과는 [3.0.10 릴리스 체크리스트](59-release-checklist.md)를 따른다.

검증일: 2026-10-10. 공통설계 46번 → 상세설계 47번 → 구현 → 회귀 검사 순서로 진행했다.

## 구현 결과

- 업무 목록/달력 오른쪽 메뉴의 `폴더 바로가기…` 또는 업무 기록의 `폴더` 탭에서 외부 폴더를 등록·열기·이름 변경·재지정·연결 삭제한다.
- 연결 삭제는 DB 정보만 지운다. 실제 외부 폴더/파일은 삭제하지 않는다. 경로가 없거나 접근이 막혀도 연결은 유지한다.
- 앱 관리 폴더와 그 안으로 향하는 junction은 연결/출력 대상으로 거절한다. 목록 조회나 앱 시작 때 외부 경로를 일괄 조사하지 않는다.
- `데이터 → 내보내기·백업 → 업무 묶음 보관…`에서 연도/기간/선택 업무를 새 외부 폴더에 담는다.
- 기본은 올해 등록한 완료 업무와 현재 첨부다. 날짜 기준은 등록일/완료일/최근 수정일을 선택하며, 진행 업무 포함과 보관본/중요시점 파일 포함은 선택 사항이다.
- 선택 업무 범위에는 기간/완료 필터를 적용하지 않는다. 기간 보관에는 주 화면 검색/필터를 적용하지 않는다. 휴지통은 항상 제외한다.
- 반복 업무는 한 업무로 담고 저장된 회차의 상태·결과를 함께 남긴다. 미래 반복 회차는 생성하지 않는다.
- 오프라인 `업무목록.html`은 접힌 상세까지 검색한다. 제목·설명·결과·일지·체크리스트·파일명/메모·폴더명/경로가 대상이며 첨부 본문/OCR 검색은 없다.
- `업무목록.xlsx`는 업무 목록/상세 내용/파일 목록/보관 안내 시트를 제공한다. 긴 본문·파일 메모는 분할하고 텍스트를 수식으로 실행하지 않는다.
- 파일은 독립 사본으로 복사한다. HTML 상대 링크와 파일 검증 목록을 함께 남기므로 다른 PC로 이동할 때 묶음 폴더 전체를 가져간다.
- 파일 종류 단위 포함 옵션이다. 개별 파일만 저장하려면 기존 첨부의 `선택 저장`을 사용한다.
- 내부 업무/첨부/이력 정리·삭제, 외부 폴더 내용 수집, URL/파일 바로가기는 추가하지 않았다.

## 자료 보호와 호환성

- DB 0016은 `task_folder_links` 테이블 추가다. 기존 업무/첨부를 옮기거나 제거하지 않는다. 첫 업그레이드 보호 사본은 기존 이행 체계를 사용한다.
- 0015 자료 이행과 폴더 연결이 포함된 전체 백업의 새 프로필 복원을 검사했다. 외부 폴더의 실제 내용은 전체 백업에 넣지 않는다.
- 보관 중 누락/변경/취소/출력 오류는 완료로 표시하지 않는다. 원본을 유지하고 오류 위치와 미완료 폴더를 안내한다.
- HTML/Excel/파일 목록 검증 후 임시 완료 표식을 작성·동기화하고 이름 변경으로 공개한다. 완료 표식 작성 실패는 미완료다. 완료 후 이전 미완료 표식 제거만 실패한 경우 성공과 정리 경고를 함께 표시한다.
- 새 묶음은 고유 이름으로 만들어 기존 묶음을 덮어쓰지 않는다. 작업 중 파일 pin·안정적 읽기·청크 복사·해시를 사용한다.
- 보관 자료는 읽기용 스냅샷이며 DB 복원/재가져오기 형식이 아니다. 전체 복원에는 기존 `.ofbackup`을 사용한다.
- 업무별 캡처 시각을 남긴다. 여러 업무 전체가 정확히 같은 순간에 동결됐다는 의미는 아니다.

새 기능 검사에는 이전/신규 DB, FK 삭제, 휴지통 읽기 전용, 연결 정보 백업/복원, 오래된 창의 변경 충돌,
폴더 누락/중복/재지정, 실제 Windows junction, 날짜/선택 범위, 반복 회차, 파일 포함 옵션,
고정 파일 훼손, 원본 유지, 취소, 완료 표식 오류, HTML 이스케이프/검색, Excel 수식/긴 텍스트,
GUI 스레드 전달·안전한 종료·보관 중 주 화면 조작을 포함했다.

별도 시험 프로세스를 복사 중/파일 준비 후 두 지점에서 강제 종료하고 미완료 표식·원본 유지·새 보관 재실행을 확인했다.
이는 실제 전원 차단이나 저장 장치 고장까지 보장하는 검사는 아니다.
32 MiB 파일의 별도 검사에서 Python 추적 메모리 최고값은 2.69 MiB, 보관 시간은 약 0.25초였다.
전체 프로세스 메모리나 회사 PC의 저장 장치 성능을 나타내는 수치는 아니다.

## 화면 검증 범위와 제한

- 밝음/어둠 제어 팔레트, Qt 배율 100/150/200%, Windows 한국어 글꼴을 로드한 offscreen 렌더링을 검사했다. 각 배율의 관련 검사 3개가 통과했다.
- 긴 폴더명은 말줄임·툴팁, 경로는 줄바꿈·툴팁으로 표시한다. 폴더 목록 세로 스크롤과 옵션 창의 스크롤/고정 하단 버튼을 확인했다.
- 캡처 예: `artifacts/folder-archive-ui-captures/folders-dark-2.png`, `archive-dark-1.5.png`.
- 실제 Windows 설정의 테마/DPI를 전환한 검사는 아니다. 실제 회사 PC의 보안 프로그램, 공유 드라이브 지연, 문서 편집기 실행은 사용자 확인이 필요하다.
- 초기 전체 UI 실행 중 진단 없는 종료 1회와 정지 1회가 있었다. 인접 검사 단독 실행은 통과했으며 verbose 재실행 372개, 최종 전체 재실행 373개가 통과했다. 초기 현상의 원인은 확정하지 않았다.

## 사용자 확인 및 배포 상태

1. `run-officeflow-dev.cmd`로 개발 소스를 실행한다. 기존 `dist/OfficeFlow/OfficeFlow.exe`에는 이번 기능이 없다.
2. 업무의 폴더 탭에서 폴더를 추가·열고, 표시 이름/실제 위치를 바꾼 뒤 재지정한다. 연결 삭제 후 실제 파일이 그대로인지 확인한다.
3. 짧은 기간 또는 선택 업무를 보관한다. HTML에서 접힌 업무 내용과 파일명/메모를 검색하고 사본 링크를 확인한다.
4. 연도 보관 시 원하는 날짜 기준과 `완료 업무만`을 확인한다. 내부 자료가 그대로이고 재보관은 별도 폴더인지 확인한다.

검사는 격리된 `artifacts` 자료만 사용했다. 실제 사용자 데이터와 `.local-data`는 테스트에 사용하지 않았다.
개발 소스를 실제 프로필에 적용하기 전 전체 백업을 권장한다. 0016 적용 후 공개 3.0.9로 되돌리려면 업그레이드 전 자료가 필요하다.

이번 작업은 소스·설계·도움말·검증까지다. 버전은 올리지 않았고 EXE/설치 파일/ZIP 재생성, Git 커밋·GitHub 업로드는 하지 않았다.
공개 3.0.9 배포 파일은 DB 0015 상태 그대로다.
