# 업무 입력·알림 연결 1~3차 구현·검증

배포 후속 기록: 2026-10-11 사용자 요청으로 3.0.10에 포함한다. 이 문서의 미배포 표기는 작성 당시 기록이며
최신 검증·GitHub 공개 결과는 [3.0.10 릴리스 체크리스트](59-release-checklist.md)를 따른다.

2026-10-10. 승인 범위와 상세설계는 [49번 문서](49-task-input-and-reminder-design.md)를 따른다.

## 구현 결과

- 날짜·시간·닫힌 중요도/상태/일정/반복 선택·반복 간격의 휠 오변경을 막고 본문 스크롤로 전달한다.
  달력 팝업/열린 선택 목록은 유지한다. 이번 적용 범위는 업무 입력창이며 다른 화면을 일괄 교체하지 않았다.
- 시간은 전체 값으로 입력한다. 진입 시 전체 선택, 11→11:00 / 1124→11:24 / 924→09:24 / 11:24,
  붙여넣기·Tab·Shift+Tab 확정. 잘못된 입력은 텍스트를 유지하고 표시하며 저장을 막는다.
- 작은 -/+ 버튼과 시간칸 ↑/↓는 분을 유지하며 한 시간 조정한다. 시작/기간 종료는 자정에서 날짜도 바뀐다.
  날짜 입력 범위 초과 또는 하루 일정 종료의 다음 날 이동은 안내하고 기존 값을 유지한다.
  버튼을 Tab 동선에 추가하지 않았고, 조정 직후 숫자로 바로 교체할 수 있다.
- 일반 새 업무는 창을 연 현재 시각 +최소 60분을 만족하는 가장 가까운 정각이다.
  초도 계산한다(14:00:00→15:00, 14:00:01→16:00). 주 화면/입력창의 현재 시각을 통일했다.
  자정/연말·DST를 검사했고, 달력에서 선택한 날짜는 유지한다. 입력 중 기본 시각을 다시 밀지 않는다.
- 새 업무의 미수정 기본 알림만 일정 없음 동안 제외하고 복귀 시 복구한다. 기존/직접 설정한 알림은 유지한다.
  기존 저장 서비스의 과거 새 알림 금지 규칙도 유지한다. 과거 업무는 알림 없음으로 기록할 수 있다.
- 직접 지정 전 종료 기본값만 시작 +1시간을 따른다. 하루 일정은 같은 날 23:59까지 제안하고
  기간 일정은 다음 날 종료도 제안한다. 실제 기존 종료/직접 입력한 종료 날짜·시각은 보존한다.
- 제목/시간/종료/반복/알림 오류는 해당 항목을 표시·스크롤·포커스한다. 숨긴 추가 설정 오류는 펼친다.
  잘못된 입력을 둔 채 취소할 수 있다. 표시 변경 중 포커스 손실 안내가 표시 상태를 재귀 변경하지 않게 했다.
- 알림의 업무 보기는 delivery의 실제 업무/원래 반복 회차를 사용한다. 기존 비모달 기록창을 재사용하고
  업무일지 하위의 동일 창도 찾는다. 작성 내용·주 화면 검색/선택을 유지한다.
  보기만으로 알림/업무 상태를 변경하지 않는다. 삭제/처리된 업무의 알림은 안내하며 다른 창을 열지 않는다.
- 알림은 상단 고정/독립 처리 상태를 유지한다. 기록 창은 옆으로 배치하며 새 modal/topmost 창을 추가하지 않는다.
  좁은 화면에서 완전한 비겹침을 보장하지는 않는다.

## 사용자 확인·배포 상태

`run-officeflow-dev.cmd`로 소스를 실행해 기본 정각, 11/1124 입력·붙여넣기·Tab, 휠 스크롤,
-/+·종료 입력·일정 없음 저장을 확인한다. 실제 알림에서 업무 보기를 눌러 기록/체크리스트/첨부를
확인하고 별도로 이번 알림 확인을 누른다.

격리된 artifacts만 사용했고 실제 프로필·`.local-data`에 접근하지 않았다.
이번 입력/알림 변경은 추가 DB 이행이 없다. 앞서 미배포 외부 폴더의 DB 0016은 그대로다.
버전 3.0.9, EXE/설치 파일/ZIP·Git 커밋/GitHub는 변경하지 않았다. 공개 파일에는 이번 기능이 없다.
미저장 보호·빠른 일정 변경·외부 보관 내역·내부 자료 정리·24개 시간 선택판을 추가하지 않았다.

## 후속 사용 확인 보완: 알림 입력·중복 메뉴

- 알림 추가/수정의 직접 시각 지정도 전체 값 입력으로 변경했다. 11/1124/11:24,
  붙여넣기, Tab/Shift+Tab, −/+와 ↑/↓, 분 유지 및 자정의 날짜 이동을 지원한다.
  새 직접 지정의 기본 시각도 최소 1시간 뒤 정각이다. 기존 직접/상대 알림 값과 취소 의미는 유지한다.
- 입력 오류는 텍스트를 남기고 추가/적용 및 Tab 이동을 막는다. 상대 방식으로 바꾸면
  숨은 직접 시각 오류는 상대 알림 저장을 막지 않는다. 휠로 닫힌 날짜/시각/간격/선택값이 바뀌지 않는다.
- 실제 Qt 마우스 포커스는 mousePress보다 먼저 도착해 기존 전체 선택이 풀렸음을 재현했다.
  공통 시간칸에서 마우스로 처음 진입한 클릭을 기억해 전체 선택을 유지한다.
  알림 창의 명시적 Tab 순서도 지정해 날짜 다음의 시각을 건너뛰지 않도록 했다.
- 목록·달력·휴지통 우클릭의 같은 기록 창 진입은 `업무 보기` 하나로 통일했다.
  업무일지·체크리스트·완료 요약·첨부 탭과 마지막 탭 기억·회차·휴지통 읽기 전용을 유지한다.
  화면의 기존 첨부 바로가기, 이력·폴더·완료·수정·삭제 기능을 제거하지 않았다.
- 후속 창 offscreen 제어 팔레트 밝음/어둠·380px·Windows 한국어 글꼴의 Qt 배율
  100/150/200% 검사는 각 2개 통과했고 `artifacts/reminder-time-input-captures/`에 캡처했다.
  실제 Windows 테마/DPI 변경 및 회사 PC 보안 환경 검증과는 구분한다.
- 최종 전체 UI 425개 + 시간 규칙 단위 21개, 총 446개가 158.03초에 통과했다.
  로그는 `artifacts/reminder-input-final-tests.log`다. Ruff·mypy 131개 소스·diff 공백 검사도 통과했다.
  최초 전체 실행은 최종 요약 없이 종료되어 완료로 인정하지 않고, 기록 창을 여는 테스트의
  명시적 shutdown을 보완한 뒤 상세 로그를 남기는 전체 검사를 재실행했다. 최초 종료 원인을
  사용자 프로그램 오류로 단정하지 않는다.
- 개발 소스와 도움말만 반영했다. DB 형식·실제 사용자 자료·버전·EXE/설치 파일/ZIP·커밋·업로드는 변경하지 않았다.
