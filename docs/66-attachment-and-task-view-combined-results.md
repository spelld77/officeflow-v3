## 1. 반영한 사용 흐름

- 목록·달력에서 더블클릭하거나 Enter를 누르면 같은 **업무 보기**를 연다.
  기존 체크리스트·완료 요약·업무일지·첨부·폴더 탭은 유지하며, 제목/일정 편집은 `수정` 버튼이나 기존 메뉴에서 한다.
- 상단에는 현재 저장된 설명·일정·상태를 읽기 전용으로 표시한다. 설명은 글자 선택·복사가 가능한 plain text다.
  없는 설명은 생략하고, 일반 진입은 실제 줄바꿈/폭 기준 3줄, `더 보기`는 6줄 높이의 스크롤 영역이다.
  설명의 저장 내용은 잘라내지 않는다. 첨부 직접 진입은 설명을 접어 목록 공간을 확보한다.
- 새 일반 보기창은 체크리스트에서 시작한다. 같은 업무/원래 회차 창은 재사용하며 열린 탭·미저장 결과/일지 초안을 유지한다.
  업무 수정·상태 변경 뒤에는 조회 헤더만 갱신한다. 휴지통은 읽기 전용이며 영구 삭제/재조회 실패 안내도 초안을 지우지 않는다.
- 기본/간결 목록의 기존 `첨부`/파일명 일치 배지를 누르면 해당 행의 첨부 탭으로 연결한다.
  그리기와 클릭 판정에 같은 좌표를 사용한다. 배지 더블클릭·연속 클릭은 같은 창을 재사용하고 일반 활성화와 분리한다.
  눌렀다 다른 곳에서 놓으면 열지 않는다. 기존 키보드/메뉴 접근은 유지하며 파일을 자동 실행하지 않는다.
- 반복은 이동한 표시 날짜와 원래 회차 키를 구분한다. 보기만으로 회차를 DB에 생성하지 않는다.
  설명은 업무 공통 값, 일정·상태는 선택 회차의 유효 값이며 `수정`은 기존 기본 업무 수정 경로다.
  완료/취소/건너뛴 회차와 반복 전체 종료의 표시 우선순위를 구분한다.
- 날짜 도움말은 정확한 날짜·요일과 시작/종료까지의 달력 날짜 차이를 표시한다.
  종일의 배타 종료·자정·시간대·월/연도 경계를 처리하며 시작일 경과를 마감 초과로 단정하지 않는다.
  완료/취소·휴지통·확인 전 회차에 남은 작업을 요구하지 않는다. 도움말 요청 때 시각만 새로 계산하고 DB/파일을 읽지 않는다.
- `.webp` 및 PNG 이름의 실제 WebP를 현재 Qt decoder로 읽는다. 원본 변환·파일명/자산/기준 해시 변경은 없다.
  재생 타이머 없이 첫 프레임을 읽는 경로다. 기존 1,600만 픽셀·64 MiB, 32 MiB/64개 LRU·32개 큐·한 reader worker를 유지한다.
- 썸네일/확대가 같은 명시적 실패 분류를 사용한다. `형식 미지원 / 크기 제한 / 파일 없음 / 읽기 불가 /
  고정 내용 불일치 / 다시 확인 필요 / 미리보기 실패`를 구분하고 세부 원인은 도움말에서 본다.
  형식 실패만으로 원본이 수정됐다고 표시하지 않으며 실제 frozen SHA-256 불일치는 이미지 공개를 거절한다.
- 이름 변경은 본문 또는 전체 파일명을 받아 완성 이름을 한 줄로 보여준다. 긴 이름은 폭에 맞춰 줄이고 전체 이름은 도움말에 유지한다.
  같은 끝 확장자 하나만 정규화하며
  중복 여러 개·금지 문자·경로·끝 공백/마침표·최종 길이는 오류로 남긴다. 점/버전 번호·다른 접미사는 유지한다.
  기존 중복 이름을 편집하지 않았다면 무변경 저장이다. 첨부 ID·내용·실제 경로·과거 이름/작업본 이름은 바꾸지 않는다.
- 파일 추가 picker에서 첫 선택 파일의 부모 폴더를 기억한다. 취소·드롭·클립보드·외부 저장은 이 값을 바꾸지 않는다.
  일반 보기·업무일지 자식 창에 최신 값을 전달하며 저장 실패는 비차단 안내만 한다.
  시작 시 경로를 검사하지 않고, 누락된 로컬 폴더는 문서 폴더로 복귀한다. 네트워크/매핑 드라이브 사전 stat은 하지 않는다.
- 회귀 검사에서 달력 알림 선택 뒤 목록 재조회가 스크롤을 초기화하는 경우를 발견해 보완했다.
  최종 행/레이아웃에서 대상을 보이게 하고, 늦은 조회는 같은 날짜에만 적용하며 다른 날짜로 이동하면 요청을 취소한다.

새 패키지·DB 이행·디스크 이미지 캐시·상시 타이머·알림 처리/삭제 정책은 추가하지 않았다.
새 설정은 `attachment_import_directory` 하나이며 구형/손상된 이 필드만 복구한다.

## 3. 시각 확인 및 중간 발견

Windows Qt의 별도 프로세스에서 앱 팔레트를 밝게/어둡게 주입하고 100/150/200%를 검사했다.
500×540 DIP 업무 보기의 설명 미리보기/펼침·첨부 직접 진입·최소 5행·실제 디코딩된 WebP 썸네일,
좁은 이름 입력창의 완성 이름·버튼 가독성을 확인했다. 작은 합성 이미지/DB만 사용했다.
캡처는 `artifacts/u27-u29-captures/{light,dark}-{1,1.5,2}/`에 보존한다.
실제 Windows 테마 설정을 변경한 것이 아니라 앱 팔레트 주입이며 회사 PC 검증과 다르다.
대표 150% 설명 미리보기/긴 완성 이름과 200% 실제 WebP 썸네일 캡처를 직접 열어 밝은 본문·글자·줄임·목록 영역을 확인했다.

- 기존 Enter/마지막 탭/달력 건수/안내 문구 검사가 옛 동작을 기대해 실패했다. 새 진입 계약에 맞췄으며
  명시적 수정·미저장 초안 보호·첨부 직접 진입 검사를 별도로 유지했다.
- 옛 달력 알림 스크롤 자료는 같은 시각의 정렬 위치를 가정했다. 더 이른 업무를 넣어 대상이 화면 아래에
  실제로 배치되게 바꾸자 재조회 뒤 스크롤 초기화가 드러났다. 제품 경로를 수정했고 조건을 느슨하게 지우지 않았다.
- 두 대량 Qt 검사 시도는 기존 첨부 삭제 테스트 부근에서 진행이 멈췄다. 정확한 pytest 명령의 프로세스만 식별해
  종료했고 실사용 OfficeFlow는 종료하지 않았다. 새 헤더 재조회를 ActivationChange 안에서 동기 실행하는 경로를 제거하고
  저장 성공/명시적 재사용 경로로 한정했다. 이후 UI 전체 실행은 끝났으나 이 변경이 이전 대기의 유일한 원인임을 입증한 것은 아니다.
- 기존 화면 캡처 자식 프로세스 한 실행이 35초 제한을 넘었다. 단독 6개 재검사 및 이후 UI 전체에서는 재현되지 않았다.
  검사를 생략하거나 제한을 늘려 통과시키지 않았다.
- 전체 format 검사에는 기존 미정돈 테스트가 있어 관련 없는 파일 전체를 일괄 정돈하지 않았다.
  실제 변경 파일의 format과 전체 lint/mypy를 확인했다.

## 4. 사용자 확인과 미검증 환경

개발 소스의 `run-officeflow-dev.cmd`를 실행해 확인한다. 실사용 폴더/공개 3.0.11 배포물은 아직 교체하지 않았다.

1. 오늘/예정/달력에서 업무 더블클릭·Enter로 설명을 보고 `수정`으로 편집한다. 결과/일지 초안은 남아 있어야 한다.
2. 목록의 첨부 배지로 직접 들어가 목록 공간을 확인한다. 일반 진입으로 설명을 다시 펼칠 수 있어야 한다.
3. WebP/PNG 이름의 WebP 썸네일, 전체 파일명 붙여넣기와 완성 이름, 파일 추가의 마지막 폴더를 확인한다.
4. 날짜 위 도움말의 정확한 날짜·요일과 남은 날짜를 확인한다. 달력 알림 건수를 눌러 선택 대상이 보여야 한다.

회사 PC의 **DRM/EDR·실제 native 파일 picker/네트워크 장애·서로 다른 권한/다중 모니터·배포물의 WebP plugin**은 미검증이다.
자동 mouse 전달/팔레트 주입은 실제 회사 PC 확인을 대신하지 않는다. 보안 정책 우회·관리자 실행·상한 확대는 하지 않았다.
Qt plugin이 없는 배포 환경과 다양한 다중 프레임 WebP 파일은 추후 실제 자료/배포물 검사 대상이다.
저장 폴더 기억은 파일 소유권/백업 복원 경로가 아니다. 느린 네트워크 picker의 OS 대기 시간을 보장하는 별도 서비스는 없다.

## 5. 테스트 자료 정리와 후속 단계

전체 검사 프로세스 종료 뒤 이번 작업 소유 임시 폴더 26개만 정확한 절대 경로·reparse point를 확인해 정리했다.
보안 검사에서 만든 Junction 3개는 연결 대상이 같은 fixture 내부임을 확인하고 링크만 먼저 제거했으며 대상은 그때 보존했다.
이후 링크가 없는 26개 디렉터리를 정리하고 남은 대상 0개를 확인했다. 논리 파일 크기 합계는 35,652,535,938 bytes
(약 33.2 GiB)이며 sparse/경계 테스트 파일을 포함하므로 이 숫자를 실제 확보한 디스크 공간으로 해석하지 않는다.
XML/소형 캡처는 남겼고 실제 사용자 자료와 다른 작업의 fixture는 보존했다. 지운 자료는 합성 테스트 데이터이며 재실행으로 생성할 수 있다.
사용 확인 후 별도 요청이 있을 때 버전·EXE/설치본/ZIP·커밋·GitHub 릴리스를 진행한다.

## 6. 사용 확인 후 작은 창 깜빡임 보완 (2026-10-15)

사용자가 업무 더블클릭 시 작은 창이 잠깐 나타났다 닫힌다고 보고했다. 창 생성 중의 전역 Show 이벤트로
설명 있는 업무/첨부 직접 진입에서는 `TaskDescription`, 반복/휴지통에서는 `WrappingLabel`이
부모 없는 별도 창으로 먼저 표시되는 것을 재현했다. 설명 없는 일반 업무만 이 현상이 없었다.
레이아웃에 추가하기 전에 `setVisible(True)`가 실행되었기 때문이다.

두 영역을 처음부터 `TaskRecordsDialog`의 자식으로 생성하도록 보완했다. 업무 보기의 실제 창·크기·설명 접기·탭,
반복 범위·미저장 기록 초안·파일/DB·알림 처리 정책은 변경하지 않았다. 새 지연 타이머나 창 숨김 우회는 넣지 않았다.

- 최초 재현: 5개 중 4개에서 불필요한 Show 이벤트 확인. `artifacts/task-view-flash-before.xml`.
- 수정 후 업무 보기·달력 기록·기록/첨부 공간·가독성 관련 63개 통과. `artifacts/task-view-flash-verified.xml`.
- Windows Qt 100/150/200%에서 각 7개 통과. `artifacts/task-view-flash-native-{1,1.5,2}.xml`.
- 목록/달력 검사는 일반 첫 클릭 뒤 실제 Qt doubleclick 이벤트를 보내 업무 보기 하나만 열림을 확인했다.
  생성 전/갱신/재사용 때의 순간 Show 이벤트도 검사하므로 최종 topLevelWidgets 목록만 확인한 결과가 아니다.
- 변경 Python format·전체 Ruff/mypy·diff 검사 통과. 이번 후속 수정에서는 전체 1,475개를 다시 실행하지 않았다.

이번 후속 격리 테스트의 임시 폴더 6개만 경로/링크 검사 후 정리하고 남은 대상 0개를 확인했다.
XML/기존 캡처를 보존하며 지운 합성 테스트 자료는 재실행으로 생성할 수 있다.
실사용 프로그램은 자동 재시작/교체하지 않았으며 소스 변경을 사용하려면 기존 창을 종료하고 개발 실행파일로 다시 실행한다.
