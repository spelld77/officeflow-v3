# 개발 로드맵

일정은 날짜보다 품질 게이트를 기준으로 관리한다. 각 단계의 종료 조건이 충족되지 않으면 다음 단계로 넘어가지 않는다.

## Phase 0. 설계 기준선 — 완료

산출물:

- 제품 요구사항과 제외 범위
- UX 정보 구조와 기간 일정 규칙
- 아키텍처와 데이터 모델
- 기존 데이터 이전 전략
- 테스트 및 릴리스 기준

종료 조건:

- 핵심 용어와 상태가 문서 간 일치한다.
- 미결정 항목이 구현을 막는지 식별되어 있다.
- 사용자 우선순위가 반영되어 있다.

## Phase 1. 프로젝트 기반 — 완료

산출물:

- 패키지 구조와 의존성 잠금
- 자동 포맷·정적 검사·테스트 명령
- 설정 경로, 로그, DB 연결과 마이그레이션
- 빈 메인 창과 테마 토큰
- 개발용 샘플 데이터 생성기

종료 조건:

- 신규 설치 상태에서 앱이 실행된다.
- 테스트가 사용자 데이터와 격리된다.
- CI 또는 동일한 로컬 품질 명령이 통과한다.

## Phase 2. 업무 관리 수직 기능 — 완료

산출물:

- 업무 생성·조회·수정·상태 전이
- 빠른 등록과 상세 패널
- 오늘/전체 목록
- 날짜, 상태, 중요도 검증

종료 조건:

- 일정 없는 업무, 하루 업무, 기간 업무의 CRUD가 동작한다.
- 종료일이 시작일보다 앞선 데이터를 저장할 수 없다.
- 재시작 후에도 데이터가 동일하다.

## Phase 3. 대량 업무 탐색 — 완료

### Phase 3A. 조회 기반과 성능 기준 — 완료

- 지연·진행 중·오늘 예정·오늘 완료 그룹 조회
- 검색·상태·중요도·고정·정렬의 조합 가능한 조회 계약
- offset/limit 페이지 결과와 전체 개수
- 그룹·완료·갱신 조회용 복합 인덱스
- 5,000건 기준 자동 성능 측정

### Phase 3B. 탐색 UI — 완료

- 그룹별 접기·펼치기와 그룹 바로가기
- 복합 필터와 정렬 컨트롤
- 완료 그룹 기본 접힘과 보기별 상태 기억

### Phase 3C. 목록 지연 로딩과 최종 검증 — 완료

- Qt 모델 `fetchMore` 기반 페이지 로딩
- 간결 보기
- 50건 사용성 및 5,000건 UI 성능 검증

산출물:

- 오늘 화면의 지연·진행·예정·완료 그룹
- 검색, 복합 필터, 정렬, 고정
- 간결 보기와 지연 로딩
- 5,000건 기준 성능 측정

종료 조건:

- 50개 이상 오늘 업무에서 스크롤 없이 그룹을 이동할 수 있다.
- 목표 장비에서 핵심 검색·필터 성능 기준을 만족한다.
- 완료 그룹은 기본적으로 접혀 있다.

## Phase 4. 캘린더와 기간 일정 — 완료

산출물:

- 월간 캘린더
- 하루 및 여러 날 일정 막대
- 날짜 겹침 조회
- 월·연도 경계 처리

종료 조건:

- 여러 날 일정이 모든 포함 날짜에 나타난다.
- 주 또는 월 경계를 넘는 일정이 끊김 표시와 함께 정확히 보인다.
- 날짜별 더 보기에서 숨은 일정을 확인할 수 있다.

## Phase 5. 반복과 알림 — 완료

### Phase 5A. 반복과 발생 이력 — 완료

- 매일·매주·매월 RRULE과 간격·종료일
- 시간대 및 일광절약시간을 고려한 발생 계산
- 발생 건별 완료·건너뛰기와 다음 발생
- 캘린더와 오늘 그룹의 반복 발생 표시
- 반복 범위와 발생 이력 조회 인덱스

### Phase 5B. 알림 신뢰성 — 완료

- 시작·종료 기준 알림 규칙
- 다시 알림과 중복 방지 키
- 앱 중단 중 놓친 알림 복구
- 묶음 알림창의 완료·대기·10분 후·확인 동작
- 발송 이력 영구 저장과 데이터베이스 고유 키

### Phase 5C. Windows 실행 통합 — 완료

- 시스템 트레이
- 단일 실행
- 전역 단축키와 시작 시 실행
- 닫기와 트레이 숨기기의 명시적 구분
- 트레이 기반 Windows 알림 전달

산출물:

- 반복 규칙과 발생 건별 완료 기록
- 알림, 다시 알림, 놓친 알림 복구
- 시스템 트레이와 단일 실행
- 전역 단축키 설정

종료 조건:

- 반복 한 건의 완료가 다음 발생을 제거하지 않는다.
- 동일 알림이 중복 표시되지 않는다.
- 앱 재시작과 절전 복귀 시 정의한 복구 정책대로 동작한다.

## Phase 6. 기록, 첨부와 내보내기

산출물:

- 업무일지와 결과 메모
- 체크리스트와 첨부파일
- Excel·ICS 내보내기
- 백업·복원

종료 조건:

- 파일 작업 실패 시 DB에 잘못된 참조가 남지 않는다.
- 기간 일정의 시작·종료가 ICS에 보존된다.
- 백업 복원 후 검증 결과가 일치한다.

## Phase 7. v2.6 이전

산출물:

- 마이그레이션 도구와 미리보기
- 변환 보고서
- 과거 스키마 fixture와 회귀 테스트

종료 조건:

- 원본 DB를 변경하지 않는다.
- 개수와 연결 관계 검증이 통과한다.
- 누락 파일과 잘못된 날짜가 보고서에 명시된다.

## Phase 8. 안정화와 배포

산출물:

- Windows 설치 프로그램
- 자동 시작 옵션
- 사용자 도움말과 문제 해결 안내
- 릴리스 체크리스트

종료 조건:

- 깨끗한 PC 설치, 업그레이드, 제거 테스트를 통과한다.
- 치명적 데이터 손실 및 알림 중복 결함이 없다.
- v2.6을 사용하는 실제 흐름과 병행 시험을 완료한다.

## 현재 미결정 항목

다음 항목은 Phase 1 전에 확정한다.

- 업무 제목을 기존 content 첫 줄에서 자동 생성하는 최대 길이
- 기존 deadline 필드의 실제 의미와 starts_at/ends_at 매핑
- 종일 일정의 기본 알림 시각
- 앱 종료 중 발생한 알림의 복구 유예 시간
- 삭제된 업무와 첨부파일의 보관 기간
