# U41 선택 첨부의 탐색기·바탕화면 드래그 복사 상세설계

2026-11-11. 사용자 `설계하고 구현까지 진행해` 승인으로 구현 전에 작성했다.
최신 구현·검증 결과와 미검증 범위는 [92번](92-attachment-drag-copy-results.md)을 따른다.
[24번](24-follow-up-common-design.md)의 독립 사본/고정 자료 보존과
[06번](06-development-process.md)의 밝은 UI 기준을 따른다.

## 범위와 사용자 결정

- 업무 보기의 현재 첨부 목록/썸네일에서 선택한 여러 파일을 탐색기·바탕화면으로 복사한다.
- 사용자 답변: **선택 시 미리 준비하고, 준비 전에 끌었으면 안내 후 다시 끈다.**
- Ctrl/Shift 다중 선택·더블클릭 열기·목록 순서·종류 필터·외부 파일 받기를 보존한다.
- 메일/메신저·전체 검색/보관함/과거 버전 목록의 드래그는 이번 범위가 아니다.
  현재 목록의 일반 첨부/원본/작업본은 동일한 독립 사본으로 전달한다.
- 버전·DB 이행·배포물·커밋/GitHub·운영 자료/실행 폴더를 변경하지 않는다.

## 자료 준비와 수명

관리 파일 경로를 MIME에 직접 넣지 않는다. worker가 선택한 첨부 ID를 기존 export.resolve로
다시 조회하고 coordinator의 job/pin 및 Windows protected_read로 안정적으로 읽는다.
고정 자료는 고정 크기/해시와 대조한다. 청크 복사·취소 확인·전후 파일 identity·사본 해시 검증을 수행한다.
미저장 외부 편집 내용이나 고정 자료의 수정된 보기 사본을 자동 포함하지 않는다.
하나라도 실패하면 부분 준비 목록으로 드래그하지 않고 전체 배치를 실패시킨다.

원장/백업과 분리된 OS 임시 폴더 `OfficeFlow-drag-copies/<무작위 세션>/`에만 쓴다.
표시 이름을 기존 safe_name으로 정리하고 Windows 대소문자를 무시한 이름 충돌에 `(2)` 등의 번호를 붙인다.
기존 번호 이름과도 충돌하지 않게 모든 출력 이름을 예약한다. 파일 내용을 변환하지 않는다.
한 배치는 최대 100개, 한 창 세션의 보존 사본은 최대 1GiB/32배치다. 초과하면 기존 저장 기능을 안내한다.
준비 전/중 변경된 선택은 300ms 지연과 취소/최신 요청 합치기로 불필요한 복사를 줄인다.

준비된 사본은 **준비 시점**의 내용이다. 상태에 이 점을 표시하고 선택을 해제/다시 선택하면 새로 준비한다.
새 선택/목록 재조회에서 즉시 이전 ready를 무효화하며, 실제 MIME 전달 직전에 선택 토큰도 확인한다.
이미 외부에 전달한 사본은 드롭 반환 직후나 창 닫기 때 삭제하지 않는다. 탐색기의 지연 읽기를 허용한다.
외부에 전달하지 않은 이전 사본은 다음 준비 worker에서, 실패한 배치는 해당 worker에서 정리한다.
종료 직전 남은 사본은 종료 중 새 worker를 만들지 않고 다음 사용의 만료 정리에 맡긴다.

세션에 OS 읽기 잠금을 유지한다. 전달 직전 작은 last-offer 표시의 시각을 갱신한다.
다음 준비 작업에서 생성/마지막 전달 이후 최소 24시간 지난, 잠금이 해제된 소유 세션만
제한된 개수로 정리한다. 살아 있는 다른 창/프로세스의 사본은 삭제하지 않는다.
세션 소유 표시·루트 경계·재분석 지점/링크를 검사하며 외부 파일/보기 사본/관리 파일을 정리하지 않는다.
크래시 뒤 남은 세션도 같은 규칙으로 다음 사용 때 정리한다. 앱 미실행 중 즉시 정리를 보장하지 않는다.

## UI와 드래그

파일 선택 시 목록 위의 작은 상태 줄에 준비 중/준비 완료/실패를 표시한다. 긴 상시 설명/새 설정은 추가하지 않는다.
준비 완료 시 `준비 시점 사본 · N개 · 탐색기/바탕화면으로 끌어 복사`를 표시한다.
준비가 안 됐으면 drag를 시작하지 않고 준비 완료 뒤 다시 끌도록 안내한다. 마우스를 나중에 자동으로 잡지 않는다.
QListWidget의 기본 drag threshold를 사용하고 startDrag만 공통 controller로 위임한다.
QMimeData.setUrls + QDrag.exec(CopyAction, CopyAction)만 사용한다. Move/Link를 광고하지 않는다.
native drag 안에서는 연결/worker 생성·복사·DB 읽기를 시작하지 않는다. 알림은 계속 동작한다.
드롭 성공 반환을 실제 대상 파일 저장/바이트 검증 완료로 표시하지 않는다. 대상 충돌/취소는 탐색기가 처리한다.
OfficeFlow 내부로 되돌려 놓는 self-drop은 차단해 첨부 중복 등록을 막는다.

controller는 ShutdownOwner/ShutdownScope로 worker를 소유하고 연결은 시작 전에 만든다.
종료 시 debounce 취소·worker 취소·진행 중 QDrag.cancel을 요청하고 native join 후 소유 잠금을 해제한다.
늦은 결과는 토큰/종료 상태로 버리며 종료 중 새 worker를 만들지 않는다.
준비 중 선택/파일 삭제는 기존 coordinator 계약으로 충돌을 처리하며 드래그 때문에 내부 파일을 삭제하지 않는다.

## 검증과 완료 기준

소형 합성 파일만 사용한다. 복수/동일 이름/원본 고정·원본 바이트 불변·실패 전체 취소·취소/
세션 한도·준비 전 드래그·ready 선택 불일치·최신 선택 합치기·종료·self-drop을 검사한다.
기존 첨부 export/drop/썸네일의 영향 회귀를 한 번 수행하고 실패한 범위만 추가한다.
큰 파일 대신 작은 한도 주입으로 용량 초과를 검증한다. 전체 회귀/장시간 stress는 수행하지 않는다.
실제 native 드래그 API 진입은 가짜 exec로도 경계를 검사하되 실제 탐색기 전달 성공과 구분한다.
가능하면 별도 작은 native 대상 창으로 URL/Copy 전달을 확인하며 탐색기 실사용·회사 DRM/보안 정책은 별도 상태로 기록한다.
밝은 스타일의 준비 상태/좁은 창/목록·썸네일 캡처와 관련 UI 검사를 수행한다.
모든 앱/DB 검증은 명시적인 별도 OFFICEFLOW_DATA_DIR/tmp_path로 제한한다.


사용 확인 후 안내 줄 때문에 버튼이 밀린다는 요청으로 상시 준비/완료 줄을 제거한다.
준비 전 드래그/시작 실패에만 레이아웃 공간을 쓰지 않는 짧은 tooltip을 표시한다.
