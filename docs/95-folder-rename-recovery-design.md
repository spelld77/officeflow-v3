# U43 연결 폴더 이름 변경 확인·복구 상세설계

2026-11-11 사용자 `구현해` 승인에 따른 구현 전 설계.
구현·관련 검증을 완료했으며 최신 근거/한계는 [96번](96-folder-rename-recovery-results.md)을 따른다.
46번·24번의 외부 자료 비변경과 06번의 밝은 UI·가독성 기준을 유지한다.

## 범위와 저장

새 연결과 사용자가 직접 다시 지정한 연결에만 가능한 경우 폴더 식별 정보를 저장한다.
DB0018은 task_folder_links에 nullable folder_identity TEXT만 추가한다. 기존 값은 NULL로 유지하며
기존 연결/첨부를 순회하거나 식별 정보를 채우지 않는다. 표시 이름만 변경할 때는 기존 식별 정보를 보존한다.
새 DB는 구버전에서 열지 않는 기존 보호 규칙을 따른다. 전체 백업 v3 포맷은 유지한다.
개발 검사는 합성 DB만 사용하며 운영 DB/폴더·앱·버전/ZIP·커밋/GitHub는 변경하지 않는다.

식별 정보는 버전·이 PC의 MachineGuid 해시·볼륨 serial·128-bit FileId·생성 시각으로 구성한다.
지원 범위는 로컬 고정 NTFS다. 미지원/공유 경로는 일반 경로 연결을 유지한다.
다른 PC/확인 불가에서는 자동 복구하지 않는다. 식별 번호가 영구/전역 유일하다고 가정하지 않는다.
외부 폴더에 표식 파일을 만들거나 핸들을 장기 보유하지 않는다.

## 열기와 복구

1. 기존 경로가 있으면 정상 검증 후 연다. 추적 연결은 저장한 식별 정보도 일치해야 한다.
   같은 경로의 다른 폴더, 다른 PC/식별 미지원은 직접 지정을 안내한다.
2. FileNotFound인 경우에만 같은 상위 폴더의 직접 하위 폴더를 제한 탐색한다.
   NULL 연결, 권한 오류, 네트워크 단절, 다른 장치/PC에는 탐색하지 않는다.
3. 링크/junction·관리 데이터 폴더를 제외하고 전체 식별 정보가 일치하는 후보 하나만 제안한다.
   숫자 접두사/비슷한 이름을 동일 폴더 판별에 사용하지 않는다.
4. 후보를 찾아도 DB/열기를 실행하지 않는다. 확인창에 이전/후보 경로를 표시하고
   `이 폴더 사용` / `다른 폴더 선택` / `취소`를 제공한다. 평소 상시 안내/버튼은 추가하지 않는다.
5. 승인 시 후보 식별/관리 루트 제외를 재검증하고 DB expected 값도 대조한다.
   경로와 이전 폴더명 그대로였던 표시 이름만 갱신한다. 별도 표시 이름은 보존한다. 성공 후 폴더를 연다.
6. 다음부터 새 경로를 바로 사용한다. 실패/취소/후보 없음·복수는 기존 연결을 보존한다.
   휴지통 업무는 경로 변경을 허용하지 않고 복원 후 직접 지정을 안내한다.

## 시간 제한·종료

스레드의 시간 검사만으로 느린 OS 파일 호출을 끊을 수 있다고 가정하지 않는다.
폴더 검증/Win32 식별/후보 탐색은 단기 helper 자식 프로세스에서 수행한다.
worker가 JSON stdin/stdout으로 요청하고 5초 상한/취소를 확인하며 초과하면 자신의 helper만 종료·회수한다.
helper는 앱/DB를 초기화하지 않는다. 후보 탐색은 최대 1,000항목/2초이며 전체 트리/상시 감시/자동 재시도는 없다.
ShutdownScope가 worker/helper 취소·join을 소유한다. 확인창은 worker 정리 후 비동기로 열고
다른 창의 변경/종료/선택 변경으로 낡은 후보를 승인하지 않는다.

## 검증

작은 합성 폴더의 실제 rename/Win32 식별, 새/NULL/재지정·표시 이름·다른 ID·후보 재변경·중복/동시수정,
다른 PC/미지원·상한/취소·확인/취소 UI·종료·백업/0017→0018 NULL 보존을 확인한다.
관련 검사만 수행하고 전체 제품 회귀/대용량 반복은 추가하지 않는다. 실제 회사 공유 폴더/DRM은 별도 확인이다.
