# 자료 검색·백업 선택 저장 2차 상세설계

작성: 2026-10-10. 1차 사용자 확인 완료 후 상세설계→구현→격리 테스트 승인.
공통 계약: 24번/38번 문서. 운영 데이터·버전·배포물·GitHub 변경 제외.

## 1. 사용자 흐름

- 기존 `파일 찾기`에서 현재 첨부, 개별 보관본, 중요 시점 보관 파일을 함께 찾는다.
  추가 조건에서 자료 범위를 좁힌다. 기본은 전체 자료/전체 기간이며 휴지통·정리 대기는 제외한다.
- 검색 대상은 현재 표시 이름/최초 이름, 당시 파일 이름, 보관 이름과 파일 메모다.
  중요 시점 보관 이름도 포함한다. 문서 바이너리 내용/자동 변경 이력 본문 검색은 아니다.
- 결과마다 현재 첨부/보관본/중요 보관 종류와 보관 이름을 표시한다. 이름이 같아도 항목 ID가
  다르면 별개 결과이며 자산 중복 제거로 과거 자료를 숨기지 않는다.
- 열기/다른 이름 저장은 선택 자료의 `(종류, ID)`를 기존 공통 파일 서비스에 전달한다.
  연결 업무는 현재 업무를 연다. 보관 자료 관리 동선은 보관함 또는 업무 이력 창이다.
- `데이터 → 내보내기·백업 → 백업 파일 꺼내기…`: 백업 선택 → 검증/목록 → 이름 검색 →
  이 페이지에서 여러 파일 선택 → 외부 폴더 선택 → 파일별 완료/실패/미처리 결과.
  전체 복원·재시작·자동 첨부 연결 없이 현재 데이터는 유지한다.

## 2. 조회 계약

현재 자료 검색은 UNION ALL로 첨부/보관본/중요 보관 파일을 같은 읽기 모델로 투영한다.
50건 기본/최대 500건 페이지. 커서는 `(생성 시각, 종류, 항목 ID)` 역순으로 동시간·동ID도 구분한다.
기존 첨부 전용 API 필드는 호환하되 종류를 함께 제공하며 ID만으로 열지 않는다.
페이지 시간 제한 3초/SQLite 진행 취소/요청 세대 번호/화면 누적 500건은 유지한다.
새 FTS 테이블이나 DB 이행 없이 매개변수화한 LIKE 검색을 사용한다. `%`, `_`, `\`는 문자로 검색한다.
큰 목록에서는 더 구체적인 검색어/기간/자료 범위를 안내한다. 목록에 바이너리를 적재하지 않는다.

## 3. 백업 조회 계약

- 기존 백업 검증을 worker에서 수행한다. 형식 1/2/3과 지원 스키마를 확인한다.
  중복/위험 경로, ZIP 구성·DB/파일 해시·연결 불일치는 선택 화면으로 전달하지 않는다.
- 검증된 DB만 앱이 소유한 임시 폴더에 풀고 읽기 전용 조회한다. 운영 DB에 복원/이행하지 않는다.
  구형 스키마는 있는 컬럼/테이블만 읽는 어댑터로 이름을 표시한다.
  조회 자원 상한은 ZIP 구성/논리 항목 100,000개, DB 512MiB, 명세 16MiB다.
  한도를 넘으면 현재 자료/백업을 보존하고 해당 선택 조회만 거절한다.
- 백업 당시 첨부·보관본·중요 보관 파일의 이름/메모/업무 제목과 내부 경로를 연결한다.
  DB에 연결되지 않은 recovery 자료는 별도 종류로 표시하고 내부 저장명만 아는 경우 그대로 표시한다.
  공유 자산의 여러 논리 항목은 목록에서 구분하고 각각 선택 저장 가능하다.
- 목록 100건/페이지, 검색 후 첫 페이지, 페이지 이동 때 선택 해제(화면에 명시).
  대량 항목을 GUI/체크 상태에 무제한 누적하지 않는다.
- 백업 열람 중 읽기 보호와 파일 특성 비교, 저장 때 다시 보호 핸들/원본 특성 확인을 한다.
  교체·수정된 백업이면 다시 선택하도록 한다. 선택 자료는 매번 크기/SHA-256 검증 후 공개한다.

## 4. 외부 저장·실패

외부 저장은 기존 ExternalExportStorage의 안전 이름/대상 검증/독립 준비 파일/검증/번호 충돌/
취소/공개 저널을 재사용한다. 현재 관리 데이터 영역으로 저장하지 않는다. 기존 외부 파일을
덮어쓰지 않으며 문서를 자동 열지 않는다. 파일별 완료를 허용하고 취소 후 완료 파일은 유지한다.
출처 ZIP에서 선택 항목 하나씩 1MiB 스트리밍으로 임시 추출·검증하고 공통 저장으로 넘긴다.
성공 후 앱 소유의 임시 자료만 정리한다. 공개 불확실 시 기존 복구 동선의 저널을 보존한다.
강제 종료 시 외부 완료 파일/출처는 유지한다. 추출 임시 폴더 잔여물은 자동 추측 삭제하지 않는다.
오래된/없는 파일·보안 잠금·권한·공간·취소는 사용자에게 실패/미처리로 표시한다.
저장 후 `저장 폴더 열기`를 제공하되 자동으로 탐색기/문서를 열지 않는다.
조회·저장은 공유 파일 작업 슬롯으로 다른 대형 파일 작업과 겹치지 않게 한다.

## 5. UI·자원

새 백업 창은 비모달(기존 알림 방해 금지), 밝은 공통 스타일/viewport/선택색 명시,
최소 500×420, 목록이 높이를 우선 사용한다. 긴 설명/전체 경로는 툴팁으로 둔다.
작업은 단일 worker에서 진행하고 진행률/취소/닫기 시 취소 후 native thread join을 보장한다.
조회/저장 중 중복 요청을 막고 결과는 queued로 GUI에 전달한다. 종료 전에 임시 DB/파일을 닫는다.
백업 검증은 전체 크기에 비례한 시간이 필요하지만 첫 프로그램 시작 조건에 추가하지 않는다.

## 6. 수용 검사

세 종류/이름·메모·보관명/같은 시각-ID 페이지/문자 LIKE/휴지통·해제/기간·확장자,
보관 자료 삭제 후 검색 제외, 보관 파일 안전 열기/저장 라우팅을 검사한다.
실제 백업의 현재·버전·snapshot-only·recovery/구형 형식, 손상·경로·중복·지원 불가,
동명 번호 저장·출처 교체·대상 권한/공간·취소·큰 파일 스트리밍·닫기 worker 해제를 검사한다.
전체 회귀/정적 타입·스타일 검사와 새 화면의 작은 창·밝은/어두운 palette 렌더링을 기록한다.
회사 DRM/모든 문서 앱·장기간/실제 OS 배율은 미검증이면 명시한다.
